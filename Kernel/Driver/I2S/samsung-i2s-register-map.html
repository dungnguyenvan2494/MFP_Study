Samsung I2S Register Map

Biến i2s-regs.h từ một danh sách #define thành bản đồ chức năng: mỗi bit làm gì trong silicon khi = 0 và khi = 1, hàm nào trong i2s.c ghi nó, và ghi ở bước nào của một phiên playback.

Xương sống: I2SMOD (format + clock, R/W hoàn toàn) → I2SPSR (một bộ chia) → I2SCON (enable + status + DMA, nửa đọc nửa ghi) → FIFO / I2STXD/I2SRXD → iDMA (I2SAHB). Hiểu 3 cái đầu là hiểu ~80% i2s.c.

4I2SPSR — một bộ chia, hai bit đáng nhớ

I2SPSR chỉ làm một việc: chia clock nguồn xuống RCLK (chính là MCLK nội). Chỉ ghi ở config_setup(), và chỉ khi không slave.

source (op_clk) ──► I2SPSR (÷ psr) ──► MCLK/RCLK ──► ÷ RFS ──► LRCLK = Fs └──────────► BCLK (= BFS × LRCLK, từ I2SMOD BFS) Ví dụ Fs = 48 kHz · RFS = 256 · BFS = 32 · source = 49.152 MHz LRCLK = 48 000 Hz BCLK = 32 × 48 000 = 1.536 MHz MCLK = 256 × 48 000 = 12.288 MHz psr = source / Fs / RFS = 49 152 000 / 48 000 / 256 = 4 ghi = ((psr − 1) << 8) | PSR_PSREN = (3 << 8) | (1 << 15) = 0x8300
  • Protocol quyết định: LRCLK = Fs, MCLK = RFS·Fs, BCLK = BFS·Fs.
  • Machine driver quyết định: chọn RFS (256), có khi ép BFS; đặt rclk_srcrate qua clk_set_rate.
  • Samsung hardware quyết định: tập RFS/BFS hợp lệ, có mux+prescaler hay không (QUIRK_NO_MUXPSR — v3 không có, nên bỏ qua nhánh ghi PSR).
  • Ghi vào I2SPSR: chỉ giá trị psr − 1 ở [13:8] và PSR_PSREN ở [15]. Phần còn lại là hệ quả.

5FIFO & I2STXD — memory hay register?

Register. I2STXD là một ô nhớ MMIO tại địa chỉ vật lý cố định regs_base + 0x10. Ghi vào đó = đẩy một word vào hàng đợi FIFO trên chip. Đó là lý do DMA nhận dma_playback.addr = regs_base + I2STXD và ghi không tăng địa chỉ.

7Register write timeline — một phiên playback

Đọc i2s.c như state machine của phần cứng: mỗi pha ghi vào lane nào, đổi bit gì. ● ghi · ○ đọc.

★Samsung I2S Hardware Architecture

Ba đường tách biệt trên một hình: clock (nguồn → PSR → MCLK → RFS/BFS → BCLK/LRCLK), data (RAM → DMA → I2STXD → FIFO → serializer → SDATA), control (CPU writel() → 3 register). Trên mỗi khối: register + hàm Linux.

9Boss level — phát 1 sample, chỉ bằng register

Không dùng khái niệm ASoC. Chỉ CPU, DMA, RAM và các thanh ghi. Đây là điều i2s.c thực sự làm bên dưới lớp callback.

SETUP (một lần) 1. ioremap vùng SFR → base 2. bật clock lõi "iis" + nguồn op_clk 3. I2SCON |= CON_RSTCLR ; nhả reset khối 4. I2SFIC |= FIC_TXFLUSH ; chờ ~1µs ; &= ~FIC_TXFLUSH ; FIFO sạch 5. I2SMOD : SDF=IIS LRP=0 MSS=0 ; khung I2S, CPU là master BLCP=16bit ; mẫu 16-bit RFS=256FS BFS=32FS ; MCLK=256·Fs, BCLK=32·Fs CDCLKCON=0 ; phát MCLK ra chân codec 6. psr = op_clk_rate / (48000 · 256) I2SPSR = ((psr-1) << 8) | PSR_PSREN ; chốt MCLK = 12.288 MHz CHẠY 7. DMA: src = &buffer_RAM (tăng) ; dst = base + I2STXD (cố định) width = 4 byte ; chế độ cyclic 8. dmaengine issue → DMA bắt đầu chép RAM → I2STXD 9. I2SMOD TXR = TXONLY 10. I2SCON |= CON_ACTIVE | CON_TXDMA_ACTIVE I2SCON &= ~CON_TXDMA_PAUSE & ~CON_TXCH_PAUSE → serializer bắt đầu tạo BCLK/LRCLK → khối kéo "DMA request" mỗi khi FIFO còn chỗ → DMA ghi word vào I2STXD → TX FIFO → serializer dịch từng bit ra SDATA theo ↓BCLK → receiver (codec) chốt bit ở ↑BCLK (lặp: FIFO đầy → CON_TXFIFO_FULL=1 → request nghỉ; FIFO vơi → request lại) DỪNG 11. I2SCON |= CON_TXDMA_PAUSE ; &= ~CON_TXDMA_ACTIVE 12. nếu không còn hướng nào chạy: I2SCON &= ~CON_ACTIVE 13. I2SFIC |= FIC_TXFLUSH (rồi clear) ; bỏ mẫu thừa 14. dmaengine terminate
