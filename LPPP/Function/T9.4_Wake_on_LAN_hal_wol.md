## 1. Phần cứng: Wake-Up Frame Unit trong GMAC (mô hình SysKonnect/Yukon-2 "YEC")

Nằm trong GMAC (Iris SB0, T5.1). Thanh ghi chính **`ETH_FILT_CSR_0`** (16-bit, trong IO_WRAP), bit:
| bit | ý nghĩa |
|-----|---------|
| `MP_EN` / `MP_DIS` | bật/tắt Magic Packet detect |
| `LNK_UP_EN` / `LNK_UP_DIS` | bật/tắt wake-on-link-up |
| `PATM_EN` / `PATM_DIS` | bật/tắt **Pattern Match Unit** (ARP/Unicast/SDK) |
| `PATM_PME_EN` / `MP_PME_EN` / `LNK_UP_PME_EN` | (`#ifdef HAVE_GBE_PME_INT`) sinh **PME** khi khớp — cần cho `PATM_STAT` hoạt động dù global PME tắt |
| `PATM_STAT` | trạng thái pattern nào vừa khớp |

**Pattern RAM**: `YEC_PATTRAM_CLUSTER_SIZE = 64` cluster × `YEC_PATTRAM_CLUSTER_WORDS = 4` word. Ghi qua `HalWol_PatternRegWrite(offset, lo, hi)` — Yukon-2 ghi 128-bit nên phải RMW (đọc 64-bit kia rồi ghi lại). Phải `HalWol_WolUnitDisable()` (`PATM_EN=0`) trước khi ghi pattern RAM, `HalWol_WolUnitEnable()` sau.

## 2. `WolMode_t g_wolMode` (`base_api.h:228`)

```c
typedef uint32_t WolMode_t;
#define WOL_MODE_MAGIC_PACKET  (1<<0)
#define WOL_MODE_LINK_ACT      (1<<4)   // wake on PHY link up
#define WOL_MODE_ARP           (1<<8)
#define WOL_MODE_UNICAST       (1<<12)
#define WOL_MASK_USE_PATTERN_FILTER  (WOL_MODE_ARP | WOL_MODE_UNICAST)
```

- **Linux đặt** qua HCI FIFO command `FW_MSG_CMD_NETWORK_WOL_MODE_WRITE` (`FW_MSG_CMD_NETWORK | 0x26`).
- **`SysHostcmd_Hello()` đặt `g_wolMode = 0`** (T6 §7.1) — khi driver Linux lên, tắt HW WoL (driver tự lo). Khi `Goodbye`, Linux đã ghi `g_wolMode` mong muốn trước đó.

## 4. Bốn kiểu wake HW

### 4.1 Magic Packet — `HalApiWol_EnableWakeOnMagicPacket()` (`:252`)
```c
ETH_FILT_CSR_0.MP_EN = 1; MP_DIS = 0;   (+ MP_PME_EN nếu HAVE_GBE_PME_INT)
// target MAC = MAC của mình:
tmphi = MV_IN32(ETH_CFG_MADDR_HI);  tmplo = MV_IN32(ETH_CFG_MADDR_LO);
MV_OUT32(ETH_MP_MADDR_LO, tmphi);   MV_OUT32(ETH_MP_MADDR_HI, tmplo);   // (đảo hi/lo — endian)
```
HW dò khung có 6×`0xFF` + 16×MAC → wake. **Không cần CPU.**

### 4.2 Wake-on-Link — `HalApiWol_EnableWakeOnLink()` (`:360`)
`ETH_FILT_CSR_0.LNK_UP_EN = 1` — wake khi PHY link chuyển up (cắm cáp). `HalApiWol_DisableWakeOnLink` kiểm `ethernet_not_accessible` trước.

### 4.3 Wake-on-ARP — `HalApiWol_EnableWakeOnArp()` (`:295`)
- lần đầu: lấy IPv4 của mình (`SysApiLan_IPv4AddressGet`), nhét vào `ArpPattern.data + ARP_PATTERN_ADDR_OFFSET` (byte 12-13...), `HalWol_PatternSet(PATTERN_ARP, &ArpPattern)`, `valid_patterns |= (1<<PATTERN_ARP)`.
- `HalWol_EnablePattern(PATTERN_ARP)`.
- `ArpPattern` = `{sizeof(ARP_FRAME_PATTERN), ARP_FRAME_PATTERN, ARP_PATTERN_MASK}` — khung ARP request hỏi IP của mình.

### 4.4 Wake-on-Unicast — `HalApiWol_EnableWakeOnUnicast()` (`:327`)
- `UnicastPattern.data` = 6 byte = MAC của mình (`UNICAST_FRAME_PATTERN[6]`), mask `{0x3f}` (so 6 byte đầu = dst MAC).
- `HalWol_PatternSet(PATTERN_UNICAST, ...)`, `HalWol_EnablePattern`.
- ⇒ bất kỳ frame unicast tới MAC mình → wake.

### 4.5 SDK Pattern — `HalApiWol_SDKPatternEnable()` (`:491`) — **placeholder**
```c
dbg_in("Unexpected call!!");   // log cảnh báo
...
if (swap_mode) HalWol_swap_pfu_on();
else { HalApiWol_PatternSet(PATTERN_SDK, &SdkPattern); HalApiWol_PatternEnable(PATTERN_SDK); }
```
`SdkPattern` = `FW_SDK_FRAME_PATTERN[8]` **toàn 0**, mask **toàn 0** ⇒ khớp mọi thứ / không có ý nghĩa. `PATTERN_SDK` được enable "special" (`HalWol_enable_pattern(Id, false)` — tham số khác 3 pattern kia). Comment "Unexpected call!!" ⇒ đường này **không dùng bình thường** trên S800.

## 5. `HalApiWol_WakeSystem()` (`:189`) — thực thi wake khi HW phát hiện

```c
WakeSystem_count++;
wake_in_progress = true;
HalChip_enter_wakeup_mode();     // chip vào chế độ wakeup
HalEth_force_pme();              // ép PME (Power Management Event) trên GMAC → tín hiệu wake ra ngoài
return false;
```
PME → tín hiệu phần cứng đánh thức PMU/A72 (không qua `SYS_EVENT_WAKE_SYSTEM` của R4 — đây là đường HW thuần, R4 có thể đang ngủ sâu).

`HalApiLan_wol_detected` (bool toàn cục) — set khi HW WoL frame được dò; **reset trong `SysSystem_handle_link_events(DRIVER_GOODBYE)`** (T6 §7.3: `HalApiLan_wol_detected = false`) và khi `SysLan_setup_gigabit_core`.

## 6. Hai tầng WoL (tổng hợp với T5.2 / T5.6)

| tầng | ở đâu | cơ chế | khi nào |
|------|-------|--------|---------|
| **A — HW Wake-Up Frame Unit** | GMAC/Iris (`hal_wol.c`, `ETH_FILT_CSR_0` + pattern RAM) | Magic Packet / Link / ARP / Unicast → **PME** → wake PMU trực tiếp | R4 ngủ sâu (Sleep2/ErP), `g_wolMode` do Linux đặt trước khi ngủ |
| **B — SW `filter_function_magic_packet`** | R4 SysFilter STAGE_1 (callback 0, T5.6) | quét 6×0xFF + 16×MAC trong `low_level_input` → ActionFlags `DISCARD\|FORWARD\|WAKE_SYSTEM` | R4 còn chạy (đang proxy), bắt magic packet mà tầng A bỏ lỡ + forward gói lên Linux |

Khi đi ngủ sâu, R4 dựa tầng A (không cần CPU). Khi R4 còn tỉnh làm net-proxy, tầng B là lưới an toàn.

## 7. FACT / INFERENCE / UNKNOWN

- **FACT**: `ETH_FILT_CSR_0` bit `MP_EN/DIS`, `LNK_UP_EN/DIS`, `PATM_EN/DIS`, `*_PME_EN`; pattern RAM 64×4 word, ghi 128-bit RMW, disable `PATM_EN` khi ghi; `g_wolMode` bit values; `HalApiWol_Enable` phân nhánh theo `g_wolMode`; magic packet target MAC = MAC mình (`ETH_MP_MADDR` ← `ETH_CFG_MADDR` đảo hi/lo); ARP pattern nhét IPv4 mình; Unicast pattern = MAC mình mask 0x3f; `SdkPattern` toàn 0 + log "Unexpected call!!"; `HalApiWol_WakeSystem` = `HalChip_enter_wakeup_mode` + `HalEth_force_pme`; `SysHostcmd_Hello` set `g_wolMode = 0`; `HalApiLan_wol_detected` reset trong GOODBYE.
- **FACT**: `g_wolMode` set qua `FW_MSG_CMD_NETWORK_WOL_MODE_WRITE` (`FW_MSG_CMD_NETWORK | 0x26`) từ Linux.
- **INFERENCE**: `HAVE_GBE_PME_INT` có định nghĩa (PME path được dùng) — vì `HalApiWol_WakeSystem` gọi `HalEth_force_pme` và comment "req'd for PATM_STAT to function". Chưa xác nhận macro.
- **INFERENCE**: `HalApiWol_SDKPatternEnable`/`PatternEnable` in "Unexpected call!!" ⇒ trên S800 chỉ dùng Magic/Link/ARP/Unicast, không dùng SDK generic pattern (cái đó là `SysFilter` STAGE_2 lo — T5.4). "swap_mode"/"FIRST_RX_PFU"/"PFU" (Pattern Filter Unit swap) chưa rõ.
- **UNKNOWN**: `ARP_FRAME_PATTERN`/`ARP_PATTERN_MASK`/`ARP_PATTERN_ADDR_OFFSET` bytes cụ thể; `ETH_FILT_CSR_0` địa chỉ tuyệt đối (trong IO_WRAP/LAN block); `HalWol_PatternInit` (xoá 64×4 = 256 word pattern RAM về 0); `HalChip_enter_wakeup_mode` làm gì.
- **UNKNOWN**: ai gọi `HalApiWol_WakeSystem` (ISR PME? polling?) — HW hay firmware. `WakeSystem_count`/`wake_in_progress` dùng ở đâu.
- **UNKNOWN**: `HalApiWol_Init` được gọi ở đâu trong luồng đi ngủ (chắc trong TR/`pmu_phase` suspend).

## Tóm tắt (theo format skill)

**WoL trên S800 có 2 tầng.** Tầng phần cứng (`hal_wol.c`) lập trình Wake-Up Frame Unit trong GMAC (Iris) qua `ETH_FILT_CSR_0` + pattern RAM 64×4: bật Magic Packet detect (target = MAC mình), wake-on-link-up, và 2 pattern (ARP request hỏi IP mình / mọi unicast tới MAC mình). `g_wolMode` (bitmask MAGIC/LINK/ARP/UNICAST) do Linux ghi qua HCI FIFO command `0x26` trước khi ngủ; `SysHostcmd_Hello` xoá nó về 0 khi driver lên. Khi HW dò được khung khớp → `HalEth_force_pme()` phát PME đánh thức PMU/A72 **không cần CPU R4** — dùng khi R4 ngủ sâu Sleep2/ErP. Tầng phần mềm là `filter_function_magic_packet` (SysFilter STAGE_1, T5.6) làm lưới an toàn khi R4 còn tỉnh chạy net-proxy: quét 6×0xFF+16×MAC rồi forward + `SYS_EVENT_WAKE_SYSTEM`. Pattern "SDK" generic không dùng ở đây (log "Unexpected call!!") — pattern động do SysFilter STAGE_2 xử lý (T5.4).

**Bảng lifecycle (đi ngủ với WoL magic):**
| bước | hàm |
|------|-----|
| Linux (trước sleep) | HCI `FW_MSG_CMD_NETWORK_WOL_MODE_WRITE` → `g_wolMode = WOL_MODE_MAGIC_PACKET` |
| TR đi ngủ | `HalApiWol_Init` → `Disable` → `Enable` → `HalApiWol_EnableWakeOnMagicPacket` → `ETH_FILT_CSR_0.MP_EN=1`, `ETH_MP_MADDR` ← MAC mình |
| R4 wfi, DDR self-refresh | — |
| PC gửi magic packet | GMAC WUF dò → `HalApiWol_WakeSystem` → `HalChip_enter_wakeup_mode` + `HalEth_force_pme` → PME → PMU wake A72 |
| thức | `SysHostcmd_Hello` → `g_wolMode = 0`; `handle_link_events(GOODBYE?)`... `HalApiLan_wol_detected = false` |
