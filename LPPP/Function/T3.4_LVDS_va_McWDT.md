## PHẦN A — LVDS power-down

### 1 · LVDS là gì

**LVDS = Low-Voltage Differential Signaling** — 8 cặp pad truyền tín hiệu video tới **print head**
của engine in: **4 màu Y/M/C/K × 2 engine (ENG0/ENG1)**. Khi engine không in, tắt transceiver
LVDS để tiết kiệm điện.

**Hoàn toàn độc lập với Sleep1/2/ErP** — chiếm 2 cột (8/9) trong ma trận `fpLPPP_ScenarioFunc`
nhưng `LPPP_LVDS_Interrupt`/`LPPP_LVDS_Timer` **luôn trả `state` không đổi** (`LPPP_Matrix.c:405,422`).
Chỉ mượn cơ chế queue/dispatch của ma trận.

### 2 · Thanh ghi (`LPPP_Task.c:29-39`)

```c
#define LPPP_Y_ENG0_P_PIOCFG  0xE8308440   // Yellow  ENG0
#define LPPP_Y_ENG1_P_PIOCFG  0xE8308444   // Yellow  ENG1
#define LPPP_M_ENG0_P_PIOCFG  0xE8308448   // Magenta ENG0
#define LPPP_M_ENG1_P_PIOCFG  0xE830844C   // Magenta ENG1
#define LPPP_C_ENG0_P_PIOCFG  0xE8308450   // Cyan    ENG0
#define LPPP_C_ENG1_P_PIOCFG  0xE8308454   // Cyan    ENG1
#define LPPP_K_ENG0_P_PIOCFG  0xE8308458   // blacK   ENG0
#define LPPP_K_ENG1_P_PIOCFG  0xE830845C   // blacK   ENG1
#define LPPP_MASK_PWRDN       (1<<25)       // bit 25 = PWRDN của pad LVDS
#define LPPP_LVDS_PERIOD      10            // × 10ms = 100ms mỗi lần poll
#define LPPP_LVDS_FIXED       5             // 5 mẫu liên tiếp = chốt
```

8 địa chỉ = `PADWRAP_AON_PIOCFG_BASE (0xE8308000) + 4×pad`, ứng với **pad 272–279** (ngay sau
272 pad thường — `AP_AP_APB_PADRING_PADS = 272` trong `regAddrs.h`, T0.3 §3).

### 3 · `LPPP_LVDS_PowerDown(bool pd)` (`LPPP_Task.c:67-80`)
```c
uint32_t value = pd ? LPPP_MASK_PWRDN : 0;
mrvl_regrdmwr32(<reg>, LPPP_MASK_PWRDN, value);   // ×8 — RMW, chỉ đụng bit 25
```
`pd == true` → set bit 25 (tắt transceiver); `false` → clear (bật).

### 4 · Vòng lặp tự khởi động rồi tự tắt

```
① GPIO XEN_LVDS_ENG (pin 224, EITHER_EDGE, INPUT) đổi cạnh
     → GPIO ISR → LPPP_GPIO_AnalyzeEventfromISR: case XEN_LVDS_ENG → LPPP_INTERNALEVT_LVDS_INTERRUPT
       (VÔ ĐIỀU KIỆN, mọi cạnh — LPPP_Gpio.c:273-274)
     → xQueueSendFromISR(gst_MsgQHandle_PowerCtrl, LVDS_INTERRUPT)
     → PwEvtMgr → fpLPPP_ScenarioFunc[*][8] = LPPP_LVDS_Interrupt → LPPP_LVDS_Polling(reset=true)
          lvds_timer_active = true;  lvds_count = 0;         ← "BẬT MÁY BƠM"
② tick ISR mỗi 10ms:  HalApiCpuTimer_UpdateTickCount(false) → LPPP_LVDS_tick()   [hal_cputimer.c:153]
     if (lvds_timer_active) { lvds_tick_cnt++;
        if (lvds_tick_cnt >= LPPP_LVDS_PERIOD/*10*/):        ← đủ 100ms
           xQueueSendFromISR(gst_MsgQHandle_PowerCtrl, LVDS_TIMER);   [OP_BTS-22999 fix]
           lvds_tick_cnt = 0; } }
③ PwEvtMgr → fpLPPP_ScenarioFunc[*][9] = LPPP_LVDS_Timer → LPPP_LVDS_Polling(reset=false)
     lvds_cur = LPPP_GPIO_Read(XEN_LVDS_ENG)
     if (lvds_last != lvds_cur)  lvds_count = 0;   else  lvds_count++;   ← chống rung
     lvds_last = lvds_cur;
④ if (lvds_count >= LPPP_LVDS_FIXED/*5*/):          ← 5 × 100ms = 500ms chốt
     if (lvds_value != lvds_cur):                    ← chỉ khi đổi so với lần chốt trước
        lvds_value = lvds_cur;
        lvds_cur == 0 ? "LVDS ON"  → LPPP_LVDS_PowerDown(false)   (bật transceiver)
                      : "LVDS OFF" → LPPP_LVDS_PowerDown(true)    (tắt 8 pad, bit 25)
     lvds_timer_active = false;  lvds_count = 0;      ← "TẮT MÁY BƠM", quay lại ①
```

**Tổng chống chattering = `LPPP_LVDS_PERIOD × LPPP_LVDS_FIXED` = 10 tick × 5 = 500ms**
(khớp comment `/* チャタリング500ms */`). Mỗi cạnh XEN bơm ~5–6 `LVDS_TIMER` vào queue 20 slot
(`PowerControlEventManager.md §8.2` cảnh báo đây là nguồn tải chính của queue nếu tín hiệu rung).

### 5 · Context & điểm nguy hiểm

| Hàm | Context | Ghi chú |
|---|---|---|
| `LPPP_LVDS_tick` | **ISR tick** (10ms), qua `HalApiCpuTimer_UpdateTickCount(do_only_timekeeping=false)` | `xQueueSendFromISR`; `portYIELD_FROM_ISR`/`taskYIELD` theo `HalApiCpu_is_irq_mode()` |
| `LPPP_LVDS_Polling` | **task** `PwEvtMgr` (qua matrix) | static `lvds_last/value/count` — an toàn vì cả 2 đường (`Interrupt`/`Timer`) đều chạy trong `PwEvtMgr` (serialize) |
| `lvds_timer_active` | **ghi** bởi `LPPP_LVDS_Polling` (task), **đọc** bởi `LPPP_LVDS_tick` (ISR) | 🟡 không khoá — race nhẹ trên `bool`, worst case 1 tick thừa/thiếu |

`LPPP_GPIO_XEN_LVDS_ENG` = **pin 224**. Là 1 trong **chỉ 2 chân** được `LPPP_GPIO_Setting`
(`LPPP_Gpio.c:557`) attach ISR (chân kia = `POWER_MONITOR`). Mọi chân input khác bị `gpio_close`.

## PHẦN B — `LPPP_McWDT.c` (69 dòng)

### 1 · Machine Control (M3) watchdog

`INTNUM_MC_WDT = 93 + INTRL_GIC_OFFSET(32)` = **SPI 93 / GIC 125** (`intnums.h:134`). Đây là
**dây ngắt riêng** từ watchdog của lõi **M3 (Machine Control)** — KHÁC `MC_LPP_IRQ0/1` (SPI 128/129).

### 2 · Ba hàm

```c
static uint32_t mc_wdt_flg = MC_WDT_NONE;   // 0

void LPPP_McWDT_init(void) {                 // gọi từ hal_main.c:139 (main giai đoạn 5)
    intAttach(INTNUM_MC_WDT, 0, LPPP_McWDT_handler, INTNUM_MC_WDT);
    intEnable(INTNUM_MC_WDT);
}

static void LPPP_McWDT_handler(uint32_t isr_input) {
    intDisable(isr_input);                    // ★ ONE-SHOT — tự tắt chính mình
    ApiSysDebug_Printf(-1, -1, "LPPP_McWDT_handler(isr %d) call!!\n", isr_input);
    mc_wdt_flg = MC_WDT_ENTER;                // = 1
}

uint32_t LPPP_get_McWDT_status(void) {
    return mc_wdt_flg;                        // KHÔNG BAO GIỜ xoá — set 1 lần là kẹt 1
}
```

### 3 · Hành vi

- M3 watchdog nổ → ngắt SPI 93 → `LPPP_McWDT_handler`: **tắt ngắt (one-shot)**, đặt `mc_wdt_flg = 1`.
- **R4 KHÔNG hành động gì** — không reset M3, không reset AP, chỉ ghi nhớ.
- `mc_wdt_flg` sticky (không hàm nào clear).
- Linux đọc qua SCPI `0x8A` → `SCPIGetPmuEvent()` (T2.6 §0):
  ```c
  if (LPPP_get_McWDT_status()) event |= KM_SCPI_PMU_MC_WDT;  // = 0x01
  ```
  → `mdels800_pmu.c` `PMU_IOCSGET_WDT_MC` → `if (event & PMU_EVENT_MC_WDT) printk("MC WDT happened.")`.

⇒ Vai trò của `LPPP_McWDT` = **đầu dò báo cáo**: R4 phát hiện M3 treo, báo Linux qua SCPI `0x8A`,
để Linux/ứng dụng quyết định xử lý (M3 do phần khác điều khiển — firmware M3 không trong repo).

## 4 · Tóm tắt (theo format skill)

**1. Tồn tại để làm gì:**
- **LVDS:** máy trạng thái con độc lập nguồn — cạnh GPIO `XEN_LVDS_ENG` (pin 224) bật "máy bơm",
  tick ISR bơm `LVDS_TIMER` mỗi 100ms, qua `PwEvtMgr` → `LPPP_LVDS_Polling` lọc rung 500ms
  (5 mẫu × 100ms), khi chốt thì ghi bit 25 vào 8 thanh ghi PIOCFG `0xE8308440–0x5C` (Y/M/C/K ×
  ENG0/1) để tắt/bật transceiver LVDS tới print head.
- **McWDT:** đầu dò one-shot — bắt ngắt watchdog của lõi M3 (SPI 93), đặt cờ sticky, báo Linux
  qua SCPI `0x8A`. R4 không tự xử lý.

**2. Call flow LVDS:**
```
GPIO XEN_LVDS_ENG edge → GPIO ISR → LVDS_INTERRUPT → gst_MsgQHandle_PowerCtrl
   → PwEvtMgr → LPPP_LVDS_Interrupt → LPPP_LVDS_Polling(true)  [lvds_timer_active=1]
tick ISR /10ms → HalApiCpuTimer_UpdateTickCount(false) → LPPP_LVDS_tick
   → mỗi 10 tick → xQueueSendFromISR(LVDS_TIMER)
   → PwEvtMgr → LPPP_LVDS_Timer → LPPP_LVDS_Polling(false)  [đếm chống rung]
   → sau 5 lần giống nhau (500ms) → LPPP_LVDS_PowerDown(0/1) → 8× mrvl_regrdmwr32(bit25)
                                    → lvds_timer_active=0  (dừng bơm)
```

McWDT:
```
M3 WDT nổ → SPI 93 → LPPP_McWDT_handler [intDisable self + mc_wdt_flg=1]
Linux → SCPI 0x8A → SCPIGetPmuEvent → LPPP_get_McWDT_status → bit KM_SCPI_PMU_MC_WDT (0x01)
```

**4. Đã xác nhận:**
- ✅ 8 reg PIOCFG `0xE8308440–0x5C` = pad 272-279 (Y/M/C/K × ENG0/1), bit 25 = PWRDN.
- ✅ Chống rung = `LPPP_LVDS_PERIOD(10) × LPPP_LVDS_FIXED(5)` = 500ms.
- ✅ `LPPP_LVDS_tick` chạy trong **tick ISR** (từ `hal_cputimer.c:153`, `do_only_timekeeping=false`).
- ✅ `XEN_LVDS_ENG` = pin 224, EITHER_EDGE, 1/2 chân duy nhất có ISR (kia = `POWER_MONITOR`).
- ✅ `INTNUM_MC_WDT` = SPI 93 (khác `MC_LPP_IRQ0/1` = SPI 128/129).
- ✅ `LPPP_McWDT_handler` one-shot (`intDisable(isr_input)`), `mc_wdt_flg` sticky, R4 không hành động — chỉ báo Linux qua `0x8A`.
- 🟡 `lvds_timer_active` ghi bởi task, đọc bởi ISR — không khoá (race nhẹ trên bool).
