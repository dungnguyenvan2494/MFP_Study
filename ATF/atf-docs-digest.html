01firmware-design.md

docs/firmware-design.md — 15 phần, ~2210 dòng · tài liệu trục

Cold boot — 5 stage (AArch64)

  • BL1 AP Trusted ROM — chạy từ reset vector ở EL3 (thường trong Trusted ROM); .data copy sang Trusted SRAM lúc chạy. Dựng vector ngắt tối giản, gọi reset_handler(), set SCTLR_EL3/SCR_EL3/CPTR_EL3/DAIF, bật watchdog + console + coherency + MMU, cấu hình storage, dò FWU vs boot thường, nạp BL2, truyền meminfo qua bộ nhớ, chuyển sang BL2 ở S-EL1.
  • BL2 Trusted Boot Firmware — S-EL1. Init kiến trúc tối thiểu (mở FP/SIMD cho EL1/EL0), console, storage, MMU, security setup; nạp lần lượt SCP_BL2 (nếu có) → BL31 → BL32 (nếu có) → BL33; điền vùng bộ nhớ chứa entry_point_info/SPSR cho BL31/BL32/BL33; raise SMC về BL1 với entrypoint BL31.
  • BL1 (lần 2) — tắt MMU + flush cache (SCTLR_EL3.M/I/C), invalidate TLB, nhảy BL31 ở EL3.
  • BL31 EL3 Runtime Software — chạy hoàn toàn trong Trusted SRAM. Init lại kiến trúc (đè BL1), dựng per-CPU data framework, thay vector bằng bộ xử lý SMC đầy đủ, set CNTFRQ_EL0, init GIC + power controller + topology, runtime_svc_init(), (nếu có SPD) init BL32, rồi dựng context EL2/EL1 non-secure và eret vào BL33 ở EL cao nhất (EL2 nếu có).
  • BL33 Non-trusted Firmware — U-Boot/UEFI… ở thế giới thường.

AArch32: bỏ BL31, BL32 (ví dụ SP-MIN) đóng vai EL3 Runtime Software; BL1 lo init kiến trúc cho cả BL2 (cùng PL1).

Giao diện cold-boot của BL31 (dùng Trusted Boot Firmware thay thế)

Vào bl31_entrypoint(): PSTATE.EL=3, RW=1, DAIF=0xf, SCTLR_EL3.EE=0. X0 = thông tin chung TF (quy ước: con trỏ bl31_params), X1 = thông tin riêng nền tảng. BL31 không phụ thuộc MMU/cache/coherency lúc vào — phải tự bật trong bl31_plat_arch_setup(). Cấu trúc dùng chung có param_header (type/version/size/attr) để tương thích ngược — dùng SET_PARAM_HEAD().

Warm boot: PSCI cung cấp entry-point warm-boot, gọi ngay sau reset handler, cùng điều kiện thanh ghi như trên.

Framework runtime service EL3 (mục 3)

Phần mềm dưới EL3 (NS hoặc S) gọi dịch vụ qua SMC theo SMCCC. Service khai báo bằng DECLARE_RT_SVC() → sinh struct rt_svc_desc trong section ELF rt_svc_descs. runtime_svc_init() (BL31, primary CPU, cold boot) duyệt và gọi init() từng service; nếu init() ≠ 0 thì service bị bỏ (không dừng firmware). Bảng rt_svc_descs_indices[128] ánh xạ mọi tổ hợp OEN/call-type → service.

PSCI (mục 4)

PSCI là thư viện tích hợp với EL3 RT SW cho ARMv8-A. Đã cài toàn bộ API bắt buộc PSCI v1.0 + toàn bộ PSCI v0.2.

SPD & BL32 (mục 5)

Trusted OS = BL32 = Secure-EL1 Payload, ghép với một SPD (Secure Monitor chạy như runtime service) lo init + mọi giao tiếp. SPD lấy thông tin qua bl31_plat_get_next_image_ep_info(SECURE), đăng ký hàm init bằng bl31_register_bl32_init(). Hai cách trao quyền BL32 trước BL33: (1) bl31_set_next_image_type() + thoát bất đồng bộ qua el3_exit(), BL32 xong thì SMC về SPD; (2) SPD tự “world-switch synchronous call” vào S-EL1. TF kèm ví dụ TSP + TSPD.

Crash reporting (mục 6)

Khi có exception không xử lý, BL31 dump toàn bộ GP + thanh ghi EL3/S-EL1/một phần EL2 ra UART riêng (PL011), dùng crash stack per-CPU lấy qua per-CPU pointer cache (crash_reporting.S). Bật theo CRASH_REPORTING (mặc định = DEBUG).

Reset handler (mục 7) & CPU-ops framework (mục 8)

  • reset_handler() gọi trong cả BL1 và BL31, cả cold & warm; gọi tiếp plat_reset_handler() + reset handler riêng CPU. Nếu hành vi lần đầu ≠ lần sau thì phải tự phát hiện lúc chạy.
  • Hành vi implementation-defined gom vào struct cpu_ops: midr, reset_func(), core_pwr_dwn(), cluster_pwr_dwn(), cpu_reg_dump(). Mỗi CPU một file trong lib/cpus/ (vd cortex_a72.S); platform makefile chọn file cần. reset_func() phải giữ nguyên x20–x29.
  • PSCI khi power-down chọn power level cao nhất rồi gọi prepare_core_pwr_dwn() / prepare_cluster_pwr_dwn() → handler CPU tương ứng; thêm hook nền tảng (vd tắt coherency CCI khi cluster power-down).

Bố cục ảnh BL (mục 9)

  • Mỗi ảnh = PROGBITS (có trên đĩa) + NOBITS (chỉ metadata, cấp phát lúc chạy). Linker gom PROGBITS trước, NOBITS sau → ảnh nhị phân nhỏ nhất.
  • Symbol linker chuẩn: __<SEC>_START__ / _END__ / _UNALIGNED_END__ / _SIZE__; bắt buộc: __BSS_START__ (căn 16B), __RO_START__/END__, __COHERENT_RAM_*. Riêng BL1: __DATA_ROM_START__, __DATA_RAM_START__, __BL1_RAM_START__/END__.
  • Không có nạp ảnh động — mọi ảnh link theo địa chỉ chạy cuối cùng. Nền tảng cấp base + limit; linker báo “BLx has exceeded its limit” nếu tràn. File map: build/<plat>/<type>/bl<x>/bl<x>.map.
  • LOAD_IMAGE_V2=0: có cơ chế chống ghi đè — nền tảng khai vùng (meminfo_t: base/size/free) qua bl1_plat_sec_mem_layout(), bl2_plat_get_{scp_bl2,bl32,bl33}_meminfo(); nạp theo kiểu top/bottom (phần nhỏ hơn bị đánh dấu unavailable). LOAD_IMAGE_V2=1: chỉ kiểm bounds theo base + max size do nền tảng khai.
  • Bố cục ARM dev-platform: 4 KB shared memory ở đáy Trusted SRAM (mailbox entrypoint CPU / payload MHU); EL3 RT SW nạp ở đỉnh Trusted SRAM, NOBITS của nó đè lên BL1 R/W → biến toàn cục BL1 chỉ hợp lệ tới lúc vào BL31. BL2 dưới BL31. BL32 có thể ở Trusted SRAM / Trusted DRAM / vùng DRAM TZC-secured.

FIP — Firmware Image Package (mục 10)

Một archive nạp từ non-volatile storage: ToC header → nhiều ToC entry → end marker → các khối payload. Mỗi entry: uuid (định danh ảnh, định nghĩa trong include/firmware_image_package.h), offset_address (tính từ base ToC), size, flags. Nền tảng dịch tên ảnh → UUID. Driver FIP ở lớp storage; chính sách nạp: plat_get_image_source(). Tool tools/fiptool.

Coherent memory (mục 11) & tách code/rodata (mục 12)

  • Mismatch thuộc tính bộ nhớ giữa các CPU (lúc bật/tắt MMU+cache dần trong power up/down) gây mất coherency. Mặc định TF để các struct nhạy cảm (psci_non_cpu_pd_nodes, bakery lock) trong vùng coherent memory — Device-nGnRE, 4 KB, Outer Shareable, non-cacheable. Tốn ≥ 1 trang.
  • USE_COHERENT_MEM=0 (nên dùng khi thiếu RAM): chuyển sang Normal WB cacheable + tự cache-maintenance. Bakery lock được thiết kế lại (bakery_info_t 1 CPU/lock, macro DEFINE_BAKERY_LOCK, linker nhân bản cho các core còn lại); có thể khai PLAT_PERCPU_BAKERY_LOCK_SIZE. Đo trên Juno: acquire lock ~3–4 µs (Normal) vs ~2 µs (Device).
  • SEPARATE_CODE_AND_RODATA=1: đẩy rodata sang trang riêng để rodata không bị executable chung trang với code. Thêm 0–1 trang/ảnh. Mặc định tắt; bật trên ARM platform.

PMF (mục 13) & cấu trúc mã (mục 14)

  • PMF: thu timestamp (CNTPCT_EL0) từ service đã đăng ký; PMF_REGISTER_SERVICE() / PMF_REGISTER_SERVICE_SMC(), PMF_CAPTURE_TIMESTAMP(), cờ PMF_STORE_ENABLE / PMF_DUMP_ENABLE / PMF_CACHE_MAINT; lấy qua PMF_GET_TIMESTAMP_BY_MPIDR/INDEX() hoặc pmf_smc_handler(). Bật theo ENABLE_PMF.
  • Mã chia theo: platform-specific / common / library (PSCI + framework runtime) / stage (bl1 bl2 bl31) / drivers / services. Bảng dùng: bl1,bl2,bl31 dùng đúng thư mục của mình; plat, common, lib dùng mọi stage; drivers dùng BL1+BL31; services chỉ BL31. File asm .S, linker .ld.S → GCC sinh .ld. Build option không cấu hình IMAGE_BLx cho từng stage.

02porting-guide.md

docs/porting-guide.md — hợp đồng plat_*, ~2245 dòng · phiên bản API mới (PSCI v1.0)

Hàm/biến khai trong include/plat/common/platform.h; bản mặc định weak để dễ port, mỗi port override khi cần. Muốn theo “ARM standard platform” thì dùng thêm plat/arm/common/. Mọi BL phải bật MMU + I/D-cache; dựng bảng trang bằng lib/xlat_tables/ (chỉ identity map cho code/data).

  • plat_macros.S — macro asm cho crash reporting.
  • plat_my_core_pos(), plat_core_pos_by_mpidr(mpidr) — chỉ số core 0..PLATFORM_CORE_COUNT-1; hàm sau phải validate MPIDR (trả −1 nếu sai).
  • Xử lý reset (mục 2.2): plat_get_my_entrypoint() [khi PROGRAMMABLE_RESET_ADDRESS==0] phân biệt cold/warm; plat_secondary_cold_boot_setup(), plat_is_my_cpu_primary() [khi COLD_BOOT_SINGLE_CPU==0]; platform_mem_init().
  • TBB: plat_get_rotpk_info(), plat_get_nv_ctr(), plat_set_nv_ctr().
  • Tùy chọn: plat_reset_handler(), plat_disable_acp(), plat_error_handler(), plat_panic_handler(), plat_report_exception(), stack (plat_set/get_my_stack()), và (LOAD_IMAGE_V2) plat_get_bl_image_load_info(), plat_get_next_bl_params(), plat_flush_next_bl_params().

Theo stage

  • BL1: bl1_early_platform_setup(), bl1_plat_arch_setup(), bl1_platform_setup(), bl1_plat_sec_mem_layout(), bl1_plat_mem_check() (bắt buộc); bl1_plat_get_next_image_id(), bl1_plat_get_image_desc(), bl1_plat_set_ep_info(), bl1_plat_prepare_exit(), bl1_plat_fwu_done() (tùy chọn).

PSCI trong BL31 (mục 3.5)

Ngắt (mục 3.6) & crash console (mục 3.7)

03user-guide.md

docs/user-guide.md — build & chạy, ~1447 dòng

Host & toolchain

  • Test trên Ubuntu 14.04 (64-bit); cũng build được trên Windows 7 (Cygwin/MSYS, GCC 4.9.1). Gói: build-essential gcc make git libssl-dev; cross GCC AArch64 little-endian (Linaro). Tùy chọn: device-tree-compiler, DS-5.
  • export CROSS_COMPILE=…/aarch64-linux-gnu- rồi make PLAT=<platform> all (AArch64) hoặc make PLAT=fvp ARCH=aarch32 AARCH32_SP=sp_min all.
  • Ra build/<plat>/<debug|release>/bl{1,2,31,32}.bin. Thêm target fip để đóng gói. make … clean / make realclean.

Tool & luồng boot thay thế

  • tools/fiptool (thay fip_create cũ) tạo/liệt kê FIP; tools/cert_create (OpenSSL ≥ 1.0.1) sinh cert X.509 (DER) khi GENERATE_COT=1; cần mbedtls cho crypto + image parser trong TF.
  • EL3 payload (EL3_PAYLOAD_BASE): bỏ luồng boot thường, BL1 nhảy thẳng payload ở EL3 (nạp qua flash, SPIN_ON_BL1_EXIT + DS-5, hoặc preload).
  • Preloaded BL33 (PRELOADED_BL33_BASE): BL33 (vd bootwrapped kernel) đã nằm sẵn trong RAM, không đưa vào FIP.
  • Chạy FVP: cần FDT phù hợp (fdts/); có chế độ “reset to BL1” và “reset to BL31/SP_MIN” (nạp bl31.bin đúng địa chỉ chạy + đổi mọi CPU reset vector từ 0x0 sang địa chỉ đó).

05psci-lib-integration-guide.md + psci-pd-tree.md

docs/psci-lib-integration-guide.md (~535) · docs/psci-pd-tree.md (~295)

PSCI như một thư viện

PSCI Library cài chuẩn PSCI, tích hợp với EL3 Runtime Software (EL3 ở AArch64; Secure SVC/Monitor ở AArch32 — có thể kèm Trusted OS). Ở AArch64 dùng chung cpu_context_t với BL31; ở AArch32 cpu_context_t bị rút gọn chỉ cho PSCI CPU context, vì Trusted OS đã có cơ chế lưu/khôi phục context world-switch riêng.

  • Cold boot: EL3 RT SW init xong → psci_setup() (Monitor mode) → (tùy chọn) psci_register_spd_pm_hook() → psci_prepare_next_non_secure_ctx() → lấy cpu_context_t NS qua cm_get_context(), nạp thanh ghi, thoát NS.
  • Warm boot (D-cache chưa bật): psci_warmboot_entrypoint() (Monitor mode) — tự init/khôi phục context NS.
  • SMC PSCI: lưu context theo SMCCC → nếu FID là SMC32 PSCI thì gọi psci_smc_handler(smc_fid, x1..x4, …) — có thể không trở về (nếu power-down); nếu trở về thì nạp R0/X0 + khôi phục thanh ghi.
  • Interface (mục 4): psci_setup(), psci_prepare_next_non_secure_ctx(), psci_register_spd_pm_hook(), psci_smc_handler(), psci_warmboot_entrypoint(). Dependency EL3 RT SW (mục 5): API context (cm_get_context/cm_set_context…), platform API bắt buộc (plat_setup_psci_ops, plat_my_core_pos, plat_get_power_domain_tree_desc…), callback power-management của secure payload (svc_on/off/suspend + *_finish, svc_migrate_info).

Cây power-domain (psci-pd-tree.md)

Bỏ plat_get_aff_count()/aff_state() cũ. Nền tảng khai một mảng unsigned char plat_power_domain_tree_desc[]: phần tử đầu = số node ở mức cao nhất; mỗi phần tử sau = số con trực tiếp của một node. Tổng số con ở một mức = số phần tử cần đọc ở mức kế. MPIDR không dùng để dựng cây; mỗi core có chỉ số riêng 0..PLAT_CORE_COUNT-1, lấy qua plat_my_core_pos() / plat_core_pos_by_mpidr() (validate). Cây gồm hai mảng, đổ đầy bằng BFS trong psci_setup():

  • cpu_pd_node_t psci_cpu_pd_nodes[PLATFORM_CORE_COUNT] — { mpidr, parent_node }.
  • non_cpu_pd_node_t psci_non_cpu_pd_nodes[PSCI_NUM_NON_CPU_PWR_DOMAINS] — { cpu_start_idx, ncpus, parent_node, local_state, level, lock_index }, xếp [mức cao → mức 1].

06auth-framework.md + trusted-board-boot.md

docs/auth-framework.md (~921) · docs/trusted-board-boot.md (~251)

Kiến trúc module xác thực

Chia lớp: GEN/IO/PP (mã generic TF + IO framework + platform port khởi động quá trình, theo CoT từ ROT tới ảnh) ↔ AM (Authentication Module) ↔ CM (Cryptographic Module, API verify_signature / verify_hash, đăng ký bằng REGISTER_CRYPTO_LIB, dựa trên CL — thường mbedTLS) & IPM (Image Parser Module, đăng ký IPL theo định dạng — raw / X.509 — bằng REGISTER_IMG_PARSER_LIB, có check_integrity() + get_auth_param()). Phương thức xác thực: theo hash, theo chữ ký, theo non-volatile counter. CoT = mảng auth_image_desc_t liên kết nhau (drivers/auth/tbbr/tbbr_cot.c).

Chain of Trust (TBBR)

  • Gốc tin cậy ngầm: hash SHA-256 của ROTPK (trong thanh ghi trusted root-key) + ảnh BL1 (giả định trong ROM, không sửa được).
  • Cert theo X.509 v3, tự ký (không cần CA — tin cậy đến từ nội dung extension, không phải issuer), PKCS#1 SHA-256 + RSA 2048.
  • Key cert xác minh public key (dùng để ký content cert); content cert chứa hash một ảnh BL.
  • Khóa: ROT key (ký BL2 content cert + trusted key cert; public = ROTPK) · Trusted World key (ký key cert của SCP_BL2/BL31/BL32) · Non-trusted World key (ký key cert của BL33) · BL3-X key (ký content cert của từng ảnh).

09firmware-update.md

docs/firmware-update.md — ~357 dòng · một phần của TBBR

FWU = cập nhật firmware từ USB/UART/SD-eMMC/NAND/NOR/Ethernet vào NV memory, chạy được cả khi firmware hiện tại hỏng (chế độ recovery). Do BL1 điều phối. Phân vai: BL1 (phát hiện + khởi động FWU, copy ảnh NS→S, xác thực, world-switch); ảnh secure khác (init nền tảng cho FWU); ảnh NS (nạp firmware từ ngoài vào NS memory).

  • Mỗi ảnh/cert có ID duy nhất → bl1_plat_get_image_desc() trả image_desc_t: executable hay không (NS có được yêu cầu chạy ảnh secure sau khi auth?), secure/non-secure, base+size, entry_point_info_t, trạng thái FWU.
  • Máy trạng thái (BL1 giữ per-image; ảnh secure phức tạp hơn): RESET → COPYING → COPIED → AUTHENTICATED → EXECUTED → INTERRUPTED. Auth fail → về RESET.
  • Giao diện SMC của BL1: BL1_SMC_CALL_COUNT (0x0), BL1_SMC_UID (0x1), BL1_SMC_VERSION (0x3), BL1_SMC_RUN_IMAGE (0x4) (BL2 dùng để BL1 trao quyền BL31 — chỉ caller EL3); FWU_SMC_IMAGE_COPY (0x10), _AUTH (0x11), _EXECUTE (0x12), _RESUME (0x13), _SEC_IMAGE_DONE (0x14), _UPDATE_DONE (0x15) (gọi bl1_plat_fwu_done, không trở về). Lỗi: -EPERM / -ENOMEM / -EAUTH.
  • BL2U — ảnh FWU tương đương BL2, làm init nền tảng cho FWU (và tùy chọn bl2u_plat_handle_scp_bl2u()). Đóng gói riêng trong fwu_fip.bin.
