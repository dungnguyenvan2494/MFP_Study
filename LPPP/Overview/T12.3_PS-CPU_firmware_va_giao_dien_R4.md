## 1. PS-CPU là gì

**FACT.** **STM32F031C6** (Cortex-M0 / ARMv6-M) — **chip riêng trên power board**, không phải core trong Quartz SoC. I²C **slave, địa chỉ 7-bit `0x3E`** trên bus I²C1 của Quartz. Bare-metal super-loop, **không RTOS** (docs `02_architecture.md` §1).

**Hai image tách biệt:**
| image | ROM | kích thước | vai trò |
|-------|-----|-----------|---------|
| **Main** | `0x08000000` | 20 KB | giám sát nguồn thường trực |
| **IAP** | `0x08005000` | 12 KB | field firmware update (nhảy vào không reset khi nhận magic `0x11223344` ở reg `0x90`) |

**Phần cứng dùng:** I2C1 (slave), **RTC + backup domain** (pin nuôi — giữ giờ khi mọi thứ tắt), TIM3 (tick 1ms), IWDG, GPIO A/B/C/F, PWR (STOP/SLEEP), + **IO expander** ("extend I/O") cho GPIO phụ mà SoC điều khiển gián tiếp qua PS-CPU.

**Vai trò:** bộ giám sát nguồn **luôn sống** — chịu trách nhiệm:
- debounce công tắc nguồn chính (MSW), giám sát 24V / power-monitor qua ADC + anti-chattering (`km_it.c`),
- **máy trạng thái tuần tự bật/tắt nguồn** (`km_extend_io.c`, 1540 dòng: `s800_power_on`/`s800_power_off`, `mc_p_on_*_proc`, `sleep_status_rem_*_proc`, `ap_power_en_proc`),
- theo dõi trạng thái CA72 (`km_ca72_status.c`: `CA72_OFF` / `CA72_ON` / `CA72_SLEEP`),
- ghi log lý do tắt nguồn vào RTC backup register,
- RTC Alarm wake định kỳ (`km_alarm_wake.c`: `set_cycle_time` → RTC Alarm A),
- field update firmware (IAP).

## 2. Bản đồ register I²C (từ `main/Inc/km_i2c.h`) — góc nhìn R4/LPPP

I²C protocol: master (Quartz) ghi 1 byte "second address" rồi ghi/đọc data. FSM 3 trạng thái (`i2c_info.state` — docs `07_state_machines.md` §1.1).

| second_addr | tên | hướng | ý nghĩa | LPPP dùng ở |
|-------------|-----|-------|---------|-------------|
| `0x00`–`0x5E` | RTC_*_CMD | R/W | **truy cập trực tiếp thanh ghi RTC** của PS-CPU (TR/DR/CR/ISR/PRER/ALRMAR/WPR/BKP0-3R…). Quartz đọc/ghi giờ qua đây | LPPP đọc/set thời gian |
| `0x5E` | `B_REGISTER_PWROFF_LOG` (= `RTC_BKP3R_CMD_2`) | R | **log lý do tắt nguồn** (RTC backup reg giữ qua mất điện) | LPPP/Linux đọc sau boot |
| `0x60` | `INT_STS_COMMAND` | R | interrupt status |
| **`0x68`** | **`INTERNEAL_STS_COMMAND`** | **W (LPPP→PS-CPU) + R** | **trạng thái nội bộ / lệnh power-state**: bit0 `BOOT_STATES` (0=Cold, 1=Reboot), bit2 `MODEL_TYPE` (0=Eagle/Sparrow Ⅰ/Ⅱ, 4=Eagle3/Sparrow3) | `send_power_state_to_pscpu` (T4.2): ghi `0x00\|gen`=Normal, `0x02\|gen`=Boot, `0x01\|gen`=Sleep2/ErP; `gen=0x04` nếu Eagle3 |
| **`0x6C`** | **`INTERNEAL_CTL_COMMAND`** | **W (LPPP→PS-CPU)** | `CTRL_OFF=0x0001` (SLEEP_STATUS_REM OFF), `CTRL_ON=0x0002` (SLEEP_STATUS_REM ON) | `send_sleep_status_rem(0/1)` (T4.2, **chỉ Eagle3**) |
| `0x70` / `0x74` / `0x78` | `EXTEND_OUTPUT_READ` / `HIGH` / `LOW` | R/W | IO-expander: đọc / set-1 / set-0 các output GPIO phụ (cầu I²C↔GPIO) |
| `0x80` | `EXTEND_INPUT_COMMAND` | R | đọc input GPIO phụ |
| `0x88` / `0x8C` | `EXTEND_CHECKSUM` / `EXTEND_VERSION` | R | checksum / version firmware PS-CPU |
| `0x90`–`0x9A` | `IAP_PG_COMMAND*` | W | field update: ghi magic `0x11223344` vào `0x90` → `DeInit()`+`jump2iap()` (không reset HW) |
| `0xA0` | `IAP_PG_COMMAND_DATA` | W | dữ liệu chương trình (IAP) |
| `0xB0` / `0xB4` / `0xB8` / `0xBC` | `EXTEND_PWROFF_WDGTIME_SET` / `TIMEOUTLOG_GET` / `TIMEOUTLOG_SET` / `SEQTIME_SET` | R/W | timer watchdog tắt nguồn + log timeout + thời gian sequence (SuperWarp — rút ngắn khởi động) |
| **`0xC0`** | **`EXTEND_EVENT_COMMAND`** | **W** | 【自動測定】ghi **event khởi động + thời gian** vào ring buffer `st_EventRecord[250]` | `SCPIGetPmuEvent`/`LPPP` ghi `THRD_EventRecord_*` (T2.6; `board.c:64` `PSCPU_REG_EVENT`, `THRD_EventRecord_ATFStart=3`) |
| `0xFC` / `0xFE` | `EXTEND_CHECK_I2C` / `EXTEND_RESET_I2C` | R/W | kiểm tra / reset kênh I²C PS-CPU |

## 3. Bắt tay nguồn R4 ↔ PS-CPU (đường LPPP, T4.2)

### 3.1 `ap806_power_on(true)` — bật A72
```
Eagle3 only (supportTEC()==RESULT_EAGLE3, T11.2):
  [nếu isAutomaticMeasurementToolOn()] LPPP_i2c_write(0x3E, 0xC0, THRD_EventRecord_ResumeRequest)
  send_sleep_status_rem(1)   → I²C 0x3E:0x6C ← 0x0002 (SLEEP_STATUS_REM ON)
  cpu_spin_delay(100ms)
GPIO AP_PWR_EN (pin 65) = 1
[EMU800] bật GPIO DDR_Config (G[25]), AP_PWR_EN (C[1]), AP_1P1_EN (I[28])
send_power_state_to_pscpu(true)  → I²C 0x3E:0x68 ← (boot_once? 0x00 : 0x02) | gen   // Normal / Boot, gen=0x04 Eagle3
poll GPIO AP_PG (pin 243) == 1   // chờ nguồn A72 ổn định
```

### 3.2 `ap806_power_on(false)` — tắt A72 (Sleep2/ErP)
```
send_power_state_to_pscpu(false)  → I²C 0x3E:0x68 ← 0x01 | gen   // Sleep2/ErP
GPIO các pin AP power = 0 (gpio_nums[] loop)
Eagle3 only:
  cpu_spin_delay(100ms)
  send_sleep_status_rem(0)  → I²C 0x3E:0x6C ← 0x0001 (SLEEP_STATUS_REM OFF)
i2c_enable(false)
```

### 3.3 Bên PS-CPU xử lý
- `0x68` write → cập nhật trạng thái nội bộ → `mc_p_on_{eagle,sparrow}_proc` / `ap_power_en_proc` chạy trong super-loop → set `IR_P_ON`(bit0) / `MC_P_ON`(bit5) / `MC_PWR_EN`(bit12) qua IO-expander → GPIO thật.
- `0x6C` write → `sleep_status_rem_{eagle,sparrow}_proc` đọc `get_ca72_status()` + control này → gate `MC_PWR_EN` (nguồn Machine-Control). Đây là "REM handshake": PS-CPU cần biết A72/CA72 ngủ hay không để tuần tự nguồn cơ khí. **Chỉ Eagle3** (thế hệ Ⅰ/Ⅱ không có).
- CA72 status: `set_ca72_status(CA72_ON/SLEEP/OFF)` gọi từ `ap_power_en_proc` / `s800_power_off`; `get_ca72_status()` đọc bởi `sleep_status_rem_*_proc` (docs `05_data_flow.md` §2.4 — có 1-iteration staleness).

### 3.4 SCPI `SCPIGetPmuEvent` (T2.6)
`LPPP_SCPI` xử lý → `LPPP_GPIO_HandleMainSW(false)` + ghi event `0xC0`. Đây là cách Linux hỏi "sự kiện PMU / nút nguồn" — PS-CPU giữ lịch sử.

## 4. Các event/reason PS-CPU log (docs `05_data_flow.md` §3, §5)

- `poweroff_factor_save()` → ghi lý do tắt vào RTC BKP reg (`B_REGISTER_PWROFF_LOG` = `0x5E`): MSW off, 24V drop, timeout, CA72 request…
- `st_EventRecord[250]` ring buffer (`setEventRecord()`) — event khởi động + timestamp; đọc qua `0xC0`. `THRD_EventRecord_ATFStart=3`, `THRD_EventRecord_ResumeRequest` (từ `board.c`).
- `EXTEND_PWROFF_TIMEOUTLOG` (`0xB4`/`0xB8`) — nếu sequence tắt nguồn quá lâu.

## 5. FACT / INFERENCE / UNKNOWN

- **FACT**: PS-CPU = STM32F031C6 riêng, I²C slave `0x3E`, 2 image (Main 20KB `0x08000000` / IAP 12KB `0x08005000`), no RTOS super-loop (docs 02).
- **FACT**: bản đồ register `km_i2c.h`: `0x00-0x5E` RTC, `0x68` internal-status/power-state (bit0 boot cold/reboot, bit2 model I·II/III), `0x6C` internal-control (`0x0001` REM off / `0x0002` REM on), `0x70/74/78` extend-out, `0x80` extend-in, `0x88/8C` checksum/version, `0x90-0xA0` IAP (magic `0x11223344`), `0xB0-0xBC` pwroff-wdt/log/seqtime, `0xC0` event-record, `0xFC/0xFE` check/reset.
- **FACT**: khớp T4.2/T2.6 — `send_power_state_to_pscpu`→`0x68`, `send_sleep_status_rem`→`0x6C`, `SCPIGetPmuEvent`→`0xC0`; `gen=0x04` Eagle3.
- **FACT**: REM handshake (`0x6C` + CA72 status) chỉ Eagle3; `mc_p_on_*_proc`/`sleep_status_rem_*_proc` có nhánh eagle vs sparrow.
- **INFERENCE**: `0x68` bit0/bit1 mã hoá power-state (0=Normal, 1=Sleep2/ErP, 2=Boot) — suy từ giá trị `send_power_state_to_pscpu` ghi vs define `BOOT_STATES_COLD=0/REBOOT=1`. Mapping chính xác 4 giá trị chưa đối chiếu thân `i2c_recv_wait` case `0x68`.
- **INFERENCE**: LPPP đọc giờ RTC qua PS-CPU `0x00-0x5E` — chưa thấy hàm LPPP cụ thể đọc (có `SysTime_*`?), nhưng PS-CPU giữ RTC battery-backed là nơi duy nhất có giờ khi tắt.
- **UNKNOWN**: `isAutomaticMeasurementToolOn()` (đo tự động — chế độ test nhà máy?). `THRD_EventRecord_*` đầy đủ danh sách. Danh sách bit IO-expander (`OUTPUT_EXTEND_*_BIT`: IR_P_ON=0, MC_P_ON=5, MC_PWR_EN=12, AP_PWR_EN input=2 — có thêm bit khác).
- **UNKNOWN**: SuperWarp (`0xBC` SEQTIME) cơ chế đầy đủ — rút ngắn khởi động bằng cách bỏ qua sequence nếu tắt "sạch".
- **UNKNOWN**: PS-CPU có nhận ngắt GPIO từ MSW/24V trực tiếp (EXTI) — có (`km_it.c` anti-chattering) nhưng quan hệ với `MWAKE`/`MAINSW_ON` phía R4 (T7.2) chưa map rõ.

## Tóm tắt (theo format skill)

**PS-CPU** là STM32F031C6 độc lập trên power board, luôn có điện, làm bộ giám sát & tuần tự nguồn cho cả máy. Giao tiếp với Quartz qua **I²C slave `0x3E`**, bản đồ register (`km_i2c.h`): `0x00–0x5E` = thanh ghi RTC battery-backed (nơi duy nhất giữ giờ khi tắt, + log lý do tắt ở BKP3R), `0x68` = power-state/model-type LPPP ghi (`send_power_state_to_pscpu`: Normal/Boot/Sleep2, `|0x04` Eagle3), `0x6C` = SLEEP_STATUS_REM on/off LPPP ghi (`send_sleep_status_rem`, chỉ Eagle3 — PS-CPU cần biết A72 ngủ để gate `MC_PWR_EN` nguồn cơ khí), `0x70/74/78/80` = IO-expander GPIO phụ, `0x90–0xA0` = field update IAP (magic `0x11223344`), `0xB0–0xBC` = timer/log tắt nguồn + SuperWarp, `0xC0` = ghi event+timestamp khởi động (`SCPIGetPmuEvent`). Bắt tay bật A72 (`ap806_power_on`): Eagle3 gửi REM=ON → 100ms → GPIO `AP_PWR_EN=1` → ghi `0x68`=Boot/Normal → chờ GPIO `AP_PG`. PS-CPU chạy máy trạng thái `s800_power_on`/`mc_p_on_*_proc`/`sleep_status_rem_*_proc` (nhánh eagle vs sparrow) để lần lượt cấp `IR_P_ON`/`MC_P_ON`/`MC_PWR_EN`.
