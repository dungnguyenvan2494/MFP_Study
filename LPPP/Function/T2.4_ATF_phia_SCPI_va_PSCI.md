## 0 · ATF dùng SCPI cho việc gì

**Rất hẹp.** ATF chỉ dùng SCPI cho **power-state của core A72 lúc PSCI**, và chỉ 3 lệnh
(`scpi.h:76-80`): `SCP_READY (0x01)`, `SET_CSS_POWER_STATE (0x03)`, `SYS_POWER_STATE (0x05)`.
Toàn bộ bộ lệnh đầy đủ (~28) do **Linux** đảm nhiệm (`arm_scpi.c` + `km_scpi.c` — T2.5).

Trong `plat/marvell/a8k/quartz/`, chỉ **2 chỗ** thật sự gọi SCPI ra R4:
- `plat_pm.c:165` — `a8k_pwr_domain_on()` → `scpi_set_css_power_state(mpidr, on, on, on)`
- `plat_pm.c:223` — `a8k_pwr_domain_off()` → `scpi_set_css_power_state(mpidr, off, cluster_state, system_state)`

`scpi_wait_ready()` và `scpi_sys_power_state()` **định nghĩa trong `quartz/scpi.c` nhưng không
thấy caller** trong plat quartz (bản generic `css_*` gọi bản generic). → có thể code chết / gọi
từ đường boot chưa grep tới. _(UNKNOWN — đánh dấu.)_

## 1 · Gán kênh SCPI — mảnh kiến trúc mà LPPP notes thiếu (`scpi.c:44-52`)

```c
/* Shift to get from cpu core id to scpi virtual ch number
 * 0 is used by linux  1-4 are used by the atf cores one per core so no locks are needed. */
static inline int this_cpu_channel(void) {
    return plat_my_core_pos() + 1;
}
```

| Kênh SCPI (0–4) | Chủ | Dùng cho |
|---|---|---|
| **0** | **Linux** | `arm_scpi.c` + `km_scpi.c` — ~28 lệnh (0x02, 0x06, 0x0a, 0x1b, 0x80, 0x8x…) |
| **1** | A72 core 0 (ATF) | PSCI power-state của core 0 |
| **2** | A72 core 1 (ATF) | PSCI power-state của core 1 |
| **3** | A72 core 4 (ATF) | PSCI power-state của core 2 (cluster 1) |
| **4** | A72 core 5 (ATF) | PSCI power-state của core 3 (cluster 1) |

⇒ **5 kênh SCPI trong shared memory** (`AppMhuTest.md §B.2`) map chính xác:
mỗi core A72 có kênh riêng → **không cần khoá** (comment ghi rõ). LPPP `process_scpi_cmd`
xử lý `case 0..4` — giờ biết ý nghĩa từng kênh:
- `case 0` = lệnh từ Linux (mọi thứ trừ per-core power)
- `case 1..4` = lệnh `0x03` per-core từ ATF (khi Linux/PSCI suspend/resume từng core)

## 2 · `scpi_set_css_power_state()` (`scpi.c:135-176`) — payload khớp LPPP

```c
void scpi_set_css_power_state(unsigned mpidr, scpi_power_state_t cpu_state,
                              scpi_power_state_t cluster_state, scpi_power_state_t css_state) {
    uint32_t channel = this_cpu_channel();              // 1..4 (per ATF core)
    uint32_t state = 0;
    state |= mpidr & 0x0f;                              // bits [3:0]   CPU ID
    state |= (mpidr & 0xf00) >> 4;                      // bits [7:4]   Cluster ID
    state |= cpu_state     << 8;                        // bits [11:8]  (3=off, 0=on)
    state |= cluster_state << 12;                       // bits [15:12]
    state |= css_state     << 16;                       // bits [19:16]

    scpi_secure_message_start(channel);                 // MHU: while (CPU_INTR_S_STAT & (1<<ch))
    cmd = SCPI_CMD_HEADER_AP_TO_SCP_X(channel);         // shared mem +0x(2ch+1)×128
    cmd->id     = SCPI_CMD_SET_CSS_POWER_STATE;         // 0x03
    cmd->set    = SCPI_SET_NORMAL;
    cmd->sender = 0;
    cmd->size   = sizeof(state);                        // 4
    *(uint32_t*)(cmd + 1) = state;                      // payload ngay sau header 8B
    flush_dcache_range((uintptr_t)cmd, 0x100);          // ★ ATF clean cache 256B → R4 thấy dữ liệu mới
    scpi_secure_message_send(channel, sizeof(state));   // dmbst() rồi CPU_INTR_S_SET |= (1<<ch)
    // "SCP does not reply to this command in order to avoid MHU interrupts from the sender,
    //  which could interfere with its power state request."   ← LÝ DO CHÍNH THỨC
    scpi_secure_message_end(channel);                   // KHÔNG chờ response
}
```

**Payload format** — **khớp 1:1** với `scpi_set_power_state.md` phía R4:
```
bit  3:0  cpuid          bit 15:12  clusterpower
bit  7:4  clusterid       bit 19:16  suspend/css
bit 11:8  cpupower  (3 = off, 0 = on)
```
`scpi_power_off = 3`, `scpi_power_on = 0`, `scpi_power_retention = 1` (`scpi.h:82-86`).
R4 chỉ phân biệt `== 3` (tắt) / khác (bật) — các mức retention gộp thành "bật".

**Cache 2 phía:** ATF `flush_dcache_range(cmd, 0x100)` (clean) ⇄ R4 `mhu_handler`
`cpu_dcache_invalidate_region(header_source, ...)` (invalidate). Đúng như `AppMhuTest.md §D`:
D-cache của R4 (không coherent với A72) là ranh giới thật; cả hai bên phải bảo trì tay.

**Không chờ response** — khớp `process_scpi_cmd` `case 0x03`: `send_response` giữ `false`
(`AppMhuTest.md §E.1`). Đây là **lý do chính thức** (từ comment ATF): tránh ngắt MHU dội ngược
về A72 đúng lúc nó đang chuẩn bị vào WFI cắt nguồn.

## 3 · Bảng PSCI → ATF handler → SCPI/GPIO (`plat_pm.c`)

`plat_arm_psci_pm_ops` (`plat_pm.c:301-315`):

| PSCI (từ Linux) | `.slot` | Handler | Việc |
|---|---|---|---|
| `CPU_ON` | `pwr_domain_on` | `a8k_pwr_domain_on(mpidr)` | ① `plat_marvell_cpu_on()`: set private UID, ghi `CCU_RVBAR(cl,cpu) = _armada8k_cpu_entry >> 16`; ② `scpi_set_css_power_state(mpidr, on, on, on)` → **SCPI 0x03 kênh 1..4** |
| `CPU_OFF` / core WFI | `pwr_domain_pwr_down_wfi` | `a8k_pwr_domain_off()` `__dead2` | ① `CCU_RVBAR(0,0) = _armada8k_cpu_entry>>16`; ② `gicv2_cpuif_disable()`; ③ suy `cluster_state`/`system_state` từ `target_state`; ④ `scpi_set_css_power_state(mpidr, off, cluster_state, system_state)` → **SCPI 0x03**; ⑤ `wfi(); while(1);` |
| `CPU_SUSPEND` / system suspend | `pwr_domain_suspend` | `a8k_pwr_domain_suspend()` → **gọi thẳng `a8k_pwr_domain_off()`** | không có impl riêng (`"needs to be implemented"`) |
| `SYSTEM_RESET` | `system_reset` | `a8k_system_reset` → `plat_marvell_system_reset()` | `#ifdef CONFIG_KM_BIZHUB`: ghi `PADWRAP + 0x220C = 0x04` (GPIOC[2] `HRESET_REQn` = LOW) + `for(;;)` — **KHÔNG qua SCPI** |
| `SYSTEM_OFF` | `system_off` | `a8k_system_off` | `wfi(); panic();` — stub |
| — | `pwr_domain_off` | **`a8k_pwr_domain_prepare()` — THÂN RỖNG `{}`** ⚠ | logic off thật nằm ở `pwr_domain_pwr_down_wfi` |
| `CPU_SUSPEND` finish | `pwr_domain_on_finish` | `a8k_pwr_domain_on_finish` | `gicv2_pcpu_distif_init()` + `gicv2_cpuif_enable()` |
| resume finish | `pwr_domain_suspend_finish` | `a8k_pwr_domain_suspend_finish` | **rỗng** (`// panic();`) — tái dùng on_finish |

**Quan sát 1:** ATF `plat_marvell_cpu_on` có dòng ghi PRCR bị **comment**:
```c
//  mmio_write_32(MVEBU_CCU_PRCR(cluster, cpu_id), 0x10001);  // get the cpu out of reset done by the R4
```
⇒ **R4 (LPPP `power_cpu`) mới là bên kéo reset thật** (`CCU_B_PRCR = 0x10001`). ATF chỉ:
(a) đặt RVBAR (điểm A72 nhảy vào), (b) gửi SCPI 0x03. Phân công rõ: **ATF = vector, R4 = nguồn/reset.**

**Quan sát 2:** `MVEBU_CCU_RVBAR(l,i) = MVEBU_REGS_BASE + (l==0 ? 0x1a40 : 0x1e40) + i*4`,
`MVEBU_CCU_PRCR = ... 0x1a50/0x1e50 + i*4` — **khớp** `AP806_CCU_B_RVBAR_0 = 0xCE001A40`,
`PRCR_0 = 0xCE001A50` (T0.3). ATF ghi qua `MVEBU_REGS_BASE` (native `0xF0…`), R4 qua alias `0xCE…`.

**Quan sát 3:** `a8k_pwr_domain_suspend` = `a8k_pwr_domain_off`. Nên với ATF, "suspend" và "off"
sinh **cùng một SCPI 0x03**. Sự phân biệt Sleep1/Sleep2/ErP hoàn toàn do **R4 `power_cpu` suy ra**
từ `cpu_state == ALL_CPU_OFF` + `g_wolMode` (`power_cpu.md §B.3`), không phải ATF nói.

## 4 · Cờ warmboot `0x7FFFFFF0` — cơ chế đầy đủ (`plat_helpers.S:73-88`)

```asm
func plat_get_my_entrypoint
    mov_imm x1, PLAT_WARMBOOT_FLAG_BASE     @ x1 = 0x7FFF0000 + 0xFFF0 = 0x7FFFFFF0
    ldr     x2, [x1]                        @ x2 = *(0x7FFFFFF0)
    cmp     x1, x2                          @ WARM  ⟺  giá trị == chính địa chỉ
    bne     cold
    mov_imm x0, PLAT_ARM_TRUSTED_MAILBOX_BASE
    ldr     x0, [x0]                        @ warm: trả địa chỉ entry từ mailbox
    ret
cold:
    mov     x0, #0                          @ cold: trả 0
    ret
```

**Quy ước:** warm boot ⟺ `*0x7FFFFFF0 == 0x7FFFFFF0`.

| Đường | Ai ghi `0x7FFFFFF0` | Giá trị | Kết quả |
|---|---|---|---|
| Suspend (core A72 cuối tắt) | **LPPP `power_cpu()`**: `*(uint32_t*)PLAT_WARMBOOT_FLAG_BASE = PLAT_WARMBOOT_FLAG_BASE` | = `0x7FFFFFF0` | ATF `plat_get_my_entrypoint` → **WARM** |
| Cold boot | **LPPP `copy_run_atf()`**: `mrvl_regwrite32(PLAT_WARMBOOT_FLAG_BASE, 0)` | `0` | **COLD** |
| Wake timer nổ | **LPPP `my_callback()`**: `*(volatile uint32_t*)PLAT_WARMBOOT_FLAG_BASE = 0` | `0` | **ép COLD** (đánh thức theo lịch → khởi động sạch) |

`platform_def.h:118-119`:
```c
#define PLAT_CSS_SCP_COM_SHARED_MEM_BASE  0x7fff0000  // match scp-shmem in linux dtb
#define PLAT_WARMBOOT_FLAG_BASE           PLAT_CSS_SCP_COM_SHARED_MEM_BASE + 0xfff0
```
Nằm trong **64KB cuối của cửa sổ DDR shared-mem SCPI** — cùng vùng MHU dùng.

⚠ Comment trên `plat_get_my_entrypoint` ghi *"Note: warm boot is currently not supported"* —
**có vẻ di sản** từ template ARM: code so sánh cờ **có tồn tại và LPPP dựa vào nó**; nhưng
`a8k_pwr_domain_suspend_finish` gần như rỗng (`// panic()`), nên "warm boot" ở đây = A72 khởi
động lại nhanh từ `bl31_warm_entrypoint` chứ **không** khôi phục đầy đủ context suspend.

## 5 · Warm entry point (`plat_psci.S:76-128`, `plat_pm.c:62-63`)

```c
extern void bl31_warm_entrypoint();
extern void _armada8k_cpu_entry();       // "jumps to bl31_warm_entrypoint"
// plat_marvell_cpu_on / a8k_pwr_domain_off:
addr = (unsigned long long)_armada8k_cpu_entry;
addr >>= 16;                              // RVBAR lưu theo đơn vị 64KB
mmio_write_32(MVEBU_CCU_RVBAR(cluster, cpu_id), addr);
```

```asm
_armada8k_cpu_entry:                      @ plat_psci.S:77 — A72 nhảy vào đây khi thoát reset
    ...                                   @ dựng lại EL3 state, stack, MMU
    b  bl31_warm_entrypoint               @ plat_psci.S:128 — ATF hoàn tất, trao lại cho kernel
```

**Nối với LPPP:** `power_cpu()` (`power_cpu.md §C.1`) ghi
`AP806_CCU_B_RVBAR_0/1 = WARM_BOOT_ADDR` (0x1003 = `0x10030000 >> 16` … suy luận trong note đó).
`copy_run_atf` ghi `RVBAR_0 = load_addr >> 16`. **Nghi vấn từ `copy_run_atf.md`** ("nếu
`load_addr == 0x10030000` thì cold và warm vào cùng điểm, chỉ cờ phân biệt") — giờ có bằng chứng
phía ATF: **cả hai đường vào `_armada8k_cpu_entry`**; `plat_get_my_entrypoint` (đọc cờ warmboot)
mới là thứ rẽ nhánh cold vs warm **bên trong** ATF sau đó.

⚠ Địa chỉ chính xác của `_armada8k_cpu_entry` / `load_addr` / `WARM_BOOT_ADDR` — cần map file
`bl1.bin`/`bl31.bin` (T12.1) để chốt. Hiện: cả hai side đồng ý "1 điểm vào, cờ rẽ nhánh".

## 6 · `plat_marvell_system_reset()` — reset toàn hệ (`plat_pm.c:119-130`)

```c
void plat_marvell_system_reset(void) {
#ifdef CONFIG_KM_BIZHUB
    NOTICE("/HRESET_REQ => LOW\n");
    mmio_write_32(MVEBU_PADWRAP_REG_BASE + 0x220C, 0x04);   // GPIOC[2](HRESET_REQn)=L
    for(;;);
#else
    mmio_write_32(MVEBU_RFU_BASE + MVEBU_RFU_GLOBL_SW_RST, 0x0);
#endif
}
```
`CONFIG_KM_BIZHUB` bật cho máy S800 → dùng **GPIOC[2] `HRESET_REQn`** (pad offset `0x220C`,
ghi `0x04`), **cùng sợi dây** LPPP kéo (`LPPP_GPIOPIN_HRESET_REQN` GPIO 66 BANK C). Xác nhận
T0.2 §3.8: ATF & R4 cùng kéo được `HRESET_REQn`.

## 8 · Tóm tắt (theo format skill)

**1. Tồn tại để làm gì:** ATF (BL31) trên A72 dùng SCPI **chỉ** để chuyển power-state core khi
PSCI: `a8k_pwr_domain_on/off/suspend` → `scpi_set_css_power_state()` → SCPI `0x03` qua MHU **kênh
1–4** (mỗi A72 core một kênh, không cần khoá; kênh 0 dành Linux). ATF đặt RVBAR = `_armada8k_cpu_entry`,
**R4 mới kéo reset thật** (`CCU_PRCR`). Cold vs warm phân biệt bằng cờ `*0x7FFFFFF0 == 0x7FFFFFF0`
mà **LPPP** ghi (power_cpu ghi = warm, copy_run_atf/my_callback ghi 0 = cold).

**2. Call flow:**
```
Linux PSCI CPU_ON(mpidr)
└─ ATF a8k_pwr_domain_on()                       [plat_pm.c:158]
   ├─ plat_marvell_cpu_on()  [set UID, RVBAR = _armada8k_cpu_entry>>16]  (PRCR write COMMENTED)
   └─ scpi_set_css_power_state(mpidr, on,on,on)  [scpi.c:135]
        ├─ this_cpu_channel() = core_pos + 1     [kênh 1..4]
        ├─ cmd @ SCPI_CMD_HEADER_AP_TO_SCP_X(ch)  [shmem +0x(2ch+1)×128]
        ├─ cmd->id=0x03, payload = state(cpuid|clusterid|cpupower|...)
        ├─ flush_dcache_range(cmd, 0x100)
        └─ MHU: CPU_INTR_S_SET |= (1<<ch)  ──► R4 mhu_handler → process_scpi_cmd case 0x03
                                                 → scpi_set_power_state → power_cpu()
                                                    → CCU_B_PRCR = 0x10001  (R4 kéo reset)

Linux PSCI CPU_OFF / SYSTEM_SUSPEND
└─ ATF a8k_pwr_domain_off() [__dead2]            [plat_pm.c:186]
   ├─ RVBAR(0,0) = _armada8k_cpu_entry>>16
   ├─ gicv2_cpuif_disable()
   ├─ scpi_set_css_power_state(mpidr, off, cluster_state, system_state)  → SCPI 0x03
   └─ wfi(); while(1);
      R4 power_cpu: khi core cuối tắt → g_wolMode ? GO_TO_ERP : GO_TO_S2, warmboot flag ≠ 0

ATF cold/warm decision  [plat_helpers.S:73]
└─ plat_get_my_entrypoint: *0x7FFFFFF0 == 0x7FFFFFF0 ? warm(→mailbox addr) : cold(→0)
```
