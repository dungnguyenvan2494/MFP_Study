## 0 · Hai doorbell song song giữa A72 và R4

| | **MHU** | **IPC0 / HCU** |
|---|---|---|
| Base | `0xE8009800` | AP: `0xE8008000` (side0="B") · R4: `0xE8008100` (side1="G") |
| Dữ liệu đi kèm | shared mem DDR `0x7FFF0000` (5 kênh × 256B) | HCI FIFO trong LCM SRAM `0xE8200800` (6.1KB) |
| Dùng cho | **điều khiển nguồn/clock/wake** — SCPI (~28 lệnh Linux + PSCI của ATF) | **dữ liệu mạng proxy + host command (IOCTL)** |
| Wrapper HAL | `hal_MHU.c` (`write/clear/get_MHU_status`) | `hal_hostcmd.c` (`HalApiHostCmd_set` / `Hal_clear_ipc_irq`) |
| Task nhận (R4) | `AppMhuTest` (`got_msg_qhandle`) | `SysSystem_ThreadMain` (`SYS_EVENT_HCU`) |
| Ngắt R4 | `INTNUM_MHU_tx0` = SPI 170 (GIC 202) | `INTNUM_HCU_WAKEUP` = SPI 152 (GIC 184) |

Hai kênh **hoàn toàn độc lập**. Note cũ chỉ phân tích MHU; IPC0 là mảnh còn thiếu.

## 1 · MHU — bản đồ thanh ghi (chuẩn xác từ ATF `mhu.c:38-52`)

```
MHU_BASE = 0xE8009800
 offset  ATF name (góc nhìn AP)   LPPP name (góc nhìn AP)   R/W   Chiều
 ─────────────────────────────────────────────────────────────────────────
 +0x00   SCP_INTR_S_STAT          SCPI_RX_INT_STATUS         R    SCP→AP
 +0x04   SCP_INTR_S_SET           SCPI_RX_INT_SET            W    SCP→AP
 +0x08   SCP_INTR_S_CLEAR         SCPI_RX_INT_CLEAR          W    SCP→AP
 +0x0C   CPU_INTR_S_STAT          SCPI_TX_INT_STATUS         R    AP→SCP
 +0x10   CPU_INTR_S_SET           SCPI_TX_INT_SET            W    AP→SCP
 +0x14   CPU_INTR_S_CLEAR         SCPI_TX_INT_CLEAR (SCIP*)  W    AP→SCP
```
\* `hal_MHU.h` gõ nhầm `SCIP_TX_INT_CLEAR` (thiếu chữ P đảo).
**Slot (bit) 31 dành riêng** cho AP báo non-secure access → tối đa **31 slot [30:0]**
(ATF `MHU_MAX_SLOT_ID = 30`). LPPP chỉ dùng 5 slot (5 kênh SCPI).

### 1.1 · Tên LPPP theo góc nhìn AP — dễ nhầm
`AppMhuTest.md` đã ghi: `INPUT_PORT = 1` (block 1 = `SCPI_TX_*` = "AP transmit" = AP→SCP),
`OUTPUT_PORT = 0` (block 0 = `SCPI_RX_*` = "AP receive" = SCP→AP).

### 1.2 · Handshake đầy đủ (1 lệnh SCPI)

```
AP (Linux/ATF)                          R4 (LPPP)
──────────────                          ─────────
ghi lệnh vào shared mem +0x(2n+1)×128
CPU_INTR_S_SET |= (1<<ch)  ────rung────►  ngắt INTNUM_MHU_tx0 (SPI 170) → mhu_handler
  (LPPP: SCPI_TX_INT_SET, +0x10)            get_MHU_status(INPUT_PORT=1) đọc +0x0C (SCPI_TX_INT_STATUS)
                                            → duyệt bit, invalidate cache, memcpy header
                                            clear_MHU(INPUT_PORT=1, 1<<bit) ghi +0x14 (SCPI_TX_INT_CLEAR)  ← ACK "tao lấy rồi"
                                            xQueueSendFromISR(got_msg_qhandle)
                                          ─────────────────────────────────
                                          AppMhuTest: process_scpi_cmd()
                                            ghi response vào shared mem +0x(2n)×128
                                            cpu_dcache_writeback_region(header_dest, 256)
   ◄──────rung────  write_MHU(OUTPUT_PORT=0, 1<<ch) ghi +0x04 (SCPI_RX_INT_SET)
đọc CPU_INTR... thực ra AP đọc                do { get_MHU_status(OUTPUT_PORT=0) đọc +0x00 }
SCP_INTR_S_STAT (+0x00) thấy bell             while (i & (1<<ch))   ← ⚠ BUSY-WAIT KHÔNG TIMEOUT
đọc response từ shared mem
SCP_INTR_S_CLEAR |= (1<<ch)  ──────────►      vòng busy-wait thoát khi AP xoá bit +0x00
  (+0x08)                                     → quay lại xQueueReceive
```

### 1.3 · Phía ATF dùng MHU thế nào (`mhu.c:63-113`)
```c
mhu_secure_message_start(slot)  → while (CPU_INTR_S_STAT & (1<<slot));   // chờ lệnh trước xong
mhu_secure_message_send(slot)   → CPU_INTR_S_SET = 1<<slot;             // gửi
mhu_secure_message_wait(slot)   → while (!(SCP_INTR_S_STAT & (1<<slot)));// chờ phản hồi
mhu_secure_message_end(slot)    → SCP_INTR_S_CLEAR = 1<<slot;           // xoá
mhu_secure_init()               → assert(CPU_INTR_S_STAT == 0);         // sanity
```
ATF chỉ gọi khi PSCI CPU_ON/OFF/SUSPEND (xem `plat_pm.c` — T2.4). Slot = per-CPU nên
comment ghi *"no lock is needed"* (`DEFINE_BAKERY_LOCK` bị comment).

## 2 · `hal_MHU.c` (`Hal/quartz/MHU/src/hal_MHU.c`) — wrapper R4

```c
static struct MHU_regs_s *MHU_register = (MHU_regs_t *)MHU_BASE;   // set lúc static-init, LUÔN != NULL
static uint8_t *shared_memory_write = 0;   // ← không bao giờ được gán
static uint8_t *shared_memory_read  = 0;   // ← không bao giờ được gán

int get_mhu_intnum(void)  { return INTNUM_MHU_tx0; }               // = INTNUM_APB_SCPI_TX
void init_MHU(void)       { }                                      // ← RỖNG (pointer đã set ở trên)

int write_MHU(uint32_t block, uint32_t value) {                    // block 0→SCPI_RX_INT_SET, 1→SCPI_TX_INT_SET
    if (!MHU_register || block > 1) return -1;
    (block==0) ? MHU_register->SCPI_RX_INT_SET = value
               : MHU_register->SCPI_TX_INT_SET = value;
    // cpu_dcache_writeback_all();  ← đã comment: "why is this here/needed, this is h/w register"
    return 0;
}
int clear_MHU(uint32_t block, uint32_t value) { ... SCPI_RX_INT_CLEAR / SCPI_TX_INT_CLEAR ... }
int get_MHU_status(uint32_t block, uint32_t *value) { ... SCPI_RX_INT_STATUS / SCPI_TX_INT_STATUS ... }

uint8_t *get_MHU_shared_write(void) { return shared_memory_write; }  // → NULL
uint8_t *get_MHU_shared_read(void)  { return shared_memory_read; }   // → NULL
```

**Ghi chú:**
- `init_MHU()` **rỗng** vì `MHU_register` đã trỏ đúng `MHU_BASE` ngay tại khai báo `static`.
  `AppMhuTest.md` từng ghi "init_MHU rỗng" — đây là lý do đầy đủ.
- `get_MHU_shared_read/write()` trả **NULL** — `app_MHU.c` **không** dùng chúng; nó truy cập
  shared mem trực tiếp qua macro `SCPI_CMD_HEADER_AP_TO_SCP_X(n)` / `..._SCP_TO_AP_X(n)`.
- `Sys/MHU/sys_MHU.c` — `MHU_send()`/`MHU_receive()` dùng `get_MHU_shared_*()` (NULL) →
  `memcpy(NULL, ...)` nếu `length != 0`. Hàm này **không ai gọi trong luồng sản xuất**
  (chỉ `MHU_init()` in "hello out there" được `AppThread_Main` gọi — và cũng chỉ in log,
  thiếu `return`). Code demo/chết.
- 🟡 `hal_MHU.h`: `typedef MHU_regs_s { ... } MHU_regs_t;` — **thiếu từ khoá `struct`**.
  `.c` lại dùng `struct MHU_regs_s`. Biên dịch được (GCC nới lỏng / warning), nhưng là header hỏng.

`INTNUM_MHU_tx0` (`intnums.h:222`) = `INTNUM_APB_SCPI_TX` (`:213`) = `170 + INTRL_GIC_OFFSET(32)`
= **SPI 170 / GIC ID 202**. Đây là ngắt *"AP đã transmit"* — kích khi AP ghi `CPU_INTR_S_SET`.
`INTNUM_MHU_rx0` = `INTNUM_APB_SCPI_RX` = SPI 171 (không dùng ở R4).

## 3 · IPC0 / HCU — doorbell của kênh HCI FIFO (GIẢI phát hiện T0.3)

### 3.1 · Cấu trúc thanh ghi `IPC0_REGS_t` (`apb_top_regheaders.h:393-406`)

```c
typedef struct IPC0_REGS_s {
    volatile uint32_t IPC_ISRR;        // 0x00 [R]  Interrupt Status Register Read
    volatile uint32_t IPC_WDR_0;       // 0x04 [W]  Write Data Register 0
    volatile uint32_t IPC_WDR_1;       // 0x08 [W]  Write Data Register 1
    volatile uint32_t IPC_ISRW;        // 0x0C [W]  Interrupt Set Register Write   ← RUNG CHUÔNG
    volatile uint32_t IPC_ICR;         // 0x10 [W]  Interrupt Clear Register       ← XOÁ
    volatile uint32_t IPC_IIR;         // 0x14 [R]  Interrupt Identification Register
    volatile uint32_t IPC_RDR_0;       // 0x18 [R]  Read Data Register 0
    volatile uint32_t IPC_RDR_1;       // 0x1C [R]  Read Data Register 1
    volatile uint32_t IPC_MAJ_MID_REV; // 0x20 [R]
    volatile uint32_t IPC_CFG_REV;     // 0x24 [R]
    volatile uint32_t IPC_DUMMY;       // 0x28 [W]  Dummy Register (flush quirk)
} IPC0_REGS_t;
```

### 3.2 · Hai side, hai chủ (`regAddrs.h:106-107` + comment `intnums.h:224`)

```
APB_IPC0_B_BASE = 0xE8008000   "AP owns"   (apb_top::IPC_2sides::IPC_side0)
APB_IPC0_G_BASE = 0xE8008100   "R4 owns"   (apb_top::IPC_2sides::IPC_side1)
                                 "AP is B, R4 is G"
```
4 kênh mỗi chiều (`intnums.h:190-197`):
- `INTNUM_APB_IPC_G2B_0..3` = SPI 147–150 — **R4 → AP** (ICU định tuyến sang AP806, `hal_icu.c:172-173` → AP int 265/266)
- `INTNUM_APB_IPC_B2G_0..3` = SPI 151–154 — **AP → R4**

### 3.3 · R4 → AP: `HalApiHostCmd_set()` (`hal_hostcmd.c:99-105`)
```c
void HalApiHostCmd_set(void) {
    IPC0_REGS_t *my_ipc = (IPC0_REGS_t *)APB_IPC0_G_BASE;   // 0xE8008100 — side R4
    // my_ipc->IPC_WDR_0/1 = ...   ← để ngỏ, hiện chỉ rung chuông
    my_ipc->IPC_ISRW = HAL_HOSTCMD_TRIGGER;                 // = 0x100 (bit 8)
}
```
`HAL_HOSTCMD_TRIGGER = 0x100` (`hal_api_hostcmd.h:41`) — comment ở `intnums.h:224` nói rõ
*"use bit 8 as trigger"*. Gọi từ `hal_lan.c:531` (khi có sự kiện mạng cần báo Linux).

### 3.4 · AP → R4: ngắt `INTNUM_HCU_WAKEUP` → `SysSystem_HcuIsr`
```
intnums.h:224   INTNUM_HCU_WAKEUP = INTNUM_APB_IPC_B2G_1   (SPI 152 / GIC 184)
hal_isr.c:75    {HAL_ISR_TYPE_HCU, NULL, INTNUM_HCU_WAKEUP, ...}   // "signal from driver"
sys_system_thread.c:137  HalApiIsr_Register(true, false, HAL_ISR_TYPE_HCU, SysSystem_HcuIsr);
sys_system_thread.c:138  HalApiIsr_Unmask(false, HAL_ISR_TYPE_HCU);
hal_reset.c:90           HalApiIsr_Enable(HAL_ISR_TYPE_HCU);
```
`HAL_ISR_TYPE_HCU = 0x08` (`hal_api_isr.h:48`).

**Luồng:** Linux ghi vào side "B" `0xE8008000` → ngắt B2G_1 (SPI 152) → `SysSystem_HcuIsr` →
set `SYS_EVENT_HCU` → `SysSystem_ThreadMain` thức → `SysHostcmd_HandlePendingCmds()` +
`SysFifo_HandlePendingRequests()` đọc HCI FIFO. (Đã thấy ở `SysSystem_ThreadMain.md §D.1`:
`SYS_EVENT_HCU` chỉ là "chuông", việc thật ở các hàm poll cuối vòng.)

### 3.5 · Ack / clear (`hal_hostcmd.c:85-97`)
```c
void Hal_clear_ipc_irq(uint32_t mask) {
    IPC0_REGS_t *my_ipc = (IPC0_REGS_t *)APB_IPC0_G_BASE;
    my_ipc->IPC_DUMMY = 0;      // flush quirk trước
    my_ipc->IPC_ICR = mask;     // xoá đúng trigger của mình
    my_ipc->IPC_DUMMY = 0;      // flush quirk sau
}
void HalApiHostCmd_clear_irq_hcu(void) { Hal_clear_ipc_irq(HAL_HOSTCMD_TRIGGER); }  // mask = 0x100
```
Ghi `IPC_DUMMY = 0` hai lần bọc quanh `IPC_ICR` — mẫu "ghi dummy để đẩy write buffer / đảm bảo
thứ tự APB" (không có giải thích trong code, nhưng nhất quán).

`HalApiHostcmd_Receive()` / `HalApiHostCmd_Ack()` / `HalApiHostCmd_Finish()` — **thân RỖNG**
(`hal_hostcmd.c:72-84`). Việc đọc lệnh thật do tầng `Sys/hostcmd` + `Sys/fifo` làm trên HCI FIFO,
không qua thanh ghi IPC (T6).

### 3.6 · `INTNUM_APB_IPC_B2G_0` = đường thức của `pause_cpu` (`hal_pause.c:36`)
```c
#define DUMMY_INT_NUM INTNUM_APB_IPC_B2G_0   // SPI 151
```
Trong `pause_cpu()` (dùng khi Linux update firmware LPPP — `Update_FW_LPPP.md`), R4 tắt **toàn
bộ** GIC rồi chừa **đúng 1 ngắt** này làm đường thoát `wfi`. Nghĩa là kênh IPC0 B2G_0 kiêm luôn
vai "đánh thức R4 khỏi pause" — Linux ghi side "B" `0xE8008000` để gọi R4 dậy.

## 4 · Bảng tổng hợp doorbell

| Hành động | Thanh ghi | Địa chỉ | Ai ghi | Kết quả |
|---|---|---|---|---|
| **SCPI** — AP gửi lệnh | `CPU_INTR_S_SET` (MHU +0x10) | `0xE8009810` | AP/ATF | ngắt SPI 170 → `mhu_handler` |
| SCPI — R4 ack lệnh | `CPU_INTR_S_CLEAR` (MHU +0x14) | `0xE8009814` | R4 | AP thấy `+0x0C` bit clear |
| SCPI — R4 gửi response | `SCP_INTR_S_SET` (MHU +0x04) | `0xE8009804` | R4 | AP thấy `+0x00` bit set |
| SCPI — AP ack response | `SCP_INTR_S_CLEAR` (MHU +0x08) | `0xE8009808` | AP | R4 thoát busy-wait `+0x00` |
| **HCU** — R4 báo AP | `IPC_ISRW` (side G +0x0C) | `0xE800810C` | R4 (`HalApiHostCmd_set`) | ngắt G2B qua ICU → AP int 265/266 |
| HCU — R4 xoá trigger | `IPC_ICR` (side G +0x10) | `0xE8008110` | R4 (`Hal_clear_ipc_irq`) | clear bit 8 |
| **HCU** — AP báo R4 | `IPC_ISRW` (side B +0x0C) | `0xE800800C` | Linux | ngắt SPI 152 → `SysSystem_HcuIsr` → `SYS_EVENT_HCU` |
| **pause wake** — AP gọi R4 dậy | side B B2G_0 | `0xE8008000` | Linux | SPI 151 (`DUMMY_INT_NUM`) đánh thức `wfi` |

## 5 · Tóm tắt (theo format skill)

**1. Tồn tại để làm gì:** MHU (`0xE8009800`) là doorbell 6-thanh-ghi cho SCPI — 3 thanh ghi mỗi
chiều (STAT/SET/CLEAR), 31 slot, dữ liệu ở shared-mem DDR. IPC0/HCU (`0xE8008000` phía AP,
`0xE8008100` phía R4) là doorbell **thứ hai, độc lập**, cho kênh HCI FIFO (dữ liệu mạng + host
command): R4 rung bằng `IPC_ISRW` bit 8, AP rung ngược lại kích ngắt `INTNUM_HCU_WAKEUP` (SPI 152)
→ `SysSystem_HcuIsr` → `SYS_EVENT_HCU`. Kênh B2G_0 (SPI 151) còn kiêm đường đánh thức `pause_cpu`.

**2. Bảng thanh ghi:** §1.0 (MHU) + §3.1 (IPC0) + §4 (tổng hợp handshake).
