§ 01 — Vai trò

PS-CPU là ai trong hệ thống S800

Nghịch lý sáng lập: khi máy tắt, CPU chính không chạy — vậy ai nghe nút nguồn?

PS-CPU = Power Sub CPU. Một STM32F031C6T6 (Cortex-M0) gắn trên board S800, chạy firmware riêng ngay khi có điện lưới, hoàn toàn không phụ thuộc vào SoC chính (Marvell AP806, cụm ARM Cortex-A72 "CA72"). Nguồn 3.3V_LIVE cấp cho nó không bao giờ bị ngắt chừng nào phích cắm còn cắm — kể cả khi công tắc nguồn chính đã tắt.

Bằng chứng rõ nhất nằm ngay ở dòng đầu main(): PS-CPU chủ động giữ /RESET ở mức thấp rồi mới gọi s800_power_on(). S800 không có điện, không thoát reset, cho tới khi PS-CPU tự khởi động xong và quyết định cho phép. 

/* entry.c:74-75 */
BSP_GPIO_WritePin(_RESET_GPIO_Port,_RESET_Pin,GPIO_PIN_RESET);   /* S800リセット */
s800_power_on();                                                /* S800電源ON */

Đặc tả gốc nêu rõ bốn điểm: (1) không điều khiển nguồn chi tiết — việc đó do LPPP làm, PS-CPU chủ yếu đóng vai I/O mở rộng; (2) không tự phán đoán mất điện tức thời — reset đi theo chỉ thị từ S800; (3) không lưu tiến trình vào bộ nhớ non-volatile; (4) không có cổng debug UART. Tên gọi cũng đổi từ power SubCPU thành PS-CPU vì phạm vi đã hẹp lại. Điểm (2) về sau bị thực tế phá vỡ — xem §9, phần failsafe mất điện chớp.

Version và checksum nằm ở địa chỉ cố định

Firmware đọc chuỗi version thẳng từ flash lúc chạy. Đoạn lọc ký tự dưới đây khá tinh tế: nếu script build chưa ghi (vùng còn 0xFF), hàm vẫn trả về chuỗi toàn dấu cách thay vì rác nhị phân có thể làm CPU chính crash khi in ra. 

void GetVersionString(void) {
    for(i = 0; i < MAIN_APPLICATION_SIZE_VERSION; ++i) {
        temp = (uint8_t *)(MAIN_APPLICATION_ADDRESS
                           + MAIN_APPLICATION_OFFSET_VERSION + i);
        g_main_version[i] = *temp;
        /* Không phải ASCII in được → thay bằng dấu cách */
        if((0x21 > g_main_version[i]) || (0x7E < g_main_version[i])) {
            g_main_version[i] = 0x20;
        }
    }
    g_main_version[MAIN_APPLICATION_SIZE_VERSION] = 0x00;
}

uint16_t checksum_calc(void) {
    uint16_t my_chk_sum = 0;
    /* Cộng dồn từng byte, TRỪ 2 byte checksum ở cuối */
    for(i = 0; i < (MAIN_APPLICATION_SIZE - MAIN_APPLICATION_SIZE_CHKSUM); i++) {
        temp = (uint8_t *)(MAIN_APPLICATION_ADDRESS + i);
        my_chk_sum += (uint16_t)*temp;
    }
    return my_chk_sum;
}

Việc loại trừ chính 2 byte checksum khỏi phép tính tránh được bài toán con-gà-quả-trứng. Giá trị tính một lần lúc khởi động, lưu vào g_checksum_value, và CPU chính đọc lại qua I2C 0x88 để xác minh firmware nguyên vẹn.

§ 04 — Kiến trúc

Ba tầng, cộng một chuẩn ARM

Tầng BSP không phải thủ tục hình thức — nó đã âm thầm chặn một bug thật.

Tầng BSP đã cứu một bug

Hàm extend_output_init() có một dòng ghi ra chân _DISCHG (PB8) — nhưng PB8 được cấu hình là INPUT. Lệnh ghi này bị bỏ qua âm thầm vì BSP kiểm tra hướng chân trước: 

void BSP_GPIO_WritePin(PortType* portno, PinType pinno, PinStateType state) {
    /* Chỉ ghi khi chân là OUTPUT */
    if(get_direction(portno, pinno) == GPIO_DIR_OUTPUT) {
        HAL_GPIO_WritePin(portno, pinno, state);
    }
}

Nếu App gọi thẳng HAL_GPIO_WritePin(), dòng lệnh vô nghĩa đó sẽ đi tới thanh ghi thật. Đây là tàn dư của một phiên bản phần cứng cũ, và tầng trừu tượng đã hấp thụ nó.

§ 06 — Vòng lặp chính

Super loop: 22 hàm, và thứ tự của chúng là một đặc tả

Không có RTOS, không có delay. Mọi thứ diễn ra theo nhịp của while(1).

Ba quy tắc vàng của super loop

1 · Không hàm nào được block lâu. Mỗi hàm phải "vào — kiểm tra — làm chút việc — ra ngay". Cách viết là máy trạng thái + timer không chặn: 

// ❌ SAI trong super loop
BSP_GPIO_WritePin(SB_PWR_EN, HIGH);
HAL_Delay(100);                      // Đứng im 100 ms — watchdog sẽ reset
BSP_GPIO_WritePin(_RESET, HIGH);

// ✅ ĐÚNG — trong s800_power_on()
BSP_GPIO_WritePin(SB_PWR_EN, HIGH);
km_timer_set(TYPE_Km_Timer_SB_RESET_RELEASE, 100, TYPE_Km_Timer_Start);
// …rồi RETURN ngay lập tức

// Ở vòng lặp sau, trong sb_reset_proc():
if(km_timer_get_state(TYPE_Km_Timer_SB_RESET_RELEASE) == TYPE_Km_Timer_End) {
    BSP_GPIO_WritePin(_RESET, HIGH);
}

2 · Watchdog vỗ về ở đúng một chỗ (dòng 3). 3 · Ngủ khi rảnh (dòng 22).

Ngoại lệ duy nhất

s800_power_off() có HAL_Delay(500) — chặn thật 500 ms. Nhưng hàm này kết thúc bằng HAL_NVIC_SystemReset(), nên "chặn" ở đây không còn ý nghĩa. Việc tự reset là quyết định thiết kế hay: thay vì phải cẩn thận đưa hàng chục biến trạng thái về giá trị ban đầu (dễ sót), cứ khởi động lại từ đầu → chắc chắn sạch.

Mốc A — s800_power_on() bật SB_PWR_EN

void s800_power_on(void) {
    if(!IS_CHECKING_CHATTERING(MSW) && BSP_GPIO_ReadPin(MSW_ON...)) {           // ① nút bật
        if((!IS_CHECKING_CHATTERING(POWER_MONI) && BSP_GPIO_ReadPin(POWER_MONITOR...))  // ② AC ổn
           && (!IS_CHECKING_CHATTERING(24V11) && !BSP_GPIO_ReadPin(MONI_24V11...))) {   // ③ 24V đã xả
            if(km_timer_get_state(Reboot_SB_PWR_EN) != TYPE_Km_Timer_Start) {           // ④ không chống reboot nhanh
                BSP_GPIO_WritePin(SB_PWR_EN, HIGH);                    // ★ BẬT NGUỒN
                km_timer_set(SB_RESET_RELEASE, 100, Start);            // ★ ĐẶT 100 ms
            }
        }
        g_power_on_flg = POWER_ON_FLG_START;
    }
}

Mốc B — sb_reset_proc() nhả /RESET

void sb_reset_proc(void) {
    if((!IS_CHECKING_CHATTERING(MSW) && BSP_GPIO_ReadPin(MSW_ON...))
       && (!IS_CHECKING_CHATTERING(24V11) && !BSP_GPIO_ReadPin(MONI_24V11...))
       && BSP_GPIO_ReadPin(SB_PG...)                                   // ★ nguồn đã ổn
       && km_timer_get_state(SB_RESET_RELEASE) == TYPE_Km_Timer_End) { // ★ đã đủ 100 ms
        BSP_GPIO_WritePin(_RESET, HIGH);                               // ★ NHẢ RESET
        km_timer_set(SB_RESET_RELEASE, 0, Normal);                     // dọn timer
        setEventRecord(THRD_EventRecord_LPPPStart);
    }
}

Cần cả hai điều kiện. Timer 100 ms là "chờ tối thiểu"; SB_PG là "xác nhận thực tế". Chỉ dùng timer thì mù quáng; chỉ dùng SB_PG thì có thể nhả reset quá sớm khi tín hiệu PG nhiễu.

§ 09 — Tắt nguồn

        km_timer_set(PWROFF_MAXTIME1, 0, Normal);

static void rx_comp(uint32_t event) {
    /* Sự kiện RELOAD: vừa nhận xong 1 byte, phần cứng hỏi "ACK hay NACK?" */
    if((event & KM_ARM_I2C_EVENT_TRANSFER_RELOAD)) {
        if(i2c_info.rx_buf_current != NULL) {
            /* Byte đầu tiên = địa chỉ thanh ghi → phải kiểm tra */
            if(i2c_info.rx_buf_current == &(i2c_info.rx_buf[0])) {
                if(valid_second_addr(i2c_info.rx_buf_current)) {
                    Driver_I2C0.Control(KM_ARM_I2C_GENERATE_NACK, 0);  // TỪ CHỐI
                } else {
                    Driver_I2C0.Control(KM_ARM_I2C_GENERATE_ACK, 0);   // CHẤP NHẬN
                }
            } else {
                Driver_I2C0.Control(KM_ARM_I2C_GENERATE_ACK, 0);       // byte 2 trở đi: luôn ACK
            }
            i2c_info.rx_buf_current++;
        }
    }
}

static int inline valid_second_addr(uint8_t* addr) {
    if(*addr % 2) return -1;                              // lẻ → sai, mọi addr đều chẵn
    if(RTC_TR_CMD      <= *addr && *addr <= RTC_BKP2R_CMD_2)        return 0;
    if(B_REGISTER_MCIR <= *addr && *addr <= B_REGISTER_PWROFF_LOG)  return 0;
    if(INT_STS_COMMAND <= *addr && *addr <= INT_STS_COMMAND_2)      return 0;
    // … kiểm tra từng dải
    return -9;
}

Và một bộ đếm tham chiếu cho ngắt — kỹ thuật bạn sẽ gặp lại trong Linux kernel.

Thứ tự "xoá cờ trước, xử lý sau" trong intr_pending_proc() là cố ý: nếu ngắt xảy ra lại trong lúc đang xử lý, cờ sẽ được set lại và vòng sau xử lý tiếp — không bỏ sót sự kiện.

Đếm tham chiếu cho ngắt

uint32_t pending_factor = 0;    // mỗi bit = 1 loại ngắt

/* Truy cập luôn qua cặp get/put — cấm ngắt trước, cho lại sau */
static uint32_t* get_pending_factor(void) { disable_external_irq(); return &pending_factor; }
static void      put_pending_factor(void) { enable_external_irq(); }

#define _CONTROL_PENDING_FACTOR(control, bit)   \
    {                                           \
        uint32_t* factor = get_pending_factor();\
        KM_##control##_BIT(*factor, bit);       \
        put_pending_factor();                   \
    }

Macro token pasting (##): KM_##control##_BIT với control = SET được tiền xử lý thành KM_SET_BIT — một macro dùng chung cho SET / CLEAR / READ.

§ 14 — Tiết kiệm điện

Sleep mode và Stop mode

Khi máy "tắt", PS-CPU thức dậy mỗi 2 giây, chạy một vòng lặp, rồi ngủ tiếp.

void sleep_mode(void) {                            // hàm #22, cuối vòng lặp
    if(!IS_CHECKING_CHATTERING(TYPE_Km_AC_Idx_MSW)
       && BSP_GPIO_ReadPin(MSW_ON...)          // ① nút nguồn vẫn bật
       && BSP_GPIO_ReadPin(SB_PG...)           // ② nguồn S800 vẫn ổn
       && !BSP_GPIO_ReadPin(AP_PWR_EN...)      // ③ CPU chính đang ngủ
       && !pending_factor) {                    // ④ không có ngắt chờ xử lý
        BSP_PWR_enter_sleepmode();               // HAL_PWR_EnterSLEEPMode(0, WFI)
    }
}

Điều kiện ③ + ④ là mấu chốt: chỉ ngủ khi CPU chính cũng đang ngủ và không còn việc gì. WFI là một lệnh assembly của ARM — "dừng thực thi, chờ ngắt". Rất khác while(1);: WFI thực sự tắt clock của lõi CPU.

Thức dậy từ STOP mode — bắt buộc cấu hình lại clock

case MSW_ON_Pin:
    level = BSP_GPIO_ReadPin(MSW_ON_GPIO_Port, MSW_ON_Pin);
    if(stop_mode == STOP_MODE_ON) {
        SystemClock_Config2();                      // ★ BẮT BUỘC

Trong STOP mode, PLL bị tắt. Khi thức dậy, MCU chạy bằng HSI thay vì 48 MHz. Không gọi SystemClock_Config2() thì I2C sai baudrate, timer sai chu kỳ.

Vì sao có hai phiên bản SystemClock_Config?

Gần như giống hệt nhau, chỉ khác cách xử lý lỗi: bản gốc gọi Error_Handler() — treo trong while(1); bản _2 chỉ return. Rất hợp lý: lúc khởi động mà clock lỗi thì chẳng làm gì được, treo để watchdog reset. Nhưng khi thức dậy, treo trong ISR sẽ chặn mọi thứ — thà cứ chạy tiếp với clock chậm còn hơn.

Đặt báo thức RTC — đọc hai lần, so sánh

HAL_StatusTypeDef set_cycle_time(uint8_t sec) {
    for(i = 0; i < 5; i++) {                    /* Thử tối đa 5 lần */
        HAL_RTC_GetTime(&hrtc, &sTime_bfr, RTC_FORMAT_BIN);
        HAL_RTC_GetTime(&hrtc, &sTime_aft, RTC_FORMAT_BIN);
        if(sTime_bfr.Seconds == sTime_aft.Seconds) break;   /* hai lần giống nhau → tin được */

                     | RTC_ALARMMASK_HOURS         /* bỏ qua giờ   */
                     | RTC_ALARMMASK_MINUTES;      /* → CHỈ so sánh GIÂY */

RTC chạy bằng clock riêng (32.768 kHz), độc lập với CPU. Nếu đọc đúng lúc nó đang cập nhật, có thể được giá trị không nhất quán (giờ đã sang 10 nhưng phút vẫn 59). Kỹ thuật "đọc 2 lần, so sánh" là cách xử lý clock domain crossing đơn giản và hiệu quả.

BSP_PWR_enter_stopmode() còn tạm dừng SysTick bằng HAL_SuspendTick() — nếu không, SysTick sẽ ngắt sau 1 ms và đánh thức MCU ngay, làm cả cơ chế trở nên vô nghĩa.

§ 16 — RTC

RTC và backup register: bộ nhớ sống sót qua reset

Ba việc, và việc thứ ba mới là thú vị nhất.

  1. Giữ ngày giờ cho cả hệ thống — CPU chính đọc qua I2C 0x00–0x46
  2. Báo thức định kỳ để thoát STOP mode (§14) và phát tín hiệu WAKEUP tới AP
  3. Lưu dữ liệu sống sót qua reset ← backup register
static void poweroff_factor_save(uint32_t factor_bit) {
    /* Backup register phải ghi theo đơn vị 4 byte */
    uint32_t align = B_REGISTER_PWROFF_LOG & 0x3;        // 0x5E & 3 = 2
    uint32_t *addr = (uint32_t *)(RTC_BASE + B_REGISTER_PWROFF_LOG - align);
    uint32_t value = *addr;                              // đọc cả 32 bit
    value |= factor_bit << (align * 8);                  // OR vào nửa TRÊN
    RTC_WRITEPROTECT_DISABLE();
    *addr = value;
    RTC_WRITEPROTECT_ENABLE();
}

Hai vòng while trong KM_RTC_Restore() (chờ RTC_ISR_INITF và RTC_ISR_INITS) đều có if(loop_limit++ > 10000) break;. Nếu phần cứng RTC gặp sự cố, code vẫn thoát ra được thay vì treo và bị watchdog reset. Không có ngoại lệ cho quy tắc này.

§ 17 — IAP

Nâng cấp firmware qua chính đường I2C có sẵn

Không cần mạch nạp, không cần mở máy — và một trò ảo thuật vector table trên Cortex-M0.

Trò ảo thuật vector table trên Cortex-M0

void jump2iap(void) {
    pFunction JumpToApplication;
    uint32_t  JumpAddress;
    /* Vector table có cấu trúc cố định:
       [0] = giá trị Stack Pointer ban đầu
       [1] = địa chỉ hàm Reset_Handler */
    JumpAddress = *(__IO uint32_t*)(IAP_DEFAULT_ADD + 4);   // đọc [1]
    JumpToApplication = (pFunction)JumpAddress;
    __set_MSP(*(__IO uint32_t*)IAP_DEFAULT_ADD);            // ★ nạp [0] vào SP TRƯỚC
    JumpToApplication();                                     // rồi mới nhảy
}

Thứ tự cực kỳ quan trọng: phải đặt Stack Pointer trước khi nhảy. Nếu nhảy trước, hàm mới sẽ dùng stack của chương trình cũ → hỏng dữ liệu.

Defense in depth — kiểm tra biên hai lần

static int32_t flash_write_32(uint32_t addr, void *data) {
