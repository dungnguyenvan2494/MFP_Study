#PSCI là gì, nói bằng một câu

PSCI (Power State Coordination Interface) là một đặc tả của ARM (tài liệu DEN0022) quy định cách hệ điều hành ở thế giới non-secure nhờ firmware ở mức đặc quyền cao hơn bật, tắt, cho ngủ một CPU, hoặc reset/tắt cả hệ thống. Nó không phải một chương trình. Linux có một driver nói theo đặc tả đó (drivers/firmware/psci/psci.c), còn TF-A có một thư viện thực thi đặc tả đó (lib/psci/).

Nói ngắn gọn
Một “mẫu đơn” chuẩn: số hiệu yêu cầu đặt vào thanh ghi x0, tham số vào x1..x3, rồi gõ cửa EL3 bằng lệnh smc.
Ví dụ đời thường
Linux là nhân viên văn phòng muốn mở điện phòng họp số 1. Nhân viên không có chìa khóa tủ điện. PSCI là mẫu đơn chuẩn (ghi “bật phòng số mấy, ai vào trước thì ngồi chỗ nào”). Secure Monitor ở EL3 là phòng kỹ thuật duy nhất có chìa khóa. Power controller là cầu dao. CPU1 là căn phòng. Phòng kỹ thuật ký “đã nhận đơn” không có nghĩa phòng đã có người làm việc.
Kỹ thuật
Đặc tả định nghĩa function ID (ví dụ CPU_ON 64-bit = 0xC4000003), tham số, mã trả về và state machine của từng CPU (OFF, ON_PENDING, ON). Đặc tả không quy định thanh ghi phần cứng nào được ghi; đó là việc của platform code trong firmware.
Vị trí trong flow
Ranh giới giữa Linux EL1 non-secure và firmware EL3 secure.
Trạng thái

#Vì sao Linux không tự ghi thanh ghi để bật CPU1

Linux có quyền ghi power controller không?
Trên kiến trúc TrustZone, các khối điều khiển nguồn/reset của core thường được cấu hình là secure-only. Linux chạy ở EL1 non-secure nên không có quyền. Trên board này có một bằng chứng gián tiếp: chính kernel vendor có file arch/arm64/kernel/quartz_cpu_pi.c ghi thẳng PWRC_CPUN_CR_REG khi tắt CPU, nhưng đường bật CPU vẫn đi qua PSCI. Việc thanh ghi đó có thật sự secure-only hay không thì NEED TO VERIFY (cần đọc cấu hình TrustZone/security của AP806).
Vì sao bật/tắt CPU phải đi qua firmware?
(1) Một số bước chỉ thực hiện được ở EL3 (thiết lập context secure, RVBAR, trạng thái GIC secure). (2) Firmware phải biết CPU nào đang ON để không có hai lệnh bật cùng lúc. (3) Một kernel duy nhất có thể chạy trên nhiều SoC: Linux chỉ cần biết “gọi CPU_ON”, còn chi tiết từng SoC nằm trong firmware.
Secure firmware đóng vai trò gì?
Nhận lệnh, kiểm tra tham số, ghi lại địa chỉ Linux muốn CPU1 chạy, ra lệnh cho phần cứng cấp nguồn và nhả reset, rồi khi CPU1 tỉnh dậy thì dọn context và thả CPU1 xuống EL1 tại đúng địa chỉ đó.
PSCI là firmware, driver, API, protocol hay specification?
Là specification định nghĩa một ABI (giao diện nhị phân qua thanh ghi). Linux PSCI driver là phía gọi. TF-A lib/psci là phía thực thi. SMCCC là quy ước gọi mà PSCI dùng để chuyển dữ liệu.

#Secure world, non-secure world và TrustZone

TrustZone chia tài nguyên (bộ nhớ, thanh ghi thiết bị, ngắt) thành phần secure và non-secure. Code non-secure (Linux) không thể chạm vào tài nguyên secure. PSCI liên quan trực tiếp vì những thứ cần chạm để bật một core (reset vector, power controller, context secure của core đích, phần secure của GIC) thường nằm ở phía secure, nên Linux phải nhờ EL3.

#Khi CPU0 thực thi lệnh SMC

Nói ngắn gọn

Ví dụ đời thường

Kỹ thuật
Không đổi sang CPU khác. Đổi EL từ EL1 lên EL3 (synchronous exception, EC = SMC64). Tham số: x0 = function ID, x1..x7 = đối số. Kết quả trả về: x0 (và x1..x3 nếu có). Trong lúc CPU0 ở EL3, Linux trên CPU0 “đứng yên”; các CPU khác vẫn chạy.

Có thể sai

     * We need to tell the secondary core where to find its stack and the
     * page tables.

    secondary_data.task = idle;
    secondary_data.stack = task_stack_page(idle) + THREAD_SIZE;
    update_cpu_boot_status(CPU_MMU_OFF);
    __flush_dcache_area(&secondary_data, sizeof(secondary_data));

    /* Now bring the CPU into our world */
    ret = boot_secondary(cpu, idle);
    if (ret) {
        pr_err("CPU%u: failed to boot: %d\n", cpu, ret);
        return ret;
    }

    /*
     * CPU was successfully started, wait for it to come online or
     * time out.
     */
    wait_for_completion_timeout(&cpu_running,
                    msecs_to_jiffies(5000));
    if (cpu_online(cpu))
        return 0;

    pr_crit("CPU%u: failed to come online\n", cpu);
    secondary_data.task = NULL;
    secondary_data.stack = NULL;
    __flush_dcache_area(&secondary_data, sizeof(secondary_data));
    status = READ_ONCE(secondary_data.status);
    if (status == CPU_MMU_OFF)
        status = READ_ONCE(__early_cpu_boot_status);

    switch (status & CPU_BOOT_STATUS_MASK) {
    default:
        pr_err("CPU%u: failed in unknown state : 0x%lx\n",
               cpu, status);
        cpus_stuck_in_kernel++;
        break;
    case CPU_KILL_ME:
        if (!op_cpu_kill(cpu)) {
            pr_crit("CPU%u: died during early boot\n", cpu);
            break;
        }
        pr_crit("CPU%u: may not have shut down cleanly\n", cpu);
        fallthrough;
    case CPU_STUCK_IN_KERNEL:
        pr_crit("CPU%u: is stuck in kernel\n", cpu);
        ...
        cpus_stuck_in_kernel++;
        break;
    case CPU_PANIC_KERNEL:
        panic("CPU%u detected unsupported configuration\n", cpu);
    }

    return -EIO;

#21 Glossary

PSCI
Ngắn gọn: Đặc tả của ARM để OS nhờ firmware bật/tắt/ngủ CPU.
Kỹ thuật: ARM DEN0022; ABI qua SMC/HVC; function ID dải 0x84000000/0xC4000000.
Xem mục liên quan
SMCCC
Ngắn gọn: Quy ước thanh ghi khi gọi firmware.
Kỹ thuật: ARM DEN0028; x0 = function ID (fast/SMC64/owner/number), x1–x7 tham số, kết quả x0–x3.
Xem mục liên quan
SMC
Ngắn gọn: Lệnh gọi lên EL3.
Kỹ thuật: Synchronous exception tới VBAR_EL3; dùng khi không có hypervisor.
Xem mục liên quan
HVC
Ngắn gọn: Lệnh gọi lên EL2.
Kỹ thuật: Dùng khi Linux chạy dưới hypervisor; DT method = "hvc".
Xem mục liên quan
EL1 / EL2 / EL3
Ngắn gọn: Ba mức đặc quyền: kernel, hypervisor, secure monitor.
Kỹ thuật: Đổi EL chỉ qua exception (lên) và eret (xuống).
Xem mục liên quan
MPIDR
Ngắn gọn: Số định danh phần cứng của core.
Kỹ thuật: MPIDR_EL1; Aff0 core, Aff1 cluster, Aff2/Aff3 cấp cao hơn; firmware dùng nó để chọn core.
Xem mục liên quan
Affinity
Ngắn gọn: Vị trí của core trong cây topology.
Kỹ thuật: Các trường Aff0–Aff3 của MPIDR; PSCI quản lý trạng thái theo affinity level.
Xem mục liên quan
Power domain
Ngắn gọn: Vùng phần cứng bật/tắt nguồn cùng nhau.
Kỹ thuật: Core, cluster, system; TF-A dựng cây power domain từ topology platform.
Xem mục liên quan
Reset vector
Ngắn gọn: Địa chỉ lệnh đầu tiên sau khi nhả reset.
Kỹ thuật: Trên AP806: MVEBU_CCU_RVBAR(cluster, cpu), giá trị dịch phải 16 bit.
Xem mục liên quan
secondary_entry
Ngắn gọn: Điểm Linux muốn CPU phụ bắt đầu.
Kỹ thuật: Nhãn asm trong head.S (.idmap.text), truyền PA cho firmware qua CPU_ON.
Xem mục liên quan
CPU hotplug
Ngắn gọn: Cơ chế online/offline CPU lúc chạy.
Kỹ thuật: State machine cpuhp_hp_states; BP chạy tới BRINGUP_CPU, AP tự chạy phần còn lại.
Xem mục liên quan
Coherency
Ngắn gọn: Các cache nhìn thấy cùng dữ liệu.
Kỹ thuật: Cần SMPEN trong CPUECTLR và interconnect (CCU) trước khi bật cache/MMU.
Xem mục liên quan
GIC
Ngắn gọn: Bộ điều khiển ngắt.
Kỹ thuật: GICv2 trên board này; CPU interface per-core được BL31 và Linux khởi tạo.
Xem mục liên quan
MMU
Ngắn gọn: Bộ dịch địa chỉ ảo sang vật lý.
Kỹ thuật: CPU1 bật MMU trong __enable_mmu; trước đó chạy bằng PA.
Xem mục liên quan
TF-A
Ngắn gọn: Trusted Firmware-A, firmware tham chiếu của ARM.
Kỹ thuật: BL1/BL2/BL31; BL31 thường trú ở EL3, chứa PSCI.
Xem mục liên quan
SCP
Ngắn gọn: Bộ xử lý quản lý hệ thống.
Kỹ thuật: Core riêng nhận lệnh SCPI qua MHU; trên board này nhận scpi_set_css_power_state.
Xem mục liên quan
PMIC
Ngắn gọn: Chip quản lý nguồn trên board.
Kỹ thuật: Cấp rail điện cho SoC; hiếm khi gây lỗi riêng một core.
Xem mục liên quan
Secure Monitor
Ngắn gọn: Code EL3 chuyển giữa secure và non-secure.
Kỹ thuật: Trong TF-A là phần runtime của BL31.
Xem mục liên quan
ON_PENDING
Ngắn gọn: CPU đang được bật, chưa xong.
Kỹ thuật: Trạng thái affinity của firmware giữa CPU_ON và psci_cpu_on_finish.
Xem mục liên quan
