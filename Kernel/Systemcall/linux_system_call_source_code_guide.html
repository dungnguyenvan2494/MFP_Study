01 · Overview

A system call is the controlled boundary between an unprivileged userspace process (EL0) and the kernel (EL1). This handbook does not re-explain that theory at length — it exists to let you open the real Linux kernel source and trace what happens, line by line, when a process executes read(3, buffer, 100);.

🧠 MENTAL MODEL — what is actually being traced
Application ↓ libc wrapper (packs args into x0-x5, syscall number into x8) ↓ syscall ABI (AArch64 SVC calling convention) ↓ ARM64 SVC #0 (CPU takes a synchronous exception, EL0 → EL1) ↓ exception entry (arch/arm64/kernel/entry.S) ↓ pt_regs (register state saved on the kernel stack) ↓ syscall dispatch (arch/arm64/kernel/syscall.c) ↓ kernel function (__arm64_sys_read / __arm64_sys_write / __arm64_sys_openat) ↓ VFS / subsystem (fs/read_write.c, fs/open.c, fs/namei.c) ↓ return (x0), eret, EL1 → EL0

04 · ARM64 Exception Entry

💡 KEY IDEA
CPU hardware behavior and Linux software behavior are two different layers. The CPU only knows how to (1) save ELR_EL1/SPSR_EL1/ESR_EL1, (2) switch EL0→EL1, and (3) jump to whatever address VBAR_EL1 + offset points to. Everything past that jump — pt_regs, dispatch, sys_call_table — is pure software, written in entry.S/entry-common.c/syscall.c.

🔍 SOURCE CODE — CPU vs software boundary
CPU hardware did: EL0→EL1, ESR_EL1/ELR_EL1/SPSR_EL1 capture, jump to VBAR_EL1+offset.
Linux software did everything else: kernel_entry saved GPRs into pt_regs, el0_sync_handler read ESR_EL1 in C via read_sysreg() and branched on the exception class.

💡 KEY IDEA — orig_x0 vs regs[0]
regs[0] gets overwritten with the syscall's return value before eret (see §32). orig_x0 preserves the original argument value for ptrace/audit/syscall-restart code that needs to know what x0 was before the syscall ran.

static void invoke_syscall(struct pt_regs *regs, unsigned int scno,
			   unsigned int sc_nr,
			   const syscall_fn_t syscall_table[])
{
	long ret;

	if (scno < sc_nr) {
		syscall_fn_t syscall_fn;
		syscall_fn = syscall_table[array_index_nospec(scno, sc_nr)];
		ret = __invoke_syscall(regs, syscall_fn);
	} else {
		ret = do_ni_syscall(regs, scno);
	}

	syscall_set_return_value(current, regs, 0, ret);
}

array_index_nospec() is a Spectre-v1 hardening clamp: even though scno < sc_nr was already checked, this forces the index used for the actual memory load to be bounded, defeating speculative out-of-bounds reads of sys_call_table. An out-of-range scno — including a genuinely bad number or the ptrace "skip syscall" sentinel — falls to do_ni_syscall(), which returns -ENOSYS via sys_ni_syscall().

Why the kernel can't just memcpy(kernel_buf, user_ptr, size): a user pointer is unprivileged and unverified — it could point outside the process's mapped range, into an unmapped hole, or (without access_ok) even be crafted to alias kernel-only ranges depending on TTBR0/addr_limit state. A plain memcpy has no exception-table protection and no range check — a bad pointer would fault deep inside the kernel with no recovery path, i.e. an oops/panic instead of a clean -EFAULT to the calling process.

fixup_exception() — full function

int fixup_exception(struct pt_regs *regs)
{
	const struct exception_table_entry *fixup;

	fixup = search_exception_tables(instruction_pointer(regs));
	if (!fixup)
		return 0;

	if (in_bpf_jit(regs))
		return arm64_bpf_fixup_exception(fixup, regs);

	regs->pc = (unsigned long)&fixup->fixup + fixup->fixup;
	return 1;
}

search_exception_tables() (generic kernel code, lib/extable.c) binary-searches the sorted __ex_table sections (built-in image + loaded modules) for an entry whose relocated insn field matches the faulting PC. If found, fixup_exception() decodes the relative fixup offset back into an absolute address and writes it straight into regs->pc — meaning the CPU's next executed instruction, after this synchronous-exception handler returns and erets back to EL1, is the fixup code, not wherever the original PC+4 would have been.

💡 KEY IDEA — why the kernel doesn't crash
A bad user pointer passed to copy_from_user causes a real CPU exception, exactly like any other invalid memory access. The kernel doesn't "check the pointer is safe" in advance in any way that avoids the fault — it lets the fault happen, catches it via the exception-table/fixup mechanism because the fault occurred at a PC known to be inside a uaccess routine, and converts it into a normal -EFAULT return. If the same bad access happened at a PC not registered in __ex_table, fixup_exception() returns 0 and the kernel oopses/panics — this is precisely how the kernel tells the difference between "a syscall got a bad pointer" (recoverable) and "a real kernel bug dereferenced garbage" (not recoverable).

Note the layering: vfs_read()/vfs_write() at the generic VFS level take no per-inode lock at all for read, and only the freeze-protection percpu-rwsem for write. {
	spin_lock(&inode->i_lock);
	if (!(inode->i_state & (I_FREEING|I_WILL_FREE))) {
		__iget(inode);
		spin_unlock(&inode->i_lock);

		inode = NULL;
	}
	return inode;
}

void iput(struct inode *inode)
{
	if (!inode) return;
retry:
	if (atomic_dec_and_lock(&inode->i_count, &inode->i_lock)) {
		if (inode->i_nlink && (inode->i_state & I_DIRTY_TIME)) {
			atomic_inc(&inode->i_count);
			spin_unlock(&inode->i_lock);
			mark_inode_dirty_sync(inode);
			goto retry;
		}
		iput_final(inode);
	}
}

i_count is literally an atomic_t (include/linux/fs.h:691). igrab() refuses to hand out a reference to an inode already being torn down (I_FREEING/I_WILL_FREE), returning NULL instead.

⚠️ IMPORTANT — refcounting is per-object, don't conflate them
files_struct.count, file.f_count, dentry.d_lockref, and inode.i_count are four independent counters on four independent objects. Closing one fd (dropping one f_count reference) does not necessarily free the struct file (another fd from dup() may hold a reference), and freeing the struct file via __fput() only then drops one dentry reference (dput()) and one inode reference indirectly through the dentry — the inode itself might still be referenced by other dentries or in-kernel holders.

Common Misconceptions

❌ fd == struct file*

Wrong. An fd is just an integer index into current->files->fdt->fd[]. Correct: the fd is looked up through fdget()/fdget_pos() to obtain the actual struct file *. Multiple fds (via dup()) can resolve to the identical struct file*. Evidence: struct fd { struct file *file; unsigned int flags; }; (include/linux/file.h:36-39) — the fd number and the file pointer are explicitly different types passed around together.

❌ struct file == inode

Wrong. struct file represents one open instance (with its own f_pos, f_flags); struct inode represents the underlying object on disk, shared by every open instance and every dentry that names it. Evidence: two independent open() calls on the same path allocate two separate struct file (via alloc_empty_file(), fresh f_count=1 each time) but resolve to the same cached f_inode pointer.

❌ access_ok() guarantees the memory access will succeed

Wrong. It only validates that the address range falls within addr_limit — a range check, not a mapping check. Correct: the actual load/store can still fault (unmapped page, permission fault), which is exactly why the exception-table/fixup mechanism (§30) exists at all — see the explicit callout in §25.

❌ the kernel directly sets userspace errno

Wrong. syscall_set_return_value() (asm/syscall.h:51-62) writes only into pt_regs->regs[0], a plain register. There is no kernel code path that writes a symbol named errno in the calling process's address space — that translation is entirely libc's job, after eret.

❌ a syscall is always one simple C function

Wrong. SYSCALL_DEFINE3(read, ...) alone expands into three separate generated functions on arm64 (__arm64_sys_read, __se_sys_read, __do_sys_read, §08) before even reaching ksys_read/vfs_read/the filesystem's read_iter — five-plus real function calls deep before touching a byte of data.

❌ the syscall table mechanism is identical on x86 and ARM64

Wrong — even the naming convention differs. On arm64, the macro that expands SYSCALL_DEFINEx generates __arm64_sys_<name> taking a single const struct pt_regs * argument (arch/arm64/include/asm/syscall_wrapper.h:51-67); the plain, multi-argument sys_<name>(a,b,c) C signature the book describes is an x86-style convention that arm64 explicitly overrides via its own __SYSCALL_DEFINEx.
