## 0 · Cách proxy được nối vào luồng gói

```
low_level_input (T5.1)  →  SysFilter_Execute_Filter(frame, len, 0)          ← STAGE_1 (raw)
     │ RC_OK
     ▼
lwIP ethernet_input → ip4_input / ip6_input:
     SysFilter_Execute_Filter(payload, len, L4_proto)                       ← STAGE_2  (ip4.c:571 / ip6.c:684)
        → SysFilter_PacketFilterGetMatchingFilterOfPacket [Stage 2]:
             với mỗi filter ENABLED khớp mọi sub-pattern:
                if (FilterFunctionID & FILTER_ENABLE_CALLBACK):
                    ffunc = FFL[FilterFunctionID & MASK]                     ← FFL[7] = filter_function_mdns_proxy
                    if (!ffunc(i, Protocol, PacketType, p, length))  continue;   // callback trả FALSE = "no match"
                return (i | FILTER_ID_MATCH)                                 // callback trả TRUE = match
```

`FFL[MAX_FILTERFUNCTION_NUM = 7]` (`sys_filter_main.c:63`) — bảng callback. `app_thread.c:685`:
```c
ApiSysSoftwarePatternSetCallBackFunction(7, filter_function_mdns_proxy);   // đăng ký FFL[7]
```

### `filter_function_mdns_proxy()` (`app_thread.c:1056-1196`) — bộ định tuyến 3 proxy
```c
if (dst_port == 5353)                          return simple_mdns_proxy_process_request(PacketType, Packet, Length);
if (FilterID == ID_FILTER_STAGE2_LLMNR_PROXY)  return llmnr_proxy_process_request(PacketType, Packet, Length);
if (FilterID == ID_FILTER_STAGE2_NBNS_PROXY)   return nbns_proxy_process_request(PacketType, Packet, Length);
```
Cùng 1 callback phục vụ cả 3 proxy: mDNS phân biệt bằng **cổng 5353**, LLMNR/NBNS bằng **FilterID**
(do Linux gán khi `MSG_CMD_PATTERN_DEFINE`).

### Giá trị trả về của proxy
| Trả | Nghĩa với `SysFilter` | Kết quả gói |
|---|---|---|
| `SYS_FALSE` | "no match" (`continue`) | gói tiếp tục vào lwIP như thường |
| `SYS_TRUE` | match (`return i \| FILTER_ID_MATCH`) | filter đã "nuốt" gói — proxy đã trả lời / đánh thức / bỏ im lặng |

## 1 · Cấu hình proxy — IOCTL từ Linux (một lần, trước khi host ngủ)

Mọi proxy nhận **cặp (query name → answer record)** từ Linux qua HCI FIFO:
| Proxy | Message | Hàm add |
|---|---|---|
| LLMNR | `MsgLlmnrProxyConfig` | `llmnr_proxy_add_records(mcfg)` |
| NBNS | `MsgNbnsProxyConfig` | (tương tự trong `nbns_proxy.c`) |
| mDNS | `MsgSimpleMdnsProxyConfig` | `add_answer_data` / `add_answer_txt` |

`llmnr_proxy_add_records`:
- kiểm `answer_type ∈ {QTYPE_A, QTYPE_AAAA, QTYPE_PTR}` (không nhận `ANY`)
- `llmnr_query_is_present(query_data)` — nếu tên chưa có → thêm vào `querylist[proxyindex]`,
  **chữ thường a-z được chuẩn hoá thành HOA** (`& ~0x20`) vì LLMNR/DNS không phân biệt hoa thường
- thêm `answerlist[answerindex]` = `{query_index, answer_type, answer_class, answer_ttl, answer_length, answer_data}`

`proxyindex == 0` → proxy tắt (`llmnr_proxy_process_request` trả FALSE ngay).
`llmnr_proxy_stop()` giải phóng tất cả.

## 2 · `llmnr_proxy_process_request(PacketType, Packet, Length)` (`llmnr_proxy.c:222-413`)

Đây là mẫu chuẩn ECMA-393 — R83–R89 (ProxZzzy for Sleeping Hosts):

```
① proxyindex == 0                                          → SYS_FALSE  (không có config)
② ethtype: 0x800 IPv4 / 0x86dd IPv6; khác                  → SYS_FALSE
③ dport != LLMNR_PORT (5355)                               → SYS_FALSE           [R85]
④ dest IP != link-local multicast:
     IPv4: 224.0.0.252 ; IPv6: ff02::1:3                    → SYS_FALSE           [R85/R86 — no unicast]
⑤ q_flags & 0x400  (bit 'C' = conflict resolution)         → ApiSysNetworkWakupAndForwardPacketToDriver()
                                                              → ★ ĐÁNH THỨC HOST + forward ; SYS_TRUE   [R89]
⑥ qdcount != 1                                             → SYS_TRUE  (nuốt, không trả lời)
⑦ tìm null-termination của query name; không có            → SYS_TRUE
⑧ llmnr_query_is_present(name)  (so HOA-hoá, case-insensitive)
     query_i < 0  (tên không trong danh sách của mình)     → SYS_TRUE  (nuốt im lặng — không phải tên mình)
⑨ QTYPE ∉ {A, AAAA, PTR, ANY}                              → SYS_TRUE           [R87 ecma393]
⑩ duyệt answerlist[]: khớp query_index == query_i && (answer_type & *p_query_type):
     matching_index[i] = i ; ancount++ ; response_size += RR_NAME + 4+2 + RDLENGTH
⑪ response_size + header > MAX_ETHERNET_FRAME_LENGTH        → SYS_TRUE           [R83 — không phân mảnh]
⑫ COMPOSE RESPONSE:
     copy request từ đầu tới hết Question section
     p_response->q_flags = 0x8000  (bit QR = response)
     p_response->ancount = ancount ; nscount = arcount = 0
     với mỗi matching_index >= 0:
        RR_NAME  = copy y hệt QUESTION_NAME
        type/class/ttl/length = từ answerlist[i]
        RDATA    = answerlist[i].answer_data (kiểm allocation_exceeded từng byte)
⑬ appSendUdpPacket(response, size, sport, ip, dport, is_ipv4, false)   ← gửi thẳng ra GMAC
   ApiSysMemFree(response)
   return SYS_TRUE  (gói yêu cầu bị discard)
```

**Điểm cốt lõi:** LPPP trả lời LLMNR query cho **đúng các tên Linux đã đăng ký**, bằng **đúng
record Linux đã cấp**, mà **KHÔNG đánh thức A72**. Chỉ đánh thức khi:
- bit conflict-resolution (`0x400`) → có host khác tranh tên → host thật phải xử lý (bước ⑤)

Các trường hợp khác (tên lạ, qtype lạ, malformed) → **nuốt im lặng** (`SYS_TRUE`, không trả lời,
không đánh thức) — đúng tinh thần "đừng làm phiền host cho query không liên quan".

## 3 · `nbns_proxy_process_request` (`nbns_proxy.c:182`) — NetBIOS Name Service

Cùng mẫu: cổng **137**, `answerlist[MAX_NBNS_PROXY_ANSWER_RECORDS_SUPPORTED]`. NBNS name = 32-byte
encoded (nửa-byte nibble → chữ). Linux cấu hình tên máy in + IP; LPPP trả NBNS response offline.

## 4 · `simple_mdns_proxy_process_request` (`simple_mdns_proxy.c`) — multicast DNS

Cổng **5353**, multicast `224.0.0.251` / `ff02::fb`. Phức tạp nhất (864 dòng) vì mDNS có nhiều
record type: `A/AAAA` (host), `PTR` (service discovery `_ipp._tcp.local` v.v.), `SRV`, `TXT`
(printer capabilities). `mdns_answerlist[]` + `add_answer_data` / `add_answer_txt`
(`MsgSimpleMdnsProxyConfig`). `get_answer_index(qi)` khớp `query_i + qtype`. Linux đăng ký toàn
bộ bản ghi mDNS của máy in (tên, dịch vụ IPP/AirPrint, TXT capabilities) → LPPP trả lời truy vấn
"máy in nào ở đây / hỗ trợ gì" mà host vẫn ngủ.

## 5 · Tóm tắt (theo format skill)

**1. Tồn tại để làm gì:** 3 proxy khám phá tên/dịch vụ (LLMNR 5355, NBNS 137, mDNS 5353) triển
khai ECMA-393 "ProxZzzy": Linux đăng ký trước (query-name → answer-records) qua IOCTL; khi host
ngủ, `SysFilter` STAGE_2 (chạy trong `ip4_input`/`ip6_input`) khớp gói, gọi callback `FFL[7] =
filter_function_mdns_proxy`, hàm này định tuyến theo cổng/FilterID tới `*_proxy_process_request`.
Proxy kiểm cổng + multicast IP + tên đăng ký + qtype hợp lệ → **tự dựng DNS response và gửi thẳng
ra GMAC** (không đánh thức A72). Chỉ đánh thức khi có xung đột tên (bit conflict-resolution). Trả
`SYS_TRUE` = đã nuốt gói, `SYS_FALSE` = gói không phải của proxy → tiếp tục vào lwIP.

**2. Call flow:**
```
low_level_input → SysFilter STAGE_1 → lwIP ethernet_input → ip4_input/ip6_input
   → SysFilter_Execute_Filter(payload, len, UDP)  [STAGE_2]
      → GetMatchingFilter: filter khớp + FILTER_ENABLE_CALLBACK
         → FFL[7](i, UDP, PacketType, payload, len) = filter_function_mdns_proxy
            ├─ dst_port 5353            → simple_mdns_proxy_process_request
            ├─ FilterID = LLMNR_PROXY   → llmnr_proxy_process_request:
            │     port 5355 + mcast 224.0.0.252/ff02::1:3 check
            │     conflict bit 0x400 → ApiSysNetworkWakupAndForwardPacketToDriver ; SYS_TRUE
            │     tên ∉ querylist / qtype lạ → SYS_TRUE (nuốt, không trả lời)
            │     match → compose DNS response (QR=0x8000, ancount, RRs) → appSendUdpPacket ; SYS_TRUE
            └─ FilterID = NBNS_PROXY    → nbns_proxy_process_request (port 137)
```
