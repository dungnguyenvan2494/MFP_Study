# T4.6 — `LPPP_QoS.c` : mọi thanh ghi AXI QoS + vì sao Sleep1 ≠ Sleep2/ErP

> Nguồn: `lppp_s800/ApplicationKM/LPPP_QoS.c` (262 dòng, toàn bộ), `LPPP_QoS.h`.
> Callers: `hal_main.c:194-197` (init_thread), `LPPP_Matrix.c:267` (TR4), `:384-385` (TR8/10).
> Bổ sung `PowerControlEventManager.md §5.4-5.5`, T3.2.

---

## 0 · QoS là gì

**AXI QoS** = trường ưu tiên (ARQOS đọc / AWQOS ghi, 0–15) mà **bộ trọng tài của AXI fabric**
dùng để phân xử khi nhiều master tranh bus DDR. Cao hơn = được ưu tiên. `LPPP_QoS.c` đặt profile
QoS cho các master (CPU A72, GPU, LCD, DMA, MoChi x4, PIDI, UL, ICU…) để **băng thông DDR không
sụt** làm chậm việc in.

## 2 · `LPPP_QoS_Init()` (`LPPP_QoS.c:245-262`) — 2 reg, **chỉ cold boot**

```c
mrvl_regwrite32(LPPP_QOS_PI_LCD_READ, 0x2);                        // 0xC0445100 ← 0x2   (LCD read pri = 2)
mrvl_regrdmwr32(LPPP_QOS_ICU_AXI_ATTR, 0x0F000000, 0x02000000);   // 0xE8310000 AWQOS[27:24] = 2  (ICU write pri = 2)
```
`LPPP_QOS_ICU_AWQOS_MASK = 0x0F000000` (bits [27:24]). Không được gọi lại ở bất kỳ resume nào —
LCD/ICU giữ giá trị.

---

## 3 · `LPPP_QoS_SetupUL()` (`LPPP_QoS.c:222-230`) — 1 reg, **cold + TR4**

```c
mrvl_regwrite32(LPPP_QOS_UL_PRI0_U2A_MAIN, 0x00021012);   // 0xC0040040 ← 0x00021012
```
`LPPP_QOS_UL_PRI0_U2A_MAIN = 0xC0000000 + 0x40000 + 0x40 = 0xC0040040` (UL System block).
`0x00021012` = 5 nibble `[2,1,0,1,2]` cho 5 kênh **U2A (UL → AXI)**:
```
ch4 = 2   ch3 = 1   ch2 = 0   ch1 = 1   ch0 = 2
```
Comment `ch43210を高い順→中→[21012]へ` = "từ ch43210 cao→trung→`[21012]`" — hạ profile từ mức
cao xuống mức trung bình (kênh giữa thấp nhất, kênh biên cao nhất).

---

## 4 · `LPPP_QoS_SetupMoChi()` (`LPPP_QoS.c:238-...`) — 10 reg, **cold + TR8/10**

```c
mrvl_regwrite32(LPPP_QOS_MISC_MCix4_RD0..RD4, 0x00000000);   // 0xC05A0080 .. 0xC05A0090  ← 0
mrvl_regwrite32(LPPP_QOS_MISC_MCix4_WR0..WR4, 0x00000000);   // 0xC05A00C0 .. 0xC05A00D0  ← 0
```
`LPPP_QOS_MISC_BASE = 0xC05A0000`. RD0-4 offset `+0x80..0x90`, WR0-4 offset `+0xC0..0xD0`.
Ghi **0** = "MCIx4 Read/Write QoS **Remapping** Register" tắt remap → giá trị QoS của master gốc
đi thẳng qua liên kết MoChi x4, không bị đổi.
(+ `#if 1` khối ~10 dòng `ApiSysDebug_Printf` đọc lại từng reg.)

## 5 · `LPPP_QoS_SetupAP()` (`LPPP_QoS.c:107-...`) — ~15 reg, **cold + TR8/10**

```c
mrvl_regwrite32(0xCE000F18, 0x441);                              // AP806 reg (không tên) ← 0x441

/* CCU_B_LTC_QOS: READ pri = [0x100], WRITE pri = [0x010], share-enable = [0x001] */
mrvl_regwrite32(0xCE001B18, 0x001);   // CCU_B_LTC_QOS_CPU01 — chỉ bật share, pri R/W = 0
mrvl_regwrite32(0xCE001F18, 0x001);   // CCU_B_LTC_QOS_CPU23
mrvl_regwrite32(0xCE001318, 0x000);   // CCU_B_LTC_QOS_DMA — tắt hẳn (kể cả share)

mrvl_regwrite32(0xC05A0000..0x0010, 0);   // PIDI Read  QoS Remap RD0..RD4 ← 0
mrvl_regwrite32(0xC05A0040..0x0050, 0);   // PIDI Write QoS Remap WR0..WR4 ← 0

/* MCIx4 outstanding 8/8 */
mrvl_regwrite32(NB_MOCHIx4_CONTROLLER_ADDR    /*0xCC000000*/, 0x090081c7);
mrvl_regwrite32(NB_MOCHIx4_CONTROLLER_ADDR + 4/*0xCC000004*/, 0x000d0120);
mrvl_regwrite32(NB_MOCHIx4_CONTROLLER_ADDR + 4/*0xCC000004*/, 0x000d0300);   // ⚠ GHI LẦN 2 CÙNG ĐỊA CHỈ
```
`CCU_B_LTC_QOS_*` (AP806 CCU): `0x001` = chỉ bit share-enable; `0x000` (DMA) = tắt hẳn.
`0xCE000F18 ← 0x441` — không có tên trong header (AP806 CCU config).
`NB_MOCHIx4_CONTROLLER_ADDR + 4` ghi **2 lần** (`0x000d0120` → `0x000d0300`): giá trị đầu bị đè
ngay. Comment "MCIx4 outstanding 8/8" = cho phép 8 giao dịch đọc + 8 ghi chưa hoàn tất trên liên
kết MoChi x4. _(Ghi 2 lần có thể là bug hoặc chuỗi bắt buộc để kích cấu hình — nguồn không nói rõ.)_
(+ `#if 1` khối ~13 dòng `ApiSysDebug_Printf` đọc lại — góp phần làm TR8/10 chậm nhất.)

## 6 · Bản đồ địa chỉ QoS đầy đủ (`LPPP_QoS.c:17-95`)

| Nhóm | Base | Thanh ghi | Địa chỉ |
|---|---|---|---|
| **UL** | `0xC0000000` | `UL_PRI0_U2A_MAIN` (`+0x40040`) | `0xC0040040` |
| **PI fabric** | `0xC0400000` | `GPU0/1_R/W` (`+0x43100/4`, `+0x44100/4`), `LCD_R/W` (`+0x45100/4`), `JPEG_R/W` (`+0x46100/4`) | `0xC0443100`… `0xC0446104` |
| **MISC** | `0xC05A0000` | `PIDI_RD0..4` (`+0x000..010`), `PIDI_WR0..4` (`+0x040..050`), `MCix4_RD0..4` (`+0x080..090`), `MCix4_WR0..4` (`+0x0C0..0D0`) | `0xC05A0000`… `0xC05A00D0` |
| **AP806 CCU** | — | `CCU_B_LTC_QOS_CPU01/CPU23/DMA` | `0xCE001B18` / `0xCE001F18` / `0xCE001318`; + `0xCE000F18` |
| **AON fabric** | `0xE8100000` | `USB2_R/W`, `R4_R/W`, `PMU_R/W`, `CS_R/W`, `SDMMC_R/W` (`+0x42100`…`+0x47104`) | `0xE8142100`… `0xE8147104` **(khai báo nhưng KHÔNG dùng)** |
| **CDMA** | `0xE8271000` | `AXI_CORE0..9_QOS` (`+0x100*(n+1)+0x0C`) | `0xE827110C`… `0xE8271A0C` **(khai báo nhưng KHÔNG dùng — CDMA code chết)** |
| **ICU** | `0xE8310000` | `ICU_AXI_ATTR` (`+0x000`), mask `AWQOS = 0x0F000000` | `0xE8310000` |
| **NB MoChi** | — | `NB_MOCHIx4_CONTROLLER_ADDR` (+0, +4) | `0xCC000000` / `0xCC000004` |

⚠ Nhóm **AON** (`USB2/R4/PMU/CS/SDMMC` QoS) và **CDMA** QoS: `#define` đầy đủ nhưng **không hàm
nào ghi** — di sản. (CDMA là code chết — `CDMA.md`.)

## 7 · Vì sao Sleep1 ≠ Sleep2/ErP (câu hỏi cốt lõi T4.6)

| | **TR4: Sleep1 → Normal** | **TR8/10: Sleep2/ErP → Sleep1** |
|---|---|---|
| Gọi | `LPPP_QoS_SetupUL()` (1 reg) | `LPPP_QoS_SetupMoChi()` (10) + `LPPP_QoS_SetupAP()` (~15) |
| Domain nào mất điện khi ngủ | **chỉ cụm CPU A72** (`pmu_baseline` giữ SYS_PLL; MCix4/PIDI/CCU/UL domain **CÒN điện**) | `pmu_MCix4`, `pmu_PIDI`, `pmu_UL`, `pmu_Mech_TOP`, **toàn bộ AP806** đều bị cắt (`power_up_dev[]` power-down B→T, `pmu_ap_link_down`) |
| Thanh ghi QoS | MCix4/PIDI/CCU QoS **giữ nguyên giá trị** (domain còn điện) → chỉ UL cần nạp lại | MCix4/PIDI/CCU QoS **về mặc định reset** khi domain mất điện → phải nạp lại toàn bộ |

**Nguyên tắc:** thanh ghi QoS nằm trong power domain nào thì **mất giá trị khi domain đó mất điện**.
- Sleep1 chỉ cắt cluster CPU → domain chứa MCix4/PIDI/CCU vẫn giữ → QoS còn nguyên.
- Sleep2/ErP cắt các domain đó → QoS về 0/reset → `SetupMoChi` + `SetupAP` phải chạy lại.

`LPPP_QoS_Init` (LCD + ICU) **không** nằm trong đường resume nào → LCD/ICU domain giữ state qua
mọi chu kỳ sleep (hoặc ít tới hạn hơn).

**Chi phí:** TR8/10 = 25 lần ghi reg + **~23 dòng `ApiSysDebug_Printf` đọc lại** + I2C tới PS-CPU
+ flash RMW B014 (T3.2) → **transition đắt nhất toàn ma trận**, chạy đồng bộ trong stack 1200B của
`PwEvtMgr`, chặn mọi event sau nó trong queue 20 slot.

## 8 · Tóm tắt (theo format skill)

**1. Tồn tại để làm gì:** `LPPP_QoS.c` đặt profile ưu tiên AXI cho các master (CPU/GPU/LCD/DMA/
MoChi/PIDI/UL/ICU) để băng thông DDR không sụt khi in. 4 hàm: `Init` (LCD+ICU pri=2, chỉ cold boot),
`SetupUL` (1 reg `0xC0040040 ← 0x21012`, cold + TR4), `SetupMoChi` (10 reg MCix4 RD/WR remap ← 0,
cold + TR8/10), `SetupAP` (~15 reg: AP806 CCU_B_LTC_QOS, PIDI remap ← 0, MoChi outstanding 8/8,
cold + TR8/10). Sleep1 chỉ cần `SetupUL` vì MCix4/PIDI/CCU domain còn điện; Sleep2/ErP cần cả
`SetupMoChi`+`SetupAP` vì các domain đó mất điện → QoS về reset.
