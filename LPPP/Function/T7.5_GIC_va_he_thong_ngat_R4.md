## 1. Phần cứng: GIC-400 (ARM GICv2)

**FACT** (`regAddrs.h:98-99`):
| block | base | struct |
|-------|------|--------|
| Distributor (GICD) | `0xE8260000 + 0x1000` = **`0xE8261000`** | `GIC_DIST_REGS_t` (`ICD_*`) |
| CPU Interface (GICC) | `0xE8260000 + 0x2000` = **`0xE8262000`** | `GIC_CPU_REGS_t` (`ICC_*`) |

`NUM_GIC_SUPPORTED = 288` (số ngắt FW cấp phát handler), `NUM_GIC_INTS = 1024` (tối đa GIC). `interrupt_max_id` tính runtime = `32 × ((ICD_ICTR & 0x1f) + 1)`.

### 1.1 Đánh số ngắt: `INTRL_GIC_OFFSET = 32`
Mọi `INTNUM_*` = `<số SPI> + 32` (SPI bắt đầu từ ID 32; ID 0–15 = SGI, 16–31 = PPI). Ví dụ:
| INTNUM | công thức | GIC ID |
|--------|-----------|--------|
| `INTNUM_TIMEBASE_1US` | 0 + 32 | 32 |
| `INTNUM_TIMER0` | 6 + 32 | 38 |
| `INTNUM_I2C_0` | 21 + 32 | 53 |
| `INTNUM_PMU` | 26 + 32 | 58 |
| `INTNUM_QSPI` | 36 + 32 | 68 |
| `INTNUM_USB` | 37 + 32 | 69 |
| `INTNUM_GPIO_A_2` | 111 + 32 | 143 (T7.3) |
| `INTNUM_MC_WDT` | 61 + 32 | 93 (T3.4) |
| `MC_LPP_IRQ0/1` | 96/97 + 32 | 128/129 (T3.5) |
| `INTNUM_HCU_WAKEUP` | 120 + 32 | 152 (T6) |
| `DUMMY_INT_NUM`/`PAUSE_R4_INT` SPI | 119 + 32 | 151 (T2.5) |

## 2. `arm_gic.c` — driver GIC

### 2.1 `gic_intInit()` (`arm_gic.c:60-137`)
1. lấy `config` (`arm_gic_get_config()`), `GicRegs = 0xE8261000`, `CpuRegs = 0xE8262000`.
2. `interrupt_max_id = 32 × ((ICD_ICTR & 0x1f) + 1)`.
3. **Disable & non-secure hoá tất cả**: vòng `ICD_ICER[i] = 0xFFFFFFFF` (disable), `ICD_IGRP[i] = 0` (group 0).
4. **Cấu hình edge/level** từ `int_config[]` (bit array, 1 = edge): ghi `ICD_ICFR[i/16]` 2 bit/ngắt (bit cao = trigger type). *Comment: bug 6270 — đọc lại ICFR không trả giá trị thật, RMW không dùng được.*
5. **cold_boot lần đầu**: `memset(Handlers, 0, ...)`. **Warm** (không cold): nạp lại priority từ `Handlers[].priority` vào `ICD_IPR` (giữ bảng handler qua warmboot — T2.4).
6. **Target**: vòng `ICD_IPTRRW[i] = 0xFFFFFFFF` — *"everybody gets each interrupt"* (mọi ngắt tới mọi CPU — nhưng R4 chỉ có 1 core).
7. `ICD_DCR = 1` (bật Distributor).
8. `ICC_PMR = 0xFF` (priority mask: nhận mọi mức), `ICC_ICR = 1` (bật CPU interface).

### 2.2 `gic_intattach(int_num, priority, handler, input)` (`:139-165`)
- ASSERT `int_num < 288`, `Handlers[int_num].Handler == NULL` (không chain), `priority < 31`.
- Lưu `Handlers[int_num] = {handler, input, priority}`.
- Ghi priority vào `ICD_IPR[int_num/4]` byte `(int_num%4)` — `priority << 3` (3 bit thấp không dùng).
- **KHÔNG enable** — phải gọi `intEnable` sau.

### 2.3 `gic_intenable` / `gic_intdisable` (`:180-215`)
- `enable`: đọc trạng thái cũ (`ICD_ISER[n/32] & bit`), rồi `ICD_ISER[n/32] = 1<<(n%32)` (set-enable). Trả trạng thái **trước đó** (để caller khôi phục).
- `disable`: `ICD_ICER[n/32] = 1<<(n%32)` (clear-enable). Trả trạng thái trước.

### 2.4 `irq_handler(void)` (`:220-260`) — gọi từ `IrqHandler_second_stage` (asm, T1.3)
```c
int_id = CpuRegs->ICC_IAR & 0x3ff;         // acknowledge, lấy ID
if (int_id == NUM_GIC_INTS - 1 /*1023*/)   return;   // spurious
Handlers[int_id].Handler(Handlers[int_id].handler_input);
CpuRegs->ICC_EOIR = int_id;                 // end-of-interrupt
```
- `TX_ENABLE_IRQ_NESTING` (ThreadX nesting) **không định nghĩa** → không nesting IRQ.
- Không kiểm `Handlers[int_id].Handler != NULL` trước khi gọi ⇒ ngắt bật mà chưa attach → nhảy NULL → crash. (An toàn nhờ `gic_intattach` bắt buộc trước `intEnable` + `Handlers` = 0 sau memset.)

### 2.5 `interrupt_hw_down()` / `interrupt_hw_init()` (`#ifdef HAVE_POWER_MGR`, `:262-300`)
- `interrupt_hw_down`: `ICD_ICER[i] = 0xFFFFFFFF` mọi slot (tắt hết trước sleep). Cảnh báo nếu còn ngắt bật (`ICD_ISER[i] && i`).
- `interrupt_hw_init`: gọi `intInit()`.

## 3. `int_common.c` — lớp định tuyến (main GIC + SIC + soft)

### 3.1 `intInit()` (`:49-71`)
1. `main_config = interrupt_config_main()` → `main_config->int_initialize()` = `gic_intInit()`.
2. Vòng SIC: `interrupt_config_sic(n)` — **`sic_config[] = {}` rỗng** ⇒ **không có SIC** (secondary interrupt controller). `arm_sic.c` không dùng.
3. `*(volatile uint32_t*)0xC05A0104 = 0x00022220` — **`ul_irq_ctrl`**: `[XSYNCLR1, XSYNCLR0, XPAGE1, XPAGE0] = falling edge (2)`, `[XINT] = low level (0)`. (Cấu hình polarity 5 ngắt UL/ICU ở tầng "extra logic" trước khi vào GIC.)

### 3.2 `intAttach/intEnable/intDisable/intDetach` (`:129-285`)
Định tuyến 3 tầng:
```
if (int_num < main_config->num_interrupts)      → main_config->intAttach (= gic_intattach)
else if (int_num ∈ [sic.first, sic.first+sic.num_ints))  → sic_intattach
else if (main_config->soft_int_check(int_num))  → soft_intAttach   (APMU virtual)
else ASSERT(0)
```
- `main_config->num_interrupts = INTNUM_LAST_UNUSED` (từ `int_config` struct).
- **SIC path**: chết (không SIC).
- **Soft/APMU path**: `interrupt_config.c:188` — trường `soft_*` **bị comment** trong `interrupt_config_t int_config = {gic_intInit, gic_intattach, gic_intdetach, gic_intenable, gic_intdisable, INTNUM_LAST_UNUSED, /*soft_int_check,...*/}` ⇒ `soft_int_check == NULL` ⇒ **APMU virtual interrupt path không hoạt động**. `soft_int_check`/`apmu_handler` (chia sẻ ngắt PMU cho Timer0-3) định nghĩa nhưng không nối vào.

⇒ **Thực tế: mọi `intAttach` của FW này → thẳng `gic_intattach` trên GIC-400.**

## 4. FIQ — không dùng cho hoạt động thường

**FACT** (`hal_vectors_gnu.asm:72-74`):
```asm
FiqHandler:
    mov  r12, #0xe5
    ldr  pc, dumpfault      ; → DumpFaultRegisters → ResetEntry2: B .  (treo)
```
Giống mọi fault handler khác (T1.3). ⇒ **FIQ = lỗi chí mạng**. R4 chỉ dùng **IRQ**. `hal_2nd_init_gnu.asm`: `F_Bit = 0x40` (khi set → FIQ disabled). LPPP có "NVAL_FIQ" (SPI 66, T3.5) nhưng nó vào qua **IRQ path** (attach bằng `intAttach` → GIC → `irq_handler`), không phải FIQ CPU exception — tên chỉ là nhãn tín hiệu.

`intnums.h` cũng có `INTNUM_LPPP_NVAL_FIQ` — được `LPPP_IRQ_Setting` attach bình thường qua `intAttach` (T3.5), tức xử lý như IRQ.

## 5. `GIC_DIST_REGS_t` / `GIC_CPU_REGS_t` — thanh ghi dùng

| reg | vai trò trong code |
|-----|--------------------|
| `ICD_ICTR` | đọc số ngắt hỗ trợ (`gic_intInit`) |
| `ICD_ICER[]` | Interrupt Clear-Enable (disable) |
| `ICD_ISER[]` | Interrupt Set-Enable (enable) + đọc trạng thái |
| `ICD_IGRP[]` | Group (đặt 0 = group 0) |
| `ICD_ICFR[]` | Config edge/level (2 bit/ngắt) |
| `ICD_IPR[]` | Priority (1 byte/ngắt, `<< 3`) |
| `ICD_IPTRRW[]` | CPU target (`0xFFFFFFFF` = mọi core) |
| `ICD_DCR` | Distributor Control (`=1` bật) |
| `ICC_PMR` | Priority Mask (`0xFF`) |
| `ICC_ICR` | CPU Interface Control (`=1` bật) |
| `ICC_IAR` | Interrupt Acknowledge (đọc ID) |
| `ICC_EOIR` | End Of Interrupt (ghi ID) |
| `ICC_RPR` | Running Priority (chỉ dùng trong `HAVE_UNIT_TEST`) |

## 6. FACT / INFERENCE / UNKNOWN

- **FACT**: GICD `0xE8261000`, GICC `0xE8262000`, `INTRL_GIC_OFFSET = 32`, `NUM_GIC_SUPPORTED = 288`, `gic_intInit` trình tự 8 bước, `gic_intattach` bắt buộc trước `intEnable`, `irq_handler` (IAR & 0x3ff → Handler → EOIR, spurious = 1023), warmboot giữ `Handlers[]` + nạp lại priority, `int_config` struct để `soft_*` **comment**, `sic_config[] = {}` rỗng, `0xC05A0104 = 0x00022220` (ul_irq_ctrl), FIQ handler = dumpfault.
- **FACT**: mọi `INTNUM_*` = SPI + 32; bảng ánh xạ ở §1.1 khớp các note trước (T3.4/T3.5/T6/T7.3).
- **INFERENCE**: APMU virtual/shared-interrupt path (`soft_int_check`, `apmu_handler`) hoàn toàn dead trong build S800 — vì trường soft_* bị comment. Chưa grep toàn repo xem có bản `interrupt_config.c` khác được build không (asic vs 88pa6220 vs mvqsim — asic là bản thật, T-context).
- **INFERENCE**: `TX_ENABLE_IRQ_NESTING` (ThreadX) không định nghĩa (FW dùng FreeRTOS) ⇒ IRQ không nesting; ngắt ưu tiên cao không cắt ngắt đang chạy ở tầng GIC handler. FreeRTOS port có thể cho phép nesting riêng — chưa xác nhận.
- **INFERENCE**: `ICD_IGRP[i] = 0` (group 0 = secure/FIQ theo GICv2) nhưng FW chạy non-secure trên R4 → group 0 ở đây đơn giản là "1 nhóm duy nhất". Không phân tích sâu security state.
- **UNKNOWN**: `int_config[]` (`INT_TYPE0..31`) giá trị bit thật (định nghĩa ở `interrupt_config.h` / generated) — cái nào edge, cái nào level.
- **UNKNOWN**: `arm_sic.c` (149 dòng) — SIC cho khối nào (DEC? `IPS_DEC_SIC_BASE` bị comment). Không dùng ở S800.
- **UNKNOWN**: quan hệ GIC-400 này (`0xE8260000`) với GIC của A72 (`AP_GIC1` tên gọi) — có phải R4 và A72 chia sẻ cùng 1 GIC-400 distributor, hay R4 có GIC riêng. Tên `AP_GIC1_GICD_BASE` gợi ý dùng chung nhưng `ICD_IPTRRW = 0xffffffff` + R4 1 core làm mờ điều này. Cần đối chiếu DTS Linux (T12.4).

## Tóm tắt (theo format skill)

**Hệ thống ngắt R4:**
R4 dùng một GIC-400 (GICv2): Distributor `0xE8261000`, CPU-interface `0xE8262000`. `arm_gic.c` là driver trực tiếp; `int_common.c` là lớp định tuyến (main GIC / SIC / soft-APMU) nhưng **SIC rỗng và soft-APMU bị comment**, nên mọi `intAttach(INTNUM_*, prio, handler, input)` đi thẳng `gic_intattach` → lưu vào `Handlers[288]` + set priority; `intEnable` set bit `ICD_ISER`. Khi có ngắt: vector IRQ → `irq_handler()` đọc `ICC_IAR`, gọi `Handlers[id].Handler(input)`, ghi `ICC_EOIR`. Mọi `INTNUM_*` = số SPI + 32. FIQ không dùng — vector FIQ nhảy thẳng vào dump-fault (treo), nên "NVAL_FIQ" của LPPP thực chất là một IRQ thường. `gic_intInit` giữ bảng `Handlers[]` qua warmboot (chỉ nạp lại priority register), khớp cơ chế warm/cold của ATF (T2.4).

**Call flow (LPPP attach MC_LPP_IRQ0):**
```
LPPP_IRQ_Setting (T3.5)
└─ intAttach(INTNUM_LPPP_MC_LPP_IRQ0 /* SPI128 → GIC ID 160 */, 0, LPPP_McChangeFreq_handler, 128)
   └─ int_num(160) < num_interrupts → main_config->intAttach = gic_intattach
      ├─ ASSERT Handlers[160].Handler == NULL
      ├─ Handlers[160] = {LPPP_McChangeFreq_handler, 128, prio 0}
      └─ ICD_IPR[40] byte 0 = 0<<3
└─ intEnable(160) → gic_intenable → ICD_ISER[5] = 1<<0
--- M3 pulse → SPI 128 ---
vector IRQ → IrqHandler_second_stage → irq_handler()
   int_id = ICC_IAR & 0x3ff = 160
   Handlers[160].Handler(128)  → LPPP_McChangeFreq_handler(128)
   ICC_EOIR = 160
```
