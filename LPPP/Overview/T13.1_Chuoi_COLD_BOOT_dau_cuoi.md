## 1. Điểm mấu chốt

1. **R4 chạy trước A72.** Mask ROM nạp R4 firmware; R4 tự train DDR (qua BLE trên A72) rồi mới thả A72 chạy ATF. `copy_run_atf` ghi warmboot flag `*0x7FFFFFF0 = 0` (cold).
2. **`init_thread` là "orchestrator"** — highest prio, chạy 1 lần rồi tự xoá. Nó gọi `LPPP_KM_Init` (khởi động ma trận TR power), `pmu_phase(ap_link_up/system_up)`, `board_init` (DDR + ATF), QoS. Sau đó R4 chỉ còn các task steady-state.
3. **2 pha power**: `pmu_baseline` (trong `main`, trước scheduler) → `pmu_ap_link_up` + `pmu_system_up` (trong `init_thread`, sau scheduler).
4. **PS-CPU vào cuộc ở `ap806_power_on`**: Eagle3 gửi REM + power-state qua I²C `0x3E` trước khi bật GPIO `AP_PWR_EN` (T12.3).
5. **`scpi_wait_ready`** — ATF chặn tới khi R4 gửi `SCP_READY` trên channel của core → đồng bộ R4↔A72.
6. **`HOSTCMD_HELLO`** (Linux driver lên) là mốc chuyển sang NORMAL: `RedirectTraffic` bật, LPPP lùi về "forward hết".

## 2. FACT / INFERENCE / UNKNOWN

- **FACT**: trình tự `main()` (hal_main.c:684-737), `init_thread` (hal_main.c:143-200), `AppInit_Initialize` → `SysApi_InitApplModules` → `power_up_system` + `vTaskStartScheduler` (sys_init.c:100-124), `board_init_emu800` → `mci_init`/`iris_init`/`init_ddr(false)`/`copy_run_atf` (board.c:195-215, 515-527), `sys_uarts[0] = AP_AON_UART10_BASE` (hal_main.c:208 — xác nhận T7.6).
- **FACT**: `supportTEC() != RESULT_BASE` → 100ms wait trong `init_thread` (Eagle3 / Machine-Type lỗi).
- **INFERENCE**: thứ tự "R4 trước A72" — từ `copy_run_atf`/`init_ddr` chạy trên R4 (đã lập luận T12.2). Mask ROM boot R4 (vs boot A72 rồi A72 kích R4) chưa có source xác nhận.
- **INFERENCE**: `pmu_baseline` trước scheduler an toàn vì chưa có task; `ap_link_up`/`system_up` sau scheduler vì cần mutex/delay/IPC.
- **UNKNOWN**: `hwConfigInit`/`hwSetProcSpeed`/`pad_config_init`/`setup_debug_print_logic` chi tiết. `isForceLogOutput` điều kiện set `isLogOut`. `zpzn_*` (ZP/ZN — efuse zero-power/... ?). Thời gian thực mỗi pha (ms).
- **UNKNOWN**: `main(argc, argv)` — ai truyền argc/argv (bare-metal, chắc rác). `hal_main_initialize_sections` `initialize_sections="5"` → `'5'=0x35` → hook&1 (copy .data) + hook&4 (zero bss); hook&2 (zero fifo) comment.

## Tóm tắt (theo format skill)

**Cold boot S800 là chuỗi R4-first:** mask ROM nạp `mvri.bin` từ QSPI CS1 → `main()` khởi tạo HAL (sections, cpu_init/MPU, pad, UART10, `pmu_phase(baseline)`, AVS, GIC, GPIO, MHU) → `early_board_init_emu800` (QSPI/chip-select/A2-windows/PIDI) → `AppInit_Initialize` → `SysApi_InitApplModules` (15 module Sys/App: filter, USB, netstack…, `SysApiFifo_Init`, tạo `init_thread` + các task) → `vTaskStartScheduler`. `init_thread` (prio cao nhất, chạy 1 lần) làm phần nặng: `LPPP_KM_Init` (khởi động ma trận TR + GPIO/IRQ/Flash/I2C KM), `pmu_phase(ap_link_up)` (bật die AP806 + bắt tay PS-CPU I²C), `pmu_phase(system_up)`, `io_update_voltage`, `board_init` → `init_ddr(false)` (nạp BLE cho A72 train LPDDR4) → `copy_run_atf` (thả A72 chạy ATF, warmboot flag = 0) → `LPPP_QoS_*`, rồi tự xoá. A72 chạy ATF (BL1→BL2→BL31, `scpi_wait_ready` chờ R4 `SCP_READY`) → U-Boot (`bspi_boot` kernel+DTB từ QSPI CS1) → Linux. Linux probe `arm_scpi`/`km_scpi` + `mvri_nonpci`/`mvri_fw`, gửi IP + WoL config, rồi `HOSTCMD_HELLO` → LPPP bật `RedirectTraffic` → trạng thái NORMAL (R4 forward hết gói lên Linux).
