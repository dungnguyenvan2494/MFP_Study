## 0 · Ba tầng phía Linux

```
① sysfs / IOCTL (userspace)
     mdels800_pmu.c: DEVICE_ATTR(...), PMU_IOCS*
        │
② KM SCPI ops  (km_scpi.c → km_scpi_ops)          — lệnh mở rộng 0x81–0x8C
     scpi_send_message_ext(cmd, tx, tx_len, rx, rx_len)
   HOẶC
   Standard SCPI ops (arm_scpi.c → scpi_ops)       — lệnh chuẩn 0x02–0x1c
     scpi_send_message(cmd, tx, tx_len, rx, rx_len, is_wfi)
        │
③ Linux mailbox framework
     mbox_send_message(scpi_chan->chan, msg)  → MHU mailbox controller driver
        → ghi shared mem 0x7FFF0000 kênh 0 + rung MHU (CPU_INTR_S_SET)
        → LPPP mhu_handler → process_scpi_cmd (case 0)
```

## 1 · `scpi_send_message_ext()` — đường gửi KM (`arm_scpi.c:~510`)

```c
int scpi_send_message_ext(u8 cmd, void *tx_buf, uint tx_len, void *rx_buf, uint rx_len) {
    chan = atomic_inc_return(&scpi_info->next_chan) % scpi_info->num_chans;   // round-robin
    mutex_lock(&send_message);                          // ★ serialize MỌI SCPI (OP-BTS_18219)

    /* ★ CHỜ LPPP THOÁT wfi — OP_BTS-47053 / OP_BTS-62319 */
    result = wait_event_timeout(wfi_wait_queue, !is_lppp_wfi, msecs_to_jiffies(60000));
    if (result == 0) { mutex_unlock(&send_message); return -ETIMEDOUT; }

    if (is_wfi) is_lppp_wfi = 1;                        // đánh dấu: lệnh này khiến LPPP vào wfi

    for (cnt = 0; cnt < SCPI_COMMUNICATE_RETRY_MAX; cnt++) {
        msg = get_scpi_xfer(scpi_chan);
        msg->slot   = BIT(SCPI_SLOT);
        msg->cmd    = PACK_SCPI_CMD_EXT(cmd, tx_len);
        msg->tx_buf = tx_buf; msg->tx_len = tx_len;
        msg->rx_buf = rx_buf; msg->rx_len = rx_len;
        init_completion(&msg->done);
        ret = mbox_send_message(scpi_chan->chan, msg);  // → MHU
        if (ret < 0 || !rx_buf) break;                 // fire-and-forget nếu không cần rx
        ... wait_for_completion_timeout(&msg->done) ...
    }
    mutex_unlock(&send_message);
}
```

**`is_lppp_wfi` — theo dõi LPPP có đang `pause_cpu` wfi không** (`arm_scpi.c:345`):
- `DECLARE_WAIT_QUEUE_HEAD(wfi_wait_queue)`; `static int is_lppp_wfi = 0`
- Mọi `scpi_send_message*` **block tối đa 60s** cho tới khi `!is_lppp_wfi`
- ⇒ khi Linux đã bảo LPPP đi ngủ để ghi QSPI, **mọi SCPI khác tự động chờ** — không dội lệnh vào R4 đang ngủ

`mutex_lock(&send_message)` + retry loop `SCPI_COMMUNICATE_RETRY_MAX` = bản vá `OP-BTS_18219`
("リトライする"), `AR1068882` ("パネル早押しでフリーズ").

## 2 · Cơ chế pause/wake LPPP khi update QSPI — GIẢI đầy đủ `Update_FW_LPPP.md`

`scpi_dvfs_set_idx(domain, index)` (`arm_scpi.c:793-826`) — MTD driver gọi `scpi->dvfs_set_idx(0, 1)`
để dừng LPPP, `(0, 0)` để đánh thức:

### `(domain=0, index=1)` — DỪNG LPPP
```c
if (domain == 0 && index == 1) is_wfi = 1;
return scpi_send_message(CMD_SET_DVFS /* 0x0a */, {domain, index}, ..., is_wfi=1);
```
→ trong `scpi_send_message`: gửi SCPI `0x0a {0,1}` xong thì `is_lppp_wfi = 1`.
→ LPPP `process_scpi_cmd case 0xa` → `pause_cpu()` → tắt GIC, `wfi`.
→ Từ đây mọi `scpi_send_message*` của Linux **block** trên `wfi_wait_queue`.

### `(domain=0, index=0)` — ĐÁNH THỨC LPPP  ★ KHÔNG dùng SCPI
```c
if (domain == 0 && index == 0) {
    // "wake up the r4 using an ipc interrupt. Not scpi since other scpi cmds
    //  will wake the r4 before it should be woken."
    base = ioremap(0xe8008000, 0x100);   // ← APB_IPC0_B_BASE (AP owns) — xem T2.3!
    base[0xc/4] |= PAUSE_R4_INT;          // PAUSE_R4_INT = 1 (bit 0); offset 0xc = IPC_ISRW
    iounmap(base);
    is_lppp_wfi = 0; wake_up(&wfi_wait_queue);   // gỡ block các SCPI đang chờ
    return 1;
}
```

**⚠ ĐÍNH CHÍNH `Update_FW_LPPP.md §C`:** note cũ viết *"`0x0a{0,0}` → MHU interrupt đánh thức R4"*.
**SAI.** Đánh thức R4 dùng **ngắt IPC0** (`0xe8008000` + `0xc` = `IPC_ISRW`, bit 0 = `PAUSE_R4_INT`),
**không phải MHU**. `PAUSE_R4_INT = 1` (bit 0) ⇒ kênh `INTNUM_APB_IPC_B2G_0` (SPI 151) —
chính là `DUMMY_INT_NUM` mà `hal_pause.c` chừa sống làm đường thoát `wfi` (T2.3 §3.6).
Lý do dùng IPC thay SCPI (comment trong code): SCPI khác sẽ đánh thức R4 **quá sớm**, trước khi
Linux ghi xong QSPI.

Có **3 chỗ** trong `arm_scpi.c` (dòng 617, 710, 808) cùng làm `base[0xc/4] |= PAUSE_R4_INT` —
các đường dự phòng đánh thức R4 (khi `wait_event_timeout` hết 60s hoặc đường unpause).

## 6 · Ba lệnh KM chạm state machine (khớp `AppMhuTest.md §F`)

```
0x88 ap_event(0)  → WAKEUP_NORMAL  ─┐ qua send_km_queue → PwMHUEv → PwEvtMgr
0x88 ap_event(1)  → GO_TO_S1       ─┘ (chỉ payload 0,1 hoạt động)
0x85 set_pwr_status(p) → LPPP_SetStatus(pwr_sd, p)  ─ ép thẳng, KHÔNG chạy scenario
0x83 set_ap_status(s)  → LPPP_SetStatus(ap_sd, s)   ─ giải giáp TR2b (mất điện)
```
`0x03` (per-core power, từ ATF) mới là đường chính vào Sleep2/ErP (qua `power_cpu` + `g_wolMode`).

## 7 · Tóm tắt (theo format skill)

**1. Tồn tại để làm gì:** Linux gửi SCPI qua **2 API** — `scpi_ops` (lệnh chuẩn 0x02–0x1c, dùng
bởi clk-scpi / scpi-cpufreq / scpi_pm_domain / scpi-hwmon) và `km_scpi_ops` (lệnh mở rộng
0x81–0x8C, dùng bởi `mdels800_pmu.c` qua sysfs/IOCTL). Cả hai đi qua `scpi_send_message[_ext]`
→ `mbox_send_message` → MHU mailbox controller → shared mem kênh 0 → LPPP `process_scpi_cmd`.
Mọi SCPI serialize bằng `mutex(&send_message)` và **block 60s cho tới khi `!is_lppp_wfi`** —
cơ chế biết LPPP có đang `pause_cpu` (update QSPI) hay không.

**2. Bảng lệnh:** §3 (chuẩn) + §4 (KM) + §5 (sysfs→SCPI).

**3. File đã tham chiếu:**
- `Kernel/K-S800/Src/drivers/firmware/arm_scpi.c:47, 99-160, 344-345, 500, 510-560, 617, 710, 782-826, 1045-1061, 1251`
- `Kernel/K-S800/Src/drivers/firmware/km_scpi.h` (toàn bộ), `km_scpi.c:33-375`
- `Kernel/K-S800/Src/drivers/mfp/pmu/mdels800_pmu.c:789-866, 1041-1045, 3299, 4074-4116, 4312-4400`

**4. Đã xác nhận / đính chính:**
- ✅ **ĐÍNH CHÍNH `Update_FW_LPPP.md`:** đánh thức R4 khỏi `pause_cpu` dùng **ngắt IPC0**
  (`0xe8008000 + 0xc = IPC_ISRW`, bit `PAUSE_R4_INT = 1` → SPI 151 = `DUMMY_INT_NUM`), **KHÔNG
  phải MHU/SCPI**. Lý do: SCPI khác sẽ đánh thức R4 quá sớm.
- ✅ `scpi->dvfs_set_idx(0,1)` = dừng LPPP (SCPI `0x0a`, đặt `is_lppp_wfi=1`);
  `dvfs_set_idx(0,0)` = đánh thức (IPC0, xoá `is_lppp_wfi`).
- ✅ Linux `scpi_std_commands` enum khớp LPPP/ATF (0x00–0x1c). `LEGACY_*` numbering không dùng.
- ✅ `0x03`/`0x04` (CSS power) không qua Linux `scpi_ops` — thuộc ATF PSCI.
- ✅ `km_scpi_ops` 12 hàm ↔ SCPI `0x81`–`0x8C`, map đủ sang case LPPP.
- ✅ `mdels800_pmu.c` các sysfs `EVENT_RECORD`/`PWRSUBCPU_*`/`PowerOff*` nói với **PS-CPU qua I²C**,
  không qua SCPI → T12.3.
- UNKNOWN: caller của `0x06/0x07` (wake timer) và `0x80` (config wake int) phía Linux — chưa grep tới.
