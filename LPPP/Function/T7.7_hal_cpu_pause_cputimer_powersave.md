## 1. `hal_pause.c` — `pause_cpu(chan)` : R4 "đứng im" chờ AP đánh thức

**FACT.** Gọi từ **`app_scpi.c:781`** khi ATF gửi SCPI `0x0A` (Set DVFS) với `domain==0 && op_point==1` (tức `scpi_dvfs_set_idx(0,1)` từ Linux — T2.5). `domain==0, op_point==0` = resume (chỉ gửi response).

```c
#define DUMMY_INT_NUM  INTNUM_APB_IPC_B2G_0     // SPI 151 → GIC ID 183 (T2.5: PAUSE_R4_INT bit0 @ 0xE8008000)

void pause_cpu(uint32_t chan) {
    int_state = cpu_disable_interrupts();
    intAttach(DUMMY_INT_NUM, 0, dummy_handler, 0);
    intEnable(DUMMY_INT_NUM);
    dummy_handler(0);                            // clear sẵn IPC/wake bit
    for (i=0..31) { ier_save[i] = ICD_ICER[i];   ICD_ICER[i] = 0xFFFFFFFF; }   // TẮT TẤT CẢ ngắt GIC, lưu lại
    ICD_ISER[DUMMY_INT_NUM/32] = 1<<(DUMMY_INT_NUM%32);   // CHỈ bật lại 1 ngắt: DUMMY (từ AP)
    clear_MHU(0, 1<<chan);                       // MHU: xoá pending kênh chan
    write_MHU(0, 1<<chan);                       // MHU: gửi response cho CA72 (báo "R4 đã dừng")
    __asm volatile ("wfi");                      // ⏸️ NGỦ — chỉ DUMMY_INT_NUM đánh thức được
    for (i=0..31) ICD_ISER[i] = ier_save[i];     // KHÔI PHỤC toàn bộ ngắt
    cpu_restore_interrupts(int_state);
    intDisable(DUMMY_INT_NUM); intDetach(DUMMY_INT_NUM);
}
```

### `dummy_handler(isr_input)`
```c
GicRegs = 0xE8261000;
Hal_clear_ipc_irq(1);                                       // IPC0 ICR = 1 (bit0 = PAUSE_R4_INT) @ 0xE8008100
ICD_ICPR[DUMMY_INT_NUM/32]     = 1<<(DUMMY_INT_NUM%32);     // clear-pending SPI 151
ICD_ICPR[INTNUM_IPC_G2B_WAKEUP/32] = 1<<(INTNUM_IPC_G2B_WAKEUP%32);   // clear-pending ipc wake (R4→AP hướng ngược)
```

**Ý nghĩa runtime:** Khi Linux muốn R4 "biến mất" (DVFS lowest = idle), ATF gửi SCPI 0x0A → `pause_cpu`. R4 tắt hết GIC, chỉ chừa 1 doorbell từ AP (`0xE8008000` bit0), rồi `wfi`. Linux đánh thức bằng `ioremap(0xe8008000); base[0xc/4] |= PAUSE_R4_INT(1)` (T2.5) → SPI 151 → `dummy_handler` → thoát `wfi` → R4 khôi phục GIC và chạy tiếp. `write_MHU` trước `wfi` để CA72 không treo chờ response SCPI.

⚠️ **`pause_cpu` chỉ có trong `ApplicationMrvl/Test/app_scpi.c`** (bản test/bring-up). Bản KM (`ApplicationKM/LPPP_SCPI.c`) — T2.6 — không thấy gọi `pause_cpu`. INFERENCE: đường DVFS-idle này thuộc firmware Marvell reference, có thể không active trong build KM S800 (KM dùng ma trận TR + `power_cpu`).

## 3. `SysSystem_CpuSleep()` (`sys_system_main.c:191`) — điều phối ngủ CPU R4

Gọi từ `vApplicationIdleHook` (task IDLE, chỉ khi `!DriverIsPresent && SysSystem_cpu_sleep_is_enabled && ...not_forbidden` — T6 §8).

```
SysApiThread_Relinquish(1)                       // nhường CPU 1 nhịp
previous_state = SysSystem_EnterCritical()
if (SysTimerIrq_low_activity() && SysSystem_fifos_are_empty()) {
    sleep_duration = SysSystem_getMaxCpuSleepDuration()    // os ticks
    if (sleep_duration) {
        HalApiUpdate_CpuTimer(sleep_duration * OS_TICK_IN_NS)   // đặt ngắt timer kế tiếp (no-op — xem §4)
        ticks_before = HalApiCpuTimer_os_tick_count()
        HalApiPowersave_CpuSleep()                            // ⏸️ wfi
        HalApiCpuTimer_UpdateTickCount(true)                  // cập nhật lại tick từ CCNT
        delta = os_tick_count() - ticks_before
        SysSystem_update_os_timer(delta)                     // bù thời gian ngủ cho FreeRTOS
        HalApiUpdate_CpuTimer(OS_TICK_IN_NS/2)
    }
}
SysSystem_ExitCritical(previous_state)
```
- `SysSystem_cpu_sleep_is_enabled` (mặc định **false**) — bật qua `ApiSysPowerSaveSet(POWERSAVE_CPU_SLEEP)` (T5.5). Linux điều khiển.
- Ngủ ngắn (giữa các tick khi rảnh), khác hẳn `pause_cpu` (ngủ dài chờ AP) và `power_cpu` (bật/tắt nguồn cả cluster A72).
- Sau `wfi`, `HalApiCpuTimer_UpdateTickCount(true)` đọc lại cycle counter → tính `delta` os-ticks đã trôi → `SysSystem_update_os_timer(delta)` cho FreeRTOS tickless.

## 4. `hal_cputimer.c` — đếm thời gian bằng cycle counter (CCNT)

### 4.1 Nguồn thời gian: `cpu_get_ccount()` (PMU cycle counter Cortex-R4)
- `HalApiGet_CpuCounter()` = `cpu_get_ccount()` (32-bit, tự tràn).
- `HalCpuTimer_reset()` = `cpu_set_ccount(0)` + zero `nanoseconds`/`tick_count`.

### 4.2 `HalApiCpuTimer_UpdateTickCount(bool do_only_timekeeping)` — gọi từ ISR timebase (tick 10ms, T7.6) **và** sau khi ra khỏi sleep
```
tim64 = cpu_get_ccount()
// ghép 64-bit từ 32-bit CCNT + phát hiện tràn
if (tim64 < (cpu_ticks & 0xffffffff))  upper_32bit++
cpu_ticks = (upper_32bit << 32) | tim64
nanoseconds = cpu_ticks / 1000 * HalChip_clock_tick_in_ps()
tick_count = nanoseconds / OS_TICK_IN_NS
```
- `HalChip_clock_tick_in_ps()` = chu kỳ 1 xung nhịp CPU tính bằng ps (phụ thuộc tần số bus R4 200MHz → 5000ps; nhưng có 3 tốc độ nên comment cảnh báo "không dùng tick_count để tính thời gian tuyệt đối").
- **Side effects** (khi `do_only_timekeeping == false`, tức từ ISR timebase): theo bit trong `polling_functions[]` (khai báo `app_init.c:74 = "\x40=..."` → `polling_functions[0] = 0x40`):

| bit | hằng | hành động khi set |
|-----|------|-------------------|
| 0x01 | `POLL_VMAIN` | `HalInit_poll_vmain_avlbl()` |
| **0x40** | `POLL_PACKETS` | **`HalEth_bmu_isr()`** — poll GMAC RX/TX (T5.1) |
| 0x02 | `POLL_LINK` | `HalEth_debug_link()` |
| 0x10 | `POLL_CHECK_STATUS` | `HalEth_check_status_bmu()` |
| 0x20 | `POLL_CHECK_RX` | `HalEth_check_rx_bmu()` (#1240) |
| 0x80 | `POLL_VBUS_ON` | `HalChip_poll_vbus_on(false)` |
| — | luôn | `calculate_irq_rate()`, **`LPPP_LVDS_tick()`** (T3.4 — LVDS 100ms self-loop) |

⇒ **`polling_functions[0] = 0x40`** ⇒ mặc định mỗi tick 10ms chỉ chạy `HalEth_bmu_isr()` (poll gói) + `LPPP_LVDS_tick()` + `calculate_irq_rate()`. GMAC RX **dựa vào polling từ timer tick**, không dùng ngắt RX (khớp T5.1 "task ETH_I").

### 4.3 `HalApiCpuTimer_os_tick_count()` = `tick_count` (đơn vị 10ms) — dùng khắp nơi làm "timestamp thô" (T6: `FwCmdResult.Result`, `SysFifo_send_msg_wake.ts`…).
`HalCpuTimer_seconds()` = `nanoseconds / 1e9`. `HalApiCpuTimer_nanoseconds()` = `nanoseconds`.
`HalApiCpuTimer_irq_rate()` = `irq_rate` (ngắt/giây, tính trong `calculate_irq_rate` từ `irq_counter` global).

### 4.4 `HalApiInit_CpuTimer()` / `HalApiUpdate_CpuTimer()` — **rỗng** (`return;`). Comment: "next timer interrupt setting is now handled in platform code or in hardware". ⇒ Timer 10ms là timebase phần cứng cố định (`INTNUM_TIMEBASE_10MS`), không lập lịch động ⇒ tickless sleep chỉ "bù" sau khi thức, không kéo dài interval.

### 4.5 `HalEpu_RegisterRead/Write(Reg)` — đọc/ghi thô địa chỉ (debug). `HalApiEpu_check_stacks()` = `false`.

## 7. FACT / INFERENCE / UNKNOWN

- **FACT**: `pause_cpu` trình tự (lưu/tắt/chừa-1/wfi/khôi phục), `DUMMY_INT_NUM = INTNUM_APB_IPC_B2G_0` (SPI 151), `dummy_handler` clear IPC + ICPR, `write_MHU` trước wfi; `HalApiPowersave_CpuSleep` = wfi; `enable/disable_10tx` rỗng; `SysSystem_CpuSleep` chỉ ngủ khi `low_activity && fifos_empty && sleep_duration>0`; `HalApiGet_CpuCounter = cpu_get_ccount`; `UpdateTickCount` ghép 64-bit CCNT + `nanoseconds = ticks/1000 * clock_tick_in_ps`; `polling_functions[0] = 0x40` (POLL_PACKETS); `HalApiInit_CpuTimer`/`HalApiUpdate_CpuTimer` rỗng; `HalApiCpu_interrupt_control` = FreeRTOS `vPortEnter/ExitCritical`; `HalCpu_trigger_emb_cpu` rỗng.
- **FACT**: `pause_cpu` gọi từ SCPI 0x0A `domain==0 && op_point==1` (`app_scpi.c:781`).
- **INFERENCE**: đường `pause_cpu`/DVFS-idle không active trong build KM S800 (chỉ ở `ApplicationMrvl/Test/app_scpi.c`; `ApplicationKM/LPPP_SCPI.c` không gọi). Cần đối chiếu Makefile xem `app_scpi.c` có link vào build KM không.
- **INFERENCE**: GMAC RX hoàn toàn dựa polling timer 10ms (`POLL_PACKETS` bit + `HalEth_bmu_isr`) chứ không ngắt RX — khớp T5.1. Chưa xác nhận có ngắt GMAC nào được attach song song.
- **INFERENCE**: `SysSystem_cpu_sleep_is_enabled` mặc định false ⇒ R4 **không** tự wfi trong idle trừ khi Linux bật qua `ApiSysPowerSaveSet`. Chưa thấy nơi Linux/KM bật nó cho S800.
- **UNKNOWN**: `HalChip_clock_tick_in_ps()` trả gì với 3 tốc độ clock (T4.3); `OS_TICK_IN_NS` (10ms?); `SysSystem_getMaxCpuSleepDuration` thuật toán.
- **UNKNOWN**: `INTNUM_IPC_G2B_WAKEUP` số SPI (hướng R4→AP wake). `clear_MHU`/`write_MHU` — T2.3 nói `hal_MHU.c` init rỗng/return NULL; nhưng `hal_pause.c` include `hal_MHU.h` và gọi `clear_MHU`/`write_MHU` — có định nghĩa thật ở đâu? (mâu thuẫn tiềm tàng với T2.3).
- **UNKNOWN**: `cpu_get_ccount` có cần bật PMU user-enable (PMCR.E, PMCNTENSET) trước — `cpu_init` (T1.6) "cycle counter enable" đã lo.

## Tóm tắt (theo format skill)

**4 file này để làm gì:**
`hal_cpu.c` = nguyên thủy CPU (đọc CPSR/SCTLR, kiểm IRQ/FIQ mode, critical section = FreeRTOS `vPortEnter/ExitCritical`, busy-wait theo chu kỳ, SWI/relocate). `hal_cputimer.c` = toàn bộ time-keeping của R4 dựa trên **cycle counter CCNT** (`cpu_get_ccount`): mỗi tick 10ms `HalApiCpuTimer_UpdateTickCount` ghép CCNT thành `cpu_ticks` 64-bit → `nanoseconds` → `tick_count` (đơn vị 10ms, dùng làm timestamp thô khắp FW), và tiện thể poll GMAC (`HalEth_bmu_isr`) + LVDS tick theo `polling_functions[0]=0x40`; timer không lập lịch động (`HalApiUpdate_CpuTimer` rỗng). `hal_powersave.c` = `wfi` primitive + dynamic clock-gating (chip + eth core) + energy-detect PHY; `enable/disable_10tx` là no-op. `hal_pause.c` = `pause_cpu(chan)`: theo lệnh SCPI 0x0A từ ATF, R4 lưu rồi tắt toàn bộ GIC, chỉ chừa doorbell `PAUSE_R4_INT` (SPI 151) từ AP, `write_MHU` để CA72 không treo, rồi `wfi` cho tới khi Linux ghi `0xE8008000` bit0 để đánh thức — sau đó khôi phục GIC. Bốn cơ chế ngủ (`SysSystem_CpuSleep` wfi ngắn / `pause_cpu` chờ AP / clock-gating / `power_cpu` tắt nguồn A72) độc lập nhau.

**Call flow (Linux idle R4 rồi wake):**
```
Linux: scpi_dvfs_set_idx(0,1)  → ATF SCPI 0x0A {domain=0, op_point=1}
  → app_scpi.c:781 pause_cpu(chan)
     ├─ cpu_disable_interrupts
     ├─ intAttach/Enable(DUMMY_INT_NUM=SPI151), dummy_handler(0)   [clear IPC/ICPR]
     ├─ save ICD_ICER[0..31]; ICD_ICER[*]=0xFFFFFFFF   (tắt hết)
     ├─ ICD_ISER[151/32] |= bit                        (chừa DUMMY)
     ├─ clear_MHU(0,1<<chan); write_MHU(0,1<<chan)     (response cho CA72)
     └─ wfi ⏸️
--- Linux: scpi_dvfs_set_idx(0,0) → ioremap(0xe8008000); base[3] |= 1 ---
  SPI 151 → dummy_handler: Hal_clear_ipc_irq(1); ICD_ICPR clear
  → thoát wfi
     ├─ restore ICD_ISER[0..31]
     ├─ cpu_restore_interrupts; intDisable/Detach(DUMMY)
     └─ return  → app_scpi gửi SCPI response  → ATF/Linux tiếp tục
```
