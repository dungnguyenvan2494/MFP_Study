Subset Firmware Update

Gói firmware là một file .TAR trên thư mục download. Bên trong có một file INDEX mô tả từng file nhị phân (loại, sector, checksum, version, tên) và các file đó. Updater đọc INDEX → qua một loạt cổng điều kiện → copy/ghi từng file theo region, rồi tới sub-controller và Boot ROM, có backup để rollback, kết thúc bằng reboot.

Nguyên tắc xuyên suốt mỗi file: tìm entry trong INDEX → so version đã cài (differential) → copy / ghi → verify checksum → ghi nhận đã flash. File nào version trùng thì bỏ qua; riêng file INDEX & node.img luôn ghi.

1Đọc gì · ghi ra đâu

Đầu vào: gói TAR, file INDEX, thông tin FW đang cài, serial + SSD-ID. Đầu ra: file lên các partition SSD, firmware vào sub-controller qua downloader, Boot ROM, và các bản backup + bản ghi “đã flash”.

2File INDEX — một dòng, tám trường

readIndexFile() đọc toàn bộ INDEX (theo sector), tách từng dòng @<KIND> thành một phần tử st_WriteMscDataList[].

DòngÝ nghĩa
@TYP=xxxLoại card / model máy — phải khớp máy đang chạy (bước điều kiện 3)
@VER=xxxCard version (được set làm default vào cardVersionList)
@<KIND>Một file nhị phân: kind + mã region (cột “sectorNum” = COPY_TO_* 0–15, không phải địa chỉ — Fig 6) + size-hint + checksum + timestamp + tên

3readIndexFile() — parser & cổng format đầu tiên

Chạy sớm — trong setMFPBinaryList() ← existFarmwareDataAtTAR(), tức lúc soi gói, trước gauntlet và trước mọi lần ghi. Việc của nó: dịch text INDEX → st_WriteMscDataList[] + đặt cờ toàn cục, và từ chối sớm nếu INDEX sai định dạng.

Đáng để ý: readIndexFile chỉ validate format text của INDEX — nó không đọc hay verify file binary thật (việc đó là checkCheckSum() ở Fig 3 cổng 5, chạy sau khi copy). · bl_ForFW chia đôi hành vi: FW INDEX (có @TYP/@VER + timestamp) vs OSS INDEX (không có). · si32_PreventingFalsification là side-effect toàn cục đặt ở đây, cổng chống giả mạo (Fig 3-3) dùng lại. · Parse bằng offset cố định (6/6/5/14 ký tự, ui_LoopCnt += 73…) ⇒ rất nhạy với thay đổi layout INDEX. · sc_RootCardType & card version chỉ set lần gọi đầu (guard flag) — idempotent qua nhiều lần gọi.

4Điều kiện tiên quyết — gauntlet trước khi ghi

Không file nào được ghi cho tới khi qua hết các cổng. Cổng nào fail ⇒ notificationEvent(UpdateFailed), dừng, không ghi. Cổng “diff” cho kết quả thứ ba: skip file (đã mới nhất).

5Trình tự update

startMscUpdateTask() chạy tuần tự; lõi là FwupFileCopyToSSD() lặp theo region, rồi theo từng file. Sau đó tới backup, sub-controller, Boot ROM, và reboot.

6Ghi vào địa chỉ nào — và địa chỉ đó lấy ở đâu

7Vòng lặp per-file & rollback

  1. Tìm entry: THRC_SearchWriteMscData(KIND, &idx) → chỉ số trong st_WriteMscDataList[].
  2. Diff: DifferentialDownloadDetermination(idx) — so t_TimeStamp/version với bản ghi FW đang cài (st_CurrentlyFMscDataList). Trùng & bl_DiffCheckTarget=True ⇒ skip, chỉ gọi DownloadedFWInformationUpdate(idx) (coi như đã cập nhật).
  3. Ghi: file cây thư mục ⇒ cp sc_DownLoadDir/sc_FileName → <mount>/sc_FileName; file ảnh ⇒ writeImageFile(): dd bs=4096 count=⌈filesize/4096⌉ conv=sync if=<download>/name of=<devPath> rồi dd | md5sum so với ul_CheckSum. (ul_SectorNum = mã region COPY_TO_*, không phải địa chỉ; devPath tra từ bảng partition — Fig 6.)
  4. Verify: checkCheckSum(COPY_TO_X, mount) → THRF_CalcSum(path) so với ul_CheckSum. Lệch ⇒ log INDEX sum / SSD sum / USB sum rồi return False.
  5. Ghi nhận: đặt bl_ExecutedDownload=True; DownloadedFWInformationUpdate(idx) cập nhật bản ghi “đã cài” cho lần diff sau; AddCheckSum() gom checksum để tính tổng.

Rollback: startBackupProc() chạy trước khi ghi những thứ khó phục hồi — nó quản lý cặp file CurBackup ↔ Rollback (changeCurBackupToRollback / changeRollbackToCurBackup). Nếu update hỏng giữa chừng, backupRollBackFile() + logic boot cho phép quay lại FW trước đó. BackupDownloadedFWInformation() lưu cả bản ghi FW-info để bản cũ khớp lại.

8Lưu ý

Watch list

  • INDEX là “bản kê khai”, không phải dữ liệu. Sai một trường (sector, checksum, tên) ⇒ hoặc fail checkCheckSum, hoặc ghi nhầm vùng. @END thiếu ⇒ huỷ toàn bộ trước khi ghi.
  • Cổng 4 (khớp máy) là chống brick. @TYP + ChkEngFW đảm bảo không nạp FW của model/engine khác.
  • Cổng 6 ≠ fail. “version trùng ⇒ skip” là hành vi bình thường của differential download; đừng nhầm là lỗi. File INDEX & node.img cố tình bỏ qua diff (luôn ghi).
  • Checksum verify chạy SAU copy, đọc lại từ SSD — nên phát hiện được cả lỗi ghi đĩa, không chỉ lỗi tải.
  • startBackupProc() phải chạy trước bước ghi rủi ro. Đổi thứ tự ⇒ mất khả năng rollback.
  • Sub-controller ghi qua downloader + callback (bất đồng bộ, có timeout/retry) — khác hẳn copy file. Tiền đề mỗi lần: THRF_CheckPowerStatus() (mất điện giữa chừng ⇒ brick sub-controller).
  • Express Download (@EXP) có thể THRG_formatFileSystem() partition trước khi ghi — mất dữ liệu vùng đó là chủ ý.
  • Boot ROM + boot hash ghi cuối cùng, ngay trước reboot — điểm không thể rollback bằng phần mềm.
