## 1. Điểm mấu chốt

1. **`SYS_EVENT_WAKE_SYSTEM` là điểm hội tụ** — mọi nguồn wake "mềm" (gói, USB, filter) đổ về đây → `power_cpu(0,0)`. WoL HW (ErP) đi PME thẳng PMU→A72, R4 có thể không tham gia.
2. **`goodbye_processing` chống race** (AR.1066939): nếu wake đến giữa lúc xử lý GOODBYE → hoãn `power_cpu` tới `SYS_EVENT_CAN_WAKE`.
3. **`pmu_resume` ngược `pmu_suspend`**: bật lại PLL → PI D0 → `ap_link_up` (retry 1 lần) → `init_ddr(warm)` (re-train nhanh) → `mc_restore_state` → `system_up` → driver `.resume()`.
4. **Gói đã forward + `SysApiSystem_Wake` trước handoff GMAC**: gói đánh thức đã được `SysFilter_Wakeup_and_Forward` đẩy vào HCI FIFO up_packets **trước khi** wake; `wake_lan()` route ngắt GMAC về AP để Linux nhận tiếp.
5. **`HOSTCMD_HELLO`** = mốc "Linux đã sẵn sàng" → `g_wolMode=0`, `HalApiEth_disable_irqs`, `SystemIsSuspended=FALSE`.
6. **B014 breadcrumb**: `BEGIN_PHASE6` (bắt đầu resume) → `TO_SLEEP1` (đã về Sleep1). Nếu CA72 watchdog fire giữa chừng, `LPPP_SpiFlashWrite_Ca72wdt_Reboot` ghi `uc_pmu_phase_rec` + status vào flash để U-Boot chẩn đoán (T3.2/T7.4).

## 2. FACT / INFERENCE / UNKNOWN

- **FACT**: `SysSystem_handle_link_events(SYS_EVENT_WAKE_SYSTEM)` → `power_cpu(0,0)` (nếu `!goodbye_processing`); `SYS_EVENT_CAN_WAKE` → hoãn (`sys_system_thread.c:307-326`).
- **FACT**: `power_cpu` nhánh ON (`app_scpi.c:283-352`): `CA72WDT_Start`, `Bregister_modify(B014, BEGIN_PHASE6)`, `pmu_phase(pmu_resume)`, `intr_event = WAKEUP_S1` → queue, `AP806_CCU_B_RVBAR_0/1 = WARM_BOOT_ADDR`, `intDisable(INTNUM_MCIX2_1)`, `clear_wake_ints()`, `wake_lan()`, `SysApiSystem_Wake()`, per-core power-on (PWR_DN_RQ=1 → ISO=0 → `CCU_B_PRCR = nReset`).
- **FACT**: `pmu_infrastructure_resume` (`power.c:~1695-1745`): restore clocks/SYS_PLL trong critical section, `pmu_set_device(MCix2_PHY, D0)`, `hwSetProcSpeed(restore)`, ND/MC PLL restore, PI D0, `pmu_phase(ap_link_up)` (retry 1 lần → fail return -1), `init_ddr(true, pmu_ddr_callback)`, `mc_restore_state()`, `pmu_phase(system_up)`, `resume()` callbacks.
- **FACT**: `LPPP_TR8_TR10` (`LPPP_Matrix.c:356`): `Bregister_modify(B014, TO_SLEEP1)`, `LPPP_QoS_SetupMoChi()`, `LPPP_QoS_SetupAP()`, return `PWR_STATUS_SLEEP1`.
- **FACT**: `SysHostcmd_Hello` (`sys_hostcmd.c:160`): `g_wolMode=0`, `SysSystem_Notify_hello`, `print_app_layer_version`, `Ack(OK)`.
- **INFERENCE**: `scpi_set_power_state` (`app_scpi.c:355`) là SCPI cmd 0x03 handler; nó gọi `power_cpu(cpuid, cpupower)` — với `cpupower` từ payload. Wake từ Linux (PSCI CPU_ON core phụ) đi đường này; wake từ gói/USB đi `SYS_EVENT_WAKE_SYSTEM` → `power_cpu(0,0)`. Chưa đọc hết `scpi_set_power_state` thân.
- **INFERENCE**: sau `power_cpu(0,0)`, chuỗi TR về `SLEEP1` chứ không thẳng `NORMAL` — cần thêm event (TR4) để về Normal đầy đủ. Ai gửi event đó (`WAKEUP_NORMAL`?) chưa rõ — có thể Linux qua SCPI KM, hoặc panel.
- **UNKNOWN**: `WARM_BOOT_ADDR` / `WARM_BOOT_ADDR` value ( = `_armada8k_cpu_entry`? `bl31_warm_entrypoint`? — T12.1 nói RVBAR = `_armada8k_cpu_entry >> 16`). `clear_wake_ints`/`wake_lan` thân đầy đủ. `pmu_ddr_callback` làm gì.
- **UNKNOWN**: thời gian resume thực (ms) — `init_ddr(warm)` re-train nhanh nhưng vẫn tốn; latency wake-on-USB tới lúc Linux xử lý lệnh in.

## Tóm tắt (theo format skill)

**Wake:** nguồn wake mềm (gói cần host / USB EP1 NAK / GPIO) → R4 `SYS_EVENT_WAKE_SYSTEM` → `SysSystem_handle_link_events` → `power_cpu(0,0)` (trừ khi đang xử lý GOODBYE thì hoãn). `power_cpu` (nhánh ON, `cpu_state==ALL_CPU_OFF`): breadcrumb `B014.BEGIN_PHASE6` → `pmu_phase(pmu_resume)` → `pmu_infrastructure_resume` đảo ngược suspend: bật lại SYS/ND/MC PLL, `pmu_phase(ap_link_up)` (retry 1 lần), **`init_ddr(warm=true)`** (nạp lại BLE, A72 re-train LPDDR4 nhanh, `syncronize_boot` `DDR_WARMBOOT`), **`mc_restore_state`** (thoát self-refresh, kiểm CRC nếu bật), `pmu_phase(system_up)`, gọi `resume()` các driver (`lpp_usbd_close` trả USB register về Linux). Rồi `power_cpu` gửi `WAKEUP_S1` vào queue KM (→ `LPPP_TR8_TR10`: breadcrumb `TO_SLEEP1` + QoS MoChi/AP re-setup), set `AP806_CCU_B_RVBAR = WARM_BOOT_ADDR`, bàn giao ngắt GMAC về AP (`wake_lan`/`clear_wake_ints`), rồi bật nguồn từng lõi A72 (PWR_DN_RQ/ISO/`CCU_B_PRCR=nReset`). A72 boot từ RVBAR → ATF thấy warmboot flag `0x7FFFFFF0` → `bl31_warm_entrypoint` → `gicv2` re-init → trả về Linux. Linux đọc `wake_reason`/`guc_wake_info`, gửi `HOSTCMD_HELLO` (→ `g_wolMode=0`, `HalApiEth_disable_irqs`, `SystemIsSuspended=FALSE`, `RedirectTraffic=true`) → NORMAL, Linux xử lý gói/lệnh in đã forward lúc wake.
