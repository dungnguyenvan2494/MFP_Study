## 1. `quartz-sb.dtsi` — các node LPPP-relevant

### 1.1 MHU + SCPI (khớp T2.4)
```dts
mailbox: mhu@8e8009800 {
    compatible = "arm,mhu", "arm,primecell";
    reg = <0x8 0xe8009800 0x0 0x1000>;
    interrupts = <0 269 4>,   /* LP-NonSecure */
                 <0 268 4>,   /* HP-NonSecure */
                 <0 270 4>;   /* Secure */
    #mbox-cells = <1>;
};
sram: sram@7fff0000 {                    /* "last 64KB DDR" */
    compatible = "arm,juno-sram-ns", "mmio-sram";
    reg = <0x0 0x7fff0000 0x0 0x10000>;
    smemmbox: scp-shmem@0 { compatible = "arm,juno-scp-shmem"; reg = <0x0 0x100>; };
};
scpi_protocol: scpi@7fff0000 {
    compatible = "arm,scpi";
    mboxes = <&mailbox 0>;               /* MHU channel 0 = Linux (T2.4) */
    shmem = <&smemmbox>;
};
```
→ Linux dùng **SCPI chuẩn ARM qua MHU `0xE8009800` channel 0** + shared-mem `0x7FFF0000` (128 byte `scp-shmem@0`). Khớp `arm_scpi.c` (T2.5).

### 1.2 HCI FIFO (khớp T6) — **địa chỉ xác nhận byte-for-byte**
```dts
usbd_qhead_lcm: lcm@8e8200000 {
    compatible = "mmio-sram";
    reg = <0x8 0xe8200000 0 0x800>;      /* 2KB — "must match .usbd2_qh_sec" */
};
lcm@e8200800 {
    compatible = "net-proxy-hci";
    reg = <0x8 0xe8200800 0 0x1880>;     /* 6272B — "must match .fifosec" */
};
```
Comment DTS chỉ thẳng: *"start addr and size must match `.fifosec` in `...\r4-freertos\Hal\quartz\asic\linker_common\memory_sections.ld`"* — tức chính `ComFifo` LPPP (T6 §1). `usbd_qhead_lcm` cũng vậy cho USB2 qhead (T9.2).

### 1.3 USB2 device (khớp T9.2)
```dts
usb2x_dev: usb2dev@8e8250000 {
    compatible = "fsl,imx27-usb", "chipidea,ci13xxx";   /* ChipIdea/VUSB20 */
    reg = <0x8 0xe8250000 0 0x200>;
    interrupts = <0 52 4>;                               /* SPI 52 = INTNUM_USB (T7.5: 37+INTRL... — xem note) */
    dr_mode = "peripheral";
    phy_type = "utmi";
    sram_qhead = <&usbd_qhead_lcm>;                      /* dQH ở LCM SRAM 0xE8200000 */
    wakeup-source;                                       /* wake-on-USB */
};
```

### 1.4 Clock gate LPPP giữ quyền
```dts
busclk_usbd: busclk_usbdgate {
    compatible = "marvell,quartz-clkgate";
    reg = <0x8 0xe8240050 0 0x8>;
    ignore-disable = <1>;   /* let LPPP handle PD */
    ignore-enable  = <1>;   /* let LPPP handle PU */
};
```
→ **Linux KHÔNG gate clock USB device** — LPPP (`lpp_usbd`) sở hữu (T9.2: `lpp_usbd_open` kiểm `PORTSC.PHCD` = "Linux đã tắt PHY clock?"). Tương tự comment `lcdx_clkgate`: *"LPPP will PD/PU device in Init/Sleep2/Resume"*.

### 1.5 QSPI — 2 chip select
| node | compat | CS | `map_memory` | size | partitions |
|------|--------|-----|--------------|------|-----------|
| `spi0`/`qspi0` | `mrvl,bspi[1]` | **1** | `0xF8000000` | 2 MB | `lppp-spi-firmware` (`0..0x200000`) |
| `spi1`/`qspi1` | `mrvl,bspi[1]` | **0** | `0xF4000000` | 4 MB | `spi-romfs` (`0..0x300000`) + `spi-user` (`0x300000..0x400000`) |

⇒ **Tinh chỉnh T1.6/T7.4/T11.2:**
- **CS1 `0xF8000000` (2MB)** = firmware LPPP `mvri.bin` — LPPP `.text` XIP chạy từ đây (T1.6 "RO-cache MPU region").
- **CS0 `0xF4000000` (4MB)** = `spi-romfs` (3MB) + **`spi-user` (1MB, `0x300000–0x400000`)** — nơi có thanh ghi B0xx (`B015 = 0xF43FF01E` → nằm trong `spi-user`), EEPROM ảo Machine Type (`0xF4079000/0x7A000`, T11.2), BSP Threshold Region (T12.2). `SPI_BASEADDRESS` trong `LPPP_Flash.h` = `0xF4000000` = CS0 (T7.4) ✓.

### 1.6 UART debug — Linux TẮT
```dts
dw_uart_165500: uart@8e8003800 {   /* "LPPP debug terminal" */
    compatible = "snps,dw-apb-uart";
    reg = <0x8 0xe8003800 0 0x800>;         /* = AON UART10 (T7.6) */
    clock-frequency = <7380000>;
    interrupts = <0 38 4>;                   /* SPI 38 */
    status = "disabled";                     /* Linux KHÔNG dùng — LPPP sở hữu (T7.6) */
};
```
Khớp T7.6: UART10 `0xE8003800` là cổng debug/console của LPPP; Linux để `disabled`.

### 1.7 `CONFIG_KM_BIZHUB` gate
Nhiều node KM chỉ có khi `#ifdef CONFIG_KM_BIZHUB`: LCD panel (`marvell,pxa168-fb` `lcd0@c057e000`), `cdma_clkgate`/`preaudio_clkgate`/`audio_clkgate` (I2S/CDMA audio), eMMC `non-removable` + `vqmmc-supply`, KM UART… ⇒ cùng flag với ATF (T12.1) và U-Boot (T12.2).

## 2. Driver Linux

### 2.1 GMAC / Ethernet — `mvri_nonpci.c` (khớp T5.1)
```c
static const struct of_device_id sky2nonpci_dt_ids[] = { { .compatible = "sky2_nonpci" }, ... };
static struct platform_driver mvri_driver = { .driver = { .name = "sky2nonpcieth", .of_match_table = ... } };
```
- Driver **SysKonnect sky2 / Yukon-2** (non-PCI) cho GMAC trong Iris SB0 — đúng mô hình BMU/LE `eth_bmu.h` mà LPPP GMAC driver mô phỏng (T5.1).
- `mvri_nonpci.c` (~3000 dòng) = phần MAC/DMA; `mvri_fw.c` = phần "net-proxy companion".

### 2.2 Net-proxy companion — `mvri_fw.c`
- `of_device_is_compatible(node, "net-proxy-hci")` (`:1007`) — tìm node DTS §1.2, map `ComFifo` `0xE8200800`/`0x1880`.
- Gửi `MSG_CMD_*` xuống R4 qua HCI FIFO down_data:
  - `MSG_CMD_NETWORK_IPV4_CREDENTIALS_WRITE` (`:728`) — nạp IP/mask (T5.5 `ApiSysNetworkIPv4AddressSet`)
  - `MSG_CMD_SYSTEM_SET_WOL` (`:761`) — nạp `g_wolMode` từ ethtool WoL (T9.4 `FW_MSG_CMD_NETWORK_WOL_MODE_WRITE`)
  - (+ pattern, proxy config — T5.4)
- `mvri_fw_wait_for_wakeup(pAC)` (`:585`) — chờ R4 báo thức; `wake_reason` đọc từ `dg->payload+4` (datagram `fifo_msg_wake` T6, hoặc SCPI wake-info T2.6).
- `mvri_fw_get_wake_reason` → `pAC->fw_ctx.lp_ctx.wake_reason` (`MVRI_WAKE_REASON_*`).

### 2.3 SCPI — `arm_scpi.c` + `km_scpi.c` (khớp T2.5)
- `arm_scpi.c` `#include "km_scpi.h"`, bind `compatible = "arm,scpi"` (node §1.1).
- `km_scpi_probe` (`:367`): `km_scpi_info = &scpi_info[1]` — KM mở rộng dùng slot SCPI thứ 2; gắn `km_scpi_ops`.
- `is_lppp_wfi` (`:345`, thêm 2024/02/26 OP_BTS-47053 "LPPP có đang wfi không (cần chờ giao tiếp)") + `wfi_wait_queue`:
  - `scpi_dvfs_set_idx(0, 1)` → `is_lppp_wfi = 1` (`:547`) — R4 sắp `pause_cpu` (T2.5/T7.7).
  - `scpi_dvfs_set_idx(0, 0)` → `is_lppp_wfi = 0` (`:811`) + (T2.5) `ioremap(0xe8008000); base[0xc/4] |= PAUSE_R4_INT(1)` — đánh thức R4.
  - `wait_event_timeout(wfi_wait_queue, !is_lppp_wfi, 60000ms)` (`:532, :645`) — Linux chặn SCPI khi R4 đang ngủ, timeout 60s.

## 3. FACT / INFERENCE / UNKNOWN

- **FACT**: DTS `mhu@8e8009800` (`arm,mhu`, IRQ SPI 268/269/270), `scpi@7fff0000` (`arm,scpi`, mbox `<&mailbox 0>`, shmem `scp-shmem@0` 0x100B), `net-proxy-hci` @ `0xe8200800` size `0x1880` + comment "must match .fifosec", `usbd_qhead_lcm` @ `0xe8200000` size `0x800`, `usb2dev@8e8250000` (`chipidea,ci13xxx`, `sram_qhead`, `wakeup-source`, IRQ SPI 52), `busclk_usbd` `ignore-enable/disable=1` "let LPPP handle", `uart@8e8003800` "LPPP debug terminal" `status=disabled`, QSPI CS1 `0xf8000000` 2MB "lppp-spi-firmware" / CS0 `0xf4000000` 4MB "spi-romfs"+"spi-user".
- **FACT**: Ethernet driver `mvri_nonpci.c` compat `sky2_nonpci` `.name="sky2nonpcieth"` (SysKonnect sky2); `mvri_fw.c` tìm `net-proxy-hci`, gửi `MSG_CMD_NETWORK_IPV4_CREDENTIALS_WRITE` / `MSG_CMD_SYSTEM_SET_WOL`, `mvri_fw_wait_for_wakeup` đọc `wake_reason`.
- **FACT**: `arm_scpi.c` `#include km_scpi.h`, `km_scpi_probe` dùng `scpi_info[1]`, `is_lppp_wfi` + `wfi_wait_queue` 60s, `scpi_dvfs_set_idx(0,1/0)` ↔ `is_lppp_wfi`.
- **INFERENCE**: CS0 `0xF4000000` = data flash (romfs + user, chứa B0xx/EEPROM/THR), CS1 `0xF8000000` = LPPP firmware `mvri.bin` XIP — tinh chỉnh T1.6 (T1.6 gọi `0xF8000000` là "128MB RO-cache" nhưng DTS nói 2MB CS1). Cần đối chiếu MPU encoding thật vs partition size.
- **INFERENCE**: IRQ SPI 52 cho USB trong DTS vs `INTNUM_USB = 37+INTRL_GIC_OFFSET(32) = 69` phía R4 (T7.5) — số khác nhau vì DTS dùng đánh số GIC của A72 (SPI base khác), phía R4 dùng ICU/local. `mailbox` IRQ 268-270 (DTS/A72) vs `INTNUM_HCU_WAKEUP=152` (R4). Đánh số ngắt AP806 ≠ R4 (T9.5 `find_wake_ints` xử lý chính chuyện này).
- **UNKNOWN**: `mvri_fw.c` toàn bộ danh sách `MSG_CMD_*` + cấu trúc datagram; `km_scpi.c` các op `0x81-0x8C` phía Linux (T2.5 đã liệt kê 1 phần).
- **UNKNOWN**: `armada-quartz-emu800.dts` top-level (CPU nodes, memory, chosen bootargs) — chưa đọc. `quartz-iris-{sb,nb}-*.dtsi` (GbE/USB/PCIe trong Iris).
- **UNKNOWN**: `net-proxy` (không -hci) driver mạng thật (ethernet_input path) — có node riêng không, hay `mvri_nonpci` + `mvri_fw` là tất cả.

## Tóm tắt (theo format skill)

**DTS `quartz-sb.dtsi` phản chiếu chính xác giao diện LPPP↔Linux:** `mhu@8e8009800` + `scpi@7fff0000` (`arm,scpi` chuẩn ARM, MHU channel 0, shmem 256B ở `0x7FFF0000`) cho SCPI/PSCI; node `net-proxy-hci` @ `0xe8200800`/`0x1880` **với comment yêu cầu khớp `.fifosec` của LPPP** cho HCI FIFO; `usbd_qhead_lcm` @ `0xe8200000`/`0x800` + `usb2dev` ChipIdea `wakeup-source` `sram_qhead` cho wake-on-USB; `busclk_usbd`/`lcdx_clkgate` đánh dấu **`ignore-enable/disable` = "let LPPP handle PD/PU"** (Linux nhường quyền power domain); `uart@8e8003800` "LPPP debug terminal" **`status=disabled`** (LPPP sở hữu UART10). QSPI 2 CS: CS1 `0xf8000000` 2MB = firmware LPPP, CS0 `0xf4000000` 4MB = romfs + "spi-user" (chứa B0xx/EEPROM/THR). Driver: `mvri_nonpci.c` (sky2 SysKonnect) = GMAC; `mvri_fw.c` = net-proxy companion (map `net-proxy-hci`, gửi `MSG_CMD_NETWORK_IPV4_CREDENTIALS_WRITE`/`SYSTEM_SET_WOL`, `wait_for_wakeup`); `arm_scpi.c` + `km_scpi.c` (`scpi_info[1]`, `is_lppp_wfi`/`wfi_wait_queue` 60s, `scpi_dvfs_set_idx(0,1/0)` để pause/wake R4).
