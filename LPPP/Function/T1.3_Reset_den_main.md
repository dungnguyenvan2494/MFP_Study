## 0 · Ảnh nằm ở đâu, R4 bắt đầu từ đâu

`memory_sections.ld:40-48`:
```ld
.reset : {
    __rom_start__ = .;          /* = ORIGIN(rom) = 0xF8000000 */
    *hal_vectors_*.o  (.text)   /* ExceptionTable — PHẢI ở offset 0 của ảnh */
    *hal_init_*.o     (.text)   /* Reset_Handler + fix_qspi */
    . = ALIGN(BOOTSECT_ALIGN);  /* memory.ld:47  BOOTSECT_ALIGN = 0x200 */
} > rom
```

- `mvri.bin` được build với `.reset` **đầu tiên** → flash vào QSPI **CS1 offset 0** = `0xF8000000`.
- BootROM kiểm checksum rồi cho R4 chạy từ `0xF8000000`. R4 **XIP** — không chép vào RAM.
- `ExceptionTable` (8 word đầu) nằm ngay tại `0xF8000000`; vector base của R4 trỏ vào đó.

## 1 · Vector table — `hal_vectors_gnu.asm`

```asm
ExceptionTable:               @ 8 lệnh LDR PC, [literal]
    LDR PC, ResetAddr         @ +0x00  → Reset_Handler
    LDR PC, UndefinedAddr     @ +0x04  → UndefinedHandler
    LDR PC, SwiAddr           @ +0x08  → SwiHandler_second_stage   (FreeRTOS ctx switch)
    LDR PC, PrefetchAddr      @ +0x0C  → PrefetchHandler
    LDR PC, AbortAddr         @ +0x10  → AbortHandler
    LDR PC, Unused            @ +0x14  → Unused1
    LDR PC, IrqAddr           @ +0x18  → IrqHandler_second_stage   (GIC dispatch)
    LDR PC, FiqAddr           @ +0x1C  → FiqHandler
```

**Handler fault đều rất cụt** (`hal_vectors_gnu.asm:59-77`):
```asm
UndefinedHandler:  MOV r12, #0xe1 ; LDR PC, dumpfault
PrefetchHandler:   MOV r12, #0xe3 ; LDR PC, dumpfault
AbortHandler:      MOV r12, #0xe4 ; LDR PC, dumpfault
FiqHandler:        MOV r12, #0xe5 ; LDR PC, dumpfault
Unused1:           MOV r12, #0xe6 ; LDR PC, dumpfault
```
`r12` mang **mã loại fault**, rồi nhảy vào `DumpFaultRegisters`.

**`DumpFaultRegisters`** (`hal_2nd_init_gnu.asm:36-41`):
```asm
DumpFaultRegisters:
@ at least trigger a wakeup      ← comment, nhưng KHÔNG có lệnh nào
ResetEntry2:
    B  ResetEntry2               @ loop forever
```
⇒ **Fault = treo vô hạn tuyệt đối.** Không dump, không log, không reset, không watchdog.
Manh mối duy nhất: cắm debugger, đọc `r12` (`0xe1`=undef / `0xe3`=prefetch abort /
`0xe4`=data abort / `0xe5`=FIQ / `0xe6`=unused) và thấy PC quay tại `ResetEntry2`.
Comment "trigger a wakeup" cho thấy ý định ban đầu (ping watchdog/PS-CPU) chưa bao giờ viết.

`IRQ` và `SWI` **không** đi vào dumpfault — chúng vào FreeRTOS (§5).

## 2 · `Reset_Handler` — 7 bước (`hal_init_gnu.asm:52-138`)

```
① Disable_interrupts        MRS/ORR/MSR cpsr  ← set I_Bit|F_Bit (0xC0), tắt IRQ+FIQ
② disable_caches            SCTLR: clear bit12 (I-cache), bit2 (D-cache); DSB/ISB
③ disable_MPU               SCTLR: clear bit0; DSB/ISB
④ _wait_for_bist_repair     poll [0xE8240808] & 1 == 0   ← chờ BIST/repair SRAM xong
                            (0xE8240808 = PMU_CONFIG vùng, bit "bist repair done")
⑤ EnableIRQsAndInterruptStacks
       lần lượt vào FIQ→IRQ→UND→ABT→SVC mode (mỗi mode I_Bit|F_Bit vẫn set),
       nạp SP = __PSTACK_<mode>_TOP__
       kết thúc: ở lại SVC mode, ngắt vẫn TẮT
⑥ [MPU sớm — xem §3]   +   fix bug cache Quartz:
       ldr r4,=0xe8273000 ; ldr r0,[r4] ; bic r0,#0x100000 ; str r0,[r4]
       ← "turn off crit word first in bspi, avoids a bug in quartz where
          the caches can't be turned on"  (BSPI reg, clear bit 20)
⑦ enable_caches            SCTLR: set bit12+bit2; invalidate I+D cache; ISB
   b continue_in_2nd_stage
```

**Chi tiết đáng chú ý:**
- **④ BIST wait** đọc `0xE8240808` (trong dải PMU `0xE8240000`). Nếu bit 0 chưa về 0
  (SRAM self-repair chưa xong) thì spin. Không timeout — nhưng đây là phần cứng, luôn kết thúc.
- **⑥ fix BSPI crit-word** (`bic r0,#0x100000`): trên Quartz có bug — nếu để "critical-word-first"
  bật ở BSPI thì **không bật được cache**. Phải clear bit 20 của `[0xE8273000]` **trước** bước ⑦.
- Ngắt được bật (`I_Bit` cleared) **KHÔNG** ở đây — vẫn tắt tới tận `SysApi_InitApplModules`
  (`HalApiIsr_Unmask(TIM)`), sau khi mọi module đã dựng.

## 3 · Hai lần cấu hình MPU

### 3.1 · MPU sớm trong asm (`hal_init_gnu.asm:100-124`)
```asm
.equiv MPU_SETUP_AND_ENABLE, 0      @ ⚠ GÁN GIÁ TRỊ 0 — nhưng vẫn ĐỊNH NGHĨA symbol
.ifdef MPU_SETUP_AND_ENABLE        @ .ifdef xét TỒN TẠI, KHÔNG xét giá trị → NHÁNH NÀY CHẠY
    MOV R4, #0 ; LDR R6, =mpu_table
LoopMpu:
    LDMIA R6!, {R0-R3}             @ 4 entry × 4 word
    SetMpuRegion R0, R1, R2, R3    @ MCR c6,c2,0 / c6,c1,0 / c6,c1,4 / c6,c1,2
    ADD R4,R4,#1 ; cmp R4,#4 ; bne LoopMpu   @ mpu_num_entries = 4
enable_mpu:
    MRC ... ORR R1,#0x1 ... MCR    @ SCTLR bit0 = 1 → BẬT MPU
.endif
```

Bảng dùng: `hal_mpu_table_gnu.asm` — **4 vùng, KHÁC bản C:**
| # | addr | size | type |
|---|---|---|---|
| 0 | `0x00000000` | 4 GB | **WBWA cache** (bản C: NOCACHE) |
| 1 | `0xC0000000` | 1 GB | DEVICE |
| 2 | `0xE8200000` | 256 KB | WBWA cache |
| 3 | `0xF8000000` | 128 MB | **WBnWA cache** (bản C: ROCACHE) |

⚠ **`.equiv MPU_SETUP_AND_ENABLE,0`** trông như "tắt tính năng", nhưng `.ifdef` trong GAS
chỉ kiểm tra symbol **đã được định nghĩa chưa** (không quan tâm giá trị 0/1). `.equiv` **có**
định nghĩa symbol → **khối này được biên dịch và chạy**. _(INFERENCE mức cao — đúng theo tài liệu
GAS; nên xác minh lại bằng disassembly `mvri.elf` phần `.reset` nếu cần chắc chắn tuyệt đối.)_

### 3.2 · MPU chính thức trong C — `cpu_init()` → `cpu_initialize_mpu()`
Gọi từ `main()` sau `hwConfigInit()`. Dùng `cortex_r4_mpu_config.c` — **5 vùng** (xem `T0.3` §2):
DDR **NOCACHE** (không phải WBWA), + vùng 4 (80KB NOCACHE đè LCM cho DMA GMAC/HCI FIFO).
Bản C **ghi đè hoàn toàn** bản asm sớm. Nên MPU asm sớm chỉ có ý nghĩa cho **khoảng từ
`Reset_Handler` tới `cpu_init()`** — chủ yếu để cache hoạt động khi XIP + copy `.data`.

## 4 · `continue_in_2nd_stage` → `main()` (`hal_2nd_init_gnu.asm:90-118`)

```asm
continue_in_2nd_stage:
stackfill_exceptions:               @ tô 0xA5A5A5A5 vào [__stack_start__ .. __stack_end__]
    LDR r0,=__stack_start__ ; LDR r1,=__stack_end__
    MOVW/MOVT r2, #0xa5a5           @ giống tskSTACK_FILL_BYTE của FreeRTOS
stackfill_loop: CMP r0,r1 ; STMLTIA r0!,{r2,r3} ; BLT stackfill_loop

InvokeMain:
    MOV r1, #0   @ argv = NULL
    MOV r0, #0   @ argc = 0
    BL  main                        @ ★ VÀO C ★
```

- **Chỉ tô các exception stack** (SVC/IRQ/FIQ/UND/ABT), không tô `.bss`/heap — cái đó do
  `main()` → `hal_main_initialize_sections()` (xem `Function/hal_main_initialize_sections.md`).
- `BL main` — nếu `main` return thì rơi vào rác (nhưng `main` có `while(1)` cuối).

## 5 · IRQ và SWI — cầu vào FreeRTOS (`hal_2nd_init_gnu.asm:250-267`)

```asm
SwiHandler_second_stage:            @ vector +0x08
    add lr, lr, #4
    portSAVE_CONTEXT                @ lưu r0-lr, spsr, ulCriticalNesting vào stack task
    ldr r0, =vTaskSwitchContext ; blx r0
    portRESTORE_CONTEXT             @ subs pc, lr, #4

IrqHandler_second_stage:           @ vector +0x18
    portSAVE_CONTEXT
    bl  irq_handler                @ GIC: đọc ICC_IAR, dispatch Handlers[id], ghi ICC_EOIR
    portRESTORE_CONTEXT
```

- `portSAVE_CONTEXT` lưu context vào **stack của task hiện tại** (`pxCurrentTCB`), không phải
  stack IRQ. Đây là cơ chế context-switch chuẩn của FreeRTOS ARM_CRx port.
- `SWI` = cách `taskYIELD()` gọi scheduler. → **không được gọi từ ISR context** (abort) —
  đây là lý do các callback dùng `HalApiCpu_is_irq_mode()` để chọn `portYIELD_FROM_ISR()`.
- Trước khi scheduler chạy, `IRQ` vẫn bị mask toàn cục (`I_Bit`), nên `IrqHandler` chưa kích hoạt.

## 6 · `fix_qspi` / `update_qspi` — đưa QSPI vào Quad Read mode (`hal_init_gnu.asm:139-183`)

```asm
fix_qspi:                          @ gọi sau, khi cần chuyển QSPI sang quad-read
    @ chép update_qspi[] vào __free_ram_start__ (RAM), rồi blx vào bản sao
    @ "must be run from ram since code goes away while this happens"
    ldr r5,=__free_ram_start__ ; cpy_lp: ...
    bl  cpu_dcache_writeback_all ; MCR c7,c5,0 (inval I-cache) ; isb
    blx r5                         @ chạy update_qspi từ RAM
update_qspi:
    str r1,[r4]      @ bscr  (bspi ctrl)
    str r0,[r4,#4]   @ bscom (read command)
    orr r1,#0x40000 ; str r1,[r4]   @ enable bspi cache
    mov r0,#200 ; spi_wait: subs r0,#1 ; bne spi_wait   @ settle
```

Cùng mẫu với `flash_modify_sub` (`Update_FW_LPPP.md §F`): **không thể vừa cấu hình QSPI vừa
fetch lệnh từ chính nó** → chép đoạn code sang RAM, tắt cache, chạy từ RAM. `fix_qspi` chuyển
từ single-read (BootROM để lại) sang quad-read để tăng băng thông XIP.

## 7 · Stack 5 chế độ ARM (`asic/build/memory.ld:52-58`, `memory_sections.ld:277-312`)

| Mode | Symbol | Size | Ghi chú |
|---|---|---|---|
| SVC | `__PSTACK_SVC_SIZE__` | `0x1C00` = **7.00 KB** | *"used from the moment when entering main"* — stack chính của `main()` và mọi code bare-metal trước scheduler |
| IRQ | `__PSTACK_IRQ_SIZE__` | `0x0300` = 768 B | |
| FIQ | `__PSTACK_FIQ_SIZE__` | `0x0010` = 16 B | gần như không dùng |
| UND | `__PSTACK_UND_SIZE__` | `0x0010` = 16 B | fault → treo ngay, không cần stack |
| ABT | `__PSTACK_ABT_SIZE__` | `0x0010` = 16 B | |
| | | **≈ 7.8 KB** | |

Section `.stack` nằm **sau `.bss`** trong LCM (không phải địa chỉ thấp cố định) → SP trỏ vào
LCM. LCM có điện + truy cập được từ reset, và `.stack` là `NOLOAD` nên chỉ cần gán SP.
Sau khi scheduler chạy, task dùng stack riêng (cấp từ heap SYSTEM), **không** dùng SVC stack —
SVC stack chỉ còn dùng cho phần lõi kernel/exception.

## 8 · Sơ đồ tổng

```
BootROM (kiểm checksum mvri.bin @ QSPI CS1) ──► R4 chạy từ 0xF8000000
   │
ExceptionTable[0] : LDR PC, ResetAddr
   ▼
Reset_Handler (hal_init_gnu.asm):
   ① tắt IRQ/FIQ   ② tắt I/D-cache   ③ tắt MPU
   ④ chờ BIST repair SRAM (poll 0xE8240808)
   ⑤ set SP cho FIQ/IRQ/UND/ABT/SVC ; ở lại SVC, ngắt vẫn tắt
   ⑥ MPU sớm 4-vùng (từ mpu_table) + enable MPU ; clear BSPI crit-word bit20
   ⑦ bật lại I/D-cache ; invalidate
   ▼ b continue_in_2nd_stage
continue_in_2nd_stage (hal_2nd_init_gnu.asm):
   • stackfill 0xA5A5A5A5 các exception stack
   • BL main   (argc=0, argv=NULL)
   ▼
main() [C] :
   hal_main_initialize_sections()   ← chép .data flash→LCM, xoá .bss  (T... đã có note)
   hwConfigInit() ; cpu_init() → cpu_initialize_mpu()  ← MPU 5-vùng bản C GHI ĐÈ bản asm
   ... (7 giai đoạn boot — Flow LPPP.md)
   AppInit_Initialize() → vTaskStartScheduler()   (không return)
   while(1)

── Sau khi scheduler chạy ──
IRQ  (vector +0x18) → IrqHandler_second_stage → portSAVE_CONTEXT → irq_handler (GIC) → portRESTORE
SWI  (vector +0x08) → SwiHandler_second_stage → portSAVE_CONTEXT → vTaskSwitchContext → portRESTORE
FAULT (undef/prefetch/abort/fiq/unused) → r12 = mã → DumpFaultRegisters → ResetEntry2: B . (treo)
```

## 9 · Tóm tắt (theo format skill)

**1. Tồn tại để làm gì:** `.reset` là 2 file asm (`hal_vectors` + `hal_init`) ở offset 0 của ảnh
firmware, đưa R4 từ trạng thái sau reset (cache/MPU/ngắt đều tắt) tới điểm gọi được `main()` C:
dựng SP cho 5 chế độ ARM, chờ SRAM BIST, bật MPU tạm + cache, tô stack, `BL main`. Fault ở giai
đoạn này = treo vô hạn tại `ResetEntry2`, chỉ `r12` cho biết loại.

**2. Call flow:**
```
Reset_Handler [hal_init_gnu.asm:52]
├─ Disable_interrupts / disable_caches / disable_MPU
├─ _wait_for_bist_repair          [poll 0xE8240808]
├─ EnableIRQsAndInterruptStacks   [SP cho FIQ/IRQ/UND/ABT/SVC; ở lại SVC, ngắt tắt]
├─ MPU sớm (nếu .ifdef MPU_SETUP_AND_ENABLE — likely CHẠY)  [mpu_table 4 vùng]
├─ clear BSPI crit-word bit20     [0xE8273000] — workaround bug cache Quartz
├─ enable_caches
└─ b continue_in_2nd_stage        [hal_2nd_init_gnu.asm:91]
   ├─ stackfill_exceptions        [0xA5A5A5A5 → __stack_start__..__stack_end__]
   └─ InvokeMain: BL main         [→ C, argc=0]

Fault path:  <handler> MOV r12,#0xeN  →  DumpFaultRegisters  →  ResetEntry2: B .   (treo)
Runtime IRQ: vector+0x18 → IrqHandler_second_stage → irq_handler (GIC)
Runtime SWI: vector+0x08 → SwiHandler_second_stage → vTaskSwitchContext
```

**3. File đã tham chiếu:**
- `Hal/quartz/asic/build/hal_vectors_gnu.asm:27-77`
- `Hal/quartz/asic/build/hal_init_gnu.asm:44-183`
- `Hal/quartz/asic/build/hal_2nd_init_gnu.asm:34-118, 250-267`
- `Hal/quartz/asic/build/hal_init_gnu.h:6-19` (Mode_*, I/F_Bit)
- `Hal/quartz/asic/build/hal_mpu_table_gnu.asm:34-38`
- `Hal/quartz/asic/linker_common/memory_sections.ld:40-48, 277-312`
- `Hal/quartz/asic/build/memory.ld:47, 52-58`

**4. UNKNOWN / cần xác minh:**
- `.ifdef MPU_SETUP_AND_ENABLE` có thật sự chạy không → disassemble `output/<board>/mvri.elf` phần `.reset`.
- Bit ý nghĩa của `[0xE8240808]` (BIST repair) — cần `PMU_regmasks.h` để đặt tên chính xác.
- Vector base của R4 được đặt bằng gì (strap phần cứng / BootROM ghi VBAR c12,c0,0) — cần BootROM (T12.2).

**Gợi ý:** `kernel-debug-toolkit` nếu muốn tập giải mã oops/fault từ `r12` + `System.map`.
