## 2. Cơ chế: giá trị trả về của callback FFL ĐIỀU KHIỂN "khớp hay không", KHÔNG phải hành động

**FACT.** `sys_filter_main.c:183-197` (`SysFilter_PacketFilterGetMatchingFilterOfPacket`):
```c
if (FilterCfgList[i].FilterFunctionID & FILTER_ENABLE_CALLBACK) {
    FilterFunction ffunc = FFL[... & MASK];
    if (!ffunc) continue;                       // no match
    if (! (*ffunc)(i, Protocol, PacketType, p, length))
        continue;                               // callback trả FALSE → COI NHƯ KHÔNG KHỚP
}
return (i | FILTER_ID_MATCH);                    // callback trả TRUE → filter i khớp
```

Sau khi có filter khớp, `SysFilter_Execute_Filter` (`:217-284`) áp **`ActionFlags` TĨNH** của filter đó:

| flag | hành vi |
|------|---------|
| `FOR_APP_LAYER` | copy gói → `SysFilter_PutPmPkt` → `PmPktQ` → `APP_EVENT_RECEIVE_PM_PACKET` (chỉ `HOST_COMMANDS` dùng) |
| `FORWARD_PACKET` (STAGE_2) | nếu có `saved_rawpacket` → `SysApiLan_PacketForwardToDriver(payload, tot_len)` rồi `pbuf_free` |
| `WAKE_SYSTEM` | `SetWakeReason(MvWakeReasonPacket)` → `SysApiSystem_Wake()` → `RedirectTraffic = true` → set `SYS_EVENT_WAKE_SYSTEM` |
| `DISCARD_PACKET` | `return RC_DISCARD_PACKET` — gói KHÔNG lên lwIP local |

**Hệ quả quan trọng:**
- **SNMP filter** ActionFlags = chỉ `DISCARD`. Proxy tự lo phần trả lời/đánh thức **bên trong** hàm (không nhờ `WAKE_SYSTEM` flag). Callback trả TRUE ⇒ chỉ để gói bị DISCARD khỏi stack local (vì proxy đã xử lý xong — hoặc đã trả lời, hoặc đã forward+wake).
- **Wake-service filter** ActionFlags = `DISCARD | FORWARD | WAKE_SYSTEM`. Proxy chỉ *quyết định* có nên đánh thức không (trả TRUE/FALSE); ActionFlags mới thực sự forward gói gốc + đánh thức host.

## 3. SNMP proxy — `snmp_proxy_process_request(PacketType, Packet, Length)`

`Packet` trỏ tới **UDP header** (byte 0-1 = src port, 2-3 = dst port, 8 = đầu payload SNMP).

### 3.1 Macro đánh thức
```c
#define WAKE_AND_RETURN(a) { ApiSysNetworkWakupAndForwardPacketToDriver(); return (a); }
```
`ApiSysNetworkWakupAndForwardPacketToDriver()` → `SysFilter_Wakeup_and_Forward()` (`sys_filter_main.c:356`):
1. nếu `saved_rawpacket` → `SysApiLan_PacketForwardToDriver(payload, tot_len)` + `pbuf_free`
2. `SetWakeReason(MvWakeReasonPacket)` + set `SYS_EVENT_WAKE_SYSTEM` (KHÔNG gọi `SysApiSystem_Wake()` — dòng đó bị comment)

`rc` luôn = `SYS_TRUE` ⇒ mọi nhánh `WAKE_AND_RETURN` cũng khiến filter "khớp" ⇒ ActionFlags `DISCARD` xoá gói local (đã forward bản gốc rồi).

### 3.2 Cấu hình OID: `snmp_proxy_add_records(MsgSNMPProxyConfig *mcfg)` (Linux gửi qua HCI FIFO)
- `proxylist[MAX_SNMP_PROXY_ENTRIES_SUPPORTED]` = mảng `SNMPProxyConfig*`.
- Mỗi record: `oidget` (OID hỏi, có prefix BER: `[0]=0x06 type, [1]=len`), `oidres` (OID trả lời), `value`/`valuelength`/`valuetype`, cờ `support`.
- `mcfg->oidgetlength == 0` ⇒ record đặc biệt lưu **community string** (`oidget[0]=0xff` — type tự chế để không đụng type SNMP thật).
- Cờ `support` (bitmask, `snmp_proxy.c:84-86`):
  - bit `OID_MATCH_EXACT (2)` — khớp chính xác cả OID
  - bit `OID_MATCH_REQUEST (4)` — "SNMP2 job": khớp chính xác nhưng mang nghĩa "đánh thức để host xử lý"
  - bit `OID_MATCH_ALL_BUT_LAST (8)` — khớp mọi sub-id trừ sub-id cuối (dùng cho GET-NEXT/walk)
  - bit0 (`support & 1`) — "được hỗ trợ trả offline"

### 3.3 Điều kiện vào
```c
if (UDPDestPort != 161)   return SYS_FALSE;   // không phải SNMP → filter không khớp
if (proxyindex == 0)      return SYS_FALSE;   // chưa có cấu hình proxy → bỏ qua
if (Length < 8+1+offset+length) return SYS_FALSE;  // gói cụt
```

### 3.4 Duyệt BER (vòng `for byte = 9+offset .. Length`)
State machine theo `SNMPMessageType`:

| type | xử lý |
|------|-------|
| `0x30` Sequence | ghi offset varbind-list / varbind đầu |
| `0x02` Integer | intIndex 1 = snmp_version (R54); 2 = RequestId; 3 = Error; 4 = ErrorIndex |
| `0x04` Octet String | community string → `match_community(start_of_value, length)`; **fail → `WAKE_AND_RETURN`** |
| `0xa0` GET / `0xa1` GET-NEXT | ghi `PDUTypeOffset`, nhảy qua length |
| `0x06` OID | lõi xử lý — xem dưới |
| `0x05` NULL | ghi `ValueLengthOffset` (chỗ nhét value khi trả lời) |
| khác | log "unknown type", bỏ qua |
| `byte + SNMPMessageLength > Length` | **`WAKE_AND_RETURN`** (gói hỏng) |

### 3.5 Xử lý mỗi OID (`case 0x06`)
```c
OIDListMatch = appHandleOID(&Packet[byte], SNMPMessageLength+1);
```
`appHandleOID` (`:352`) duyệt `proxylist[]`:
- nếu record có cờ `ALL_BUT_LAST | REQUEST` → so `match_length = oidgetlength` (đủ cả OID)
- ngược lại → `match_length = oidgetlength - 1` (bỏ sub-id cuối; tức mặc định coi như prefix match)
- so byte-by-byte; khớp → trả index; không khớp bất kỳ record nào → **`-1`**

Quyết định:

| tình huống | hành động | offline? |
|------------|-----------|----------|
| `OIDListMatch < 0` (OID lạ, "snmp mode 3") | `WAKE_AND_RETURN` | ❌ WAKE + forward |
| `support & OID_MATCH_REQUEST` ("snmp mode 2") | `LPPP_SetWakeInfo(LPPP_WAKE_INFO_SNMP2)`; `snmp_job_events++`; `WAKE_AND_RETURN` | ❌ WAKE (host làm job) |
| `appHandleOIDSupported()` == TRUE | thêm vào `requested_oid[OIDSupportIndex++]` | ✅ sẽ trả offline |
| `appHandleOIDSupported()` == FALSE | `OIDNotSupportIndex = OIDIndex` (đánh dấu lỗi) | ✅ trả SNMP error offline |

`appHandleOIDSupported(i)` (`:400`):
```c
return (proxylist[i]->support & 1) && (proxylist[i]->valuetype != 0x05 /*NULL*/);
```
→ chỉ trả offline khi record **có bit0** VÀ **value không phải NULL**.

Ghi chú trong code: nhánh so `match_value` cho SNMP2 (`OID_MATCH_REQUEST`) bị `#if 0` — bản hiện tại **không** so value, chỉ cần khớp OID là đánh thức CPU (comment tiếng Nhật: *"SNMP2 không trả trạng thái thay host, luôn đánh thức main CPU"*).

### 3.6 Sau vòng lặp — gửi trả lời offline
```c
snmp_proxy_get_ip_info();
if (OIDNotSupportIndex) {
    ret = appSendSNMPErrResponse(Packet, Length, OIDNotSupportIndex, UDPSrcPort, &srcIP);
    if (!ret) WAKE_AND_RETURN(rc);         // gửi lỗi thất bại → đành đánh thức
} else {
    ret = appSendSNMPResponse(Packet, Length, OIDSupportIndex, UDPSrcPort, &srcIP);
    if (!ret) WAKE_AND_RETURN(rc);
}
return rc;   // rc = SYS_TRUE → filter khớp → DISCARD gói local (đã tự trả lời)
```
- `appSendSNMPResponse` xây gói response tại chỗ: đổi PDU type → `0xa2` (GET-RESPONSE), nhét `oidres` + `value` từ record, `appSendUdpPacket(msg, len, dstPort, srcIP, 161, isIPv4, false)`.
- `appSendSNMPErrResponse` → PDU `0xa2` + error-status/error-index (noSuchName) trỏ tới OID hỏng.
- IPv4 và IPv6 đều hỗ trợ (`PacketIpSrcAddrv4` / `PacketIpSrcAddrv6[]`, `IsIPv4Addr`/`IsIPv6Addr` set trong `snmp_proxy_get_ip_info`).

### 3.7 `snmp_job_events` / `snmp_proxy_get_job_events()`
Biến đếm số lần OID "REQUEST/SNMP2" khớp. **Không** đọc được qua IOCTL — comment nói phải `devmem <địa chỉ trong map.txt>` từ Linux.

### 3.8 Tóm tắt SNMP: OID nào offline, OID nào wake

| Loại truy vấn | Kết quả |
|---------------|---------|
| Community sai | 🔴 WAKE + forward |
| OID không có trong `proxylist` | 🔴 WAKE + forward |
| OID khớp record có `OID_MATCH_REQUEST` (SNMP2 job) | 🔴 WAKE + `LPPP_WAKE_INFO_SNMP2` + `snmp_job_events++` |
| OID khớp, `support&1` & value≠NULL | 🟢 R4 tự trả GET-RESPONSE (`0xa2`), host ngủ tiếp |
| OID khớp nhưng `support&1`==0 hoặc value==NULL | 🟢 R4 tự trả SNMP error (noSuchName) |
| Gói SNMP hỏng / build response lỗi | 🔴 WAKE + forward (fallback an toàn) |

## 4. Wake-service proxy — `wake_service_proxy_process_request(PacketType, Packet, Length)`

Chỉ để **phát hiện có nên đánh thức host** cho 3 giao thức discovery. **Không tự trả lời gì.**

### 4.1 Giao thức & địa chỉ mục tiêu (`wake_service_proxy.c:106-113`)
| Tên | Port | IPv4 mcast | IPv6 mcast |
|-----|------|-----------|-----------|
| SSDP (UPnP) | **1900** | `239.255.255.250` (`0xeffffffa`) | `ff02::c` hoặc `ff05::c` |
| WSD (WS-Discovery) | **3702** | `239.255.255.250` | `ff02::c` |
| SLP | **427** | `239.255.255.253` (`0xeffffffd`) | `ff02::123` / `ff02::116` / `ff02:...:1xxx` (mask `0x1fc00 == 0x11000`) |

### 4.2 Cấu hình chuỗi: `wake_service_proxy_add_records(MsgWakeServiceProxyConfig *mcfg)`
- `stringlist[MAX_STRINGS_SUPPORTED]`: mỗi entry `{data, data_length, data_type}`.
- `data_type`: `0x76c` = SSDP, `0xe76` = WSD, `0x1ab` = SLP → tăng `ssdp_strings` / `wsd_strings` / `slp_strings`.
- Cấp phát `ApiSysMemAlloc(data_length)`, copy chuỗi. Linux nạp trước khi ngủ (ví dụ ST/URN cần bắt).
- `wake_service_proxy_stop()`: free hết, reset `proxyindex` + 3 bộ đếm.

### 4.3 Luồng xử lý gói
```
proxyindex == 0                    → SYS_FALSE   (chưa cấu hình)
ethtype ∉ {0x0800, 0x86dd}         → SYS_FALSE
dport ∉ {1900,3702,427}            → SYS_FALSE
dst IP không đúng mcast của proto  → SYS_FALSE
for p in [udp_payload .. end]:
    string_i = string_is_present(p, -1, dport)   // quét cửa sổ trượt so từng chuỗi
    if match: matching_index[string_i]=TRUE; matches++
matches == 0                       → SYS_FALSE
// giả định: khớp bất kỳ chuỗi của loại đó + có cấu hình chuỗi loại đó → thức
dport==1900 && matches && ssdp_strings → SYS_TRUE
dport==3702 && matches && wsd_strings  → SYS_TRUE
dport==427  && matches && slp_strings  → SYS_TRUE
else                               → SYS_FALSE
```
Có đo thời gian quét (`ApiSysGetSystemTime_nanoseconds`, `duration_us`) để log/profiling.

### 4.4 Khi trả `SYS_TRUE`
Về `filter_function_snmp_llmnr_nbns_etc` (`app_thread.c:1201`) — chỉ gọi khi `dst_port ∈ {427,1900,3702}`.
Callback trả TRUE ⇒ filter `ID_FILTER_STAGE2_WAKE_SERVICE_REQUEST` khớp ⇒ ActionFlags
`DISCARD | FORWARD | WAKE_SYSTEM`:
- `saved_rawpacket` → forward bản gốc cho Linux driver
- `SysApiSystem_Wake()` + `RedirectTraffic = true` + `SYS_EVENT_WAKE_SYSTEM`
- DISCARD khỏi lwIP local

### 4.5 Nhánh STAGE_1 (`filter_function_wake_services_stage1`, cb1)
Chỉ build nếu `WAKE_SERVICE_PROXY` + filter `ID_FILTER_STAGE1_WAKE_SERVICE_REQUEST`.
- `save_stage1_data(EthType, Packet, Length)` — lưu context L2.
- lọc thêm theo dst_mac SLP (`0x123` / `0x116` / `& 0x1fc00 == 0x11000`)
- tính `udp_header` (34 cho IPv4, 54 cho IPv6) rồi gọi thẳng `wake_service_proxy_process_request(&Packet[udp_header], Length-udp_header)`.
→ đường STAGE_1 chủ yếu dành cho SLP (bắt sớm ở tầng raw). SSDP/WSD đi đường STAGE_2 sau khi lwIP bóc UDP.

## 5. So sánh 2 proxy

| | SNMP proxy | Wake-service proxy |
|--|-----------|--------------------|
| Mục tiêu | Trả lời thay host khi có thể | Chỉ phát hiện & đánh thức |

| STAGE | chỉ STAGE_2 (port 161) | STAGE_1 (SLP raw, cb1) + STAGE_2 (cb6) |

## 6. Đánh dấu FACT / INFERENCE / UNKNOWN

- **FACT**: toàn bộ bảng filter, 8 callback, macro `WAKE_AND_RETURN`, các port/địa chỉ mcast, logic `appHandleOID`/`appHandleOIDSupported`, `support` bitmask, `SysFilter_Execute_Filter` áp ActionFlags tĩnh, `#define FILTERS_DEFINED_IN_THIS_MODULE` vô điều kiện — đọc trực tiếp từ source.
- **INFERENCE**: "đường STAGE_1 chủ yếu cho SLP, SSDP/WSD đi STAGE_2" — suy từ pattern raw của `ID_FILTER_STAGE1_WAKE_SERVICE_REQUEST` chỉ có port 427 và lọc dst_mac SLP; SSDP/WSD không có filter STAGE_1 tương ứng trong bảng mặc định.
- **INFERENCE**: `SysApiSystem_Wake()` trong `SysFilter_Wakeup_and_Forward` bị comment nhưng trong `SysFilter_Execute_Filter` (nhánh `WAKE_SYSTEM`) thì KHÔNG — nên SNMP proxy (dùng đường Wakeup_and_Forward) chỉ set event flag, còn wake-service (dùng ActionFlags) gọi cả `SysApiSystem_Wake()`. Ý nghĩa thực tế của khác biệt này chưa truy tiếp (cần T đọc `SysSystem_ThreadMain` xử lý `SYS_EVENT_WAKE_SYSTEM` vs `SysApiSystem_Wake`).
- **UNKNOWN**: giá trị số thực của `MAX_SNMP_PROXY_ENTRIES_SUPPORTED`, `MAX_STRINGS_SUPPORTED`, `MAX_OID_SIZE`, `MAX_VALUE_SIZE` (nằm trong header chưa mở — `snmp_proxy.h` / `wake_service_proxy.h`).
- **UNKNOWN**: `string_is_present` / `string_i` thuật toán so khớp cửa sổ trượt (chưa đọc thân hàm, dòng ~40-80).
- **UNKNOWN**: `match_community` thân hàm (chỉ biết fail → wake).

## Tóm tắt (theo format skill)

**Hàm/struct tồn tại để làm gì:**
`snmp_proxy_process_request` là bộ phân tích BER SNMP chạy trên R4: với các OID mà Linux đã nạp sẵn (OID+value) nó tự dựng GET-RESPONSE/error và bắn trả bằng `appSendUdpPacket`, giữ cho host ngủ; mọi thứ ngoài danh sách (OID lạ, community sai, OID loại "SNMP2 job", gói hỏng) thì forward gói gốc cho driver và set cờ đánh thức. `wake_service_proxy_process_request` không trả lời gì — nó chỉ soi gói multicast SSDP(1900)/WSD(3702)/SLP(427), quét payload tìm các chuỗi Linux đã đăng ký, và trả `SYS_TRUE` để lớp filter (ActionFlags `DISCARD|FORWARD|WAKE_SYSTEM`) đánh thức host. Cả hai được gọi từ **callback FFL #6** `filter_function_snmp_llmnr_nbns_etc` ở STAGE_2, cộng thêm đường STAGE_1 (#1) riêng cho SLP.

**Call flow:**
```
low_level_input (task ETH_I)
└─ RedirectTraffic? ──yes──> HCI FIFO (host driver có mặt)
   └─no─> SysFilter_Execute_Filter(pkt, len, STAGE_1)
          ├─ magic packet (cb0) ─ ActionFlags DISCARD|FORWARD|WAKE
          └─ wake_services_stage1 (cb1, SLP raw) ─> wake_service_proxy_process_request
   xNetIf->input → lwIP → ip4_input/ip6_input
   └─ SysFilter_Execute_Filter(payload, len, STAGE_2)
      ├─ SNMP (port 161, cb6) ──> filter_function_snmp_llmnr_nbns_etc
      │     └─ snmp_proxy_process_request
      │        ├─ khớp+supported ─> appSendSNMPResponse (0xa2)         [offline, ActionFlags=DISCARD]
      │        ├─ khớp+not-supported ─> appSendSNMPErrResponse         [offline]
      │        └─ lạ / community sai / SNMP2 / hỏng
      │           └─ WAKE_AND_RETURN → SysFilter_Wakeup_and_Forward
      │              (forward saved_rawpacket + SYS_EVENT_WAKE_SYSTEM)
```
