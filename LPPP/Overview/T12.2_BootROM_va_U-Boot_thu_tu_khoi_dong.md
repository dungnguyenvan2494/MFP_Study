## 0. 🔴 Thư mục `BootROM/` = **U-Boot** (BL33), KHÔNG phải mask ROM

`BootROM/BootROM/Emu800/Src/` là cây **U-Boot** đầy đủ (có `arch/`, `board/`, `drivers/`, `dts/`, `configs/`, `Kconfig`, `common/main.c`…), port Marvell mvebu Armada-8K, biến thể KM.
- Build: `Src/build_uboot.sh 800` → `CROSS_COMPILE=s800-linux-`, config `km_mvebu_quartz_*_defconfig` → `output/u-boot.bin`.
- Đây chính là **`BL33`** mà `atf_s800/build_atf.sh` cần (`BL33=../uboot_s800/output/u-boot.bin`, T12.1).
- `Readme.txt`: compile SW `CONFIG_KM_BOARD_EMU800` (bắt buộc cho Emu800) + `CONFIG_KM_MACHINE_{EGL,EGLZ,DNBMLK,SPAM,SPAAS}` (theo model).

**Mask ROM thật (BootROM silicon)** nằm trong SoC 88PA6220 — **không có source**. Vai trò: lúc power-on, đọc QSPI CS0, verify `code_header`, nhảy vào.

## 1. Thứ tự khởi động cold (quartz) — **R4 chạy TRƯỚC**

```
[Power on / HRESET]
  │
  ▼
① Mask ROM silicon (88PA6220)
   → đọc QSPI CS0 (0xF4000000), verify code_header (magic), load & jump
   → nạp firmware R4 = LPPP "mvri.bin"
  │
  ▼
② R4 / LPPP  (mvri.bin — T1.3)
   Reset_Handler → hal_init → cpu_init/MPU → main → AppInit_Initialize (T1.5)
   ├─ early_board_init(false) → board_init(false)   (board.c, T1.4/T11.2)
   ├─ init_ddr(warm=false, callback)                (ddr_init.c, T8.1)
   │    └─ init_lpddr4_from_ap806_sram(BSPI_CS0_ADDR, ...)
   │         ├─ nạp BLE image → AP806 L3-SRAM 0xCCF00000
   │         ├─ RVBAR_0 = BLE; start_ap806(true)   → A72 chạy BLE, train LPDDR4
   │         └─ chờ BOOT_SYNC_DDR_READY (0xE82460B0)
   ├─ copy_run_atf((void*)BSPI_CS0_ADDR)            (board.c:524/639, T2.4)
   │    → set A72 entry = ATF, thả A72
   └─ (R4 tiếp tục chạy LPPP net-proxy / power state machine)
  │
  ▼
③ ATF trên A72  (flash-image.bin — T12.1)
   BL1 (FIP) → BL2 → BL31 (EL3: PSCI/SCPI client) → BL33
  │
  ▼
④ U-Boot  (u-boot.bin — thư mục "BootROM")
   board_init → dram_init (DDR đã sẵn) → quartz_late_init → boot lệnh
  │
  ▼
⑤ Linux 5.10  (booti $kernel_addr - $fdt_addr)
```

**Warm boot (resume từ Sleep2/ErP):** cờ `*0x7FFFFFF0 == 0x7FFFFFF0` (T2.4) → ATF `plat_get_my_entrypoint` trả `bl31_warm_entrypoint` thay vì chạy lại BL1/BL2; DDR đã self-refresh (T8.1) nên `init_ddr(warm=true)` chỉ re-train nhanh.

## 2. `board/mvebu/armada8k/quartz.c` — board U-Boot

### `get_quartz_board()` (`:118`)
```c
i2c_set_bus_num(3); ret = i2c_probe(0x50);       // EEPROM trên bus I2C 3
if (ret == 0)  board = BOARD_TYPE_TOC;
else {
    gpio_set_direction(271 /* gpio_i31 = FW_CONFIG[5] */, IN);
    gpio_get_value(271) ? board = ESEVAL : board = EMU800;
}
```
> ⚠️ **Khác R4/ATF** (T11.2): U-Boot **dùng I²C probe 0x50** (active) để nhận TOC; R4 `board.c` `#if 0` I²C, chỉ GPIO. U-Boot đọc **GPIO 271** ("FW_CONFIG[5]"); R4 đọc **BANK_I[31]** (pin 287 theo `LPPP_Gpio.h`?). Đánh số GPIO 2 stack lệch — cần cẩn thận khi so.

### `quartz_late_init()` (`:152`)
| board | `dtb_name` env | thêm |
|-------|----------------|------|
| TOC | `armada-quartz-toc.dtb` | tự `bspi_boot()` |
| ESEVAL | `eseval.dtb` | — |
| EMU800 | `emu800.dtb` | — |

### `do_raw_boot(base, hdr_off)` (`:39`) + lệnh `quartz`
```c
header = (cs1_bspi_kernel_header*)(base + hdr_off);
if (header->header != 0xbaadc0de)  return -1;      // magic
setenv fdt_addr=FDT_ADDR, kernel_addr=KERNEL_ADDR
setenv bootcmd = "booti $kernel_addr - $fdt_addr"
memcpy(FDT_ADDR,    base+hdr_off+header->dtb_offset,    header->dtb_size);
memcpy(KERNEL_ADDR, base+hdr_off+header->kernel_offset, header->kernel_size);
```
- `bspi_boot()` = `do_raw_boot(BSPI_CS1 /*0xF8000000*/, HEADER_OFFSET)` — kernel+DTB đóng gói trong QSPI **CS1** sau 1 header magic `0xbaadc0de`.
- `mmc_raw_boot()` = `do_raw_boot(0x1000, 0)` (từ eMMC).
- `mmc_fs()` = `ext2load` kernel `Image` + `armada-quartz-eseval.dtb` từ mmc 0:1.
- `U_BOOT_CMD(quartz, ...)`: `bspi_boot` / `mmc_raw_boot` / `mmc_fs` / `limit_mem` (thêm `mem=256M` cho test DDR).

## 3. `THRG_*BspThrRegion` — hộp thư flash chung R4 ↔ U-Boot ↔ Linux

**FACT.** U-Boot có API `THRG_getBspThrRegion(offset, buf, len)` / `THRG_setBspThrRegion(...)` đọc/ghi **BSP Threshold Region** — chính là vùng flash dự phòng 2 bản mà LPPP ghi qua `flash_modify_sub` (T7.4: `FLASH_BspThrRegion1/2_TOP`, `OFS_PDFLAG_UBOOT`, `OFS_CA72WDT_*`). Vùng redundant `0xF4377000`/`0xF4378000` (context earlier notes) — cờ power-flicker `0x10` ở offset `+0x07`.

U-Boot `common/main.c` đọc:
| offset | dùng để |
|--------|---------|
| `THRD_SPI_OFFSET_RESTART_FLG` | cờ restart (LPPP set khi power flicker / CA72 wdt) |
| `THRD_SPI_OFFSET_EXEC_HW_CHECK_MODE` | chế độ kiểm HW |
| `DEF_OFFSET_SUPERWARP_*` | SuperWarp (warm-boot nhanh KM) decision/state |
| `DEF_OFS_UBOOT_SSDVENDOR_TABLE` | bảng vendor SSD (nvme.c) |

⇒ **3 stage (R4-LPPP, U-Boot, Linux) trao đổi cờ khởi động/lỗi qua vùng flash này** thay vì IPC — vì lúc U-Boot chạy, R4 có thể đang bận net-proxy và Linux chưa lên.

## Tóm tắt (theo format skill)

**"BootROM" trong repo = U-Boot (BL33)**, không phải mask ROM. Mask ROM silicon (không có source) chỉ đọc QSPI CS0 và nạp firmware R4. Thứ tự cold boot trên quartz là **R4-first**: mask ROM → R4/LPPP (`mvri.bin`) → LPPP tự `init_ddr` (nạp BLE cho A72 train LPDDR4) rồi `copy_run_atf` (kích A72 chạy ATF) → BL1/BL2/BL31 → **U-Boot** → Linux. U-Boot board file `quartz.c` phát hiện board (I²C EEPROM 0x50 → TOC; GPIO FW_CONFIG[5] → ESEVAL/EMU800 — khác cách R4 phát hiện), set `dtb_name`, và `do_raw_boot`/`bspi_boot` copy kernel+DTB (đóng gói QSPI CS1 sau header magic `0xbaadc0de`) vào RAM rồi `booti`. R4-LPPP, U-Boot và Linux trao đổi cờ khởi động/lỗi (restart flag, CA72-wdt, SuperWarp, power-flicker `0x10`) qua **vùng flash BSP Threshold Region 2 bản dự phòng** (`THRG_*BspThrRegion` ↔ LPPP `flash_modify_sub`), không qua IPC.
