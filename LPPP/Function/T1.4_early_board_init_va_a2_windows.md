## 3 · `turn_on_qspi()` — chuyển QSPI sang quad-read + bật WDT (`board.c:215-232`)

```c
static void turn_on_qspi(uint bscom_regval, uint bscr_regval) {
    fix_qspi(bscom_regval, bscr_regval);      // ★ asm từ T1.3: chép code sang RAM, chạy từ RAM
    cpu_icache_invalidate_all();
    getLogOutput();                           // "この関数を本丸からQSPIのモード可能" — QSPI đọc mode được từ đây
    HalApiWatchdog_Enable(0, 50000, 0);       // ★ WDT PHẦN CỨNG BẬT — timeout 50 s
                                              //   OP_BTS-28411: "コールドブートで起動しない" →
                                              //   dời thời điểm start WDT về sớm hơn
    getFunctionVersion();                     // OP_BTS-30209: đọc IT6 function version (CA72 WD EXT)
}
```

**Đây là nơi WDT phần cứng của R4 thật sự bật** (50s), **trước** khi scheduler chạy.
Trước đó (`hal_init_gnu.asm`) không có WDT. Nếu `init_thread` treo giữa chừng (ví dụ `pidi_init`
fail và `break` mà không xử lý) → 50s sau WDT reset máy. Đây là lưới an toàn cho toàn bộ pha 2.

`turn_on_qspi_early()` (`board.c:234`) = bản gọn (chỉ `fix_qspi` + inval I-cache), không bật WDT.

## 4 · `set_chip_select()` (`board.c:242-249`)

```c
#define BSPI_CFG_REG          0xe8273000
#define NCS_MUX_SEL_MASK      (0x3 << 16)
#define NCS_MUX_SEL_CS0_CS1   (0x2 << 16)
static void set_chip_select() {
    *reg = (*reg & ~NCS_MUX_SEL_MASK) | NCS_MUX_SEL_CS0_CS1;   // bits[17:16] = 0b10
}
```
"Set the qspi block to see **CS0 at 0xf400_0000 and CS1 at 0xf800_0000**".

⚠ Gọi **2 lần** trong `board_init_emu800` (`board.c:504`, `:511`) với cùng comment:
_"This should be unnecessary after emu800 calls turn_on_qspi() with an appropriate value in
bscr_regval!"_ → workaround tạm chưa dọn. **R4 XIP từ CS1** → chọn nhầm CS = mất đường fetch lệnh
= treo ngay. Nên viết dư cho chắc.

## 6 · `setup_a2_primary_windows()` (`a2_bus.c:15-48`) — **làm DDR hiện ra ở địa chỉ 0**

**A2 bus** = bộ giải mã địa chỉ nội bộ của AP806. R4 truy cập bảng cấu hình của nó qua
`AP806_WIN_CONFIG_BASE = 0xCE004000` (alias tới `0xF06F0010` phía AP806).

```c
volatile uint32_t *a2_global_default = (uint32_t*)0xCE0040D0;
a2_win_config_t   *a2_win_configs    = (a2_win_config_t*)AP806_WIN_CONFIG_BASE;

// Lúc boot AP806: window 0 = config space; global default target = IO; IO miss → PIDI
*a2_global_default = 0x0300;                 // ★ đổi global default target → DDR

a2_win_configs[1] = { .low=0xC000, .high=0xFFF0, .config=0x0001 };   // 0xC0000000–0xFFFFFFFF → IO (PIDI)
a2_win_configs[2] = { .low=0x80000,.high=0xFFFF0,.config=0x0001 };   // 0x08_00000000–0x0F_FFFFFFFF → IO (MoChi)
a2_win_configs[3] = { .low=0xCCF0, .high=0xCCF0, .config=0x4001 };   // 0xCCF00000–0xCCFFFFFF → SRAM
```

**Hệ quả:** từ R4, mọi địa chỉ **không** rơi vào window nào ở trên → target mặc định = **DDR**.
Đó là lý do `DDR_START = 0x00000` (trong `ap806.c`) — R4 đọc/ghi RAM của AP806 bắt đầu từ `0x0`.
Window 1 giữ dải `0xC0000000+` là IO (thanh ghi), window 2 giữ dải 64-bit `0x8_00000000+` là MoChi.

`setup_a2_primary_windows_enable(id, enable)` (`a2_bus.c:50`) — bật/tắt riêng 1 window theo `id`
(bit `config >> 8`). `ap806.c:163` gọi `setup_a2_primary_windows_enable(0x40, false)` — tắt tạm
1 window quanh lúc reset AP806.

## 7 · `setup_a2_io_windows()` (`a2_bus.c:86-127`) — 6 cửa sổ cho 3 MoChi

```
IO windows (a2_io_win_configs @ AP806_IO_WIN_CONFIG_BASE = 0xCE6F0010):
 idx  vùng địa chỉ                         target
  0   MCIx4 DATA    0x8_00000000 (+0x1FFF0)   IO_TARGET_MCIx4  (=0)
  1   MCIx2_0 DATA  0xA_00000000 (+0x1FFF0)   IO_TARGET_MCIx2_0(=1)
  2   MCIx2_1 DATA  0xC_00000000 (+0x3FFF0)   IO_TARGET_MCIx2_1(=2)   (chừa chỗ cho downlink)
  3   MCIx4 CTRL    0xCC000000               IO_TARGET_MCIx4
  4   MCIx2_0 CTRL  0xCC100000               IO_TARGET_MCIx2_0
  5   MCIx2_1 CTRL  0xCC200000 (+0x100000)   IO_TARGET_MCIx2_1

+ ghi CONTROLLER_CONFIG_ADDR (>> 8):
  AP806_MOCHIx4_CONTROLLER_CONFIG_ADDR   ← NB_MOCHIx4_CONTROLLER_ADDR >> 8   (0xCC000000)
  AP806_MOCHIx2_0_CONTROLLER_CONFIG_ADDR ← 0xCC100000 >> 8
  AP806_MOCHIx2_1_CONTROLLER_CONFIG_ADDR ← 0xCC200000 >> 8
```

Đây là những cửa sổ mà **DMA / master** phải đi qua để với tới RAM/thanh ghi bên kia MoChi
(x4 = Quartz↔AP806, x2 = ↔Iris). Nối thẳng với địa chỉ 64-bit trong `regAddrs.h` (`T0.3 §5`).
IO_TARGET: `0`=MCIx4, `1`=MCIx2_0, `2`=MCIx2_1, `3`=PIDI, `4`=SPI, `5`=STM, `6`=BOOTROM.

## 8 · `pidi_init()` (`power.c:1199-1256`) — dựng liên kết die-to-die Quartz↔AP806

**PIDI** = giao diện PHY die-to-die (Package-Integrated Die Interconnect). Đây là "sợi dây" vật lý
giữa Quartz và AP806; A2 window + MoChi chạy **bên trên** nó.

```c
int pidi_init(void) {
    mrvl_regwrite32(PADWRAP_AON_PIDIPWR, 0);          // un-tristate chân PIDI (0xE8308460)

    flash_read(qspibuf, QSPI_CHIP_VERSION_ADDR, 8);   // đọc DDR param từ flash
    qspi_rev_speed = qspibuf[7];
    ddr_sar = (qspi_rev_speed == 0x01) ? DDR_2400MHZ : DDR_2100MHZ;

    // dựng SAR (System Address Register) cho PIDI
    if (get_quartz_rev() == QUARTZ_REV_A0) {          // A0 chạy NỬA tốc độ
        pidi_sar_val = (0<<0)|(ddr_sar<<3)|(1<<8)|(1<<12);   // [12]=1 → 500 MHz divider
        pidi_flags   = PMU_PIDI_PHY_LINK_500MHZ | PHY_INIT | PHY_DONE;
    } else {
        pidi_sar_val = (0<<0)|(ddr_sar<<3)|(1<<8)|(0<<12);   // [12]=0 → 1000 MHz
        pidi_flags   = PMU_PIDI_PHY_LINK_1000MHZ | PHY_INIT | PHY_DONE;
    }
    // SAR field: [2:0] boot source (0=PIDI/IHBx2), [7:3] clock freq, [8] refclk sel, [12] divider

    mrvl_regwrite32(PI_PIDI_DIE2DIE_SAR0, pidi_sar_val);      // 0xC057B014

    while ((PMU_MISC_REGS->AP_SYSRST & 0x2) == 0);            // chờ confirm — "THIS MIGHT fix
                                                             //   pidi_init_failures?" (không timeout!)
    ... đo thời gian chờ, cập nhật ap806_init_reset_max ...

    pmu_set_device(pmu_PIDI, pmu_D0, pidi_flags);             // cấp nguồn + init PHY

    if (!PIDI_PHYStatus.PIDI_LINK_OK) {
        ++pidi_init_failures;
        "********** PIDI down! ..."
        return -1;                                            // → pmu_ap_link_up phase: fail=-1, break
    }
    return 0;
}
```

⚠ Vòng `while (AP_SYSRST & 0x2 == 0)` **không timeout** — nếu AP806 không confirm reset thì R4 spin
ở đây. Chỉ WDT 50s (bật ở `turn_on_qspi`) cứu được. Comment "THIS MIGHT fix pidi_init_failures?"
cho thấy `pidi_init` **từng fail thật ngoài hiện trường** (`pidi_init_failures` là bộ đếm toàn cục).

## 9 · Pha `pmu_ap_link_up` — bối cảnh gọi (`power.c:1936-1958`)

```c
case pmu_ap_link_up:
    ap806_power_on_prep();
    ap806_power_on(true);              // bật NGUỒN AP806 (I2C → PS-CPU) — xem power.c chi tiết (T4.2)
    ap806_mcix4_enable(true);
    if (pidi_init()) { fail = -1; break; }     // ★ §8
    setup_a2_primary_windows();        // ★ §6 — DDR hiện ra ở 0x0
    setup_a2_io_windows();             // ★ §7 — 6 cửa sổ MoChi
    ap806_update_voltage();
    icu_init(ICU_BASE);               // 0xe8310000 — Interrupt Consolidation Unit
    pmu_init_ap806_gpios();
    if (mci_init_mcix4()) { fail = -2; break; }
    ...
```

**Phát hiện (giải T0.2 UNKNOWN):** pha `pmu_baseline` trước đó có
`pmu_set_device(pmu_PMU_M4, pmu_D2, 0)` với comment **_"PMU m4 is currently unused, keep off.."_**
(`power.c:1935`). ⇒ Cortex-M4 PMU **là lõi thật nhưng bị giữ TẮT**. `libpmu_r4.a` chạy trên **R4**,
không phải M4. `pmu_phase()` = code R4 ghi thẳng thanh ghi PMU hardware.

Pha `pmu_baseline` cũng: đặt divider an toàn cho `pmu_pibusclk`/`pmu_qspi_clk`, khoá `SYS_PLL`
(`SSPLL_SYS_DEFAULT`), `hwSetProcSpeed(SYS_BUS_CLOCK)` (200 MHz), khoá `MC_PLL`/`ND_PLL`,
`pmu_set_device(pmu_PI, D0)`. QSPI clock divider: rev ≥ A1 và GPIO I[31]==0 → `div = 8`
(1600/8 = 200 MHz); ESEVAL-A1 → giữ nguyên.

## 10 · Vai trò tham số `resume`

| Hàm | `resume == false` (cold) | `resume == true` (thức từ Sleep2/ErP) |
|---|---|---|
| `early_board_init_*` | chạy full (turn_on_qspi + bind MCiClk) | **KHÔNG LÀM GÌ** — cả thân bọc `if (resume == false)` |
| `board_init(false)` từ `init_thread` | luôn `false` (cold) | — |
| `pmu_phase(pmu_ap_link_up)` | chạy full | chạy (`pmu_resume` phase gọi lại, có guard nội bộ — xem T4.1) |
| `board_init_emu800(true)` (từ `pmu_resume`) | — | bỏ dò phần cứng, bỏ Iris SB0/NB0, bỏ DDR training + copy ATF; ⚠ NB1 vẫn init lại (xem `board_init_emu800.md`) |

Cơ chế làm resume nhanh: QSPI đã ở quad mode (không `fix_qspi` lại), phần cứng Iris đã dò
(`static` cache), DDR chỉ thoát self-refresh, ATF vẫn nằm trong RAM.

## 11 · Tóm tắt (theo format skill)

**1. Tồn tại để làm gì:** `early_board_init` (trong `main`) chỉ chuyển QSPI sang quad-read
(`turn_on_qspi` → `fix_qspi` chạy từ RAM) và bật WDT phần cứng 50s, rồi bind clock MCix cho Iris.
Việc nặng ở pha `pmu_ap_link_up` trong `init_thread`: bật nguồn AP806, `pidi_init()` dựng liên
kết die-to-die, `setup_a2_primary_windows()` khiến DDR của AP806 hiện ra ở địa chỉ `0x0` từ R4,
`setup_a2_io_windows()` mở 6 cửa sổ MoChi, `mci_init_mcix4()`. Bo được nhận diện bằng GPIO BANK I
pin 31 (0 = EMU800 sản xuất).
