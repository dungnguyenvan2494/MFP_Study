## 1 · `ap806_power_on(bool on)` (`power.c:316-398`)

`static bool isStartup = true;` — lần gọi đầu = cold boot.

### 1.1 · Đường ON

```
① i2c_enable(true)                                    gpio_set_func_sel(pad 0..3, 1) — mux → I2C0
                                                       comment: "I2Cの初期化処理を早く実行する"
② [chỉ resume (!isStartup) VÀ supportTEC()==RESULT_EAGLE3]:
     [nếu isAutomaticMeasurementToolOn()]  LPPP_i2c_write(0, 0x3E, 0xC0, ResumeRequest=88)   ← log
     send_sleep_status_rem(1)              LPPP_i2c_write(0, 0x3E, 0x6C, 0x0002)             ← REM=1
     cpu_spin_delay(100 ms)               ← "100ms後、AP_PWR_EN=1"  ★ THỨ TỰ BẮT BUỘC
③ [board == EMU800]:  pmu_gpio_handle(...)
     GPIO_BANKG[25] = 1    DDR_Config
     GPIO_BANKC[1]  = 1    AP_PWR_EN  (customer ES eval dùng IO_PAD[65] = GPIOC_1)
     GPIO_BANKI[28] = 1    AP_1P1_EN
④ [isStartup] j = 1 ; isStartup = false ; "skip GPIO No.0"   ← OP_BTS-13438 "画面のまま起動しない"
   [else]      j = 0
⑤ for (i = j; i < 5; i++)  pmu_gpio_handle(gpio_nums[i], OUTPUT, ACTIVE_HIGH, 1)
     gpio_nums[] = { G[3] SD_PWR_EN, C[1] AP_PWR_EN, I[26], I[27], I[29] }
     (AR.1043460 DeepSleep復帰; 2019/03/05 EagleBK/Z+/ZBK+ コンパイルSW)
⑥ send_power_state_to_pscpu(on)           LPPP_i2c_write(0, 0x3E, 0x68, val)   ← §2
⑦ ap_pg = ap806_power_good(500)           poll GPIO_BANKH[19] (AP_PG) ≤ 500×1ms  (§3)
     ap_pg < 0 → "AP_PG gpio error" ; !ap_pg → "AP_PG no good"  (chỉ log, KHÔNG treo)
     (AR.1043716 省電力復帰短縮: bỏ regulator delay 250ms, poll AP_PG thay)
```

### 1.2 · Đường OFF

```
① send_power_state_to_pscpu(off)          LPPP_i2c_write(0, 0x3E, 0x68, 0x01 | gen)   ← Sleep2/ErP
② for (i = 0; i < 5; i++)  pmu_gpio_handle(gpio_nums[i], OUTPUT, ACTIVE_HIGH, 0)      ← hạ hết (kể cả SD_PWR_EN)
③ [supportTEC()==RESULT_EAGLE3]:
     cpu_spin_delay(100 ms)               ← "AP_PWR_EN=0 の後、100ms待つ"  ★ THỨ TỰ BẮT BUỘC
     send_sleep_status_rem(0)             LPPP_i2c_write(0, 0x3E, 0x6C, 0x0001)        ← REM=0
④ i2c_enable(false)                        gpio_set_func_sel(pad 0..3, 0) — pad về GPIO thuần
                                           (chống rò dòng qua pull-up khi ngủ sâu)
```

### 1.3 · Thứ tự bắt buộc trên máy **Eagle3** (2023/01/30 "Eagle3 PS-CPU本流対応")

| | ON | OFF |
|---|---|---|
| 1 | `SLEEP_STATUS_REM = 1` (I2C `0x6C ← 2`) | `power_state = Sleep2/ErP` (I2C `0x68 ← 1`) |
| 2 | **chờ 100ms** | `AP_PWR_EN = 0` |
| 3 | `AP_PWR_EN = 1` | **chờ 100ms** |
| 4 | `power_state` (I2C `0x68`) | `SLEEP_STATUS_REM = 0` (I2C `0x6C ← 1`) |

**Vì sao:** nếu `SLEEP_STATUS_REM` không tới PS-CPU **trước** khi `AP_PWR_EN` lên, PS-CPU hiểu
nhầm là **mất điện đột ngột (瞬断)** chứ không phải ngủ có kế hoạch → xử lý ride-through sai.
Máy không-Eagle3 bỏ qua bước REM.

## 2 · `send_power_state_to_pscpu(bool on)` (`LPPP_I2C.c:1020-1055`)

```c
static bool boot_once = false;
uint32_t gen = (supportTEC() == RESULT_EAGLE3) ? 0x04 : 0;   // "gen" = generation marker Eagle3

if (on) {
    if (!boot_once) { LPPP_i2c_write(0, 0x3E, 0x68, 0x00000002 | gen); boot_once = true; }  // Boot
    else            { LPPP_i2c_write(0, 0x3E, 0x68, 0x00000000 | gen); }                    // Normal
} else            { LPPP_i2c_write(0, 0x3E, 0x68, 0x00000001 | gen); }                      // Sleep2/ErP
```

| Giá trị `0x68` | Ý nghĩa |
|---|---|
| `0x00` (`\| gen`) | Normal (mọi lần bật sau lần đầu) |
| `0x01` (`\| gen`) | Sleep2 hoặc ErP |
| `0x02` (`\| gen`) | **Boot** (lần bật đầu tiên — AR.1070585 "初回時は電源状態(Boot)を通知") |
| bit `\|0x04` | máy Eagle3 / Sparrow3 / Eagle3MLK |

PS-CPU dùng giá trị này để biết SoC đang ở pha nào (log timeline khởi động + logic ride-through).

## 3 · `send_sleep_status_rem(int32_t sw)` (`LPPP_I2C.c:1069-1085`)

```c
uint32_t param = (sw == 0) ? 0x0001 /* REM=0 */ : 0x0002 /* REM=1 */;
LPPP_i2c_write(0, 0x3E, 0x6C, param);
```
⚠ Header comment của hàm gõ nhầm tên là `send_power_state_to_pscpu` (copy-paste); tên thật là
`send_sleep_status_rem`. **Chỉ Eagle3.** `SLEEP_STATUS_REM` = tín hiệu để PS-CPU phân biệt
"ngủ có kế hoạch" (`REM=1` trước khi tắt AP) với "mất điện" (`SuperWarp`/`瞬断`).

## 3.1 · `ap806_power_good(uint32_t timeout_ms)` (`power.c:290-313`)
```c
gpio_open(GPIO_BANKH, 19, INPUT, ACTIVE_HIGH);       // AP_PG (Power Good)
for (i = 0; i < timeout; i++) {
    gpio_read(&level); if (level) break;
    cpu_spin_delay(1 * MILLISEC);
}
return level;   // hoặc -1 nếu gpio_open fail
```
Poll AP_PG mỗi 1ms, tối đa `timeout` lần (500 khi bật AP806). Timeout → trả `level=0`, log "no good",
**không treo, không fail luồng** — chỉ cảnh báo.

## 3.2 · `ap806_power_on_prep()` (`power.c:400-413`)
```c
if (board == ESEVAL || board == EMU800) {
    gpio_open(&iris_reset, GPIO_BANKC, 10, OUTPUT, ACTIVE_HIGH, 0);   // GPIOC[10] = IRIS nRESET, ép LOW
    gpio_close(iris_reset);
}
```
Ép/giữ `IRIS nRESET` (GPIOC[10]) trước khi bật nguồn AP806. Iris nRESET được **nhả** trong
`mci_init`/`iris_init` (T1.4 §3). OP_BTS_11668 "IRIS nRESET初期化をKM側でも有効にする".

## 4 · `ap806_mcix4_enable(bool enable)` (`power.c:956-1055`)

MCIx4 = liên kết die-to-die **Quartz ↔ AP806** (băng thông cao nhất). Truy cập thanh ghi cấu
hình MCIx4 qua cặp `PI_MCIX4_CFG_REG_ACCESS_DATA` (`0xC057D000`) / `_CMD` (`+4`).

### ON — dựng remap địa chỉ hai chiều
```
pmu_set_device(pmu_MCiClk0_x4, D0) ; pmu_set_device(pmu_MCix4, D0)

── Outgoing (Quartz → AP): địa chỉ 0x2x_xxxxxxxx từ Quartz  →  0x0x_xxxxxxxx phía AP ──
   OG_RMAP0_CMP   = 0x00200000       (cmd 0x00140020)
   OG_RMAP0_MASK  = 0x0003ffff       (cmd 0x00120020)
   OG_RMAP0_ADDR  = 0x00000000       (cmd 0x00160020)

── Incoming (AP → Quartz): địa chỉ 0x8_xxxxxxxx từ AP  →  0x0_xxxxxxxx phía Quartz ──
   IC_RMAP0_CMP   = 0x00080000       (cmd 0x00640020)
   IC_RMAP0_MASK  = 0x0001ffff       (cmd 0x00620020)
   IC_RMAP0_ADDR  = 0x00000000       (cmd 0x00660020)

── nếu mcix4_lanes / mcix4_gbit: cấu hình PHY ──
   PHY_REG_IF_MODE bit 25 = 1
   lanes: 1→0, 2→1, 4→2   (pwm_ctrl_reg0 phy 4, bits 19+16)
   gbit:  1→0, 2→1, 4→2, 8→3   (pwm_ctrl_reg2 phy 6, bits 10+0)
```

### OFF
```
pmu_set_device(pmu_MCix4_PHY, D2, PMU_MCI_PHY_SKIP_WAIT)   // D2, không chờ settle
```

**Nối với T0.3/T1.4:** đây là lớp remap **dưới** a2_bus windows. a2_bus global default → DDR (địa
chỉ `0x0` nhìn từ R4); MCIx4 remap chuyển `0x2x...`/`0x8...` qua liên kết vật lý. MoChi 64-bit
DATA window (`0x800000000ULL`) đi qua đúng cơ chế này.

## 5 · `ap806_update_voltage()` (`power.c:1812-1844`) — AVS cho A72

```c
int millivolts = 990;                                  // mặc định
uint32_t r = *(volatile uint32_t*)0xce6f9000;          // AVS fuse register của AP806
fuse_avs_enable = r & 0x7;
fuse_avs_lo = (r >> 4)  & 0xFF;
fuse_avs_hi = (r >> 12) & 0xFF;
if (fuse_avs_enable == 0x5 && lo != 0 && hi != 0 && lo == hi)
    millivolts = fuse_avs_lo * 10 + 640;               // AVS từ efuse (mỗi lô chip khác nhau)
ap806_millivolts_set(millivolts);
```
- Đọc efuse tại `0xCE6F9000`, kiểm hợp lệ (`enable == 5`, `lo == hi != 0`), tính điện áp lõi A72
  = `lo × 10 + 640` mV. Không tin cậy → **990 mV mặc định**.
- Khác `avs_set_from_efuse(1097)` cho R4/Quartz trong `main()` (→ T4.4).
- Có prompt debug tuỳ chọn (`AP806_VOLT_PROMPT_DURATION_MS`).

`power_set_clock_div()` (`power.c:1846-1880`): duyệt `power_up_clk[]`; với mỗi clock (`clk != 255`)
`pmu_get_clock` rồi `pmu_set_clock` **chỉ khi khác** (gate/div/src != 0 và != giá trị hiện tại —
"0 = NO CHANGE"). Rev A0: `pidi_c2c_clk.div = ND_PLL/300 = 8`.

## 6 · Nối vào pha `pmu_ap_link_up` (T4.1 §2)

```
pmu_phase(pmu_ap_link_up):
   ap806_power_on_prep()       §3.2  — ép IRIS nRESET
   ap806_power_on(true)        §1.1  — I2C→PS-CPU (REM=1 → 100ms → AP_PWR_EN=1 → 0x68 → poll AP_PG)
   ap806_mcix4_enable(true)    §4    — remap Quartz↔AP806
   pidi_init()                 T1.4 §8
   setup_a2_primary/io_windows() T1.4 §6-7
   ap806_update_voltage()      §5    — AVS A72
   icu_init(ICU_BASE)          Iris ICU (→ phần Iris)
   pmu_init_ap806_gpios()
   mci_init_mcix4()            huấn luyện liên kết MCIx4 (→ phần Iris/MCI)
```

Chiều ngược (`pmu_ap_link_down`, T4.1 §2): `ap806_mcix4_enable(false)` → PIDI D2 → tri-state PIDI
→ `ap806_power_on(false)` (I2C `0x68 ← Sleep2/ErP` → hạ GPIO → REM=0 → `i2c_enable(false)`).

## 7 · Tóm tắt (theo format skill)

**1. Tồn tại để làm gì:** `ap806_power_on(on)` là hàm bật/tắt **nguồn cụm A72** — điều phối
`i2c_enable` (mux pad), GPIO nguồn (`gpio_nums[]`: SD_PWR_EN, AP_PWR_EN, AP_1P1_EN…), 3 giao dịch
I2C tới PS-CPU (`0x68` power-state, `0x6C` SLEEP_STATUS_REM, `0xC0` event-log), và poll `AP_PG`
(GPIO_BANK_H[19]). Trên Eagle3, thứ tự **REM → 100ms → AP_PWR_EN** (ON) và ngược lại (OFF) là bắt
buộc để PS-CPU không nhầm ngủ với mất điện. `ap806_mcix4_enable` dựng remap địa chỉ die-to-die
(Quartz `0x2x`→AP `0x0x`; AP `0x8`→Quartz `0x0`). `ap806_update_voltage` đặt điện áp lõi A72 theo
efuse AVS (`lo×10+640` mV, mặc định 990).

**2. Call flow:**
```
pmu_phase(pmu_ap_link_up)
├─ ap806_power_on_prep()          [IRIS nRESET = GPIOC[10] LOW]
├─ ap806_power_on(true) [power.c:316]
│    ├─ i2c_enable(true)                 gpio_set_func_sel(pad0-3, 1)
│    ├─ [Eagle3, resume] send_sleep_status_rem(1)  → I2C 0x3E:0x6C ← 2 ; delay 100ms
│    ├─ [EMU800] pmu_gpio_handle G[25]/C[1]/I[28] = 1
│    ├─ for gpio_nums[j..4] pmu_gpio_handle(... = 1)   [j=1 cold boot skip SD_PWR_EN]
│    ├─ send_power_state_to_pscpu(true) → I2C 0x3E:0x68 ← (Boot 2 | Normal 0)|gen
│    └─ ap806_power_good(500)            poll GPIO_H[19] AP_PG
├─ ap806_mcix4_enable(true)      [OG/IC RMAP0 qua PI_MCIX4_CFG @ 0xC057D000]
├─ pidi_init() / setup_a2_*windows()
├─ ap806_update_voltage()        [efuse 0xCE6F9000 → ap806_millivolts_set]
├─ icu_init(ICU_BASE) / pmu_init_ap806_gpios() / mci_init_mcix4()
```

**3. File đã tham chiếu:**
- `Hal/quartz/asic/build/power.c:260-313 (gpio_nums, ap806_power_good), 316-413 (power_on, prep), 956-1055 (mcix4_enable), 1812-1880 (update_voltage, clock_div)`
- `ApplicationKM/LPPP_I2C.c:1020-1105 (send_power_state_to_pscpu, send_sleep_status_rem, i2c_enable)`

**4. Đã xác nhận / phát hiện:**
- ✅ `send_power_state_to_pscpu` → I2C `0x3E:0x68`: `0`=Normal, `1`=Sleep2/ErP, `2`=Boot (lần đầu), `|0x04`=Eagle3.
- ✅ `send_sleep_status_rem` → I2C `0x3E:0x6C`: `0x0001`=REM 0, `0x0002`=REM 1 (Eagle3-only). Header comment gõ sai tên hàm.
- ✅ Thứ tự Eagle3 ON: `REM=1 → 100ms → AP_PWR_EN=1 → 0x68`. OFF: `0x68 → AP_PWR_EN=0 → 100ms → REM=0`.
- ✅ `gpio_nums[]` = `{G[3] SD_PWR_EN, C[1] AP_PWR_EN, I[26], I[27], I[29]}`; cold boot **skip** SD_PWR_EN (OP_BTS-13438).
- ✅ `ap806_power_good` poll GPIO_BANK_H[19] (AP_PG), 500×1ms, timeout chỉ log không treo (AR.1043716 thay regulator delay 250ms).
- ✅ `ap806_mcix4_enable` remap: Quartz `0x2x_xxxxxxxx`→AP `0x0x`; AP `0x8_xxxxxxxx`→Quartz `0x0` (qua `PI_MCIX4_CFG_REG_ACCESS`).
- ✅ `ap806_update_voltage`: efuse `0xCE6F9000` (`enable&7==5`, `lo==hi`), `mV = lo*10 + 640`, default 990. Khác AVS của R4 (T4.4).
- ✅ `ap806_power_on_prep` ép `IRIS nRESET` = GPIOC[10] (OP_BTS_11668).
- ✅ `i2c_enable` = mux pad 0-3 sang I2C0 (bật) / GPIO (tắt — chống rò dòng khi ngủ).
