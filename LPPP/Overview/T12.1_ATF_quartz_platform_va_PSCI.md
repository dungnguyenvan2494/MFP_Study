## 1. ATF = Trusted Firmware-A, port Armada-8K → "quartz"

`atf_s800` = TF-A với `PLAT=quartz`, kế thừa `plat/marvell/a8k` (Armada 8K / AP806). Chạy trên **A72 (AP806)**, không phải R4.

### Build (`build_atf.sh`)
```bash
export CROSS_COMPILE=s800-linux-              # toolchain Linux (khác s800-r4- của LPPP)
export BL33=../uboot_s800/output/u-boot.bin   # non-secure bootloader
make DEBUG=1 USE_COHERENT_MEM=0 LOG_LEVEL=30 PLAT=quartz all fip
→ build/quartz/debug/flash-image.bin
```
- `CALL_DOIMAGE := y` — hậu xử lý bằng `doimage` → `flash-image.bin` (định dạng nạp QSPI của Armada).
- `ENABLE_PLAT_COMPAT := 0` — dùng PSCI API mới (không lớp tương thích cũ).
- `DEBUG=1`, `LOG_LEVEL=30` (VERBOSE).

## 2. Các BL stage

| stage | chạy trên | vai trò |
|-------|-----------|---------|
| **BootROM** | A72 | mask ROM trong SoC; nạp & nhảy BLE |
| **BLE** (BootROM Loadable Extension) | A72 (từ **AP806 SRAM / L3-SRAM**) | **train LPDDR4** (`ble/mv_lpddr4_apn806.c` 13.7K dòng, `lpddr4_config()`), sync với R4 qua `mv_sync.c` |
| **BL1** | A72 | trusted boot, đọc FIP (`io_fip.c`) |
| **BL2** | A72 | nạp BL31/BL32/BL33 từ FIP vào DRAM |
| **BL31** | A72 EL3 | **runtime EL3**: PSCI, SMC handler, GICv2, MHU/SCPI client. Nguồn quartz: `plat_bl31_setup.c`, `plat_pm.c`, `mhu.c`, `scpi.c` |
| **BL32** | A72 S-EL1 | secure payload (tuỳ chọn) |
| **BL33** | A72 EL2/EL1 NS | **U-Boot** → Linux |

### 2.1 BLE ⟷ LPPP (T8.1)
**FACT.** `ble/` chứa `mv_lpddr4_apn806.c`, `mv_sync.c`, `mv_xor_v2.c`, `KM_LPDDR4_config.h`/`KM_LPDDR4_prot.h` — **chính là "BLE image" mà R4 nạp** trong `init_lpddr4_from_ap806_sram()` (T8.1): R4 copy BLE từ QSPI vào L3-SRAM `0xCCF00000`, set `AP806_CCU_B_RVBAR_0`, thả A72 chạy BLE để train DDR, chờ `BOOT_SYNC_DDR_READY` (kênh `0xE82460B0`). `ble_main(bootrom_flags)` → `lpddr4_config()`.
- `a8k_common.mk`: `BLE_PORTING_SOURCES = plat/marvell/a8k/quartz/board/dram_port.c` — tham số DDR board-specific.
- `mv_sync.c` / `mv_xor_v2.c` trong `ble/` là **bản sinh đôi** của `lppp_s800/Hal/quartz/asic/build/mv_sync.c`/`mv_xor_v2.c` (T8.1) — cùng giao thức boot-sync + XOR engine, R4 và BLE chia sẻ.

## 3. PSCI (`plat_pm.c` — `plat_arm_psci_pm_ops`)

| PSCI op | handler | hành vi |
|---------|---------|---------|
| `pwr_domain_on` | `a8k_pwr_domain_on(mpidr)` | `scpi_set_css_power_state(mpidr, on, on, on)` → **nhờ R4 cấp nguồn core**; rồi `plat_marvell_cpu_on`: `MVEBU_PRIVATE_UID_REG = cluster+4`, `MVEBU_CCU_RVBAR(cluster,cpu) = _armada8k_cpu_entry>>16` (→ `bl31_warm_entrypoint`). **PRCR write (thả reset thật) BỊ COMMENT** — "get the cpu out of reset done by the R4" |
| `pwr_domain_off` | `a8k_pwr_domain_prepare` (**rỗng**) | chuẩn bị (no-op) |
| `pwr_domain_pwr_down_wfi` | `a8k_pwr_domain_off` (`__dead2`) | encode `cluster_state`/`system_state` từ `target_state` → `scpi_set_css_power_state(mpidr, off, cluster_state, system_state)`. Comment (T2.4): "SCP không trả lời lệnh này" |
| `pwr_domain_suspend` | `a8k_pwr_domain_suspend` → `a8k_pwr_domain_off` | suspend = off (chưa tách riêng) |
| `pwr_domain_on_finish` | `a8k_pwr_domain_on_finish` | `gicv2_pcpu_distif_init()` + `gicv2_cpuif_enable()` |
| `pwr_domain_suspend_finish` | `a8k_pwr_domain_suspend_finish` | VERBOSE "needs to be implemented"; `panic()` comment → **gần như trống** |
| `system_off` | `a8k_system_off` (`__dead2`) | VERBOSE + `wfi()` + `panic()` — **chưa implement** |
| `system_reset` | `a8k_system_reset` → `plat_marvell_system_reset()` | xem §4 |
| `cpu_standby` | `a8k_cpu_standby` | WFI |
| `validate_power_state` / `validate_ns_entrypoint` | `a8k_validate_*` | |

### 3.1 `psci_put_in_reset(mpidr)` / `plat_marvell_cpu_on`
- `psci_put_in_reset`: `dsb sy` → `mmio_write_32(MVEBU_CCU_PRCR(cluster, cpu_id), 0)` — đưa core vào reset.
- `plat_marvell_cpu_on`: set entry point + UID; **không** thả reset (R4 làm sau SCPI).

⇒ **Chuỗi Linux bật core phụ**: `psci CPU_ON` → `a8k_pwr_domain_on` → `scpi_set_css_power_state(0x03)` qua MHU → R4 `LPPP_SCPI`/`pmu_phase` cấp nguồn + **thả reset core** → core boot từ `_armada8k_cpu_entry` → `bl31_warm_entrypoint`.

## 4. `plat_marvell_system_reset()` — customization **`CONFIG_KM_BIZHUB`**

```c
void plat_marvell_system_reset(void) {
#ifdef CONFIG_KM_BIZHUB
    NOTICE("/HRESET_REQ => LOW\n");
    mmio_write_32(MVEBU_PADWRAP_REG_BASE + 0x220C, 0x04);   // GPIOC[2] (HRESET_REQn) = LOW
    for(;;);                                                 // spin — HW kéo reset
#else
    mmio_write_32(MVEBU_RFU_BASE + MVEBU_RFU_GLOBL_SW_RST, 0x0);   // SW reset chuẩn Armada
#endif
}
```
- **`CONFIG_KM_BIZHUB` được define** cho build này (grep chỉ thấy trong `plat_pm.c`).
- Trên bizhub: reset hệ thống = ATF **kéo GPIOC[2] `HRESET_REQn` xuống LOW** qua pad-wrap register `0x220C`, rồi spin vô hạn → **PS-CPU / mạch board** phát hiện và cắt/khởi động lại nguồn. Không dùng SW reset của SoC.
- Khớp T2.4 (`plat_marvell_system_reset → GPIOC[2] HRESET_REQn LOW`) và T7.2 (`LPPP_GPIOPIN_HRESET_REQN = 66` = GPIOC[2]).

## 5. SCPI / MHU phía ATF (nhắc lại T2.4, xác nhận)

`scpi.c`:
- `PLAT_CSS_SCP_COM_SHARED_MEM_BASE` = **`0x7FFF0000`** (đầu DDR).
- `SCPI_CMD_HEADER_AP_TO_SCP_X(n) = base + (2n+1)×SCPI_CHANNEL_BUFFER_SIZE` (AP→R4);
  `SCPI_CMD_HEADER_SCP_TO_AP_X(n) = base + 2n×SCPI_CHANNEL_BUFFER_SIZE` (R4→AP).
- `this_cpu_channel() = plat_my_core_pos() + 1` — channel 0 = Linux, 1-4 = ATF per-core.
- `scpi_secure_message_{start,send,wait,receive,end}` → `mhu_secure_message_*` (`mhu.c`, MHU tại `0xE8009800`).
- `scpi_wait_ready(mpidr)` — lúc boot, ATF **chờ R4 gửi `SCP_READY`** trên channel của mình trước khi tiếp.
- `scpi_set_css_power_state(mpidr, cpu, cluster, css)` — encode `mpidr` + 3 state → gửi command `0x03`, **không chờ response** (T2.4 byte-for-byte khớp `km_scpi.h`).
- `scpi_dvfs_*` / `scpi_get_*` — có chờ response.

## 6. FACT / INFERENCE / UNKNOWN

- **FACT**: build `PLAT=quartz`, `CROSS_COMPILE=s800-linux-`, `BL33=u-boot.bin`, `DEBUG=1 LOG_LEVEL=30 USE_COHERENT_MEM=0`, output `flash-image.bin` (`doimage`); `ENABLE_PLAT_COMPAT=0`.
- **FACT**: BLE (`ble/mv_lpddr4_apn806.c` 13.7K) train LPDDR4, có `mv_sync.c`/`mv_xor_v2.c` sinh đôi với LPPP — chính là "BLE image" R4 nạp (T8.1).
- **FACT**: `plat_pm.c` PSCI ops table; `a8k_pwr_domain_on` → `scpi_set_css_power_state(on,on,on)` + set RVBAR, **PRCR write comment** (R4 thả reset); `pwr_down_wfi` = `a8k_pwr_domain_off` (`scpi ... off`); `on_finish` = GICv2 init; `suspend_finish`/`system_off` gần như chưa implement.
- **FACT**: `CONFIG_KM_BIZHUB` define → `plat_marvell_system_reset` ghi `MVEBU_PADWRAP_REG_BASE + 0x220C = 0x04` (GPIOC[2] HRESET_REQn LOW) + `for(;;)`.
- **FACT**: `cp110_init` skip cho quartz; `apn806_init` chạy; SCPI shared-mem `0x7FFF0000`, `this_cpu_channel = core_pos+1`, MHU `0xE8009800`, `scpi_wait_ready` chờ `SCP_READY`.

- **INFERENCE**: `pwr_domain_suspend` = `off` + `suspend_finish` trống ⇒ ATF **không tự làm CPU suspend đầy đủ** — dựa R4/`pmu_phase` + warmboot flag `0x7FFFFFF0` (T2.4) để khôi phục qua `bl31_warm_entrypoint`.
- **UNKNOWN**: `MVEBU_PADWRAP_REG_BASE` địa chỉ tuyệt đối; `plat_def.h` các `PLAT_*` constant (channel buffer size, shared-mem base value thật). BL32 có build/dùng không. `dram_port.c` tham số LPDDR4 S800.

## Tóm tắt (theo format skill)

**ATF `atf_s800` chạy trên A72 (AP806)**, port TF-A Armada-8K → `PLAT=quartz` cho KM bizhub. Chuỗi boot: BootROM → **BLE** (train LPDDR4, `mv_lpddr4_apn806.c` — cùng bộ code R4 nạp vào L3-SRAM ở T8.1) → BL1 (FIP) → BL2 → **BL31** (EL3 runtime: PSCI + SMC + GICv2 + client MHU/SCPI) → BL33 (U-Boot → Linux). PSCI (`plat_pm.c`): mọi thao tác nguồn core/cluster/system đều **ủy quyền cho R4 qua SCPI** — `pwr_domain_on` gửi `scpi_set_css_power_state(on)` rồi để R4 thả reset core (PRCR write bị comment); `pwr_down_wfi` gửi `scpi ... off` (R4 không trả lời); `suspend_finish`/`system_off` gần như trống (dựa R4 + warmboot flag `0x7FFFFFF0`). `CONFIG_KM_BIZHUB` đổi `plat_marvell_system_reset` thành "kéo GPIOC[2] HRESET_REQn LOW rồi spin" — để PS-CPU/board cắt nguồn, thay vì SW reset SoC. Build bằng `s800-linux-` toolchain, ra `flash-image.bin` qua `doimage`.

**Call flow (Linux psci CPU_ON core 1):**
```
Linux smc PSCI_CPU_ON → BL31 → a8k_pwr_domain_on(mpidr)
├─ scpi_set_css_power_state(mpidr, on, on, on)
│    → SCPI_CMD_HEADER_AP_TO_SCP_X(channel=core_pos+1) @ 0x7FFF0000+(2n+1)*bufsz
│    → mhu_secure_message_send(channel) @ 0xE8009800
│    → (R4: LPPP_SCPI / pmu_phase cấp nguồn cluster + THẢ RESET core)   ← không response
├─ plat_marvell_cpu_on: MVEBU_PRIVATE_UID_REG = cluster+4
│                       MVEBU_CCU_RVBAR(cluster,cpu) = _armada8k_cpu_entry >> 16
└─ core 1 boot ← _armada8k_cpu_entry → bl31_warm_entrypoint → a8k_pwr_domain_on_finish
                 (gicv2_pcpu_distif_init + gicv2_cpuif_enable)
```
