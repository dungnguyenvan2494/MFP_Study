R4 **không tự train DDR** — nó nạp ảnh **BLE** (BootROM Loadable Extension) vào L3-SRAM của AP806 rồi cho A72 chạy để train; R4 chỉ điều phối qua thanh ghi boot-sync và tự tay đưa DDR vào self-refresh/power-down khi ngủ.

## 1. Khởi tạo DDR — `init_ddr(warm_boot, callback)` (`ddr_init.c:188`)

```c
board = get_board_type();     // T1.4: EMU800 = production
switch (board):
  PALLADIUM/PROTIUM → ddr_emu_configure(plat, warm_boot)       // emulator, không phải S800
  TOC              → init_lpddr4_from_ap806_sram(&__rom_start__ + 0x100000, warm_boot, cb)
  EMU800/ESEVAL    → init_lpddr4_from_ap806_sram(BSPI_CS0_ADDR, warm_boot, cb)   ← S800
```

### `init_lpddr4_from_ap806_sram(code_header_loc, warmboot, callback)` (`ap806.c:171`)
1. `ap806_l3_sram_config()` — bật L3-SRAM của AP806 (`SRAM_START = 0xCCF00000`, qua `AP806_LLC_MNT_BALOC`) để BLE chạy được từ đó.
2. **`mc_configure_dram(warmboot)`** — ghi breadcrumb boot-sync cho A72 (xem §3).
3. `memcpy((void*)SRAM_START, &code_header->ble_image_start, code_header->ble_image_size)` — copy ảnh BLE (từ QSPI, sau `code_header_t {magic, ble_image_size, ble_image_start}`) vào L3-SRAM. `cpu_dcache_writeback_region(SRAM_START, align64)`.
4. `mrvl_regwrite32(AP806_CCU_B_RVBAR_0, SRAM_START >> 16)` — đặt reset-vector A72 = địa chỉ BLE.
5. `start_ap806(true)` — thả reset A72 → BLE chạy, train DDR.
6. `if (callback) callback()` — trong lúc chờ DDR, R4 làm việc khác (không cần DDR).
7. **`mc_ddr_get_ready()`** — `syncronize_boot_get(BOOT_SYNC_DDR_READY(1), block=true)` — chờ A72 báo DDR xong; rồi `while (!(1 & AP806_CCU_B_PSR_0))` — chờ A72 CPU0 vào WFI.
8. `start_ap806(false)` — giữ A72 reset lại (BLE xong nhiệm vụ).
9. `ap806_l3_sram_deconfig()` — trả L3-SRAM (ATF sau này dùng làm system cache).

Cold boot đường này chạy từ `board.c:205/406` (hoặc `copy_run_atf` — T2.4). Resume (`warm=true`) chạy từ `power.c:1734` (`pmu_resume`).

## 2. `mc_*` — R4 tự thao tác MC6 controller

`MC6_REGS_t` tại `MC_BASE` / `MC6_EXT_BASE` (INFERENCE: `0xCE0xxxxx` qua `AP806_ACCESS`, cửa sổ MoChi tới AP806 — T4.2). Thanh ghi chính: `USER_COMMAND_0`, `DRAM_STATUS`, `MC_STATUS_CH0/CH1`, `MMAP0/1_Low_CH0/CH1`.

### 2.1 `mc_drain()` (`:493`) — flush write buffer trước khi cắt clock
```c
USER_COMMAND_0 = CH1|CH0|CS|WCP_DRAIN_REQ
poll MC_STATUS_CH0 & 0xFDFFF == 0xF9FFF   (drain idle, bỏ qua bit 31:20,13)
poll MC_STATUS_CH1 ...
timeout MC_STATUS_TIMEOUT = 200 (bình thường 1–3 lần)     ← "リコ対応済み" (fix của KM)
```

### 2.2 `mc_enter_sr(mc_reg, ch, cs)` (`:270`) — vào **self-refresh**
- đọc `MMAP1_Low_CH0/CH1` để biết CS1 có hợp lệ không → chọn `ch`/`cs`/`mask`.
- `USER_COMMAND_0 = <SR cmd> | (ch+1)<<CH_SHIFT | (cs+1)<<CS_SHIFT`.
- poll `DRAM_STATUS & mask == mask` ("Waiting for SR Enter"), timeout 100×1µs.

### 2.3 `mc_exit_sr(mc_reg, ch, cs)` (`:182`) — thoát self-refresh (ngược lại, `DRAM_STATUS` bit SR clear).

### 2.4 `mc_enter_pd(mc_reg, 2, 2)` (`:392`) — vào **power-down** (sâu hơn SR)
- `mc_enter_sr(mc_reg, ch, cs)` trước.
- bật pull-down PHY: 4 pup × `nova_ddrphy_write(0xA8, CnD=1, pup, reg | 0x200)`.
- `USER_COMMAND_0 = 0x20 | (ch+1)<<CH | (cs+1)<<CS` (PD cmd).
- poll `DRAM_STATUS & mask == mask`, timeout 100.
- `ch=2, cs=2` = "cả 2 channel, cả 2 CS".

### 2.5 `mc_exit_pd` = `mc_exit_sr` + ... (`:366`).

### 2.6 `nova_ddrphy_read/write(reg, CnD, pup_num, data)` (`:123/153`) — truy cập gián tiếp PHY DDR "Nova" (chỉ dùng cho pull-down khi PD).

## 3. Boot-sync giữa R4 ↔ A72 — `mv_sync.c`

**FACT.** `SYNC_regs[]` = 8 cặp thanh ghi `{SYNC_STATUS (R), SYNC_SET (W1S)}`:
```
[0..5] = 0xE8246040, 50, 70, 80, A0, B0     (scratch/semaphore APB)
[6,7]  = 0xE8009800, 0xE800980C             (= MHU! T0.2/T2.3)
```
`PLATFORM_SYNC_PORT = 5` → **`SYNC_regs[5] = 0xE82460B0`** = kênh boot-sync DDR.

| API | thao tác |
|-----|----------|
| `syncronize_boot_set(value)` | `SYNC_regs[5]->SYNC_SET = value` (set bit) |
| `syncronize_boot_get(mask, block)` | đọc `SYNC_STATUS`, nếu `block` thì poll tới khi `& mask`; trả `status & mask` |

### Bit `BOOT_SYNC_*` (`mv_sync.h:48-62`)
| bit | tên | ai set |
|-----|-----|--------|
| [15:0] | `DDR_FREQ(x)` | R4 (`mc_configure_dram`) — tần số DDR mong muốn (r4 build: 0 = "AP tự quyết") |
| 16 | `DDR_FREQ_VALID` | R4 |
| 17 | `DDR_WARMBOOT` | R4 (chỉ khi warm) |
| 18 | `DDR_CONT_BOOT` | R4 (`FLEX_quartz`) |
| 20 | `DDR_READY` | **A72/BLE** — "DDR train xong" |
| 21 | `DDR_FAIL` | A72/BLE |
| 22 | `AP_READY` | A72 |
| 23/24 | `AP_WARMBOOT_DONE/FAIL` | A72 |

### `mc_configure_dram(bool warm)` (`:759`)
```c
ddr_clk = (BUILD_r4) ? 0 : 1200;              // r4: để AP quyết
if (!warm) syncronize_boot_get(-1, false);    // clear sạch mọi bit (cold)
syncronize_boot_set(DDR_FREQ_VALID(1) | DDR_FREQ(ddr_clk));
if (warm) {
    syncronize_boot_get(DDR_FAIL(1) | DDR_READY(1), false);   // dọn cờ cũ
    syncronize_boot_set(DDR_WARMBOOT(1));
}
```

## 4. Luồng SLEEP — `mc_save_state()` (`power.c:1524`, trong TR đi ngủ Sleep2/ErP)

```c
mc_save_state():
  if (power_debug_flags_get_pdf_verify_ddr()) {          // debug flag, mặc định OFF
      xor_corruption = mrvl_regread32(0);                 // XOR DMA làm hỏng addr 0 → lưu
      ddr_verify_crc(false);                              // chụp CRC32 nội dung DDR (qua XOR)
  }
  mc_drain();                                             // flush write buffer
  mc_enter_pd((MC6_REGS_t*)MC6_EXT_BASE, 2, 2);           // DDR → power-down + PHY pull-down
```
Sau `mc_save_state`, `power.c` tiếp: `pmu_jtag_select(JTAG_R4M4_ONLY)`, `pmu_phase(pmu_ap_link_down)`, `pmu_set_device(pmu_PI, pmu_D3)`, tắt `MC_PLL`/`ND_PLL` (`pmu_set_sspll(... pmu_D2)`) — T4.1/T4.3.

**⇒ Khi R4 ngủ (Sleep2/ErP), DDR KHÔNG mất điện — nó ở power-down/self-refresh, tự giữ nội dung. R4 chỉ cắt MC_PLL và PI (PIDI) link.** Nội dung RAM của Linux được bảo toàn.

## 5. Luồng RESUME — `mc_restore_state()` (`power.c:1734`, trong `pmu_resume`)

```c
init_ddr(true, pmu_ddr_callback);       // warm: nạp lại BLE, A72 re-train NHANH (config gần cold, trừ vài điểm)
mc_restore_state():
  if (pdf_verify_ddr) {
      mrvl_regwrite32(0, xor_corruption);     // khôi phục addr 0 TRƯỚC khi check
      ddr_verify_crc(true);                   // so CRC32 với snapshot lúc sleep
      mrvl_regwrite32(0, xor_corruption);     // khôi phục lại SAU check (XOR lại làm hỏng)
  }
  #ifdef FLEX_quartz: syncronize_boot_set(DDR_CONT_BOOT(1))   // thả A72 chạy tiếp
```
Comment: *"we will just RE-TRAIN (quickly)"* — không lưu/khôi phục thanh ghi training, chỉ train lại nhanh với config gần cold-boot.

`pmu_resume` sau đó: `pmu_phase(pmu_system_up)` → gọi `lpp_pm_operations.cb[i]->resume()` cho từng driver ("DDR online").

## 6. `ddr_verify_crc(bool verify)` + XOR engine (`mv_xor_v2.c`)

### Mục đích
Kiểm tra tính toàn vẹn nội dung DDR qua chu kỳ sleep (debug — `pdf_verify_ddr`). Tính CRC32 của 4 vùng (CH0-CS0, CH0-CS1, CH1-CS0, CH1-CS1) trước khi ngủ, so lại sau khi thức.

### Cách tính bản đồ vùng (`ddr_verify_crc:520-660`)
- đọc `MC6_MMAP0_LOW_CHx` field `AREA_LENGTH` (0xD=0.5GB, 0xE=1GB, 0x2=1.5GB, 0xF=2GB per CS) → tính `crc_addr[]`/`crc_size[]`.
- CH1 bắt đầu ở `GB_8` (8GB offset). CH0 case 0xF: mặc định 3GB liền + 1GB vào remap; kiểm `CCU_MC_RCR` (`0xCE001700` bit0) + `CCU_MC_RTBR` (`0xCE001708`) để đảo ngược remap.
- `#if FLEX_quartz`: `crc_addr[0] += 0x100000` (bỏ qua L3-SRAM), `crc_size[0] -= 0x100000`.

### `mv_xor_4dma_crc32_list(src[], size[], result[], dma_num, block, iterations)` (`:821`)
- Dùng **XOR-v2 DMA engine** để đọc DDR và tính CRC32 — **bypass MPU** của R4 (R4 MPU chặn DDR ở `0x0`? — thực ra R4 map DDR ở `0x0` NOCACHE, T1.6; XOR engine đọc địa chỉ vật lý trực tiếp, không qua MPU/cache của R4).
- `MV_XOR_BASE = 0x00400000`, `MV_XOR_ENGINE(n) = 0x400000 + n*0x20000`, **4 engine** (`AP806_ACCESS(MV_XOR_ENGINE(n))` → cửa sổ AP806). Descriptor 32B/128B, burst 256B, tối đa 128 desc.
- `xor_corruption` (`static uint32_t`): XOR DMA "làm hỏng địa chỉ 0" → save/restore quanh mỗi lần dùng.

## Tóm tắt (theo format skill)

**DDR trên S800:** LPDDR4 gắn AP806 (controller MC6 + PHY Nova). R4 **không train DDR** — khi cold boot hoặc resume, R4 nạp ảnh **BLE** từ QSPI vào L3-SRAM của AP806 (`0xCCF00000`), đặt reset-vector A72 tới đó, thả A72 chạy BLE để train, rồi chờ bit `BOOT_SYNC_DDR_READY` (kênh scratch-register `0xE82460B0`, port 5) và A72 vào WFI. Khi R4 đi ngủ Sleep2/ErP, R4 tự tay `mc_drain()` (flush) → `mc_enter_pd()` (self-refresh + PHY pull-down) rồi cắt MC_PLL/ND_PLL/PI — **DDR giữ nội dung, không mất điện**. Khi thức, `init_ddr(warm=true)` re-train nhanh + `mc_restore_state`. Có đường tùy chọn `ddr_verify_crc` dùng **XOR-v2 DMA engine** (`0x400000`, 4 engine, bypass MPU R4) chụp/so CRC32 nội dung DDR qua chu kỳ ngủ để debug corruption (mặc định tắt).

**Call flow (đi ngủ Sleep2):**
```
TR (LPPP_Matrix, đi Sleep2/ErP) → power.c sleep path
├─ mc_save_state()
│   ├─ [pdf_verify_ddr?] xor_corruption = *(u32*)0; ddr_verify_crc(false)  [XOR CRC snapshot]
│   ├─ mc_drain()                     [USER_COMMAND_0 |= WCP_DRAIN_REQ; poll MC_STATUS_CHx]
│   └─ mc_enter_pd(MC6_EXT_BASE, 2, 2)
│        ├─ mc_enter_sr()             [USER_COMMAND_0 SR cmd; poll DRAM_STATUS]
│        ├─ nova_ddrphy_write(0xA8, ... |0x200) ×4 pup   [PHY pull-down]
│        └─ USER_COMMAND_0 PD cmd; poll DRAM_STATUS
├─ pmu_jtag_select(JTAG_R4M4_ONLY)
├─ pmu_phase(pmu_ap_link_down); pmu_set_device(pmu_PI, pmu_D3)
└─ pmu_set_sspll(pmu_MC_PLL, D2); pmu_set_sspll(pmu_ND_PLL, D2)     [cắt PLL]
--- wfi ---
RESUME (pmu_resume):
├─ pmu_phase(pmu_ap_link_up)
├─ init_ddr(true, pmu_ddr_callback)
│   └─ init_lpddr4_from_ap806_sram(BSPI_CS0, warm=true, cb)
│        ├─ mc_configure_dram(true) → syncronize_boot_set(DDR_WARMBOOT | DDR_FREQ_VALID)
│        ├─ memcpy BLE → 0xCCF00000; RVBAR_0 = ...; start_ap806(true)
│        ├─ cb() [bring up non-DDR items]
│        └─ mc_ddr_get_ready() → wait BOOT_SYNC_DDR_READY + A72 WFI
├─ mc_restore_state()  [pdf_verify? ddr_verify_crc(true)]
└─ pmu_phase(pmu_system_up) → driver .resume() callbacks
```
