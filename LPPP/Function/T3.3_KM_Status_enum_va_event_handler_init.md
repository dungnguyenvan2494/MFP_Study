## 1 · Enum trạng thái (`LPPP_KM_Status.h`)

```c
typedef enum {
    PWR_STATUS_POWEROFF = 0,
    PWR_STATUS_NORMAL   = 1,
    PWR_STATUS_SLEEP1   = 2,
    PWR_STATUS_SLEEP2   = 3,
    PWR_STATUS_ERP      = 4,
    PWR_STATUS_INVAL    = 5,
    PWR_STATUS_MAX      = PWR_STATUS_INVAL,   // = 5  ← KÍCH THƯỚC mảng, KHÔNG phải index hợp lệ
} pwr_status_t;

typedef enum {
    AP_STATUS_NO_BOOT                    = 0,
    AP_STATUS_WARP_BOOT_OR_GET_SNAPSHOT  = 1,   // chỉ 2 giá trị
} ap_status_t;
```

`LPPP_INTERNALEVT` (`LPPP_inc.h:44-56`): `PWR_SW_OFF=0 … LVDS_TIMER=9, INVALID=10, MAX=INVALID=10`.

Ma trận khai báo `fpLPPP_ScenarioFunc[PWR_STATUS_MAX][LPPP_INTERNALEVT_MAX]` = **`[5][10]`**.
Index state hợp lệ **0..4**, event hợp lệ **0..9**.

**Đối chiếu SCPI (T2.6 §1):** `pwr_status_t` khớp `KM_SCPI_PWR_*` (Linux `km_scpi.h`): OFF=0,
NORMAL=1, SLEEP1=2, SLEEP2=3, ERP=4. `ap_status_t` khớp `KM_SCPI_AP_*`: NOT_BOOT=0, WARP_BOOT=1.
⇒ SCPI `0x85`/`0x83` truyền thẳng số này vào `LPPP_SetStatus(pwr_sd/ap_sd, ...)`.

## 2 · `event_handler()` (`LPPP_Task.c:187-210`) — 2 lớp guard

```c
void event_handler(LPPP_INTERNALEVT e_Evt) {
    stat_t e_lppstat;

    /* Guard 1 — dải EVENT */
    if ((LPPP_INTERNALEVT_PWR_SW_OFF /*0*/ > e_Evt) ||
        (LPPP_INTERNALEVT_MAX /*10*/  <= e_Evt)) {
        APPKM_DBG_MSG(... "Error:e_Evt %d");
        return;                                  // chặn e_Evt < 0 hoặc >= 10
    }

    /* lấy state hiện tại */
    e_lppstat = LPPP_GetStatus(pwr_sd);          // 0..4 · hoặc -1 nếu mutex timeout 10ms

    /* Guard 2 — dải STATE (CHỈ chặn CẬN TRÊN) */
    if (PWR_STATUS_MAX /*5*/ <= e_lppstat) {
        APPKM_DBG_MSG(... "Error:LPPP_GetStatus() return %d");
        return;                                  // chặn e_lppstat >= 5
    }

    /* dispatch — KHÔNG giữ khoá ở đây */
    e_lppstat = (*fpLPPP_ScenarioFunc[e_lppstat][e_Evt])(e_lppstat, e_Evt);
    LPPP_SetStatus(pwr_sd, e_lppstat);
}
```

### 2.1 · Guard 1 vs caller — bảo vệ 2 lớp cho giá trị `10`
`PowerControlEventManager` (`LPPP_Task.c:585-587`) đã kiểm `intr_event != LPPP_INTERNALEVT_INVALID`
(`!= 10`) **trước khi** gọi `event_handler`, rồi `event_handler` guard 1 kiểm lại `>= 10`.
Cả hai chặn `10` — cố ý (fix bug CT#7690). Đây là "2-layer" mà `PowerControlEventManager.md §3(d)` nhắc.

### 2.2 · 🔴 Guard 2 **KHÔNG chặn cận dưới** — lỗ hổng thật
`LPPP_GetStatus` trả **`-1`** khi `xSemaphoreTake` timeout (10ms) hoặc `check_sd_range` sai
(T2.6 §3). `PWR_STATUS_MAX(5) <= -1` là **`false`** → guard 2 **cho qua** →
`fpLPPP_ScenarioFunc[-1][e_Evt]` = **truy cập mảng ngoài biên** (đọc con trỏ hàm ở địa chỉ trước
mảng) → gọi vào rác → nhiều khả năng crash.

Trên thực tế **chưa xảy ra** vì mutex `_status_info.mutex_handle` gần như không bao giờ bị tranh
chấp (chỉ `PwEvtMgr` + đôi khi `AppMhuTest` qua `0x85`, tách biệt thời gian). Nhưng guard đúng
phải là `if (e_lppstat < 0 || PWR_STATUS_MAX <= e_lppstat)`.

### 2.3 · Non-atomic get→dispatch→set (khớp `PowerControlEventManager.md §5`)
`LPPP_GetStatus` và `LPPP_SetStatus` mỗi cái tự lấy/nhả mutex → **khoảng giữa (chạy scenario)
không khoá**. An toàn nhờ:
| Bảo đảm | Chi tiết |
|---|---|
| Single consumer | `event_handler` chỉ được `PwEvtMgr` (prio 0) gọi trong runtime — nó là consumer duy nhất của `gst_MsgQHandle_PowerCtrl`, xử lý tuần tự 1 event/lượt |
| Caller thứ 2 chạy trước | `LPPP_KM_Init` → `event_handler(PWR_SW_ON)` ở `init_thread` **prio 3** → chạy xong hẳn trước khi `PwEvtMgr` prio 0 có lượt |
| ⚠ Writer thứ 3 | SCPI `0x85` `SCPISetPowerStatus` gọi `LPPP_SetStatus(pwr_sd, p)` **trực tiếp** từ `AppMhuTest` (prio 0) — **có** ghi `pwr_sd` đồng thời. Nhưng nó bỏ qua `event_handler` (không get→dispatch→set), và `LPPP_SetStatus` tự khoá mutex → không torn write, chỉ race logic (SM Set đè `0x85` Set hoặc ngược). CA72 chỉ dùng `0x85` để đồng bộ lại sau resume khi máy đứng yên |

## 3 · `LPPP_KM_Init()` (`LPPP_Task.c:236-253`) — thứ tự khởi tạo KM

Chạy trong `init_thread` (prio 3), **trước khi bất kỳ task prio 0/1 nào có lượt** (T1.5 §7).

```
1. LPPP_que_create()          ★ TẠO 3 QUEUE ĐẦU TIÊN
     scpi_msgq_create()                → got_msg_qhandle          (16 × sizeof(int_msg_format_t)=129B)
     PowerControlMHUEventQueCreate()   → gst_MsgQHandle_MHU       (10 × sizeof(scpi_header_t))
     PowerControlEventManagerQueCreate()→ gst_MsgQHandle_PowerCtrl (20 × ...)
2. LPPP_IRQ_Setting()         attach 6 IRQ nội bộ (c_intirq_table)
3. LPPP_Flash_Setting()       QSPI flash init
4. LPPP_GPIO_Setting()        GPIO + đăng ký LPPP_GPIO_Callback cho chân wake
5. LPPP_InitStatus()          tạo mutex statlib
6. LPPP_i2c_init()            I2C (OP_BTS-32007)
7. ap_sd  = LPPP_OpenStatus()               → descriptor 0
8. pwr_sd = LPPP_OpenStatus()               → descriptor 1
9. LPPP_SetStatus(pwr_sd, PWR_STATUS_POWEROFF /*0*/)
10.LPPP_SetStatus(ap_sd,  AP_STATUS_NO_BOOT /*0*/)
11.event_handler(LPPP_INTERNALEVT_PWR_SW_ON /*1*/)   ★ GỌI TRỰC TIẾP (không qua queue)
     → fpLPPP_ScenarioFunc[POWEROFF=0][PWR_SW_ON=1] = LPPP_TR0_OFFToNormal
        → busy-wait ≤100ms · MOTION_EN nếu Stop không nhấn · return NORMAL
     → LPPP_SetStatus(pwr_sd, PWR_STATUS_NORMAL /*1*/)
```

**Vì sao thứ tự này bắt buộc:**
| Bước | Phụ thuộc | Lý do |
|---|---|---|
| (1) queue **trước tiên** | — | ISR bật ở (2)/(4) có thể `xQueueSendFromISR` ngay; `PwEvtMgr`/`PwMHUEv`/`AppMhuTest` sẽ `xQueueReceive` các queue này (`scpi_msgq_create` treo `while(1)` nếu hết heap) |
| (5) `LPPP_InitStatus` trước (7)(8) | — | `LPPP_OpenStatus` cần mutex đã tạo |
| (7)(8) trước (9)(10)(11) | — | `LPPP_SetStatus`/`event_handler` cần descriptor hợp lệ |
| (11) **cuối cùng** | tất cả | `TR0` đọc GPIO `PANEL_STOP`, ghi `MOTION_EN` → cần `LPPP_GPIO_Setting` xong; state phải `POWEROFF` để tra `[0][1]=TR0` |

⇒ Khi `PwEvtMgr` bắt đầu vòng `while(1)` đầu tiên, `pwr_sd` **đã là `NORMAL`**. Transition
`POWEROFF → NORMAL` là lần **duy nhất** `event_handler` chạy ngoài `PwEvtMgr` — về mặt thiết kế
`event_handler` là **hàm 2-context** (`PowerControlEventManager.md §2 "Điểm mấu chốt #1"`).

trong tài liệu". `MC_LPP_IRQ0/1` = ngắt từ lõi M3 (T0.2 §3.6). Chi tiết attach → **T3.5**.

phần tử của `got_msg_qhandle` (`AppMhuTest.md §D`).

## 5 · Tóm tắt (theo format skill)

**1. Tồn tại để làm gì:** `LPPP_KM_Status.h` định nghĩa 5 trạng thái nguồn (`pwr_status_t`, index
0..4, `MAX=5` là kích thước mảng) + 2 trạng thái AP. `event_handler` là bộ điều phối 2-context của
máy trạng thái: guard dải event (0..9) + guard cận-trên state, tra `fpLPPP_ScenarioFunc[state][event]`,
`get→dispatch→set` không atomic nhưng an toàn nhờ single-consumer + chênh priority. `LPPP_KM_Init`
dựng KM theo thứ tự bắt buộc: **queue trước tiên** → IRQ/flash/GPIO/statlib/I2C → mở 2 descriptor →
`event_handler(PWR_SW_ON)` cuối (POWEROFF→NORMAL, lần duy nhất chạy ngoài `PwEvtMgr`).

**2. Lifecycle:**
```
init_thread (prio 3):
  LPPP_KM_Init:
    que_create (3 queue)  → IRQ_Setting (6 IRQ)  → Flash/GPIO/Statlib/I2C init
    ap_sd  = OpenStatus() → 0
    pwr_sd = OpenStatus() → 1
    SetStatus(pwr_sd, POWEROFF); SetStatus(ap_sd, NO_BOOT)
    event_handler(PWR_SW_ON):
       GetStatus(pwr_sd)=0 → guard OK → fpLPPP_ScenarioFunc[0][1]=TR0 → NORMAL
       SetStatus(pwr_sd, NORMAL)
── runtime ──
  PwEvtMgr (prio 0): xQueueReceive(PowerCtrl) → event_handler(evt):
       guard1: 0 <= evt < 10 ?
       GetStatus(pwr_sd) → guard2: < 5 ? (⚠ KHÔNG kiểm < 0)
       fpLPPP_ScenarioFunc[state][evt](state, evt) → new_state
       SetStatus(pwr_sd, new_state)
  AppMhuTest (prio 0): SCPI 0x85 → SetStatus(pwr_sd, p)   ← writer thứ 3, bỏ qua event_handler
```

**3. File đã tham chiếu:**
- `ApplicationKM/LPPP_KM_Status.h` (toàn bộ)
- `ApplicationKM/LPPP_inc.h` (toàn bộ)
- `ApplicationKM/LPPP_Task.c:178-262`

**4. Đã xác nhận / phát hiện:**
- ✅ `PWR_STATUS_MAX = 5` = kích thước mảng; ma trận `[5][10]`.
- ✅ Enum `pwr_status_t`/`ap_status_t` khớp 1:1 `KM_SCPI_PWR_*`/`KM_SCPI_AP_*` (Linux).
- 🔴 **Guard 2 trong `event_handler` chỉ kiểm cận trên** (`>= 5`), KHÔNG kiểm `< 0` → nếu
  `LPPP_GetStatus` trả `-1` (mutex timeout) thì `fpLPPP_ScenarioFunc[-1][evt]` = OOB → crash.
  Chưa xảy ra vì mutex không tranh chấp. Đúng phải là `e_lppstat < 0 || PWR_STATUS_MAX <= e_lppstat`.
- ✅ `event_handler` là hàm **2-context**: `init_thread` (1 lần, POWEROFF→NORMAL) + `PwEvtMgr` (runtime).
- ✅ SCPI `0x85` là **writer thứ 3** của `pwr_sd`, đồng thời với SM nhưng không torn (mutex trong `LPPP_SetStatus`).
- ✅ `LPPP_KM_Init` thứ tự: queue **trước tiên** (ISR có thể bắn ngay), statlib trước OpenStatus, `event_handler` cuối.
- ✅ 6 IRQ nội bộ: `NCTI/NPMU/NVAL_FIQ/NVAL_IRQ` (SPI 64-67), `MC_LPP_IRQ0/1` (SPI 128/129, từ M3).
