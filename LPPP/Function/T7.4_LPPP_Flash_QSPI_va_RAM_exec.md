## 1. Phần cứng QSPI (BootSPI) — `LPPP_Flash.h`

| define | giá trị | nghĩa |
|--------|---------|-------|
| `SPI_BASEADDRESS` | `0xF4000000` | vùng **memory-mapped read** của QSPI CS0 (XIP) |
| `SPI_REGISTERADDRESS` | `0xE8273000` | thanh ghi điều khiển `BOOTSPI_REGS_t` |
| `SPI_MEMORY_SIZE` | 4 MB | dung lượng flash |
| `SPI_PAGE_SIZE` | 256 B | page program |
| `SPI_SECTOR_SIZE` | 4 KB | sector erase |
| CS | `SPI_CHIP_SELECT_0` (=0) | KM dùng CS0 |

SPI opcode: `PP=0x02` (Page Program), `WD=0x04` (Write Disable), `RSR=0x05` (Read Status), `WE=0x06` (Write Enable), `SE=0x20` (Sector Erase 4KB).

### 1.1 `BOOTSPI_REGS_t` (`0xE8273000`)
`BSCR` (0x0 config), `BSCOM` (0x4 command words), `BSCMDR` (0x8 command mode — half-duplex manual), `BSSR` (0xc status), `BSIEN/BSIACK/BSISTAT/BSITEST` (0x10-0x1c IRQ), `BSACTIVE` (0x20 tri-state ⇄ active pins), `BSTR` (0x24 timing), `REV0/1` (0x30-0x34).

`BSCR` bit fields (quan trọng): `INTERFACEMODE` bit0 (1 = command mode), `NCSMUXSEL` [17:16] (chip-select mux), `DUMMYCLOCKCOUNT` [15:12], `ADDRESSBYTECOUNT` [9:8], `OPCODEBYTECOUNT` [6:5], `CACHEENABLE` bit18.
`BSSR`: `COMMANDBUSY` bit8, `CSS` bit17, `DATA` [7:0].
`BSCMDR` mã lệnh half-duplex (dùng trong code như magic):
- `0x100 + byte` = **gửi 1 byte** ra MOSI
- `0x0` = **nhận 1 byte** (đọc `BSSR.DATA`)
- `0x200` = **assert CS**
- `0x300` = **drop CS** (deassert)

## 2. Nguyên thủy half-duplex (`LPPP_Flash.c:107-163`)

| hàm | việc |
|-----|------|
| `wait_cmd(regs)` | busy-wait `while (BSSR & COMMANDBUSY)`; trả `BSSR` |
| `get_byte(regs)` | `wait_cmd` → `BSCMDR = 0` (clock in) → `wait_cmd` → trả `BSSR & 0xff` |
| `send_byte(regs, buf, size)` | vòng: `BSCMDR = buf[i] + 0x100` → `wait_cmd` |
| `send_addr(regs, addr, n)` | gửi `n` byte địa chỉ **MSB trước**: `BSCMDR = 0x100 + ((addr >> (n-1)*8) & 0xff)` |
| `execute_cmd(regs, cmd, cs)` | dựng `BSCR` (NCSMUXSEL=cs, DUMMYCLOCKCOUNT=cmd->dummy_bytes, ADDRESSBYTECOUNT=cmd->addr_bytes, OPCODEBYTECOUNT=cmd->op_bytes, INTERFACEMODE=1) → `wait_cmd` → `BSCMDR=0x200` (assert CS) → `wait_cmd` → `BSCMDR = 0x100 + cmd->command` (gửi opcode) → `wait_cmd` |

`struct op_info_s { command; addr_bytes; op_bytes; dummy_bytes; }` — cấu hình trong `LPPP_Flash_Setting()`:
- `program_op`: PP, addr=3, op=0, dummy=1
- `erase_op`: SE, addr=3, dummy=1
- `write_enable`: WE, addr=0, dummy=1
- `write_disable`: WD, addr=0, dummy=1

## 3. Nguyên thủy tầng "mrvl_qspi" (`LPPP_Flash.c:165-311`)

| hàm | luồng |
|-----|-------|
| `qspi_write_reg(pd, opcode, buf, len)` | save `BSCR` → `execute_cmd(op_bytes=1)` → `send_byte(buf,len)` → `BSCMDR=0x300` → restore `BSCR` |
| `qspi_read_reg(pd, opcode, buf, len)` | save `BSCR` → `execute_cmd` → `len × get_byte()` → `BSCMDR=0x300` → restore `BSCR` |
| `mrvl_qspi_read(pd, buf, addr, size)` | `BSCR &= ~1` (tắt command mode) → **`memcpy(buf, (void*)addr, size)`** — đọc trực tiếp qua XIP `0xF4xxxxxx` |
| `wait_for_write_complete(pd)` | vòng `qspi_read_reg(0x05, buf, 1)` tới khi `!(buf[0] & 0x01)` — poll WIP bit. *(comment "put a timeout here" — chưa có timeout)* |
| `mrvl_qspi_write(pd, buf, addr, size)` | save `BSCR` → **vòng theo page 256B**: `execute_cmd(write_enable)` `0x300` → `execute_cmd(program_op)` → `send_addr(addr, 3)` → `send_byte(page)` → `0x300` → `wait_for_write_complete` → cuối: `execute_cmd(write_disable)` `0x300` → restore `BSCR` |
| `mrvl_qspi_erase(pd, addr)` | save `BSCR` → `execute_cmd(write_enable)` `0x300` → `execute_cmd(erase_op)` → `send_addr(addr,3)` → `0x300` → poll WIP → `execute_cmd(write_disable)` → restore `BSCR` |

`plat_data` = global `struct qspi_s lppp_flash` (khởi tạo trong `LPPP_Flash_Setting`: `register_base=0xE8273000`, `base=0xF4000000`, `size=4MB`, `page_size=256`, `sector_size=4KB`, `chip_select=0`, 4 `op_info_s`).

## 4. Interface KM (`LPPP_Flash.c:376+`)

| hàm | ý nghĩa | thuật toán |
|-----|---------|-----------|
| `flash_read(buf, addr, size)` | đọc | → `mrvl_qspi_read` (memcpy từ XIP) |
| `flash_erase(addr, sector_num)` | xoá N sector | vòng `mrvl_qspi_erase` mỗi 4KB |
| `flash_write(buf, sector_addr, sector_num)` | ghi (đã xoá) | vòng `mrvl_qspi_write` theo sector |
| `flash_modify_sector(sector_addr, offset, buf, size)` | **RMW 1 sector** | `flash_read` cả 4KB vào `write_sector_buffer` → `memcpy(&buf[offset], src, size)` → `flash_erase(sector,1)` → `mrvl_qspi_write` lại cả 4KB. Kiểm: addr trong range, aligned 4KB, `offset+size ≤ 4KB` |
| `flash_modify(dst, src, size)` | **RMW tuỳ ý (cắt qua nhiều sector)** | tách `sector = dst & ~0xFFF`, `offset = dst & 0xFFF`; tính `size_top` (phần sector đầu), `num_sector`, `size_end` (sector cuối); gọi `flash_modify_sector` cho đầu → giữa → cuối |

`flash_modify` **không tự chạy trên RAM** — chỉ `flash_modify_sub` mới copy code lên RAM.

## 5. `LPPP_FlashSub.c` — thực thi trên RAM (2018/05/10, Sky)

### 5.1 Vì sao?
QSPI flash là XIP (`.text` của FW cũng nằm trên flash, đọc qua `0xF8000000` — T1.6). Khi **erase/program flash**, không thể đồng thời **fetch lệnh từ flash** → CPU treo. Giải pháp: copy code `LPPP_Flash.o` sang RAM và nhảy tới bản RAM để ghi flash.

### 5.2 Linker (`memory_sections.ld`)
```
:104  __lppp_flash_start__ = .;
:105  *LPPP_Flash.o (.text .text.* .gnu.linkonce.t.*)     ← toàn bộ .text của LPPP_Flash.c gom 1 chỗ
:106  __lppp_flash_end__ = .;
...
:314  .qspi_ram_code_start (NOLOAD) : ALIGN(0x8) {
:315     __qspi_ram_code_start__ = .;
:316     . += __lppp_flash_end__ - __lppp_flash_start__ + 1;    ← reserve đúng kích thước trong RAM
:318     __qspi_ram_code_end__ = .;
```

### 5.3 `flash_code_copy_to_ram()` (static, 1 lần — `copy_flag`)
```c
memcpy(&__qspi_ram_code_start__, &__lppp_flash_start__, __lppp_flash_end__ - __lppp_flash_start__);
cpu_dcache_writeback_all();
cpu_icache_invalidate_all();
__asm volatile("isb");
copy_flag = 1;
```

### 5.4 `flash_modify_sub(dst, src, size)` — điểm vào chính
```c
flash_code_copy_to_ram();
// tính địa chỉ flash_modify() bản RAM = base RAM + (offset của flash_modify trong .text flash)
flash_mod = (flash_modify_func)( &__qspi_ram_code_start__
              + ((uint32_t)flash_modify - (uint32_t)&__lppp_flash_start__) );
int_state = cpu_disable_interrupts();     // toàn bộ ghi flash chạy với IRQ TẮT
ret = flash_mod(dst, src, size);           // gọi bản RAM
cpu_restore_interrupts(int_state);
return ret;
```
→ Trong lúc erase/program: **IRQ tắt** + **code chạy từ RAM** ⇒ không fetch flash. `flash_read` (memcpy từ `0xF4xxxxxx`) bên trong vẫn là data-read, không phải instruction-fetch — an toàn.

### 5.5 `Bregister_modify(dst, mask, data)` — RMW 1 thanh ghi B (16-bit trên flash)
```c
flash_read(&reg, dst, 2);
reg = (reg & ~mask) | (data & mask);
flash_modify_sub(dst, &reg, 2);      // ghi lại qua đường RAM-exec
```

## 6. Thanh ghi B0xx (breadcrumb trong flash) — `LPPP_Flash.h`

| addr | = `SPI_BASEADDRESS +` | size | ý nghĩa |
|------|----------------------|------|---------|
| `B013_ADDRESS` | `0x3FF01A` | 2B | (chưa dùng nhiều) |
| `B014_ADDRESS` | `0x3FF01C` | 2B | **breadcrumb pha ErP/Sleep** |
| `B015_ADDRESS` | `0x3FF01E` | 2B | breadcrumb Motion/Power-on MC/IR |

### B015 bits: `MC_P_ON`(0), `IR_P_ON`(2), `XMC_MOTION_EN`(4), `XIR_MOTION_EN`(5).
### B014 bits (16): `ERP_RCV_RET_REQ`(0) … `ERP_ON_PD5`(10), **`TO_SLEEP2_OR_ErP`(11)**, **`BEGIN_PHASE6`(12)**, **`TO_SLEEP1`(13)**, `BIT14`(14), `ERP_LOG_EN`(15).
Khớp T3.2: TR5/6 set bit 11, `power_cpu` resume set bit 12, TR8/10 set bit 13.

## 8. FACT / INFERENCE / UNKNOWN

- **FACT**: địa chỉ `0xF4000000` (XIP data) / `0xE8273000` (regs), `BOOTSPI_REGS_t` layout, mã `BSCMDR` 0x100/0x0/0x200/0x300, opcode SPI, `op_info_s` 4 lệnh, `flash_read` = memcpy XIP, `mrvl_qspi_write` theo page 256B với WE trước mỗi page + poll WIP (0x05 bit0), `flash_modify_sector` = read-4KB / erase / write-4KB, `flash_modify` cắt sector, `flash_modify_sub` copy `LPPP_Flash.o .text` → `__qspi_ram_code_start__` + tắt IRQ + gọi bản RAM, `Bregister_modify` RMW 16-bit, bảng bit B014/B015, linker section :104-106 / :314-318.
- **FACT**: callers trong `LPPP_Matrix.c` (TR函数) — flash_write BSP region ×2, flash_modify_sub PDFLAG/CA72WDT, Bregister_modify B014.
- **INFERENCE**: đọc `reg_B015` trong `LPPP_GPIO_Setting` (T7.2) và `wait_for_write_complete` không timeout ⇒ tiềm ẩn treo nếu flash lỗi; không có bằng chứng đã gặp.
- **INFERENCE**: `flash_read` an toàn khi gọi từ bản RAM của `flash_modify` vì là data-read từ `0xF4xxxxxx` (khác vùng instruction `0xF8xxxxxx`). QSPI controller có phục vụ song song data-read trong lúc program không thì tuỳ HW — code giả định được (đọc status reg `0x05` liên tục trong `wait_for_write_complete` cũng là data-read qua command mode, không phải XIP). Chưa xác nhận từ datasheet.
- **UNKNOWN**: `struct qspi_s` full field, `write_sector_buffer` (4KB static ở đâu — BSS), `FLASH_BspThrRegion1/2_TOP` và các `OFS_*` giá trị (trong header KM chưa mở — `LPPP_Matrix.h`/`error_types.h`).
- **UNKNOWN**: quan hệ `0xF4000000` (CS0 4MB) vs `0xF8000000` (CS1 128MB, RO-cache MPU region T1.6) — có phải cùng chip khác cửa sổ, hay 2 chip. T1.4 nói `set_chip_select` NCS_MUX_SEL=0b10.
- **UNKNOWN**: `cpu_disable_interrupts`/`cpu_restore_interrupts` có tắt cả FIQ không (ảnh hưởng `LPPP_GPIO_Callback` FIQ-mode path).

## Tóm tắt (theo format skill)

**`LPPP_Flash.c`/`FlashSub.c` để làm gì:**
Cung cấp cho firmware KM khả năng đọc/xoá/ghi/sửa QSPI NOR flash (chip 4MB, CS0) qua BootSPI controller ở `0xE8273000` bằng chế độ command half-duplex (`BSCMDR` magic 0x100/0x200/0x300). Đọc là `memcpy` trực tiếp từ cửa sổ XIP `0xF4000000`. Sửa dữ liệu = Read-Modify-Write nguyên sector 4KB (`flash_modify_sector`). Vì `.text` của FW cũng nằm trên flash, mọi thao tác erase/program phải chạy từ RAM: `LPPP_FlashSub.c` copy toàn bộ `LPPP_Flash.o` `.text` (linker gom vào `__lppp_flash_start__..end__`) sang `__qspi_ram_code_start__` trong RAM, tính lại con trỏ hàm `flash_modify` theo offset, **tắt IRQ**, rồi gọi bản RAM (`flash_modify_sub`). `Bregister_modify` dùng đường này để RMW an toàn các thanh ghi breadcrumb 16-bit B013/B014/B015 nằm ở cuối flash (`0xF43FF01A/1C/1E`) — nơi ma trận TR (T3.2) ghi pha Sleep1/Sleep2/ErP và cờ CA72-watchdog.

**Call flow (TR8 → set B014 bit TO_SLEEP1):**
```
LPPP_Matrix.c TR函数
└─ Bregister_modify(B014_ADDRESS=0xF43FF01C, mask=1<<13, data=1<<13)
   ├─ flash_read(&reg, 0xF43FF01C, 2)  → mrvl_qspi_read → BSCR&=~1 → memcpy từ 0xF43FF01C
   ├─ reg = (reg & ~(1<<13)) | (1<<13)
   └─ flash_modify_sub(0xF43FF01C, &reg, 2)
      ├─ flash_code_copy_to_ram()   [1 lần: memcpy LPPP_Flash.o→RAM, dcache wb, icache inv, isb]
      ├─ flash_mod = RAM_base + (flash_modify - __lppp_flash_start__)
      ├─ cpu_disable_interrupts()
      ├─ flash_mod(0xF43FF01C, &reg, 2)   [chạy từ RAM]
      │   └─ flash_modify → flash_modify_sector(sector=0xF43FF000, offset=0x01C, &reg, 2)
      │       ├─ flash_read(write_sector_buffer, 0xF43FF000, 4096)
      │       ├─ memcpy(&buf[0x01C], &reg, 2)
      │       ├─ flash_erase(0xF43FF000, 1) → mrvl_qspi_erase (WE, SE 0x20, poll WIP, WD)
      │       └─ mrvl_qspi_write(buf, 0xF43FF000, 4096)  [16 page × 256B: WE, PP 0x02, addr, data, poll WIP]
      └─ cpu_restore_interrupts()
```
