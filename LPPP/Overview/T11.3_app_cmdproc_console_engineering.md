## 1. `cmd_thread(void)` — vòng lặp console (`app_cmdproc.c:1126`)

```c
while (1) {
    if (uartReceive(uart=0, 1, _buf, &num, timeout=100) != 0)  continue;   // đọc 1 byte UART, timeout 100ms
    for each byte c:
        ESC / '[' / arrow  → lịch sử lệnh (↑↓ = _hist[16], ← = xoá cuối)
        CR/LF              → _line[cmdlen]=0; gen_argv(_line) → runcmd(argc,argv); free; _add_to_history; in _PROMPT
        BS/DEL (0x08/0x7f) → xoá 1 ký tự (_RUBOUT = "\b \b")
        Ctrl-U/Ctrl-C     → xoá dòng
        0x20-0x7e         → append + echo (_putc)
}
```
- Nhập/xuất qua `uartReceive` / `_putc`/`_puts` (→ `HalApiPrint_printsmbus` → `printuart`, T7.6). Cổng = UART10.
- Lịch sử 16 dòng (`_hist[]`, cấp phát `SysMemory_*`).
- `gen_argv` tách token; `runcmd` phân nhánh `strcmp(argv[0], ...)`.

## 2. Danh sách lệnh (`runcmd` / `help` — `app_cmdproc.c:649-690`)

| lệnh | tác dụng |
|------|----------|
| `help` | in danh sách + Proc Speed, `cpu_get_ccount`, `SysTimerIrq_Isr_count` |
| `peek <addr> [n]` / `poke <addr> <val>` / `memset <ptr> <val> <len>` | đọc/ghi bộ nhớ thô |
| `poll <addr> <seconds> [changes] [poke]` | theo dõi 1 địa chỉ tìm thay đổi |
| `wakeevents` | in nguồn wake (T9.5) |
| `mdio` | truy cập PHY MDIO |
| `gpio` | đọc/ghi GPIO (qua `app_gpio.c`) |
| `reset` | **watchdog reset** |
| `avs [mV]` / `ap806avs [mV]` | get/set AVS Quartz / AP806 (T4.4) |
| `bspi_cs1` | ngắt chân BSPI (lập trình flash TOC board) |
| `cpu_spin <us>` / `thread_sleep <ticks>` | delay |
| `power schema/debug_set/debug_clr/iris/up/down/get/set/phase/isolate` | điều khiển PMU thủ công (T4.1) — `power isolate` = cô lập AP806 "no recover!!" |
| `pmucmd trace[_min] / loop / <raw cmd>` | gửi lệnh thô tới `libpmu_r4.a` |
| `mcix4_params <gbit> <lanes>` / `mci_ap <port> <Pstate>` / `mci_debug <mask>` / `mci_patch` / `mci <link> <cmd> [data]` | điều khiển MoChi/MCI (T8.1) |
| `jtag <2\|3>` | 2 = R4-only, 3 = R4+AP (T7.7 — `pmu_jtag_select`) |
| `sleep_kill` | ép ngủ không hồi phục |
| `resume_test [#loops=20000]` | khi đang Sleep2, lặp resume/sleep để test |
| `systick` | in system ticks |
| `xor crc_test [block] [iter]` / `xor crc <src> <len> [40bit]` / `xor memcpy <src><dst><len> ...` | test XOR-v2 DMA + CRC32 DDR (T8.1) |

⇒ Toàn bộ là **công cụ bring-up/gỡ lỗi phần cứng cấp thấp** (memory poke, PMU, MCI, AVS, XOR, sleep test). Không có lệnh nghiệp vụ mạng/proxy.

## 5. Quan hệ với `LPPP_SCPI.c` / `app_scpi.c`
- `app_scpi.c` (Mrvl test) chứa handler SCPI đầy đủ (DVFS, `pause_cpu`, op_points…) — T2.5/T7.7.
- `LPPP_SCPI.c` (KM) chứa 11 wrapper KM + xử lý SCPI KM `0x81`–`0x8C` — T2.6.
- **INFERENCE**: chỉ **một** trong hai được đăng ký làm SCPI message handler với ATF/MHU. Việc `app_scpi.c` được *compile* không có nghĩa handler của nó *active* — có thể chỉ `AppScpiTest` (nếu có task) hoặc không được gọi. `LPPP_SCPI.c` + `LPPP_Task.c` (`PowerControlMHUEvent`) là đường KM chính. Chưa xác định handler nào ATF thực gọi cho lệnh 0x02–0x80.

## 6. FACT / INFERENCE / UNKNOWN

- **FACT**: `Makefile-rules` thu `*.c` mỗi thư mục có `Makefile`; `ApplicationMrvl/Test/Makefile` tồn tại ⇒ `app_cmdproc.c`/`app_scpi.c`/`app_MHU.c`/`app_gpio.c`/`app_rewrite-loop.c` compile & link.
- **FACT**: `app_init.c:162,169` tạo task "MHU" (`AppMhuTest`) và "cmd thread" (`cmd_thread`) vô điều kiện, prio IDLE.
- **FACT**: `cmd_thread` vòng lặp `uartReceive(UART10, timeout 100ms)` → parse dòng → `runcmd`; lịch sử 16 dòng; danh sách lệnh (peek/poke/power/pmucmd/mci/xor/jtag/reset/resume_test/sleep_kill…).
- **FACT**: `PowerControlIRQEvent` task `#if 0` (T7.2 xác nhận đường polling GPIO 10ms không chạy).
- **INFERENCE (đính chính T11.1/T7.7)**: firmware S800 production **có** console kỹ thuật sống trên UART10 — không phải chỉ bản test. `HAVE_CMD` off chỉ tắt framework `cmd_register` khác.
- **INFERENCE**: `pause_cpu`/DVFS handler trong `app_scpi.c` được link nhưng có thể không phải đường SCPI active (KM dùng `LPPP_SCPI.c`). Cần xác định handler SCPI nào ATF gọi.
- **UNKNOWN**: `runcmd` có kiểm quyền/khoá không (bất kỳ ai cắm UART gõ `poke`/`power isolate`/`reset` là thực thi ngay — backdoor kỹ thuật). Có build-flag nào loại `cmd_thread` cho firmware phát hành chính thức không (không thấy trong Makefile đã đọc).
- **UNKNOWN**: `app_rewrite-loop.c` (self-update loop?), `app_gpio.c` chi tiết lệnh `gpio`.
- **UNKNOWN**: `AppMhuTest` (task "MHU") làm gì — test MHU doorbell? có can thiệp đường SCPI thật không.

## Tóm tắt (theo format skill)

**`app_cmdproc.c` là console kỹ thuật CHẠY trong firmware S800 production** (đính chính T11.1): `Makefile-rules` compile mọi `*.c` dưới thư mục có `Makefile`, và `ApplicationMrvl/Test/` là submodule; `app_init.c` tạo task "cmd thread" (`cmd_thread`) vô điều kiện. Task này đọc UART10 debug từng byte (`uartReceive`, timeout 100ms), hỗ trợ lịch sử lệnh ↑↓ và line-edit, phân nhánh bằng `runcmd`. Bộ lệnh toàn là công cụ bring-up cấp thấp: `peek`/`poke`/`memset`, `power <up/down/get/set/phase/isolate>`, `pmucmd`, `mci*`, `avs`/`ap806avs`, `xor crc/memcpy`, `jtag`, `reset` (watchdog), `sleep_kill`, `resume_test`. Không có lệnh mạng.
