`LPPP_WAKE_GPIO_INFO_NUM = 14`. Các pin này gắn `LPPP_GPIO_CallbackDummy` (return false) rồi `gpio_isr_setup()` + `gpio_close()` ⇒ **cấu hình phần cứng ngắt/wake nhưng KHÔNG chạy callback phần mềm** — mục đích là để **HW wake domain** (PMU / GIC wake) nhận biết, đánh thức R4/hệ thống khỏi sleep. Xử lý logic thật do phía AP hoặc `power_cpu` lo (T6 §7.3, T9).

## 2. `LPPP_INTERNALEVT` (enum, `LPPP_inc.h:44-56`)

```
0 PWR_SW_OFF   1 PWR_SW_ON   2 GO_TO_S1   3 GO_TO_S2   4 GO_TO_ERP
5 WAKEUP_NORMAL   6 WAKEUP_S1   7 PWR_FLICKER   8 LVDS_INTERRUPT   9 LVDS_TIMER
10 INVALID (= MAX)
```
Đây là **cột** của ma trận `fpLPPP_ScenarioFunc[PWR_STATUS_MAX][LPPP_INTERNALEVT_MAX]` (T3.2).

## 3. `LPPP_GPIO_Setting()` (`LPPP_Gpio.c:521-624`) — gọi 1 lần từ `LPPP_KM_Init`/`LPPP_Task`

1. `flash_read(&reg_B015, B015_ADDRESS, 2)` — đọc B015 (`SPI_BASEADDRESS + 0x3FF01E`, QSPI). *(giá trị đọc ra `reg_B015` không dùng tiếp trong hàm — có thể chỉ để verify flash OK / còn nợ logic).*
2. **Vòng `gpio_info[]`** (`LPPP_GPIO_INFO_NUM` phần tử):
   - `bank = pinno/32`, `index = pinno%32`.
   - `gpio_open(&pin[i], bank, index, direction, logical_setting, logic_level)` → lưu handle vào `static gpio_handle_t *pin[LPPP_GPIO_INFO_NUM]`.
   - Nếu `direction == INPUT` **và** pin ∈ {`POWER_MONITOR`, `XEN_LVDS_ENG`}:
     - `gpio_isr_attach(pin[i], LPPP_GPIO_Callback, &gpio_info[i].pinno, isr_type)` + `gpio_isr_enable(pin[i])`.
   - Ngược lại (input khác / mọi output): `gpio_close(pin[i])` ngay.
3. **Vòng `wake_gpio_info[]`** (14 phần tử): `gpio_open` → `gpio_isr_attach(..., LPPP_GPIO_CallbackDummy, ...)` → `gpio_isr_setup(wake_pin)` → `gpio_close(wake_pin)`. (setup ≠ enable: chỉ nạp cấu hình phần cứng.)
4. `LPPP_GPIO_HandleMainSW(true)` — gắn ISR cho MAINSW_ON (62).

## 4. `LPPP_GPIO_Callback` (ISR, `LPPP_Gpio.c:319-368`) — ISR của POWER_MONITOR + XEN_LVDS_ENG

```
intr_event = LPPP_GPIO_AnalyzeEventfromISR(logic_level, *pinno);
if (intr_event < PWR_SW_OFF(0) || intr_event >= MAX(10))   return false;   // lọc INVALID
if (intr_event == WAKEUP_S1)                                return false;   // GPIO wake xử lý ở power_cpu, không đẩy queue
xQueueSendFromISR(gst_MsgQHandle_PowerCtrl, &intr_event, &woken);          // → task PowerCtrl → event_handler (T3.3)
if (woken) { HalApiCpu_is_irq/fiq_mode() ? portYIELD_FROM_ISR() : taskYIELD(); }
return false;   // luôn false: không "tiêu thụ" theo nghĩa HAL
```
Ghi chú lịch sử: `taskYIELD` thay vì `portYIELD_FROM_ISR` khi không ở IRQ/FIQ mode — SWI trong ngữ cảnh ngắt gây abort (OP_BTS-22999, 2020/07/07).

### 4.1 `LPPP_GPIO_AnalyzeEventfromISR(logic_level, pinno)` (`:251-306`)

| pinno | điều kiện | → `LPPP_INTERNALEVT` |
|-------|-----------|---------------------|
| `MAINSW_ON` (62) | `logic == 1` | `PWR_SW_ON` |
| | `logic == 0` | `PWR_SW_OFF` |
| `POWER_MONITOR` (48) | `is_power_flicker(logic)` true | `PWR_FLICKER` |
| `XEN_LVDS_ENG` (224) | luôn | `LVDS_INTERRUPT` |
| `WAKE_UP`(51) / `PANEL_SUBSW`(50) / `PANEL_WAKE`(54) / `DSET_EDH`(60) / `IR_CLOSE_WAKE`(59) / `UART16_WAKE`(56) / `WAKE_FAXSUBCPU`(57) / `WAKE_FIERY`(52) / `WAKE_USB_VBUS`(53) / `DOOR_OPEN`(61) | luôn | `WAKEUP_S1` |
| khác | – | `INVALID` (log "no event") |

`is_power_flicker(logic)` (`:225-238`): phát hiện **sườn lên 0→1** (`prev_logic_level==0 && logic==1`) với chống dội theo tick (`prev_tick_cnt < tick_cnt+1`). Static giữ `prev_logic_level` (init 1) + `prev_tick_cnt`. Dùng `xTaskGetTickCountFromISR`.

> Lưu ý: các pin `WAKEUP_S1` liệt kê trong switch **không nằm trong `gpio_info[]` có ISR** (chúng ở `wake_gpio_info[]` với `CallbackDummy`). Nên nhánh này của `AnalyzeEventfromISR` **thực tế không được kích qua `LPPP_GPIO_Callback`** — chỉ MAINSW/POWER_MONITOR/LVDS mới tới đây. (INFERENCE — xem §7.)

## 5. `LPPP_GPIO_CallbackMainSW` / `LPPP_GPIO_HandleMainSW` (`:641-712`)

- `LPPP_GPIO_HandleMainSW(true)`: `gpio_open` pin 62 IN → `gpio_isr_attach(msw_pin, LPPP_GPIO_CallbackMainSW, NULL, FALLING_EDGE)` → `gpio_isr_enable`. Static `msw_pin` chống đăng ký trùng.
- `LPPP_GPIO_HandleMainSW(false)`: `gpio_isr_detach` + `gpio_close` + `msw_pin = NULL`. Được `SCPIGetPmuEvent()` gọi với `false` (T2.6).
- `LPPP_GPIO_CallbackMainSW(ppin, logic, p)`:
  - `itern3 = gpio_get_itern(bank(62), 3)` — nếu bit của pin 62 set trong "itern register 3" ⇒ **"AP đang bật ngắt này, LPPP không làm gì"** (log).
  - ngược lại, nếu `logic == 0` (falling → OFF) ⇒ `LPPP_GPIO_Write(HRESET_REQN(66), 0)` — **kéo HRESET_REQN xuống LOW để tắt nguồn AP** (đường tắt nguồn cứng khi AP không phản hồi).
  - return false.

## 6. Đường "không ngắt": `LPPP_GPIO_WatchPort` + task `PowerControlIRQEvent`

`LPPP_GPIO_WatchPort(uint32_t *readval)` (`:405-505`): đọc lần lượt `PANEL_STOP, SSD_DETECT2, AP_PG, WARP_SW, SSD_DETECT, LOG_SW` bằng `LPPP_GPIO_Read` (→ `gpio_read` qua handle), set/clear bit `LPPP_GPIOFLAG_*` trong `*readval`. Lỗi đọc → `SYS_ERROR`.

`PowerControlIRQEvent` task (`LPPP_Task.c:480+`):
- đọc mốc `gpio_val` 1 lần đầu.
- vòng lặp: `vTaskDelayUntil(10ms)` → `LPPP_GPIO_WatchPort(&readval)` → nếu `gpio_val != readval` → `LPPP_GPIO_AnalyzeEvent(readval)` (🔴 thân **T.B.D**, luôn trả `PWR_SW_ON` — T3.2 đã ghi) → đẩy queue.
⇒ Đường polling GPIO 10ms này **chưa hoàn thiện** (`AnalyzeEvent` là stub). Chỉ đường ISR (`LPPP_GPIO_Callback`) là hoạt động thật.

## 8. FACT / INFERENCE / UNKNOWN

- **FACT**: toàn bộ 3 bảng pin + thuộc tính, `LPPP_INTERNALEVT` enum, `LPPP_GPIO_Setting` chỉ attach ISR cho pin 48 & 224, `wake_gpio_info` dùng `CallbackDummy` + `gpio_isr_setup` (không enable), `AnalyzeEventfromISR` mapping, `is_power_flicker` logic, `CallbackMainSW` kéo HRESET_REQN=0, `WatchPort` 6 flag, `PowerControlIRQEvent` 10ms + `AnalyzeEvent` stub, `c_intirq_table`.
- **INFERENCE**: nhánh `WAKEUP_S1` trong `AnalyzeEventfromISR` là code "để sẵn" — các pin đó ở `wake_gpio_info[]` (CallbackDummy) nên không gọi tới `LPPP_GPIO_Callback`. Việc đánh thức thực tế do HW wake domain + `power_cpu`. Chưa trace `gpio_isr_setup` vs `gpio_isr_enable` khác nhau ở HAL để khẳng định 100%.
- **INFERENCE**: `reg_B015` đọc trong `LPPP_GPIO_Setting` không dùng → chỉ kiểm tra flash đọc được (hoặc dead code). B014/B015 là breadcrumb ErP/sleep (T3.2).
- **UNKNOWN**: `gpio_get_itern(bank, 3)` — "itern register 3" là thanh ghi ngắt nào của GPIO controller (interrupt-enable của AP domain?). Cần đọc `Hal/quartz/.../gpio` driver (T7.3).
- **UNKNOWN**: `LPPP_GPIO_INFO_NUM` giá trị chính xác (sizeof bảng — ~40 phần tử), `gst_MsgQHandle_PowerCtrl` độ sâu.
- **UNKNOWN**: `gpio_api.h` chi tiết `gpio_isr_type_t` (LEVEL vs EDGE tác động HW thế nào), `gpio_logic_setting_t`.

## Tóm tắt (theo format skill)

**`LPPP_Gpio.c` để làm gì:**
Định nghĩa toàn bộ GPIO mà firmware KM đụng tới trên S800, chia 3 nhóm: (1) `gpio_info[]` — pin LPPP đọc/ghi trực tiếp (output điều khiển AP_PWR_EN/HRESET_REQN/IRIS_RESETN/ENG_STATUS…, input đọc mức SSD_DETECT/AP_PG/FW_CONFIG…), nhưng **chỉ 2 input POWER_MONITOR(48) và XEN_LVDS_ENG(224) gắn ISR thật**; (2) `wake_gpio_info[]` — 14 pin đánh thức phần cứng, chỉ nạp cấu hình ngắt (CallbackDummy) để HW wake domain đánh thức hệ thống; (3) MAINSW_ON(62) có ISR riêng kéo HRESET_REQN=0 khi tắt nguồn. ISR `LPPP_GPIO_Callback` chuyển sườn tín hiệu thành `LPPP_INTERNALEVT` (PWR_SW_ON/OFF, PWR_FLICKER, LVDS_INTERRUPT) rồi `xQueueSendFromISR` tới task PowerCtrl → `event_handler` → ma trận TR (T3.2/T3.3). Đường polling 10ms `PowerControlIRQEvent`/`LPPP_GPIO_AnalyzeEvent` còn là stub.

**Lifecycle 1 sự kiện PWR_SW_OFF:**
```
LPPP_KM_Init → LPPP_GPIO_Setting()
  ├─ gpio_open tất cả pin; gpio_isr_attach(LPPP_GPIO_Callback) cho pin 48, 224
  ├─ wake_gpio_info[]: gpio_isr_attach(CallbackDummy) + gpio_isr_setup (14 pin)
  └─ LPPP_GPIO_HandleMainSW(true): gpio_isr_attach(LPPP_GPIO_CallbackMainSW, FALLING) pin 62
người dùng nhấn công tắc nguồn → pin 62 falling edge
  → LPPP_GPIO_CallbackMainSW: itern3 bit set? (AP xử lý) : LPPP_GPIO_Write(HRESET_REQN,0)
(riêng đường event) MAINSW logic=0 trong AnalyzeEventfromISR → PWR_SW_OFF
  → xQueueSendFromISR(gst_MsgQHandle_PowerCtrl)
  → task PowerCtrl: event_handler(PWR_SW_OFF) → fpLPPP_ScenarioFunc[status][0] → TR函数
```
