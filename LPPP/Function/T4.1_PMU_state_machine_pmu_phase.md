| | Ở đâu | Nội dung |

## 1 · `pmu_init_level` — 7 pha (`power_api.h:12-20`)

```c
typedef enum {
    pmu_baseline = 0,   pmu_ap_link_up,   pmu_ap_link_down,
    pmu_system_up,      pmu_system_down,  pmu_suspend,   pmu_resume,
} pmu_init_level;
```

### Ai gọi pha nào (grep toàn repo)

| Pha | Caller | Ngữ cảnh |
|---|---|---|
| `pmu_baseline` | `hal_main.c:710` | `main()` giai đoạn 4 (bare-metal) |
| `pmu_ap_link_up` | `hal_main.c:184` (init_thread) + `power.c:1718/1724` (bên trong `pmu_infrastructure_resume`, có retry) | cold boot + resume |
| `pmu_system_up` | `hal_main.c:186` (init_thread) + `power.c:1737` (bên trong resume) | cold boot + resume |
| `pmu_system_down` | `power.c:1476` — bên trong `pmu_infrastructure_suspend` | suspend |
| `pmu_ap_link_down` | `power.c:1528` — bên trong `pmu_infrastructure_suspend` | suspend |
| `pmu_suspend` | `app_scpi.c:261` (`power_cpu` khi core A72 cuối tắt) + `power.c:2113` (`pmu_sleep_test`) | Sleep2/ErP |
| `pmu_resume` | `app_scpi.c:293` (`power_cpu` khi core A72 đầu bật) + `power.c:2110` (`pmu_sleep_test`) | wake |

`pmu_suspend` = `pmu_infrastructure_suspend()`; `pmu_resume` = `pmu_infrastructure_resume()`
(hai hàm này **gọi lại `pmu_phase`** cho `system_down`/`ap_link_down` và `ap_link_up`/`system_up`).

### Breadcrumb `uc_pmu_phase_rec` (`power.c:1884, 1898, 2120`)
```c
unsigned char uc_pmu_phase_rec = 0;
// đầu pmu_phase:  uc_pmu_phase_rec |= (1 << level);
// cuối pmu_phase: uc_pmu_phase_rec &= ~(1 << level);
```
Bitmap "pha nào đang chạy" (7 pha → bit 0-6). `LPPP_SpiFlashWrite_Ca72wdt_Reboot` (T3.2) ghi byte
này vào flash offset `+0x3E` → sau reboot biết CA72WDT nổ lúc `pmu_phase` nào (OP_BTS-16528).

### `pmu_suspend_active` (`power.c:1434-1439`) — guard chống gọi sai thứ tự
```
AWAKE=0 → TRANSITION_SLEEP=1 → SLEEP=2 → TRANSITION_AWAKE=3 → AWAKE
```
`pmu_infrastructure_suspend` yêu cầu vào ở `AWAKE`, `resume` yêu cầu vào ở `SLEEP` — sai →
`while(1)` ("should never happen, find the bug"). Toàn bộ suspend/resume bọc trong
`pmu_transition_mutex`.

## 2 · Chi tiết từng pha (từ `power.c:1900-2113`)

### `pmu_baseline` (0) — dựng PLL + clock cho R4/system
```
cpu_spin_delay(POWER_PHASE_BASELINE_DELAY)
lấy index: pmu_SYS_PLL, C2D(pmu_qspi_clk), C2D(pmu_i_clk_yyy_0s)
[rev ≥ A1 && GPIO I[31]==0]  power_up_clk[pmu_qspi_clk].div = 8   → 1600/8 = 200 MHz
pmu_set_clock(pmu_pibusclk / pmu_qspi_clk / pmu_i_clk_yyy_0s, ...)   ← chia an toàn trước khi khoá PLL
pmu_set_sspll(pmu_SYS_PLL, D0, SSPLL_SYS_DEFAULT=1600, ssc_off)
hwSetProcSpeed(SYS_BUS_CLOCK = 400/2 = 200)
power_set_clock_div()
pmu_set_sspll(pmu_MC_PLL, D0, 2100, ssc_off)
pmu_set_sspll(pmu_ND_PLL, D0, 2400, ssc_off)
pmu_set_device(pmu_PI, D0, 0)
pmu_set_device(pmu_PMU_M4, D2, 0)   ← M4 TẮT
pmu_set_device(pmu_UART0, D0, 0)    ← "temp"
```
`SSPLL_SYS_DEFAULT=1600`, `_MC=2100`, `_ND=2400` MHz (`power_api.h:26-33`).
SSC (spread-spectrum) mặc định: SYS `ssc_on_down_2`, MC `ssc_on_down_3` (`power_api.h:39-41`) —
nhưng `pmu_baseline` truyền `ssc_off` (SSC bật lại ở `pmu_system_up` qua SSCG reg).

### `pmu_system_up` (3) — bật mọi power domain: duyệt `power_up_dev[]` TỪ ĐẦU → CUỐI
```c
for (i = 0; i < POWER_DEVICE_TABLE_SIZE; i++) {
    if (b_isMCResume && device ∈ {MC_M3, MC_SPI0, MC_SPI1, MC_QSPI})  continue;   // MC tự giữ state khi resume
    if (!only_suspend_resume && !disabled_pu_sequence)  power_up_device_index(i);
    if (device == pmu_MC_M3)  { LPPP_traceclk_set(); LPPP_mc_spi_clk_set(); }      // T3.5
    else if (device == pmu_UL) { vbo_ul_init(); }
}
mrvl_regrdmwr32(0xE8241018, 0x01, 0x01) ; mrvl_regwrite32(0xE824101C, 0x23280095)  // SSCG (spread-spectrum) enable
if (!b_isMCResume) b_isMCResume = true;   // lần đầu = cold boot; các lần sau = resume
```

### `pmu_system_down` (4) — cắt mọi power domain: duyệt `power_up_dev[]` TỪ CUỐI → ĐẦU
```
[trừ khi pdf_skip_ap_l2_pd]:
  AP806 L2 flush: mrvl_regrdmwr32(AP806_CCU_B_L2EFR_0/1, 1, 1)  ; chờ bit 0x100
  AP806 L3 flush: mrvl_regwrite32(AP806_LLC_MNT_CIW, 0xFFFFFFFF)
for (i = TABLE_SIZE-1; i >= 0; i--) {
    power_up_dev[i].only_suspend_resume = false;    // cho phép resume lần sau
    if (!disabled_pd_sequence) {
        if (device == pmu_UL) {                     // ⚠ workaround "PMU_LIB で固まるため暫定"
            ghi 0xE82400A8/B0/40/D8/150/158/170/168/160  ← trực tiếp, 2× cpu_spin_delay(1s)
            mrvl_regwrite32(0xE8240994, 1) ; continue;   // KHÔNG gọi power_down_device_index
        }
        power_down_device_index(i);
    }
}
```
⚠ `pmu_UL` không đi qua `power_down_device_index` mà ghi ~9 thanh ghi PMU trực tiếp + 2 lần
`cpu_spin_delay(SECOND)` — vì `pmu_lib` treo với UL. Đây là điểm chậm nhất của suspend.

### `pmu_resume` (6) = `pmu_infrastructure_resume()` (`power.c:1692-1760`)
```
mutex_get(pmu_transition_mutex)
guard: pmu_suspend_active == SLEEP ? else while(1)
critical section:
   pmu_suspend_active = TRANSITION_AWAKE
   pmu_set_clock(i_clk_yyy_0s / qspi_clk, ..., div đã lưu)
   pmu_set_sspll(SYS_PLL, ssc_restore, freq_restore, ...)   ← khôi phục
pmu_set_device(pmu_MCix2_PHY, D0, P_STATE(0))
hwSetProcSpeed(proc_speed_restore)
pmu_set_sspll(ND_PLL, restore) ; pmu_set_sspll(MC_PLL, restore)
pmu_set_device(pmu_PI, D0, 0)
if (pmu_phase(pmu_ap_link_up)) {                 ← RETRY 1 lần:
     pmu_phase(pmu_ap_link_down) ; PI→D3 ; delay 100ms ; PI→D0
     if (pmu_phase(pmu_ap_link_up)) return -1;   ← thất bại → -1 (power_cpu để CA72WDT nổ)
}
init_ddr(true, pmu_ddr_callback)                 ← DDR THOÁT self-refresh; callback bơm item không cần DDR song song
mc_restore_state()
pmu_phase(pmu_system_up)                          ← §pmu_system_up (b_isMCResume=true → skip MC_*)
notify drivers: cb[i]->resume(dev[i], 1<<i)
pmu_suspend_active = AWAKE
mutex_put ; return 0
```

## 3 · `power_up_dev[]` — bảng thứ tự power domain (`power_device_init.h:27-100`)

```c
typedef struct {
    pmu_devices  device;              // pmu_MC_M3, pmu_SB_iris, pmu_UL, pmu_GPU, pmu_PG02...
    pmu_devices  clock;               // clock buộc vào device
    pmu_device_state power_up_state;  // thường pmu_D0
    pmu_device_state power_down_state;// pmu_D1 / D2 / D3
    uint32_t pu_param, pd_param;
    PFN_POWER_ACTION pfn;             // hành động tuỳ biến: pmu_iris_actions / pmu_ap806_mci / pmu_ap806_pll / pmu_clkgen_autoenable
    uint32_t restore_state:4;         // trạng thái để khôi phục
    uint32_t only_suspend_resume:1;   // chỉ đụng lúc suspend/resume (Iris) — đặt lúc init, xoá lúc suspend
    uint32_t disabled_pd_sequence:1;  // bỏ qua trong pmu_system_down
    uint32_t disabled_pu_sequence:1;  // bỏ qua trong pmu_system_up
    uint32_t resume_restore:1;        // RESUME dùng restore_state thay vì power_up_state
} device_settings_t;
#define C2D(x)  (x | 0x80)           // mã hoá CLOCK thành device (schema sleep2)
```

**`pmu_device_state`** (`pmu_lib.h:12-18`): `D0`=bật đầy đủ, `D1`=trung gian, `D2`=tắt (đa số
device khi sleep2), `D3`=tắt sâu nhất (PI), `SKIP`=15.

**Thứ tự bảng** (power up từ trên xuống, power down từ dưới lên) — nhóm chính:

| Vị trí | Device | Ghi chú |
|---|---|---|
| đầu (không trong seq) | `SYS_PLL`, `C2D(i_clk_yyy_0s)` div1, `C2D(qspi_clk)` div2, `clkgen_d1`, `NB_mci0/1/2` (`pfn=pmu_ap806_mci`), `NB_PLLc0/1` (`pfn=pmu_ap806_pll`) | `disabled_pu/pd_sequence=1` — chỉ dùng qua lệnh `power` thủ công |
| MoChi/clock | `MCiClk0_x4`, `MCix4_PHY`, `MCiClk1` (KM=SB), `MCiClk2` (KM=NB) | |
| **Iris** | `SB_iris` (PCIe PU/PD, USB PU/PD, `pfn=pmu_iris_actions`, `only_suspend_resume=1`) | 2 entry (PCIe + USB) tách riêng (`commit ec36a21e` — "USB Host と PCIE の PU/PD を切り離す") |
| **UL** | `pmu_UL` D0→D2, `pu/pd_param=PMU_UL_SKIP_UNGATEWAIT`, `resume_restore=1` | bật **trước** NB0_iris (2018/04/13) |
| **Iris NB** | `NB0_iris` (`pu_param=POWER_IRIS_TOP_PU_LINK`), `NB1_iris` (+PCIe+USB+GBE clk) | `pd_param=0` (AP806/Iris power removed) |
| | `MCix2`, `MCix2_PHY`, **`Mech_TOP`** D0→D2 (`resume_restore`), `VBO_RX_0/1` | |
| **MC** | `MC_SPI0`, `MC_SPI1`, `MC_QSPI`, `MC_M3` — tất cả D0→D2, `resume_restore=1` | `pmu_system_up` skip nếu `b_isMCResume` (MC tự giữ) |
| | `TSEN`, `CDMA` (`resume_restore`), `UART1..6`, `I2S` (`resume_restore`), `LCD` (`resume_restore`) | |
| | `USB` D0→D2 (`disabled_pu/pd_sequence=1` — LPPP USBD driver tự quản) | |
| | `GPU` (`resume_restore`), `JPEG` (`resume_restore`), `SDMMC` D0→**D1**, `SDMMC_PHY` D0→D2 | |
| cuối | **`PG02, PG10..PG14, PG23..PG34`** (~20 power gate) D0→D2 | |

**`resume_restore` = chìa khoá tiết kiệm điện resume:** device có cờ này → sau wake dùng
`restore_state` (trạng thái trước sleep) thay vì `power_up_state`. Nếu device đã TẮT trước sleep,
nó vẫn TẮT sau resume. `UART0` cố tình **không** trong bảng ("lets keep this running in sleep").

## 5 · Tóm tắt (theo format skill)

**1. Tồn tại để làm gì:** `pmu_phase(level)` (source ở `power.c`) là bộ điều phối 7 pha PMU —
`baseline` (PLL + clock R4), `ap_link_up/down` (nguồn + liên kết AP806), `system_up/down` (duyệt
`power_up_dev[]` bật/tắt ~50 power domain theo thứ tự), `suspend/resume` (= `pmu_infrastructure_*`:
notify driver → system_down → DDR self-refresh → ap_link_down → PLL D2 · và chiều ngược). Các
primitive `pmu_set_device/clock/sspll` + `pmu_send_cmd` nằm trong `libpmu_r4.a` (binary), chạy
trên R4 (M4 tắt), điều khiển PMU hardware `0xE8240000`.

**2. Call flow:**
```
COLD: main → pmu_phase(baseline)
      init_thread → pmu_phase(ap_link_up) → pmu_phase(system_up)
SUSPEND: power_cpu[core cuối] → pmu_phase(pmu_suspend) = pmu_infrastructure_suspend
           ├ drivers.suspend()
           ├ pmu_phase(pmu_system_down)   [power_up_dev[] B→T, L2/L3 flush]
           ├ sys_save_state (DDR→SR) + mc_save_state
           ├ pmu_phase(pmu_ap_link_down)  [ap806_power_on(false)]
           └ PI→D3, MC/ND/SYS PLL→D2, drop proc speed → SLEEP
RESUME: power_cpu[core đầu] → pmu_phase(pmu_resume) = pmu_infrastructure_resume
           ├ restore clk/PLL, hwSetProcSpeed
           ├ pmu_phase(pmu_ap_link_up)  [retry 1 lần; fail→-1]
           ├ init_ddr(true, callback)   [DDR thoát SR]
           ├ pmu_phase(pmu_system_up)   [power_up_dev[] T→B, skip MC_* nếu b_isMCResume]
           └ drivers.resume() → AWAKE
```

**3. File đã tham chiếu:**
- `Hal/quartz/asic/build/power.c:1434-1608, 1692-1760, 1884-2130`
- `Hal/quartz/asic/build/power_api.h:12-90`
- `Hal/quartz/asic/build/power_device_init.h:1-100`
- `Hal/quartz/asic/build/pmu_lib.h:10-360`
- `lib/libpmu_r4.a` (binary — prototype only)

**4. Đã xác nhận / phát hiện:**
- ✅ 7 pha: `baseline / ap_link_up / ap_link_down / system_up / system_down / suspend / resume`.
- ✅ `pmu_suspend`/`pmu_resume` = wrapper `pmu_infrastructure_*` gọi lại `pmu_phase` cho các pha con.
- ✅ `power_up_dev[]` = danh sách có thứ tự ~50 device; `system_up` duyệt xuôi, `system_down` duyệt ngược.
- ✅ `resume_restore:1` = nhiều device dùng trạng-thái-trước-sleep khi wake (tiết kiệm điện).
- ✅ `b_isMCResume` → `system_up` **bỏ qua** `MC_M3/SPI0/SPI1/QSPI` khi resume (MC tự giữ state).
- ✅ `pmu_UL` không đi qua `power_down_device_index` — ghi ~9 reg PMU trực tiếp + 2×1s delay
  (workaround "PMU_LIB で固まる"). Điểm chậm nhất của suspend.
- ✅ `pmu_resume` retry `ap_link_up` 1 lần; thất bại lần 2 → return `-1` → `power_cpu` để CA72WDT nổ.
- ✅ `uc_pmu_phase_rec` = bitmap pha đang chạy, ghi vào flash khi CA72WDT nổ (OP_BTS-16528).
- ✅ `pmu_suspend_active` (AWAKE/TRANS_SLEEP/SLEEP/TRANS_AWAKE) + `pmu_transition_mutex` chống race.
- ✅ M4 (`pmu_PMU_M4`) bị giữ `D2` (tắt) ở `pmu_baseline`.
- UNKNOWN: nội dung `pmu_send_cmd(command)` word format, và `libpmu_r4.a` sequencing nội bộ (binary — cần disassemble với arm toolchain).
