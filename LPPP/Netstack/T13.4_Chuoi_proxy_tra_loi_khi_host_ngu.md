# T13.4 — Chuỗi "trả lời proxy khi host ngủ" đầu-cuối

Tổng hợp T5.1 (lwIPv6 + GMAC) → T5.6 (SysFilter callback) → T5.3/T5.4 (proxy) → T6 (HCI FIFO).
Nguồn: `Netstack/lwipv6/src/netif/ethernetif.c`, `Sys/filter/sys_filter_main.c`, `Application/thread/app_thread.c`, `Application/{llmnr_proxy,snmp_proxy,wake_service_proxy,simple_mdns_proxy}/`.

**Bối cảnh:** máy đang **Sleep2/ErP** (T13.2). A72 off, DDR self-refresh. R4 còn tỉnh (hoặc wfi nhẹ, thức bởi ngắt). GMAC (Iris) còn điện. `RedirectTraffic == false` (Linux đã GOODBYE — T6). IP/MAC của máy đã được Linux nạp vào netif R4 trước khi ngủ (T5.5).

---

## 0. Sơ đồ tổng — trường hợp LLMNR query "PRINTER01?"

```
PC trên mạng phát: UDP mcast 224.0.0.252:5355  "who is PRINTER01?"
  │
  ▼
① GMAC (Iris SB0) DMA gói vào RX descriptor (.netbufsec, NOCACHE, LCM/vùng 80KB — T5.1)
   → poll timer 10ms: HalApiCpuTimer_UpdateTickCount → HalEth_bmu_isr (POLL_PACKETS bit, T7.7)
  │
  ▼
② task ETH_I: ethernetif_input → low_level_input (ethernetif.c, T5.1)
   ├─ if (RedirectTraffic)  → HCI FIFO ... (KHÔNG — host ngủ, RedirectTraffic=false)
   ├─ SysFilter_Execute_Filter(pkt, len, STAGE_1)                              (T5.2)
   │     magic-packet cb0? (không) ; wake_services_stage1 cb1 (SLP raw)? (không) ; CATCH_UNKNOWN cb4:
   │        EthType 0x0800 (IPv4) → save_stage1_data(...) → return SYS_FALSE   (không claim, cho qua)
   ├─ saved_rawpacket = pbuf_ref(p)   (giữ tham chiếu cho STAGE_2 forward)
   └─ xNetIf->input(p, netif)  →  ethernet_input  →  ip4_input  (lwIP)
  │
  ▼
③ ip4.c: sau khi bóc IP header, trước khi giao L4 →
   SysFilter_Execute_Filter(udp_payload, len, STAGE_2)   (filterprot != 0)     (T5.2/T5.3)
   ├─ SysFilter_PacketFilterGetMatchingFilterOfPacket:
   │     duyệt FilterCfgList; filter ID_FILTER_STAGE2_LLMNR_PROXY:
   │        pattern {offset 2, val 0x14eb0000, mask 0xffff0000} → dst port 5355 KHỚP
   │        FilterFunctionID & FILTER_ENABLE_CALLBACK → FFL[6] = filter_function_snmp_llmnr_nbns_etc
   │        (*ffunc)(i, Protocol, PacketType, p, length):
   │           FilterID == ID_FILTER_STAGE2_LLMNR_PROXY → llmnr_proxy_process_request(...)   (T5.3)
   │              ├─ dst port 5355, mcast 224.0.0.252 ✓
   │              ├─ parse DNS question: qname="PRINTER01", qtype
   │              ├─ conflict bit (q_flags & 0x400)?  → nếu có: ApiSysNetworkWakupAndForwardPacketToDriver (wake+forward)
   │              ├─ normalize name uppercase, so với query_name đã cấu hình (Linux nạp qua IOCTL/MSG_CMD)
   │              │     - không khớp / qtype lạ  → return SYS_TRUE (silent — filter khớp → DISCARD, không trả lời)
   │              │     - KHỚP  → build DNS response:
   │              │         q_flags = 0x8000 (response), ancount=1, RR: name + type + TTL + rdata (IP máy)
   │              │         appSendUdpPacket(msg, len, dst_port=5355, src_ip=PC, src_port=5355, is_ipv4, false)  (T5.6)
   │              │            → ApiSysSocket(AF_INET, DGRAM) → bind 5355 → SendTo → close
   │              │            → lwIP udp_sendto → ip4_output → etharp → low_level_output → HalApiLan_Send
   │              │            → GMAC TX descriptor → gói RESPONSE ra dây
   │              └─ return SYS_TRUE
   │     → filter LLMNR "khớp" → return (i | FILTER_ID_MATCH)
   ├─ ActionFlags của filter LLMNR = PATTERN_FLAG_DISCARD_PACKET  (T5.4)
   │     → KHÔNG FOR_APP_LAYER, KHÔNG FORWARD, KHÔNG WAKE_SYSTEM
   │     → return RC_DISCARD_PACKET
   └─ ip4_input: gói bị DISCARD khỏi lwIP local ; pbuf_free(saved_rawpacket)
  │
  ▼
④ Kết quả: PC nhận LLMNR response "PRINTER01 = <IP máy>".
   Máy VẪN NGỦ. A72 không thức. Linux không biết gì.
```

## 1. Các nhánh proxy khác (cùng khung)

| proxy | filter (port) | callback | offline trả lời | wake khi |
|-------|---------------|----------|-----------------|----------|
| **LLMNR** | 5355 (`ID_FILTER_STAGE2_LLMNR_PROXY`, DISCARD) | FFL[6] `filter_function_snmp_llmnr_nbns_etc` → `llmnr_proxy_process_request` | tên khớp query_name → DNS response `appSendUdpPacket` | conflict bit `q_flags&0x400`, hoặc build/send lỗi |
| **NBNS** | 137 (`ID_FILTER_STAGE2_NBNS_PROXY`, DISCARD) | FFL[6] → `nbns_proxy_process_request` | tương tự LLMNR (NetBIOS name) | tương tự |
| **SNMP** | 161 (`ID_FILTER_STAGE2_SNMP_PROXY`, DISCARD) | FFL[6] → `snmp_proxy_process_request` (T5.4) | OID trong `proxylist[]` + `support&1` & value≠NULL → GET-RESPONSE `0xa2`; not-supported → SNMP error | community sai / OID lạ / `OID_MATCH_REQUEST` (SNMP2 → `LPPP_SetWakeInfo(SNMP2)`) / gói hỏng → `WAKE_AND_RETURN` |
| **mDNS** | 5353 (`ID_FILTER_STAGE2_MDNS_PROXY`, flags NONE) | FFL[7] `filter_function_mdns_proxy` → `simple_mdns_proxy_process_request` (T5.3) | tên khớp → mDNS response | — (flags NONE: khớp xong nhả cho stack) |
| **wake-service** SSDP/WSD/SLP | 1900/3702/427 (`ID_FILTER_STAGE2_WAKE_SERVICE_REQUEST`, DISCARD\|FORWARD\|WAKE_SYSTEM) | FFL[6] → `wake_service_proxy_process_request` (T5.4) | **không trả lời** — chỉ phát hiện | khớp ≥1 chuỗi đã đăng ký → return SYS_TRUE → ActionFlags forward + WAKE_SYSTEM |
| **ARP** | ethertype 0x0806 | (không filter — DISABLED) → lwIP `etharp` tự trả (T5.5) | ARP reply cho IP máy | gratuitous ARP trùng IP (FFL[2] nếu bật) |
| **NS (IPv6)** | — | (không filter) → lwIP `nd6` tự trả (T5.5) | Neighbor Advertisement | DAD (`filter_function_check_icmpv6_solit`, không đăng ký) |

## 2. Ba loại kết cục cho 1 gói khi host ngủ

| kết cục | cơ chế | ví dụ |
|---------|--------|-------|
| **A. Trả lời offline** (host ngủ tiếp) | proxy build response + `appSendUdpPacket`/`etharp` → GMAC TX; filter DISCARD gói vào | LLMNR/NBNS/mDNS tên khớp; SNMP OID có sẵn; ARP/NS cho IP mình |
| **B. Nuốt im lặng** (host ngủ tiếp, không trả lời) | proxy return SYS_TRUE nhưng không gửi gì; filter DISCARD | LLMNR tên lạ; mDNS không khớp; broadcast/mcast không quan tâm; `CATCH_UNKNOWN` |
| **C. Đánh thức host** | `WAKE_AND_RETURN` (SNMP) hoặc ActionFlags `WAKE_SYSTEM` (wake-service, magic-packet) → `SYS_EVENT_WAKE_SYSTEM` + forward gói qua HCI FIFO up_packets → `power_cpu(0,0)` (T13.3) | lệnh in (USB/wake-service); SNMP2 job; TCP SYN tới cổng in; magic packet; unicast lạ tới MAC mình |

## 3. Vì sao chạy được khi DDR self-refresh

- **Buffer mạng ở LCM/NOCACHE 80KB** (T1.6, T5.1): RX/TX descriptor (`.netbufsec`), pbuf pool (`.bufpools`) — KHÔNG ở DDR. GMAC DMA vào LCM.
- **HCI FIFO ở LCM `0xE8200800`** (T6): forward gói lên Linux cũng không cần DDR (nhưng Linux ngủ nên ring chỉ tích lại tới khi wake).
- **Code proxy** chạy XIP từ QSPI CS1 `0xF8000000` (T12.4) + stack/heap R4 ở SRAM nội (T1.5) — không đụng DDR.
- lwIP stack + `SysFilter` + proxy tables đều trong SRAM R4.
⇒ R4 xử lý mạng hoàn toàn độc lập với DDR/A72.

## 4. FACT / INFERENCE / UNKNOWN

- **FACT**: luồng `low_level_input` → STAGE_1 (`save_stage1_data`, `saved_rawpacket = pbuf_ref`) → `xNetIf->input` → `ip4_input` → STAGE_2; STAGE_2 filter khớp port → FFL callback → proxy; ActionFlags DISCARD → gói không lên stack local (T5.2/T5.3/T5.6).
- **FACT**: `appSendUdpPacket` tạo socket → bind → SendTo → close, đi qua lwIP udp_sendto → `HalApiLan_Send` → GMAC TX (T5.6).
- **FACT**: bảng §1 (filter/callback/ActionFlags) khớp `filter_stage_2[]` trong `app_thread.c` (T5.4) và Makefile (`SNMP_PROXY`/`LLMNR_PROXY`/`NBNS_PROXY`/`WAKE_SERVICE_PROXY`/`SIMPLE_MDNS_PROXY` bật, T11.1).
- **INFERENCE**: query_name/OID/wake-string được Linux nạp trước khi ngủ qua `MSG_CMD_PATTERN_*` / IOCTL (HCI FIFO down_data). Chưa trace lệnh Linux cụ thể cho từng proxy (T5.4 nói `snmp_proxy_add_records`, `wake_service_proxy_add_records`).
- **INFERENCE**: "R4 còn tỉnh khi host ngủ" — R4 không power-off ở Sleep2; có thể `SysSystem_CpuSleep` wfi nhẹ giữa các tick nhưng thức bởi timer 10ms để poll GMAC (T7.7). Chưa đo hiệu năng.
- **UNKNOWN**: độ trễ từ gói vào tới response ra (phụ thuộc timer poll 10ms + xử lý). `llmnr_proxy_process_request` / `nbns` thân đầy đủ (T5.3 đọc 1 phần).
- **UNKNOWN**: pbuf pool có đủ khi burst gói lúc ngủ không (heap APP 3KB — T1.5). Xử lý khi hết buffer.

## Tóm tắt (theo format skill)

**Khi host ngủ (Sleep2/ErP), R4 tự trả lời các truy vấn mạng vặt mà không đánh thức A72.** Gói vào GMAC (Iris) → DMA vào buffer LCM (không DDR) → poll timer 10ms → task ETH_I → `low_level_input`: vì `RedirectTraffic==false`, không forward lên Linux mà chạy `SysFilter` 2 tầng. STAGE_1 (raw) chủ yếu bắt magic-packet/SLP; STAGE_2 (sau khi lwIP bóc IP/UDP) so `dst_port` với bảng filter → callback FFL[6]/FFL[7] gọi proxy tương ứng (LLMNR 5355, NBNS 137, SNMP 161, mDNS 5353, wake-service 1900/3702/427). Proxy: nếu tên/OID khớp cấu hình Linux nạp sẵn → build response + `appSendUdpPacket` → lwIP → `HalApiLan_Send` → GMAC TX (gói trả lời ra dây), filter DISCARD gói vào → **host ngủ tiếp**; nếu không khớp → nuốt im; nếu là lệnh in / SNMP2 / gói lạ tới MAC mình → `WAKE_AND_RETURN` / ActionFlags `WAKE_SYSTEM` → forward gói qua HCI FIFO + `SYS_EVENT_WAKE_SYSTEM` → `power_cpu(0,0)` đánh thức A72 (T13.3). ARP/NS do lwIP `etharp`/`nd6` tự lo. Toàn bộ chạy trong SRAM R4 + LCM + XIP QSPI CS1, độc lập DDR.
