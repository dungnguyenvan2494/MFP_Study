# T9.2 — `wake_USBD` (`Sys/wake_USBD/lpp_usbd.c`): tiếp tục USB2-device khi host ngủ

Nguồn: `lppp_s800/Sys/wake_USBD/lpp_usbd.c` (375 dòng),
`lppp_s800/Hal/quartz/asic/a0/include/asic_usb.h:129-145`,
`lppp_s800/Hal/quartz/asic/a0/include/regAddrs.h:96` (`USB2D_BASE`), `intnums.h:82` (`INTNUM_USB`),
`lppp_s800/Sys/init/sys_init.c:173-177` (`lpp_usbd_init` gọi từ `SysApi_InitApplModules`),
`lppp_s800/Hal/quartz/asic/linker_common/memory_sections.ld:60-64` (`.usbd2_qh_sec`, T6).

Mục tiêu: khi Linux ngủ, R4 giữ **USB2.0 device** (cổng USB-B của máy in, "USBPrinter") "sống" đủ để **đánh thức host** khi PC gửi lệnh in, mà không cần DDR.

---

## 1. Phần cứng

| | |
|-|-|
| Controller | USB2 device (ChipIdea/Marvell **VUSB20**, EHCI-derived) tại **`USB2D_BASE = 0xE8250000`** |
| Ngắt | `INTNUM_USB = 37 + 32` = **GIC ID 69** |
| dQH list | **`__qhead_start__` = LCM SRAM `0xE8200000` + 0** (2KB, section `.usbd2_qh_sec` — T6 §1). Thanh ghi `EPLISTADDR` phải trỏ tới đây |
| Wake EP | `LPP_USBD_WAKE_EP = USBD_EP(1)` = bit 1 (endpoint 1, cả RX & TX) |

**Vì sao dQH ở LCM SRAM chứ không DDR:** LCM SRAM luôn có điện (kể cả Sleep2/ErP), còn DDR ở self-refresh (T8.1). Controller USB DMA descriptor từ LCM ⇒ USB nhận/NAK được trong khi DDR ngủ và Linux tắt. Linux driver phải cấu hình `EPLISTADDR = 0xE8200000` (khớp DTS `usbd_qhead_lcm`).

`USB3D_USB2D_REGS_t`: `USBCMD` (RS bit = run/stop), `USBSTS`, `USBINTR` (SLE/URE/PCE/UEE/UE/NAKE), `PORTSC` (PHCD = "PHY Low Power Clock Disable"), `EPLISTADDR`, `ENDPTSTAT`, `ENDPTFLUSH`, `ENDPTPRIME`, `ENDPTNAK`, `ENDPTNAKEN`, `DCCPARAMS` (max EP).

## 2. `lpp_usbd_init(mem, memsize)` — `SysApi_InitApplModules` (T1.5)

```c
pmu_set_device(pmu_USB, pmu_D0, 0);      // giữ USB power domain ON
pmu_pm_ops(&usbd_ops, NULL);             // đăng ký callback suspend/resume
return 0;
```
```c
pmu_pm_ops_t usbd_ops = {
    .suspend = lpp_usbd_open,     // gọi KHI ĐI NGỦ  (sau khi CPU power-down, DDR còn on)
    .resume  = lpp_usbd_close,    // gọi KHI THỨC   (DDR còn on, trước khi CPU power-on)
};
```
`pmu_pm_ops` = danh sách callback được `pmu_phase` (T4.1) gọi theo thứ tự trong quá trình chuyển trạng thái; `pmu_pm_ops_done(flags)` báo hoàn tất (`PMU_PM_DONE_WITH_ERROR` nếu lỗi).

> ⚠️ Tên hàm ngược trực giác: `lpp_usbd_open` = **suspend** hook (mở đường wake-on-USB), `lpp_usbd_close` = **resume** hook (đóng lại, trả cho Linux).

## 3. `lpp_usbd_open` / `_lpp_usbd_open` — thiết lập wake-on-USB khi đi ngủ (`:276-345`)

### 3.1 Kiểm tra điều kiện (nếu fail → `pmu_pm_ops_done(flags | PMU_PM_DONE_WITH_ERROR)` + restore power, `return -1`)
| kiểm | ý nghĩa fail |
|------|--------------|
| `usbd_init` đã true | double-suspend |
| `pmu_get_device(pmu_USB, &restore_power_state)` > 0 | USB đã ở D1+ (Linux đã tắt) → không wake được |
| `PORTSC.PHCD == 1` | **Linux đã tắt PHY clock** (disable WAKE-on-USBD) → bus rớt → bỏ qua |
| `USBCMD.RS == 0` | controller đã stop |
| `EPLISTADDR != __qhead_start__` | Linux chưa đặt dQH vào LCM SRAM |

Nếu OK: `pmu_set_device(pmu_USB, restore_power_state, 0)` (đảm bảo D0 đầy đủ, không half-gated).

### 3.2 Cấu hình wake
```c
endpoint_wake = LPP_USBD_WAKE_EP;                 // EP1
lpp_usbd_endpoint_convert(&endpoint_wake);
intAttach(INTNUM_USB, 0, lpp_usbd_isr, 0);
intEnable(INTNUM_USB);
usbd_init = true;
```

### 3.3 `lpp_usbd_endpoint_convert(endpoint_wake)` (`:225-259`)
```c
usbd_entry_intr  = USBINTR;        // LƯU để khôi phục
usbd_entry_naken = ENDPTNAKEN;

USBINTR = 0;
USBINTR |= SLE  (sleep/suspend)    // bus vào suspend
USBINTR |= URE  (usb reset)        // host reset bus
USBINTR |= PCE  (port change)      // cắm/rút, resume
USBINTR |= UEE  (error)
USBINTR |= UE   (usb int)
USBINTR.NAKE = 0;

ENDPTNAK = 0xFFFFFFFF;             // xoá NAK cũ
ENDPTNAKEN = *endpoint_wake;       // EP1 rx16|tx16 bit → sinh ngắt khi EP đó NAK
if (*endpoint_wake) USBINTR.NAKE = 1;   // bật NAK interrupt
```
⇒ **R4 sẽ thức khi**: bus suspend/reset/port-change/error, HOẶC **EP1 NAK** (host PC gửi data tới EP1 nhưng R4 không có buffer sẵn → controller trả NAK → ngắt → wake).

`lpp_usbd_config_t` (bitfield 32-bit): `rx16:16` (b15:0 = RX EP cần wake), `tx16:16` (b31:16 = TX EP).

### 3.4 `lpp_usbd_enter_nak()` (`:72-170`) — xả các EP đang dở dang
Cho mỗi EP (tới `DCCPARAMS & MAX_ENDPTS`):
- nếu `dQH->SIZE_IOC_INT_STS & ACTIVE` và `ENDPTSTAT & bit` → `ENDPTFLUSH = bit`; poll `while (ENDPTFLUSH & bit)`.
- sau flush: nếu TD **vẫn** active → *"why? Handle wake?"* → `SYS_EVENT_WAKE_SYSTEM` ngay (đang giữa transaction, không ngủ được).
- nếu đã hết active (packet "raced in" trước flush) → gói đó sẽ tự sinh wake, không cần làm gì.
- TD hoàn tất chưa xử lý → bit ngắt sẽ wake khi tới lượt.

⇒ Mục đích: đưa mọi EP về trạng thái "sẽ NAK" khi có data mới, thay vì nhận thầm vào buffer mà không ai xử lý.

## 4. `lpp_usbd_isr(value)` — khi USB đánh thức (`:62-70`)

```c
usbd_exit_intr = USBSTS;                     // lưu nguyên nhân
intDisable(usbd_intnum);                     // một-lần
SysApiThread_EventFlagsSet(SysSystem_SysEventGroup, OR, SYS_EVENT_WAKE_SYSTEM);
LPPP_SetWakeInfo(LPPP_WAKE_INFO_USB);        // báo host lý do wake = USB (T2.6)
```
`SYS_EVENT_WAKE_SYSTEM` → `SysSystem_handle_link_events` → `power_cpu(0,0)` (T6 §7.3) đánh thức A72.

## 5. `lpp_usbd_close` — resume hook (`:347-368`)

```c
if (!usbd_init) { pmu_set_device(pmu_USB, restore_power_state); ...ERROR; return -1; }
intDisable(usbd_intnum);
lpp_usbd_endpoint_restore();       // USBINTR = usbd_entry_intr; ENDPTNAKEN = usbd_entry_naken
usbd_init = 0;
pmu_pm_ops_done(flags);
```
`lpp_usbd_exit_nak()` (`:173-223`) — re-prime (`ENDPTPRIME = bit`) các EP đã flush lúc `enter_nak`, để USB stack của Linux tiếp tục bình thường sau khi thức.

> Comment: `lpp_usbd_close` "MUST be called while DDR is on, before CPU is PowerOn" — nghĩa là khôi phục USB register **trước** khi A72/Linux chạy lại, để driver Linux thấy trạng thái nhất quán.

## 6. Vị trí trong luồng power (T4.1)

```
đi ngủ (pmu_phase → suspend callbacks):
  ... pmu_infrastructure_suspend ...
  usbd_ops.suspend = lpp_usbd_open()
     ├─ validate (PHCD? RS? EPLISTADDR?)
     ├─ lpp_usbd_endpoint_convert(EP1)   → USBINTR = SLE|URE|PCE|UEE|UE|NAKE; ENDPTNAKEN = EP1
     ├─ (lpp_usbd_enter_nak — flush EP dở)
     └─ intAttach/Enable(INTNUM_USB, lpp_usbd_isr)
  ... R4 wfi, DDR self-refresh, Linux off ...

PC gửi lệnh in → USB EP1 NAK → GIC 69 → lpp_usbd_isr
  → SYS_EVENT_WAKE_SYSTEM + LPPP_SetWakeInfo(USB)
  → power_cpu(0,0) → A72/Linux thức

thức (pmu_resume → resume callbacks):
  usbd_ops.resume = lpp_usbd_close()
     ├─ intDisable(INTNUM_USB)
     ├─ lpp_usbd_endpoint_restore()   → USBINTR/ENDPTNAKEN về giá trị Linux
     └─ (lpp_usbd_exit_nak — re-prime EP)
  → Linux USB driver tiếp tục, nhận nốt lệnh in
```

## 7. FACT / INFERENCE / UNKNOWN

- **FACT**: `USB2D_BASE=0xE8250000`, `INTNUM_USB=GIC 69`, dQH tại `__qhead_start__` = LCM `0xE8200000`; `lpp_usbd_init` = `pmu_set_device(pmu_USB, D0)` + `pmu_pm_ops(&usbd_ops)`; `usbd_ops.suspend = lpp_usbd_open`, `.resume = lpp_usbd_close`; `lpp_usbd_open` validate PHCD/RS/EPLISTADDR rồi `endpoint_convert` + attach ISR; `USBINTR` wake bits = SLE|URE|PCE|UEE|UE(+NAKE nếu có EP); `ENDPTNAKEN = EP1`; `lpp_usbd_isr` → `SYS_EVENT_WAKE_SYSTEM` + `LPPP_SetWakeInfo(LPPP_WAKE_INFO_USB)`; `enter_nak` flush EP dở, `exit_nak` re-prime; gọi từ `sys_init.c:174`.
- **INFERENCE**: USB device = cổng USB-B "USBPrinter" (khớp `wake_gpio_info` pin 53 `WAKE_USB_VBUS` "for PMU, USBPrinter" — T7.2). Wake path chính là **EP1 NAK** khi PC gửi print job. Chưa xác nhận EP1 = bulk-OUT của giao thức in.
- **INFERENCE**: Linux tắt wake-on-USB bằng cách set `PORTSC.PHCD` (PHY clock disable) → `lpp_usbd_open` phát hiện và bỏ qua. Nghĩa là wake-on-USB là **tuỳ chọn do Linux bật/tắt** trước khi ngủ.
- **INFERENCE**: `pmu_USB` D2 = PMUlib tắt PHY (comment); ở đây `lpp_usbd_open` ép D0 để giữ PHY → USB nhận được. Trade-off điện năng.
- **UNKNOWN**: `VUSB20_EP_QUEUE_HEAD_STRUCT` layout, `pmu_pm_ops` cơ chế danh sách (số slot, thứ tự gọi), `power_get_schema`/`power_debug_flags`.
- **UNKNOWN**: có `wake_USBD` cho USB3 không (file chỉ USB2D). USB3/PCIe = `wake_PCIE` (T9.3).
- **UNKNOWN**: `restore_power_state` được `pmu_get_device` trả về cái gì khi USB "half on" (D0 nhưng gated).

## Tóm tắt (theo format skill)

**`lpp_usbd.c` để làm gì:**
Đăng ký cặp callback suspend/resume vào PMU (`pmu_pm_ops`) để, khi máy in đi ngủ, R4 tiếp quản controller USB2-device (`0xE8250000`) và giữ nó nhận dữ liệu từ PC dù DDR đang self-refresh và Linux đã tắt — nhờ dQH đặt ở LCM SRAM (`0xE8200000`) luôn có điện. Hook suspend (`lpp_usbd_open`) kiểm tra Linux chưa tắt PHY (`PORTSC.PHCD`), cấu hình `USBINTR` để ngắt khi bus suspend/reset/port-change/error hoặc **EP1 NAK**, flush các endpoint đang dở, rồi attach `lpp_usbd_isr` vào `INTNUM_USB` (GIC 69). Khi PC gửi lệnh in → EP1 NAK → ISR set `SYS_EVENT_WAKE_SYSTEM` + `LPPP_SetWakeInfo(USB)` → `power_cpu` đánh thức A72. Hook resume (`lpp_usbd_close`) khôi phục `USBINTR`/`ENDPTNAKEN` về giá trị Linux và re-prime endpoint trước khi Linux chạy lại.

**Bảng lifecycle:**
| pha | hàm | thao tác chính |
|-----|-----|----------------|
| init | `lpp_usbd_init` | `pmu_set_device(pmu_USB, D0)`; `pmu_pm_ops(&usbd_ops)` |
| suspend | `lpp_usbd_open` → `lpp_usbd_endpoint_convert` | lưu `USBINTR`/`ENDPTNAKEN`; set wake bits + `ENDPTNAKEN=EP1`; `intAttach(INTNUM_USB, lpp_usbd_isr)` |
| (suspend) | `lpp_usbd_enter_nak` | flush EP active; wake ngay nếu TD kẹt |
| wake | `lpp_usbd_isr` | `USBSTS` lưu; `intDisable`; `SYS_EVENT_WAKE_SYSTEM`; `LPPP_SetWakeInfo(USB)` |
| resume | `lpp_usbd_close` → `lpp_usbd_endpoint_restore` | `intDisable`; khôi phục `USBINTR`/`ENDPTNAKEN` |
| (resume) | `lpp_usbd_exit_nak` | `ENDPTPRIME` các EP đã flush |
