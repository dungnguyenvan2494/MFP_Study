## 1. `Sys/sdk/` là lớp SDK "mỏng" — vỏ bọc 1 dòng

**FACT.** Mọi hàm `ApiSys*` trong `Sys/sdk/mvbase_api_*.c` chỉ là wrapper pass-through:
- ép kiểu (ví dụ `Pattern*` ↔ `SYS_FILTER*`, `sock_addr*` ↔ `SYS_SOCK_ADDR*`) để tách kiểu SDK-public khỏi kiểu nội bộ Sys,
- (một số) bọc mutex `SysSystem_MutexSystemLayerApiGet()` / `...Put()`,
- rồi gọi thẳng hàm `SysApi*` (tầng Sys) hoặc `Hal*` (tầng Hal).

Đây là **bề mặt API mà tầng App gọi** (`ApplicationMrvl`, `ApplicationKM/LPPP_*`, `Application/*proxy`). Khai báo tập trung ở `base_api.h` (~140 prototype `ApiSys*`).

| File | `#ifdef` bảo vệ | Nhóm chức năng |
|------|----------------|----------------|
| `mvbase_api_network.c` | `NETSTACK_lwipv6` (phần IGMP/MLD) | link state, IP/GW/MAC get·set (v4+v6), DHCP, **raw send / forward-to-driver / wake+forward**, **join/leave nhóm multicast**, enable/disable IPv6 |
| `mvbase_api_pattern.c` | `MRVL_FILTER_ENABLED` | định nghĩa/đọc/xoá/bật/tắt filter + set·get callback → `SysApiFilter_*` (T5.2/T5.4 dùng) |
| `mvbase_api_socket.c` | `MRVL_BSD_SOCKETS_ENABLED` | BSD socket (`socket/bind/listen/accept/send/recvfrom/select/setsockopt/fcntl`) → `SysApiSocket_*` |
| `mvbase_api_offload.c` | `MRVL_PROXY_MODULE_ENABLED` / `MRVL_PROXY_OFFLOAD_MODULE_ENABLED` | `ApiSysOffloadEnable/Configure/GetConfiguration/Disable` → `Proxy*()`; `...TransactionIsOpen` → `SMB_transaction_id_is_open` (SMB2 offload). Nếu không bật → trả `SYS_ERROR_NOT_AVAILABLE` |
| `mvbase_api_statusinfo.c` + `mvbase_statusinfo.h` | – | bitmask trạng thái FW báo cho host (xem §5) |
| `mvbase_api_system.c` (731 dòng) | – | wake/wakeReason, mem alloc, event, host req/resp, debug printf, JTAG, power-save, wake-on-linkchange, timer chu kỳ, GPIO, critical section |
| `mvbase_api_ipsec.c` (832 dòng) | `MRVL_IPSEC_*` | IPsec/IKE offload — **INFERENCE: không dùng trong S800/KM** (KM chỉ dùng SysFilter proxy) |

## 2. API mạng cốt lõi (`mvbase_api_network.c`)

### 2.1 Hai đường "đẩy gói ra"
**FACT** (`sys_lan_api.c`):

| API SDK | → Sys | Cơ chế | Dùng cho |
|---------|-------|--------|----------|
| `ApiSysNetworkForwardPacketToDriver(data,len)` | `SysApiLan_PacketForwardToDriver` | `SysFifo_Write(fifo_msg_packet, …)` — **HCI FIFO → Linux** (có mutex system-layer) | chuyển gói "cần host xử lý" lên Linux |
| `ApiSysNetworkRawPacketSend(data,len)` | `SysApiLan_PacketRawSend` | `HalApiLan_Send()` **trong critical section** — bơm thẳng khung Ethernet lên dây | proxy tự gửi trả lời (ARP reply, `appSendUdpPacket`…) |
| `ApiSysNetworkWakupAndForwardPacketToDriver()` | `SysFilter_Wakeup_and_Forward` | forward `saved_rawpacket` qua FIFO + set `SYS_EVENT_WAKE_SYSTEM` | proxy quyết định "phải đánh thức" (T5.4) |

### 2.2 Get/Set cấu hình L3 (Linux nạp trước khi ngủ)
`ApiSysNetworkIPv4AddressSet/Get`, `...IPv4GatewaySet/Get`, `...IPv6AddressSet/Get` (Index + PrefixLen, `NUM_IPV6_ADDRESSES` địa chỉ), `...IPv6GatewaySet/Get`, `...MacAddressSet` (ghi cả HW qua `HalApiLan_MacAddressSet` **và** stack qua `SysApiLan_MacAddressSet`), `...LinkModeSet/Get`, `...DhcpStart`, `...DisableIPv6/EnableIPv6` (yêu cầu riêng của khách).
→ Đây là cách R4 "trở thành host trên mạng": nó mượn IP/MAC/GW của Linux để tự trả lời ARP/ND/mDNS… khi Linux ngủ.

### 2.3 Join/Leave nhóm multicast — **đây là phần "offload" IGMP/MLD**
**FACT** (`mvbase_api_network.c:158-244`, chỉ build khi `NETSTACK_lwipv6`):

| API | lwIP call | ghi chú |
|-----|-----------|---------|
| `ApiSysNetworkJoinIpv4Group(u32 addr)` | `igmp_joingroup(INADDR_ANY, &group)` | trả `RC_OK`/`RC_ERROR`; log |
| `ApiSysNetworkLeaveIpv4Group` | `igmp_leavegroup` | |
| `ApiSysNetworkJoinIpv6Group(u32 addr[4])` | `mld6_joingroup` (chỉ khi `ENABLE_IP_V6_SUPPORT`) | |
| `ApiSysNetworkLeaveIpv6Group` | `mld6_leavegroup` | |

- Comment trong file: *"chưa biết làm gì với dữ liệu đến qua nhóm đã join — hiện tại bỏ qua"* → join chỉ để (a) lwIP gửi IGMP/MLD report giữ nhóm sống trên switch, (b) bộ lọc multicast MAC của GMAC nhận các frame đó.
- **Ai gọi:** `AppThread_mcip_handler(ip_heap *mcip, join)` (`app_thread.c`) — lặp `mcip->count`, gọi `ApiSysNetworkJoinIpv4Group(...)` cho từng IP. `mcip` = `own_mcip_heap`, do Linux nạp danh sách nhóm cần giữ (mDNS `224.0.0.251`, LLMNR `224.0.0.252`, SSDP `239.255.255.250`, SLP `239.255.255.253`…).
- `filter_function_check_ip_multicast` (callback FFL #5, T5.4) so IPv4 dst của gói đến với `own_mcip_heap.ip_address[]` → khớp ⇒ trả `SYS_TRUE` để gói được "nhận" (không bị `CATCH_UNKNOWN` xoá) rồi mới tới proxy STAGE_2 tương ứng.

## 3. ARP offload

**FACT.** Không có "ARP responder" riêng trong SDK. Bảng filter mặc định có `ID_FILTER_STAGE1_ARP` nhưng **`SYS_FALSE` (disabled)**; comment ngay trên entry:
> *"if inactive arp is done completely by network stack."*

⇒ **lwIP `etharp` tự trả lời ARP request** hỏi IP của netif R4 trong khi Linux ngủ. Đó chính là ARP offload — miễn phí, do stack lo.

### 3.1 `filter_function_check_arp_request` (callback FFL #2 — hiện DISABLED)
Nếu bật, nó chỉ **bổ sung** 2 hành vi (không thay thế etharp):

| tình huống | xử lý | ghi chú |
|------------|-------|---------|
| `own_address == 0` (chưa có IP) | `return SYS_TRUE` → DISCARD | không có gì để trả lời |
| gratuitous/conflicting ARP: `sender_ip == own_address` **và** sender MAC ≠ MAC của mình | `ApiSysNetworkWakupAndForwardPacketToDriver()` → `SYS_TRUE` | **R24** — phát hiện xung đột địa chỉ theo RFC 5227 §2.4, để host tự giải quyết |
| `arp_op == 2` (ARP reply thường) | `return SYS_FALSE` | nhả cho network stack |
| ARP probe (`#ifdef ARP_PROBE`, **không build**) | tự dựng `_arp_reply` 42 byte, `ApiSysNetworkRawPacketSend` | **R21** — không được yêu cầu |
| còn lại (R18/R19 = ARP request thường) | `return SYS_FALSE` | **etharp lo** |

Comment: R20/R22 (nhiều IPv4 của mình) không hỗ trợ.

## 4. NS / NDP offload (IPv6 Neighbor Solicitation)

**FACT.** Tương tự ARP: `nd6.c` trong lwIPv6 **tự trả lời Neighbor Solicitation** hỏi các địa chỉ IPv6 của netif R4 (đã set qua `ApiSysNetworkIPv6AddressSet`). MLD report do `mld6.c` lo.

### 4.1 `filter_function_check_icmpv6_solit` — **"not used"** (không đăng ký vào FFL[])
Nếu dùng, nó chỉ thêm phát hiện **DAD (Duplicate Address Detection)**:
- gói tới MAC multicast `33:33:FF:xx:xx:xx` (solicited-node),
- duyệt `NUM_IPV6_ADDRESSES` địa chỉ của mình; nếu 3 byte cuối MAC khớp `myaddress[3] & 0x00ffffff` **và** target address (offset 0x3e..0x4d) == địa chỉ của mình:
  - nếu **source == `::`** (unspecified) ⇒ đây là DAD của node khác đòi trùng địa chỉ ⇒ `ApiSysWakeSystem()`,
  - `return SYS_TRUE`.
- Bình thường (source ≠ `::`) chỉ `return SYS_TRUE` để nd6 xử lý; không khớp → `SYS_FALSE`.

`ApiSysWakeSystem()` → `SysApiSystem_Wake()` (`mvbase_api_system.c:93`).

## 5. Status-info bitmask — host biết "cái gì đánh thức mình" (`mvbase_statusinfo.h`)

**FACT.** `ApiSysStatusInfoBitsRead/Set/Clear`, `ApiSysStatusInfoAppBitsRead`, `ApiSysStatusAdditionalInfoRead`. Bố cục 32 bit:

| bit | tên | ý nghĩa |
|-----|-----|---------|
| 0 | `FW_INIT_ERROR` | lỗi init FW |
| 1 / 2 | `ALLOC_ERR_HEAP` / `ALLOC_ERR_PKT` | hết heap / hết buffer gói |
| 3 / 4 / 5 | `UDP_ENA` / `TCP_ENA` / `IPSEC_ENA` | |
| 6 / 7 | `SERVICE_OFFL_ENA` / `SERVICE_RESP_ENA` | offload/response service đang bật |
| 8 / 9 | `PKT_FILTERST_1_ENA` / `PKT_FILTERST_2_ENA` | STAGE_1 / STAGE_2 filter bật |
| 10 | `CPU_PS_MODE_ON` | R4 đang ở chế độ tiết kiệm điện |
| 16–20 | `WOL_PAT_ID` | ID pattern WoL đã kích |
| 21–22 | `WOL_PAT_STAGE` | stage của pattern WoL |
| 24–28 | `MATCH_PAT_ID` | **ID filter/pattern vừa khớp (nguyên nhân thức)** |
| 29–30 | `MATCH_PAT_STAGE` | stage của filter vừa khớp |

Helper: `StatusInfoWolPatternSet/Clear(stage, patt_id)`, `StatusInfoMatchPatternSet/Clear(stage, patt_id)` — đóng gói dịch bit vào field 16-22 / 24-30. Linux đọc field 24-30 để biết filter nào (SNMP? LLMNR? magic packet?) đã đánh thức nó.

## 7. FACT / INFERENCE / UNKNOWN

- **FACT**: toàn bộ chữ ký hàm, `#ifdef` bảo vệ mỗi module, bản chất wrapper 1 dòng, 2 đường đẩy gói (FIFO vs `HalApiLan_Send`), join group qua `igmp_joingroup`/`mld6_joingroup`, `ID_FILTER_STAGE1_ARP` disabled + comment "arp done by network stack", `filter_function_check_icmpv6_solit` không đăng ký ("not used"), bố cục bit `mvbase_statusinfo.h`.
- **INFERENCE**: `mvbase_api_offload.c` (Marvell Proxy module) và `mvbase_api_ipsec.c` không được biên dịch/không dùng trong build S800-KM — vì KM dùng cơ chế SysFilter proxy (T5.3/T5.4), và các hàm này trả `SYS_ERROR_NOT_AVAILABLE` khi macro tắt. Chưa xác nhận bằng Makefile/`.config`.
- **INFERENCE**: "ARP/NS offload thực chất do lwIP etharp/nd6 lo" — suy từ (a) filter ARP disabled + comment, (b) không có responder trong SDK, (c) lwIPv6 có sẵn `etharp.c`/`nd6.c`. Chưa trace vào thân `etharp_input`/`nd6_input` để xác nhận nó trả lời khi netif ở trạng thái này.
- **UNKNOWN**: `SysFifo` / `fifo_msg_packet` chi tiết (để dành T6). `HalApiLan_Send` đường xuống GMAC TX (một phần T5.1).
- **UNKNOWN**: giá trị `NUM_IPV6_ADDRESSES`, `NUM_IPV4_ADDRESSES`, kích thước `own_mcip_heap` (trong header App chưa mở).
- **UNKNOWN**: `mvbase_api_system.c` các hàm 491-618 (WDT/timer/critical) chưa đọc thân, chỉ liệt kê từ danh sách.

## Tóm tắt (theo format skill)

**Lớp `Sys/sdk/mvbase_api_*` để làm gì:**
Là "SDK façade" — một tập ~140 hàm `ApiSys*` mà tầng Application (proxy KM/Mrvl) gọi, mỗi hàm chỉ ép kiểu + (đôi khi) khoá mutex rồi ủy quyền xuống `SysApi*`/`Hal*`. Nó gom 7 nhóm: network (IP/MAC/link, raw-send, forward-to-driver, **join multicast IGMP/MLD**), pattern/filter, BSD socket, offload (Marvell Proxy/SMB — coi như tắt), status-info bitmask, system (wake/event/timer/gpio/mem), ipsec (tắt). **ARP và IPv6-NS offload không nằm ở đây** — chúng do lwIP `etharp`/`nd6` tự lo; SDK chỉ thêm phát hiện xung đột địa chỉ (RFC 5227 / DAD) qua 2 filter callback mà bản S800 để **disabled/not-used**.

**Bảng lifecycle "R4 mượn danh tính host":**
| bước | API | tác dụng |
|------|-----|----------|
| Linux (trước khi ngủ) nạp IP/MAC/GW | `ApiSysNetworkIPv4AddressSet`, `...IPv6AddressSet`, `...MacAddressSet` | netif R4 có cùng L2/L3 với Linux |
| Linux nạp danh sách nhóm mcast | `AppThread_mcip_handler` → `ApiSysNetworkJoinIpv4Group` mỗi IP | IGMP report giữ nhóm; GMAC nhận mcast |
| Gói ARP request đến | (không filter) → lwIP `etharp_input` | tự trả ARP reply |
| Gói NS đến | (không filter) → lwIP `nd6_input` | tự trả NA |
| Gói mcast (mDNS/LLMNR/SSDP) đến | FFL#5 `check_ip_multicast` khớp `own_mcip_heap` → nhận → STAGE_2 proxy | T5.3/T5.4 |
| Gratuitous ARP trùng IP mình | FFL#2 (nếu bật) → `WakupAndForwardPacketToDriver` | host giải quyết xung đột |
| Proxy có câu trả lời | `appSendUdpPacket`/`ApiSysNetworkRawPacketSend` → `HalApiLan_Send` | bơm thẳng lên dây |
| Proxy cần host | `ApiSysNetworkWakupAndForwardPacketToDriver` → FIFO + `SYS_EVENT_WAKE_SYSTEM` | + set `MATCH_PAT_ID` bit 24-30 để host biết lý do |
