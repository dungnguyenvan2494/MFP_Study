dQH và dTD — cấu trúc DMA của ChipIdea (rất quan trọng)

Controller này không có FIFO để CPU ghi dữ liệu bằng tay. Nó là DMA master: đọc danh sách mô tả trong RAM rồi tự chép dữ liệu.

  • dQH (device Queue Head) — 64 byte/endpoint-hướng, mảng 32 phần tử, địa chỉ đầu mảng ghi vào thanh ghi EPLISTADDR.
  • dTD (device Transfer Descriptor) — mô tả một bộ đệm (tối đa 5 trang × 4 KB = 20 KB), nối thành danh sách liên kết từ dQH.

DRIVER drivers/usb/chipidea/udc.h:20-58:

c
struct ci_hw_td {          /* dTD */
    __le32 next;           /* bit0 TD_TERMINATE */
    __le32 token;          /* bit7 ACTIVE, bit6 HALTED, bit5 DT_ERR, bit3 TR_ERR,
                              bit15 IOC, bits30:16 TOTAL_BYTES (byte còn lại) */
    __le32 page[5];        /* con trỏ buffer, 4 KB mỗi trang */
};
struct ci_hw_qh {          /* dQH */
    __le32 cap;            /* bit15 IOS, bits26:16 MAX_PKT, bit29 ZLT, bits31:30 MULT */
    __le32 curr;
    struct ci_hw_td td;    /* "overlay" – vùng HW làm việc */
    __le32 RESERVED;
    struct usb_ctrlrequest setup;   /* 8 byte SETUP do HW ghi vào */
};

Thanh ghi chỉ làm nhiệm vụ "bấm nút" và "báo trạng thái"; dữ liệu thật nằm trong dQH/dTD/buffer ở RAM:

text
   CPU (driver)                         RAM                         USB Controller (DMA)
   ------------                         ---                         --------------------
   1. tạo dTD, trỏ buffer  ───────────► dTD{token=ACTIVE, page[]}
   2. dQH.td.next = dTD    ───────────► dQH[n]
   3. writel(BIT(n), ENDPTPRIME) ───────────────────────────────────► đọc dQH[n] → dTD → buffer
                                                                     ENDPTSTAT bit n = 1
                                        buffer ◄──── DMA ───────────  (OUT) / ────► (IN)
                                        dTD.token: ACTIVE=0, bytes   ◄ HW cập nhật
   5. IRQ ◄───────────────────────────────────────────────────────── ENDPTCOMPLETE bit n, USBSTS.UI
   6. đọc dTD.token, giveback request

Như vậy phần cứng là một tổ hợp 2 khối:

  1. USB2 Device Controller — lõi ChipIdea/Synopsys USB-HS (PDF gọi là "USB-HS USB 2.0 core", có thanh ghi HCIV_CAPLENGTH, DCCPARAMS, ENDPTPRIME… đúng kiểu ChipIdea). Linux dùng driver drivers/usb/chipidea/ (glue ci_hdrc_imx.c + core core.c + UDC udc.c).
  2. USB2 Transceiver Macro — PHY analog (PLL, calibration, TX/RX driver). Linux dùng driver drivers/usb/phy/phy-utm-mv.c (framework usb_phy cũ).

Không có Host Controller ở đây. Bằng chứng kép:

  • HW-SPEC DCCPARAMS.HC (bit 8) reset = 0: "Host Capable - RO… This is a USB Device port"; DCCPARAMS.DC (bit 7) = 1.
  • DRIVER DT dr_mode = "peripheral"; defconfig # CONFIG_USB_CHIPIDEA_HOST is not set.

Điều này quan trọng: tài liệu này chỉ nói về USB Device (UDC). Các thanh ghi ChipIdea dành cho Host/OTG (OTGSC, TTCTRL, HCCPARAMS chi tiết…) hoặc không có trong PDF, hoặc không được driver chạm tới (xem 1.6).

USB PHY / Transceiver Macro

Khối analog nằm ở base riêng 0x8_E827_4000, có driver riêng phy-utm-mv.c. Chi tiết từng register ở nhóm PHY / Transceiver.

Đừng nhầm: các thanh ghi này nằm ở khối khác (0xE827_4000), driver khác (phy-utm-mv.c), và không liên quan trực tiếp tới endpoint hay giao thức. Chúng điều khiển phần analog: tạo clock 480 MHz, chỉnh trở kháng, ngưỡng phát hiện tín hiệu. Nếu PHY sai, controller vẫn "chạy" nhưng PC báo "device descriptor read error", rớt HS về FS, hoặc không thấy thiết bị.

INFERENCE Driver đọc HCCPARAMS.LEN (bit 17) ở offset 0x108 — offset này không được mô tả trong PDF. Nếu bit này đọc ra 1, driver sẽ chuyển sang bảng LPM (USBMODE @0x1C8…) và mọi thứ sai. Vì bản đồ PDF khớp bảng non-LPM, có thể kết luận trên silicon bit này đọc ra 0. Nên xác minh trên board: devmem 0x8E8250108.

DRIVER Mảng ENDPTCTRL: hw_alloc_regmap (core.c:114-119) → regmap[OP_ENDPTCTRL + i] = op + 0x80 + 4*i. Vì vậy trong udc.c driver chỉ cần viết OP_ENDPTCTRL + num (ví dụ hw_ep_enable, udc.c:179) là ra đúng 0x1C0 + 4*num. Mỗi endpoint number có một thanh ghi riêng, chứa cả nửa RX (bit 0–7) và nửa TX (bit 16–23) — xem Chương 4.

              if (~mask)                                   /* mask != 0xFFFFFFFF  → read-modify-write */

              __hw_write(ci, data, regmap[reg]);           /* iowrite32 */
          }

/* 421 */ static inline u32 hw_test_and_clear(ci, reg, mask)
          {
              u32 val = ioread32(regmap[reg]) & mask;      /* đọc các bit quan tâm */
              __hw_write(ci, val, regmap[reg]);            /* ghi lại đúng các bit =1 → W1C xóa chúng */
              return val;
          }

/* 439 */ static inline u32 hw_test_and_write(ci, reg, mask, data)
          { u32 val = hw_read(ci, reg, ~0); hw_write(ci, reg, mask, data);
            return (val & mask) >> __ffs(mask); }

SUTW và ATDTW — hai "tripwire" (semaphore phần cứng)

Cả hai giải quyết cùng một loại race: CPU đang đọc/sửa cấu trúc trong RAM trong khi DMA của controller cũng có thể ghi vào đó. Thay vì khóa, phần cứng cho một bit: software set lên, làm việc, rồi kiểm tra bit còn 1 không; nếu HW đã xóa ⇒ "có sự kiện chen ngang, làm lại".

SUTW — isr_setup_packet_handler() udc.c:1169-1172:

do {
    hw_test_and_set_setup_guard(ci);                       /* USBCMD.SUTW = 1 (RMW) */
    memcpy(&req, &hwep->qh.ptr->setup, sizeof(req));      /* chép 8 byte SETUP từ dQH[0] */

3.5. Cảnh báo & quan sát (không thay đổi hành vi, chỉ ghi nhận)

  2. [DRIVER] hw_device_init ghi 0xFFFFFFFF vào USBSTS (core.c:252), bao gồm cả các bit Reserved mà PDF ghi "Always write 0". Upstream làm vậy cho mọi SoC; trên thực tế chưa ghi nhận tác dụng phụ, nhưng về hình thức là lệch spec.
  3. [DRIVER] isr_reset_handler xóa SLI bằng RMW (udc.c:897): đọc USBSTS rồi ghi lại toàn bộ cộng bit 8 ⇒ mọi bit W1C khác đang = 1 tại thời điểm đó (ví dụ UI của một SETUP vừa tới ngay sau reset) cũng bị xóa. INFERENCE Rủi ro thấp: ENDPTSETUPSTAT/ENDPTCOMPLETE vẫn giữ thông tin, nhưng nếu UI bị xóa mà không có IRQ nào khác, xử lý SETUP sẽ trễ tới lần ngắt sau. Đây là upstream code, không phải patch KM.

Phân tích chi tiết — đánh số bit, ENDPTCTRL, ENDPTSETUPSTAT Chương 4 · §4.1, 4.2, 4.7

Hình dung endpoint như một quầy giao dịch có hai ô cửa: ô RX (nhận hàng host gửi — OUT) và ô TX (giao hàng cho host — IN). ENDPTCTRLn là biển "mở cửa/đóng cửa/tạm ngưng" của quầy số n. } while (hw_read(ci, OP_ENDPTSTAT, BIT(n)));        /* packet đang chạy → STAT còn 1 → flush lại */

Vòng ngoài đúng với ghi chú PDF "packet in progress will continue": sau khi packet đó xong, STAT có thể lại = 1 ⇒ flush lần nữa.

Flush tất cả (ghi 0xFFFFFFFF):

  • hw_device_reset core.c:485 — trước RST (yêu cầu của PDF).
  • hw_usb_reset udc.c:347 — khi nhận bus reset.

Flush từng endpoint: _ep_nuke (udc.c:761) ← ep_disable, isr_setup_packet_handler (dọn EP0 trước SETUP mới), _ep_queue cho control khi queue không rỗng; ep_dequeue (udc.c:1566); ep_fifo_flush (udc.c:1642).

Nếu không flush trước khi giải phóng dTD? HW vẫn có thể DMA vào buffer đã trả lại cho function driver ⇒ hỏng bộ nhớ. Đó cũng là lý do _hardware_dequeue giữ lại dTD cuối (pending_td, udc.c:723-732): "As the hardware could still address the freed td… the cleanup of the td has to be delayed by one."

7.6. Kiến thức cần nắm vững sau khi hoàn thành

  1. Phần cứng là ChipIdea USB-HS Device-only + PHY UTM Marvell, hai base riêng; driver chipidea/ + phy-utm-mv.c.
  2. Địa chỉ thanh ghi controller = base + 0x100 (capoffset) + CAPLENGTH(0x40) + offset op; ENDPTCTRLn = 0x1C0 + 4n.
  3. Bốn kiểu ghi trong hw_write: ghi thẳng (mask ~0), RMW (mask hẹp), "đọc-ghi lại" (mask 0 → xóa W1C), test-and-clear.
  4. W1C: USBSTS, ENDPTCOMPLETE, ENDPTSETUPSTAT (và cờ lỗi DIG0). Self-clearing: USBCMD.RST, ENDPTPRIME, ENDPTFLUSH. WS: ENDPTCTRL.TXR/RXR. Edge-trigger: CAL.*_START, RX1.REG_SQCAL_START.
  5. Controller là DMA master: dữ liệu ở buffer, mô tả ở dTD, cấu hình endpoint (max packet) ở dQH; thanh ghi chỉ là "nút bấm và đèn báo".
  6. Trình tự attach: RST → USBMODE → ITC → EPLISTADDR → USBINTR → RS.
  7. IRQ: USBSTS & USBINTR, W1C đúng bit đã lấy, xử lý Reset → PCI → UI/UEI → SLI.
  8. SETUP: ENDPTSETUPSTAT + SUTW (vì SLOM=1); SET_ADDRESS ghi DEVICEADDR sau status stage.
  9. Transfer: PRIME → (ATDTW/STAT khi nối) → COMPLETE → đọc dTD.token; FLUSH khi hủy; TXS/RXS khi lỗi.
  10. USB suspend ≠ system suspend. Trên Quartz (SRAM QH) system suspend/resume không chạm thanh ghi controller, chỉ PHY được init lại.
  11. PHY init: TX0 (power) → RX0/RX1 (squelch) → PLL0 (25→480 MHz) → DIG0 → PLL1 (power PLL) → CAL/RX1 (cạnh lên) → poll DONE/READY (có timeout từ OP_BTS-70923).
  12. Những thanh ghi trong PDF không dùng: HW*, GPTIMER*, DCIVERSION, FRINDEX, ENDPTNAK/NAKEN, TX1, DIG1, TEST*, MON, RESERVE.
