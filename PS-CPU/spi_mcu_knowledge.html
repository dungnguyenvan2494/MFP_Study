    Chapter 01

    SPI Overview — SPI là gì?

    🎯Mục tiêu

    Hiểu SPI (Serial Peripheral Interface) giải quyết vấn đề gì, khác gì UART/I2C, và khi nào nên/không nên dùng.

    🧠Core Concept
    🧠 Concept
    SPI là giao thức truyền dữ liệu nối tiếp (serial), đồng bộ (có đường Clock riêng do Master phát ra), full-duplex (truyền và nhận đồng thời), theo mô hình Master–Slave. Đây là de-facto standard (do Motorola đưa ra), không phải chuẩn ISO/IEC chính thức.

    Vấn đề SPI giải quyết: UART không có Clock riêng → 2 bên phải tự thống nhất tốc độ trước, dễ lệch pha ở tốc độ cao. SPI có Clock riêng do Master phát → Slave chỉ "bắt tín hiệu theo Clock" → cho phép tốc độ cao hơn UART/I2C nhiều lần (thường vài chục MHz).

    ⚖️Ưu điểm / Nhược điểm
    Ưu điểmNhược điểm
    Tốc độ cao (chục MHz), full-duplex thật sựKhông có địa chỉ trên bus → cần 1 chân CS riêng cho mỗi Slave
    Không cần thỏa thuận baud rate như UARTNhiều dây hơn I2C (4 dây cơ bản, thêm 1 CS/Slave)
    Phần cứng đơn giản (shift register)Không có ACK/NACK chuẩn hóa như I2C
    Hỗ trợ nhiều Slave trên cùng 3 dây chungKhoảng cách truyền ngắn (board-level)
    🧪Ứng dụng thực tế

    Flash (bộ nhớ ngoài), EEPROM (cấu hình), ADC/DAC, Sensor (accelerometer, gyro), Display (LCD/OLED nhỏ), Touch controller, RTC, PMIC, Ethernet/CAN controller ngoài.

    🎯Key Takeaways
    • SPI = đồng bộ + full-duplex + Master-Slave, không có địa chỉ trên bus.
    • Chọn SPI khi cần tốc độ cao, khoảng cách ngắn (trong board); chọn I2C khi cần tiết kiệm chân với nhiều thiết bị; chọn UART cho point-to-point đơn giản, khoảng cách xa hơn.
    Chapter 02

    SPI Architecture

    ⚙️Hardware
    Thành phầnVai trò
    MasterThiết bị tạo SCLK, chủ động khởi tạo mọi transaction
    SlaveThiết bị bị động, chỉ phản hồi khi CS của nó được kéo active
    SCLKClock đồng bộ, luôn do Master phát ra
    MOSIMaster Out Slave In — dữ liệu từ Master → Slave
    MISOMaster In Slave Out — dữ liệu từ Slave → Master
    CS/SS/NSSChip Select — chọn đúng 1 Slave để giao tiếp, thường active-LOW
    ⭐ Important
    CS gần như luôn được điều khiển bằng GPIO thường (Software CS) do phần mềm bật/tắt, vì SPI peripheral thường chỉ có 1 chân NSS "cứng" trong khi hệ thống cần nhiều Slave. STM32 SPI hỗ trợ cả 2: LL_SPI_NSS_SOFT (bit CR1.SSM=1, GPIO điều khiển) và LL_SPI_NSS_HARD_OUTPUT (phần cứng tự quản lý, chỉ dùng khi có đúng 1 Slave).
    stm32f0xx_ll_spi.h
    #define LL_SPI_NSS_SOFT         (SPI_CR1_SSM)   // NSS quản lý nội bộ, GPIO CS tự kéo tay
#define LL_SPI_NSS_HARD_OUTPUT  (((uint32_t)SPI_CR2_SSOE << 16U))  // NSS pin cứng, dùng ở Slave mode
    Chapter 03

    SPI Signals

    DâyMasterSlaveÝ nghĩa tên gọi
    SCLKOUTINMaster luôn là bên tạo Clock — khác biệt căn bản với UART
    MOSIOUTINMaster Out Slave In
    MISOINOUTMaster In Slave Out
    CS/SS/NSSOUTINChọn đúng 1 Slave để "nói chuyện"
    ⚠️ Common Bug
    Nếu cả Master và Slave cùng lúc "output" trên MISO (do cấu hình sai chiều GPIO), xảy ra bus contention — có thể gây ngắn mạch điện (hai bên cùng kéo mức khác nhau trên cùng 1 dây).

    Tại sao CS thường active-LOW? Đây là quy ước phổ biến (không bắt buộc theo lý thuyết SPI) để khi bus rảnh (mọi CS = HIGH), không Slave nào bị "đánh thức" nhầm do nhiễu ngẫu nhiên kéo dây xuống thấp — nhờ pull-up giữ mức HIGH mặc định.

    Chapter 04

    Full Duplex

    🧠 Concept
    Full-duplex trong SPI là thuộc tính vật lý của bus, không phải tính năng phần mềm: mỗi cạnh Clock, TX shift register đẩy 1 bit ra MOSI đồng thời RX shift register nhận 1 bit vào từ MISO.
    💻Source Code — HAL_SPI_Transmit (STM32F0, thật)
    stm32f0xx_hal_spi.c :494-544
    /* Transmit data in 8 Bit mode */
while (hspi->TxXferCount > 0)
{
  if((hspi->Instance->SR & SPI_FLAG_TXE) == SPI_FLAG_TXE)     // (1) polling cờ TXE
  {
    if(hspi->TxXferCount > 1)
    {
      hspi->Instance->DR = *((uint16_t*)hspi->pTxBuffPtr);    // (2) packing mode: ghi 2 byte 1 lần
      hspi->pTxBuffPtr += sizeof(uint16_t);
      hspi->TxXferCount -= 2;
    }
    else
    {
      *((__IO uint8_t*)&hspi->Instance->DR) = (*hspi->pTxBuffPtr++); // (3) byte cuối
      hspi->TxXferCount--;
    }
  }
  else { /* timeout check */ }                                 // (4)
}
    ⚠️ FACT quan trọng
    FACT Trước vòng lặp này, HAL đặt hspi->pRxBuffPtr = NULL; hspi->RxXferCount = 0; — nghĩa là HAL_SPI_Transmit hoàn toàn bỏ qua dữ liệu RX dù phần cứng vẫn nhận bit trên MISO song song. Nếu bạn cần đọc data trả về thật, phải dùng HAL_SPI_TransmitReceive.
    📈Waveform mô phỏng shift từng clock
    TX = 0xA5 = 1010 0101 (MSB-first), Slave gửi về 0x3C = 0011 1100 Trước CLK1: TX shift reg = 10100101 RX shift reg = 00000000 CLK1: MOSI=1(bit7) ra | MISO=0(bit7 slave) vào -> TX=0100101_ RX=_______0 CLK2: MOSI=0(bit6) | MISO=0(bit6 slave) -> TX=100101__ RX=______00 CLK3: MOSI=1(bit5) | MISO=1(bit5 slave) -> TX=00101___ RX=_____001 ... CLK8: MOSI=1(bit0) | MISO=0(bit0 slave) -> TX=00000000 RX=00111100 = 0x3C
    ⚠️Common Mistakes
    • Gọi HAL_SPI_Transmit liên tiếp mà không xử lý RX → RX shift register cứ latch dữ liệu cũ vào DR nhưng không ai đọc → có thể set cờ OVR.
    • Nhầm SPI "transmit" 1 chiều giống UART TX — dẫn tới thiết kế sai khi Slave cần trả lời ngay trong cùng byte.
    Chapter 05

    Shift Register

    🧠 Concept
    Shift Register là một dãy flip-flop nối tiếp: mỗi xung Clock, dữ liệu dịch sang 1 vị trí, bit ngoài cùng bị đẩy ra chân, đồng thời 1 bit từ chân khác được nạp vào đầu kia.
    📚MSB-first vs LSB-first
    Giá trị: 0xA5 = 1010 0101 MSB-first (mặc định đa số chip): bit ra: 1 0 1 0 0 1 0 1 ^ đầu tiên ^ cuối LSB-first: bit ra theo thứ tự bit0 -> bit7 (đẩy bit thấp nhất ra chân trước)
    stm32f0xx_ll_spi.h :218-219
    #define LL_SPI_LSB_FIRST   (SPI_CR1_LSBFIRST)      // set bit -> LSB first
#define LL_SPI_MSB_FIRST   ((uint32_t)0x00000000U) // clear bit (mặc định) -> MSB first

    FACT Chỉ 1 bit duy nhất (CR1.LSBFIRST) điều khiển hướng dịch của cả TX lẫn RX cùng lúc — không có bit riêng cho từng chiều.

    Chapter 06

    SPI Clock — Prescaler & Baud Rate

    🎯Mục tiêu

    Hiểu SCLK = PCLK chia qua prescaler, tính đúng tần số thực tế từ register.

    ⚙️Hardware
    APB Bus Clock (PCLK, vd 48 MHz trên STM32F0) | v Prescaler (chia bởi CR1.BR[2:0]) | v SCLK --------> chân vật lý SCK
    📝Register
    stm32f0xx_ll_spi.h
    #define LL_SPI_BAUDRATEPRESCALER_DIV2    (0U)                                  // fPCLK/2
#define LL_SPI_BAUDRATEPRESCALER_DIV4    (SPI_CR1_BR_0)                        // fPCLK/4
#define LL_SPI_BAUDRATEPRESCALER_DIV8    (SPI_CR1_BR_1)                        // fPCLK/8
#define LL_SPI_BAUDRATEPRESCALER_DIV16   (SPI_CR1_BR_1 | SPI_CR1_BR_0)         // fPCLK/16
#define LL_SPI_BAUDRATEPRESCALER_DIV32   (SPI_CR1_BR_2)                        // fPCLK/32
#define LL_SPI_BAUDRATEPRESCALER_DIV64   (SPI_CR1_BR_2 | SPI_CR1_BR_0)         // fPCLK/64
#define LL_SPI_BAUDRATEPRESCALER_DIV128  (SPI_CR1_BR_2 | SPI_CR1_BR_1)         // fPCLK/128
#define LL_SPI_BAUDRATEPRESCALER_DIV256  (SPI_CR1_BR_2 | SPI_CR1_BR_1 | SPI_CR1_BR_0) // fPCLK/256

    Chỉ 3 bit BR[2:0] → 8 mức chia cố định. Ví dụ: PCLK=48MHz, chọn DIV4 → SCLK = 48/4 = 12 MHz (T ≈ 83.3ns).

    💻Source Code — ghi CR1 thật trong HAL_SPI_Init
    stm32f0xx_hal_spi.c :302-308
    hspi->Instance->CR1 = (hspi->Init.Mode | hspi->Init.Direction |
                       hspi->Init.CLKPolarity | hspi->Init.CLKPhase | (hspi->Init.NSS & SPI_CR1_SSM) |
                       hspi->Init.BaudRatePrescaler | hspi->Init.FirstBit  | hspi->Init.CRCCalculation);
    ⚠️ Common Mistake
    Dòng trên ghi toàn bộ CR1 một lần — nếu gọi lại HAL_SPI_Init chỉ để đổi baud rate mà quên set lại các field khác (CPOL/CPHA/NSS/FirstBit), chúng có thể bị reset về giá trị mặc định/rác của struct.
    🔍Debugging

    SCLK đo được khác tính toán? Kiểm tra theo thứ tự: (1) PCLK thật đang chạy tần số nào (clock tree), (2) giá trị BR trong CR1 đọc bằng debugger, (3) có code khác ghi đè CR1 sau đó không.

    🎯Key Takeaways
    • SCLK = PCLK / prescaler (8 mức cố định).
    • Giới hạn tốc độ thực tế phụ thuộc CPU (polling/interrupt) lẫn Slave, không chỉ giá trị ghi vào BR.
    Chapter 07

    CPOL / CPHA

    📚Kiến thức nền

    Clock idle là mức SCLK giữ khi không giao dịch. Rising edge = cạnh lên (LOW→HIGH), Falling edge = cạnh xuống. Dữ liệu không được đổi đúng lúc bị đọc (setup/hold time) → SPI dùng nguyên tắc: 1 cạnh dùng để đổi dữ liệu, cạnh còn lại dùng để lấy mẫu (sample).

    🧠 Concept
    CPOL (Clock Polarity) quyết định mức idle của SCLK: CPOL=0 → idle LOW; CPOL=1 → idle HIGH.
    CPHA (Clock Phase) quyết định cạnh nào dùng để sample: CPHA=0 → sample cạnh đầu tiên; CPHA=1 → sample cạnh thứ hai.
    📝Register (STM32F0, thật)
    stm32f0xx_ll_spi.h
    #define LL_SPI_PHASE_1EDGE   ((uint32_t)0x00000000U)  // CPHA=0, sample cạnh đầu
#define LL_SPI_PHASE_2EDGE   (SPI_CR1_CPHA)            // CPHA=1, sample cạnh thứ 2
#define LL_SPI_POLARITY_LOW  ((uint32_t)0x00000000U)   // CPOL=0, idle LOW
#define LL_SPI_POLARITY_HIGH (SPI_CR1_CPOL)             // CPOL=1, idle HIGH

MODIFY_REG(SPIx->CR1, SPI_CR1_CPHA, ClockPhase);   // chỉ đổi bit CPHA
MODIFY_REG(SPIx->CR1, SPI_CR1_CPOL, ClockPolarity);// chỉ đổi bit CPOL
    ⭐ Important
    Master và Slave bắt buộc cùng SPI Mode. Nếu lệch, Slave có thể đọc dữ liệu đúng lúc nó còn đang biến đổi (chưa ổn định) hoặc lấy sai bit hoàn toàn — dữ liệu nhận được là rác dù waveform "trông có vẻ đúng" nếu không để ý đúng cạnh sample.
    📈Waveform 4 SPI Mode

    Ký hiệu: S = sample, dữ liệu đổi ở cạnh còn lại.

    Mode 0: CS‾‾\_____________ SCLK ___/‾\___/‾\___/‾\___ MOSI ==C1====C2====C3====== (sample rising, đổi ở falling) Mode 1: CS‾‾\_____________ SCLK ___/‾\___/‾\___/‾\___ MOSI ==C1====C2====C3====== (sample falling, đổi ở rising) Mode 2: CS‾‾\_____________ SCLK ‾‾‾\___/‾‾‾\___/‾‾‾__ MOSI ==C1====C2====C3====== (idle HIGH, sample falling) Mode 3: CS‾‾\_____________ SCLK ‾‾‾\___/‾‾‾\___/‾‾‾__ MOSI ==C1====C2====C3====== (idle HIGH, sample rising)
    🔍Debugging
    🔧 Debug
    Đây là nguyên nhân phổ biến bậc nhất của "SPI có clock, có data, nhưng đọc ra toàn giá trị sai/lệch bit". Xác nhận bằng cách đối chiếu Mode trong datasheet Slave với CLKPolarity/CLKPhase code đang set — không đoán.
    🎯Key Takeaways
    • 4 mode = 2(CPOL) × 2(CPHA); STM32 chỉ dùng 2 bit CR1.CPOL/CR1.CPHA.
    • Sai CPOL/CPHA thường biểu hiện: byte đầu "có vẻ đúng" do trùng hợp, byte sau sai rõ ràng.

    MSB / LSB First

    Xem chi tiết cơ chế ở Chương 05 — Shift Register. Tóm tắt: chỉ 1 bit CR1.LSBFIRST quyết định hướng dịch của toàn bộ TX/RX. Sai bit order → clock/mode đúng nhưng giá trị byte hoàn toàn sai (dễ nhầm với lỗi CPOL/CPHA nếu không kiểm tra riêng).

    Chapter 10

    Chip Select — Timing chi tiết

    CS setup time: thời gian tối thiểu giữa CS xuống LOW và xung clock đầu tiên — Slave cần thời gian "tỉnh dậy".
    CS hold time: thời gian tối thiểu giữ CS LOW sau xung clock cuối trước khi thả lên — đảm bảo Slave latch xong byte cuối.

    📈Waveform — 2 cách dùng CS
    Case 1 — Một CS cho toàn bộ transaction (phổ biến, đa số SPI Flash/EEPROM): CS \_________________________________/ Command Address Data SCLK ___/‾\/‾\/‾\/‾\/‾\/‾\/‾\/‾\/‾\_____ Case 2 — CS toggle giữa từng byte (ít gặp, một số chip cho phép): CS \____/‾‾\____/‾‾\____/‾‾\____ SCLK /‾\ /‾\ /‾\

    FACT STM32F0 có tính năng phần cứng NSSP để tự sinh 1 xung NSS giữa mỗi data frame (chỉ áp dụng khi dùng NSS hardware, không áp dụng khi SSM — software NSS — đang bật):

    stm32f0xx_hal_spi.h / ll_spi.h
    #define SPI_NSS_PULSE_ENABLE   SPI_CR2_NSSP
#define SPI_NSS_PULSE_DISABLE  ((uint32_t)0x00000000)
SET_BIT(SPIx->CR2, SPI_CR2_NSSP);   // bật NSS pulse (chỉ có tác dụng ở NSS hardware mode)
    ⭐ Important
    Đa số SPI Flash bắt buộc giữ CS LOW xuyên suốt command+address+data vì command decoder bên trong Flash reset trạng thái mỗi khi CS lên HIGH. Thả CS giữa command và data sẽ khiến Slave hiểu nhầm là bắt đầu 1 lệnh mới.
    Chapter 11

    SPI Transaction

    Một transaction là khoảng thời gian CS active liên tục, chứa command + address + dummy + data theo giao thức riêng của Slave.

    CS LOW | +-- Command (vd 0x03 = READ) | +-- Address (24-bit với Flash) | +-- Dummy cycles (nếu cần) | +-- Data | CS HIGH

    Xem case study đầy đủ ở Chương 22 — SPI Flash và bug thực tế liên quan CS transaction boundary ở Chương 23 — Case Study Sensor.

    Chapter 12

    Frame / Word Size

    STM32F0 SPI hỗ trợ data width cấu hình được từ 4-bit đến 16-bit qua CR2.DS[3:0]:

    stm32f0xx_ll_spi.h
    #define LL_SPI_DATAWIDTH_4BIT   (SPI_CR2_DS_0 | SPI_CR2_DS_1)
...
#define LL_SPI_DATAWIDTH_8BIT   (SPI_CR2_DS_2 | SPI_CR2_DS_1 | SPI_CR2_DS_0)
...
#define LL_SPI_DATAWIDTH_16BIT  (SPI_CR2_DS_3 | SPI_CR2_DS_2 | SPI_CR2_DS_1 | SPI_CR2_DS_0)

    Data width ảnh hưởng trực tiếp đến cách CPU ép kiểu con trỏ khi ghi/đọc DR (xem Chương 04 — "packing mode"), đến ngưỡng FIFO (Chương 15), và đến cách tính TxXferCount khi dùng DMA (Chương 18).

    💻Source Code thật — HAL_SPI_IRQHandler
    stm32f0xx_hal_spi.c :1728-1784
    void HAL_SPI_IRQHandler(SPI_HandleTypeDef *hspi)
{
  uint32_t itsource = hspi->Instance->CR2;   // (1) interrupt nào đang được bật
  uint32_t itflag   = hspi->Instance->SR;    // (2) cờ nào đang set

  if(((itflag & SPI_FLAG_OVR) == RESET) &&
     ((itflag & SPI_FLAG_RXNE) != RESET) && ((itsource & SPI_IT_RXNE) != RESET))
  {
    hspi->RxISR(hspi);   // (3) con trỏ hàm — không hardcode!
    return;
  }
  if(((itflag & SPI_FLAG_TXE) != RESET) && ((itsource & SPI_IT_TXE) != RESET))
  {
    hspi->TxISR(hspi);   // (4)
    return;
  }
  if((itflag & (SPI_FLAG_MODF | SPI_FLAG_OVR | SPI_FLAG_FRE)) != RESET)
  {
    /* xử lý lỗi, disable interrupt, gọi HAL_SPI_ErrorCallback(hspi); */  // (5)
  }
}
    ⭐ Important
    hspi->RxISR(hspi) và TxISR(hspi) là con trỏ hàm, HAL tự đổi hàm xử lý theo runtime tùy 8-bit/16-bit/CRC. Đặt breakpoint ngay trong HAL_SPI_IRQHandler sẽ không thấy code xử lý thật — phải step tiếp vào con trỏ hàm.

    Case Study — SPI NOR Flash READ

    CS \_______________________________________________/ SCLK __/\/\/\/\/\/\/\/\/\/\/\/\/\/\/\/\/\/\/\/\/\/\/\_____ MOSI [ 0x03 ][ 0x12 ][ 0x34 ][ 0x56 ][ xx ][ xx ] command addr[23:16] addr[15:8] addr[7:0] MISO [ xx ][ xx ][ xx ][ xx ][ D0 ][ D1 ]

    Chapter 23

    Case Study — Bug CS Transaction Boundary (Sensor Read)

    🧪Code lỗi
    Ví dụ minh họa (dùng đúng API HAL thật)
    HAL_StatusTypeDef Sensor_ReadReg(SPI_HandleTypeDef *hspi, uint8_t reg, uint8_t *data)
{
    uint8_t cmd = 0x80 | reg;
    uint8_t dummy_tx = 0x00, rx_dummy;

    HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_RESET);   // CS LOW
    HAL_SPI_TransmitReceive(hspi, &cmd, &rx_dummy, 1, 100);    // gửi command

    HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_SET);     // CS HIGH  <-- (A) BUG
    HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_RESET);   // CS LOW lại <-- (B) BUG

    for (int i = 0; i < 4; i++)
        HAL_SPI_TransmitReceive(hspi, &dummy_tx, &data[i], 1, 100);

    HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_SET);
    return HAL_OK;
}

    Triệu chứng: data[0] luôn đúng, data[1..3] sai theo 1 pattern cố định (không ngẫu nhiên).

    ⚠️ Root Cause
    Dòng (A)+(B) thả CS lên HIGH rồi hạ xuống lại ngay sau command — sensor coi mỗi lần CS HIGH→LOW là bắt đầu transaction mới, command decoder bị reset. Đoạn đọc 4 byte data trở thành 1 transaction không có command hợp lệ → data trả về là giá trị mặc định/rác cố định của sensor (giải thích vì sao lỗi lặp lại y hệt, không random).

    ✅Fix
    Fixed
    HAL_StatusTypeDef Sensor_ReadReg(SPI_HandleTypeDef *hspi, uint8_t reg, uint8_t *data)
{
    uint8_t cmd = 0x80 | reg;
    uint8_t rx_dummy;
    uint8_t tx_dummy[4] = {0};

    HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_RESET);   // CS LOW — 1 lần duy nhất
    HAL_SPI_TransmitReceive(hspi, &cmd, &rx_dummy, 1, 100);
    HAL_SPI_TransmitReceive(hspi, tx_dummy, data, 4, 100);     // cùng 1 transaction
    HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_SET);     // CS HIGH — kết thúc
    return HAL_OK;
}

    Vấn đề tiềm ẩn thứ hai: gọi 4 lần HAL_SPI_TransmitReceive riêng biệt (mỗi lần 1 byte) có overhead hàm chèn giữa các byte — nếu sensor có ràng buộc timeout tối đa giữa các byte trong 1 transaction, nên gộp thành 1 lệnh transfer 4 byte như bản fix, vừa đúng vừa hiệu quả hơn.

    ⚠️ Fact quan trọng nhất
    Clear MODF tự động tắt SPI (CR1 &= ~SPI_CR1_SPE)! Driver phải enable lại SPI thủ công sau khi xử lý xong lỗi này.
    🔧Quy trình debug 5 bước theo triệu chứng
    🔧 Bước 1 — Không có SCLK
    Kiểm tra: RCC clock của SPI instance → GPIO MODER=AF → GPIO AFR đúng số AF → SPI_CR1_SPE đã set → (nếu vẫn không có sóng) phần cứng board.
    🔧 Bước 2 — Có SCLK nhưng MOSI sai
    Kiểm tra: giá trị ghi vào DR đúng chưa → FirstBit (MSB/LSB) → DataSize khớp cách ép kiểu con trỏ ghi DR chưa.
    🔧 Bước 3 — MOSI đúng nhưng MISO sai
    Kiểm tra phía Slave: CPOL/CPHA khớp 2 bên → CS setup/hold time đủ theo datasheet Slave → bus contention (2 Slave cùng nghĩ mình được chọn).
    🔧 Bước 4 — Byte đầu đúng, byte sau sai
    Kiểm tra: CS bị thả sai thời điểm giữa các byte (xem Chương 23) → thiếu dummy byte để tạo đủ clock → OVR do gọi HAL_SPI_Transmit (bỏ qua RX) rồi Receive riêng biệt ngay sau.
    🔧 Bước 5 — Chạy lâu mới lỗi (ngẫu nhiên)
    Kiểm tra: race condition (2 task cùng gọi SPI, xem Chương RTOS) → DMA transfer count sai ở trường hợp biên (Size lẻ/chẵn, Chương 18) → FIFO overflow nếu ISR xử lý không kịp ở baud rate cao.

    SPI là gì?
    Giao thức truyền dữ liệu nối tiếp, đồng bộ, full-duplex, Master-Slave, dùng 4 dây SCLK/MOSI/MISO/CS.
    MOSI/MISO là gì?
    MOSI = Master Out Slave In (dữ liệu Master→Slave). MISO = Master In Slave Out (dữ liệu Slave→Master).
    Master/Slave là gì?
    Master chủ động tạo Clock và khởi tạo transaction; Slave bị động, chỉ phản hồi khi được chọn qua CS.
    🟡Intermediate
    CPOL/CPHA là gì?
    CPOL quyết định mức idle của Clock (LOW/HIGH). CPHA quyết định cạnh nào dùng để sample dữ liệu (cạnh 1 hay cạnh 2).
    SPI Mode là gì?
    Tổ hợp CPOL×CPHA tạo ra 4 mode (0-3), quy định chính xác cách 2 bên đồng bộ đổi/đọc dữ liệu theo Clock.
    Vì sao SPI full duplex?
    Vì có 2 dây dữ liệu riêng (MOSI, MISO) chạy song song dùng chung 1 Clock — TX và RX shift register hoạt động đồng thời mỗi cạnh clock.
    🟠Advanced
    SPI FIFO hoạt động thế nào?
    FIFO đệm giữa CPU/DMA và Shift Register, cho phép CPU nạp/lấy nhiều byte mà không cần chờ từng bit shift xong, giảm số lần CPU can thiệp.
    SPI interrupt hoạt động thế nào?
    Phần cứng set cờ (TXE/RXNE/lỗi) trong SR khi có sự kiện; nếu bit enable tương ứng trong CR2 đang bật, NVIC báo CPU nhảy vào ISR xử lý, thường qua con trỏ hàm tùy độ rộng dữ liệu.
    SPI DMA hoạt động thế nào?
    SPI tự phát "DMA request" mỗi khi TXE/RXNE set (khi TXDMAEN/RXDMAEN bật); DMA controller tự copy dữ liệu giữa RAM và DR mà không cần CPU can thiệp từng byte.
    Tại sao RX overflow (OVR)?
    Khi RX shift register latch xong 1 byte mới vào DR nhưng byte cũ trong DR chưa được CPU đọc kịp — byte cũ bị mất, cờ OVR set.
    Tại sao CS timing quan trọng?
    CS không chỉ chọn Slave mà còn là ranh giới transaction; thả CS sai thời điểm giữa các byte có thể khiến Slave reset command decoder giữa chừng, làm sai toàn bộ phần data còn lại.
    🔴Expert
    Trace SPI từ application đến register — trình bày các bước.
    Application gọi API driver → driver ghi CR1/CR2 (mode, baud, CPOL/CPHA) → enable SPE → ghi DR (hoặc bật interrupt/DMA) → Shift Register dịch bit ra MOSI theo SCLK, đồng thời nhận bit vào từ MISO → CS đánh dấu ranh giới transaction. Xem đầy đủ ở Chương 20.
    Debug SPI bằng logic analyzer — quy trình?
    Bắt đồng thời CS/SCLK/MOSI/MISO → xác định tần số SCLK, Mode (idle level + sample edge), bit order, số xung clock/byte, timing CS so với clock đầu/cuối, rồi so khớp giá trị byte thực tế với giá trị mong đợi.
    Debug race condition trong SPI driver?
    Kiểm tra: có 2 task/ISR cùng truy cập chung 1 SPI peripheral hoặc chung buffer không có mutex/critical section; kiểm tra thứ tự lock/unlock trong driver (__HAL_LOCK/__HAL_UNLOCK) có bị bỏ qua ở đường lỗi (error path) không.
