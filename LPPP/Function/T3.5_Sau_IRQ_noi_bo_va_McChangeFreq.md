## 1 · `c_intirq_table[6][2]` (`LPPP_Task.c:445-452`)

```c
const uint32_t c_intirq_table[6][2] = {
    { LPPP_INTIRQ_LPPP_NCTI_IRQ    /*SPI 64*/ , (uint32_t)&LPPP_IntIRQ_Callback       },
    { LPPP_INTIRQ_LPPP_NPMU_IRQ    /*SPI 65*/ , (uint32_t)&LPPP_IntIRQ_Callback       },
    { LPPP_INTIRQ_LPPP_NVAL_FIQ    /*SPI 66*/ , (uint32_t)&LPPP_IntIRQ_Callback       },
    { LPPP_INTIRQ_LPPP_NVAL_IRQ    /*SPI 67*/ , (uint32_t)&LPPP_IntIRQ_Callback       },
    { LPPP_INTIRQ_LPPP_MC_LPP_IRQ0 /*SPI 128*/, (uint32_t)&LPPP_McChangeFreq_handler  },   // ← DUY NHẤT khác
    { LPPP_INTIRQ_LPPP_MC_LPP_IRQ1 /*SPI 129*/, (uint32_t)&LPPP_IntIRQ_Callback       },
};
```

`LPPP_IRQ_Setting()`:
```c
for (i = 0; i < 6; i++) {
    intAttach(c_intirq_table[i][0], 0, (PFN_ISR)c_intirq_table[i][1], c_intirq_table[i][0]);
    intEnable(c_intirq_table[i][0]);
}
```
Gọi từ `LPPP_KM_Init` bước 2 (T3.3 §3). Comment `2017/07/27 M.Adachi CTバグ対応(#7691)`.

- `NCTI/NPMU/NVAL_FIQ/NVAL_IRQ` (SPI 64-67) — ngắt power-island nội bộ của LPPP (tài liệu
  `88PAQZ21 §3.2.2`; "N" = active-low). **`LPPP_AnalyzeIRQEvent` lẽ ra phải giải mã chúng thành
  internal event — nhưng chưa implement (T.B.D)**.
- `MC_LPP_IRQ0/1` (SPI 128/129) — từ lõi **M3 (Machine Control)**. IRQ0 → đổi tần số QSPI (§3);
  IRQ1 → `LPPP_IntIRQ_Callback` (hỏng).

⚠ **`MC_LPP_IRQ0` attach 2 lần:** một lần ở `LPPP_McChangeFreq_init()` (từ `main()` giai đoạn 5,
`intAttach((96+32), ...)` = SPI 128), một lần ở `LPPP_IRQ_Setting()` (từ `init_thread`). Cả 2 tới
cùng handler `LPPP_McChangeFreq_handler` → `intAttach` ghi đè, vô hại (`gic_intattach` ASSERT rỗng).

## 2 · 🔴 `LPPP_AnalyzeIRQEvent()` — hàm **KHÔNG có `return`** (`LPPP_Task.c:373-378`)

```c
LPPP_INTERNALEVT LPPP_AnalyzeIRQEvent(uint32_t ui_PortNo) {
    APPKM_DBG_MSG(... "%s() START");
    /* T.B.D:内部割込み発生時にどの割り込みかを判定し、適切な内部イベントへ変換する */
    APPKM_DBG_MSG(... "%s() END");
}   // ← KHÔNG có câu lệnh return nào. Toàn thân = 2 dòng debug + 1 comment T.B.D
```

Khai báo trả `LPPP_INTERNALEVT` nhưng **không return** → **undefined behavior**: giá trị nhận
được là **rác trong r0** (thường là kết quả của lệnh cuối — ở đây là `APPKM_DBG_MSG`/`printf`).
ARM/GCC không bật `-Werror=return-type` → **biên dịch được**.

### Bộ lọc phía sau (`LPPP_IntIRQ_Callback`, `LPPP_Task.c:398-404`)
```c
intr_event = LPPP_AnalyzeIRQEvent(ui_isr_input);         // rác
if ((LPPP_INTERNALEVT_PWR_SW_OFF /*0*/ > intr_event) ||
    (LPPP_INTERNALEVT_MAX /*10*/  <= intr_event)) {
    APPKM_DBG_MSG(... "Error:LPPP_AnalyzeIRQEvent() return %d");
    return;                                              // lọc phần lớn rác
}
xQueueSendFromISR(gst_MsgQHandle_PowerCtrl, &intr_event, &woken);   // ⚠ nếu rác ∈ [0,9]
```

**Đánh giá nguy hiểm thật:**
| | |
|---|---|
| Xác suất rác rơi vào `[0,9]` | thấp nhưng **khác 0** — nếu trúng → **transition SAI ngẫu nhiên** bơm vào SM |
| Hệ quả nếu trúng | ví dụ rác = `2` (`GO_TO_S1`) khi đang NORMAL → chạy `TR3` (cắt I2S) không đúng lúc; rác = `7` (`PWR_FLICKER`) → `TR2b` có thể reset cứng CA72 nếu `ap_sd==NO_BOOT` |
| Giảm nhẹ thực tế | 4 ngắt `NCTI/NPMU/NVAL_*` là ngắt power-island; chuỗi ErP giờ "handled by Marvell" (`pmu_phase`) nên **có thể gần như không bao giờ bắn** trong firmware hiện tại — _(INFERENCE — chưa xác minh bằng đo)_ |
| `MC_LPP_IRQ1` | cũng vào `LPPP_IntIRQ_Callback` hỏng → nếu M3 kích IRQ1, cùng rủi ro |

Đúng phải là: `LPPP_AnalyzeIRQEvent` return `LPPP_INTERNALEVT_INVALID` mặc định + `switch(ui_PortNo)`.

## 3 · `LPPP_McChangeFreq.c` — đổi tần số QSPI của M3 (thương lượng clock liên lõi)

### 3.1 · Bài toán
Lõi **M3 (Machine Control)** muốn đổi tần số **`mc_qsclk`** (clock QSPI của nó) — ví dụ để tiết
kiệm điện. Nhưng thanh ghi PMU clock **thuộc miền của R4**, M3 không chạm được. ⇒ M3 ghi tần số
đích vào **shared memory**, kích `MC_LPP_IRQ0` (SPI 128) → R4 cấu hình hộ rồi báo lại.

### 3.2 · `LPPP_McChangeFreq_init()` (từ `main()` giai đoạn 5)
```c
if (LPPP_McChangeFreq_init_flg) return;        // chỉ init 1 lần (2018/01/11)
LPPP_McChangeFreq_init_flg = 1;
LPPP_mc_window_set();                          // MODE_CF0 → MC D-SRAM1 (MECH_SHARE_MEM_BASEADDR)
intAttach((96+32) /*SPI 128*/, 0, LPPP_McChangeFreq_handler, (96+32));
intEnable((96+32));
// khối #if 0: polling GIC Set-Pending Reg 0xe8261210 tối đa 2s lúc boot — "Marvell対応で早期検知" nên bỏ
```

### 3.3 · `LPPP_McChangeFreq_handler(isr_input)` — chạy trong **ISR context**
```
① LPPP_mc_window_set()                         mở cửa sổ shared-mem MC
② div = *(MECH_CONTROL_WINDOW_BASEADDR + LPPP_OFS + FROM_MC1_OFS)   ← tần số đích M3 ghi vào
③ div = MC_PLL_CLK / div                       tính tỉ số chia
④ if (div < MC_QSCLK_DIV_MIN || div > MC_QSCLK_DIV_MAX):
      "Error!!" ; return  ← KHÔNG gửi thông báo hoàn tất
⑤ Cấu hình mc_qsclk bằng GHI THANH GHI TRỰC TIẾP (PMU_CLK_RST_GEN_BASEADDR + MC_QSCLK_CONFIG_OFS):
      CLKEN = 0                                 tắt clock
      div /= 2  (mc_qsclk luôn chia 2 bất kể PREDIVEN)
      LODIV, HIDIV = div/2 (+1 nếu lẻ)          chia đôi high/low
      PREDIVEN = 1
      CLKEN = 1                                 bật lại
   // #else: pmu_set_clock(pmu_mc_qsclk, ...) — bị bỏ vì "pmu_lib中にこの割込みが入ると固まる" (2018/01/11)
⑥ poll MC_QSCLK_STATUS.CLKGATE clear, timeout = CLK_STATUS_TIMEOUT + 5 tick  (OP_BTS-28610)
      xTaskGetTickCountFromISR() ; timeout → return KHÔNG gửi thông báo
⑦ *(PULSE_TX_BASEADDR + PULSE_TX_SET_SUB_MAIN_OFS) |= PULSE_TX_SET_SUB_MAIN_LPPP
   ← ★ "pulse doorbell" báo M3: "đổi tần số QSPI xong"
```

**Chi tiết đáng chú ý:**
- **Ghi thanh ghi trực tiếp thay vì `pmu_set_clock()`** (comment `2018/01/11`): nếu ISR này bắn
  đúng lúc `pmu_lib` đang chạy và cũng gọi `pmu_lib` → **treo** (pmu_lib không reentrant). Đây là
  cùng lý do `LPPP_traceclk_set()` ghi thẳng `*(uint32_t*)0xE82401A8 |= 0x00040403`.
- **Thất bại im lặng có chủ ý:** ở bước ④ (div out-of-range) và ⑥ (timeout) → `return` mà
  **không gửi pulse hoàn tất** → M3 sẽ tự biết là chưa xong (timeout phía M3).
- `xTaskGetTickCountFromISR()` dùng trong ISR — đúng API (khác `AppMhuTest` dùng sai).

### 3.4 · Hàm phụ (không trong `c_intirq_table`)
- `LPPP_traceclk_set()` — `*(uint32_t*)0xE82401A8 |= 0x00040403` (trace clock; ghi thẳng vì `pmu_set_clock` treo)
- `LPPP_mc_spi_clk_set()` — `pmu_set_clock(pmu_mc_spi_clk_0/1, no_change, 8, NO_CHANGE)` (đặt divider MC SPI0/1 = 8)
- `LPPP_mc_window_set()` — cấu hình MODE_CF0 để cửa sổ shared-mem trỏ vào MC D-SRAM1

## 4 · Tóm tắt (theo format skill)

**1. Tồn tại để làm gì:**
- **6 IRQ nội bộ:** `LPPP_IRQ_Setting` attach 6 ngắt. 5/6 vào `LPPP_IntIRQ_Callback` — mà callback
  này gọi `LPPP_AnalyzeIRQEvent` **không hề có `return`** (chỉ T.B.D + 2 debug print) → nhận rác
  r0; range-check `[0,9]` lọc phần lớn, nhưng nếu rác trúng dải → transition SAI ngẫu nhiên vào
  state machine. 4 ngắt `NCTI/NPMU/NVAL_*` có lẽ gần như không bắn (chuỗi ErP đã sang `pmu_phase`).
- **`LPPP_McChangeFreq`:** `MC_LPP_IRQ0` (SPI 128) từ M3 → R4 đọc tần số đích từ shared-mem MC,
  cấu hình thanh ghi `mc_qsclk` PMU **trực tiếp** (tránh `pmu_lib` không reentrant), poll settle
  có timeout, rồi pulse doorbell (`PULSE_TX`) báo M3 xong. Thương lượng clock liên lõi vì M3
  không chạm được thanh ghi PMU của R4.

**2. Call flow:**
```
── 6 IRQ ──
LPPP_KM_Init → LPPP_IRQ_Setting → for 6: intAttach + intEnable
  SPI 64-67 (NCTI/NPMU/NVAL_FIQ/NVAL_IRQ) + SPI 129 (MC_LPP_IRQ1) → LPPP_IntIRQ_Callback:
     intr_event = LPPP_AnalyzeIRQEvent(port)   ← 🔴 KHÔNG return → rác
     if (0 <= intr_event < 10)  xQueueSendFromISR(gst_MsgQHandle_PowerCtrl, intr_event)
  SPI 128 (MC_LPP_IRQ0) → LPPP_McChangeFreq_handler

── MC change-freq ──
main() giai đoạn 5 → LPPP_McChangeFreq_init → mc_window_set + intAttach(SPI 128)
M3 ghi tần số → MC_LPP_IRQ0 → LPPP_McChangeFreq_handler [ISR]:
   đọc div từ shared-mem → MC_PLL_CLK/div → range check
   → ghi mc_qsclk CONFIG (CLKEN=0 → LODIV/HIDIV/PREDIVEN → CLKEN=1)
   → poll CLKGATE clear (timeout CLK_STATUS_TIMEOUT+5tick)
   → PULSE_TX_SET_SUB_MAIN |= LPPP   (báo M3 xong)
```
